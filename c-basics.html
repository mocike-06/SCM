C 语言基础入门（变量、类型、运算符、流程控制）

系列：C 语言基础 入门 更新：2026-10-25

学习路线的第 1 站。学完本课你会写出第一个 C 程序，看懂变量、数据类型、运算符和 if/while/for 流程控制，并能在 Keil 里编译运行——这是进入 51 单片机开发前必须夯实的语言地基。

一、本课目标与前置知识

学完本课你能做到：

  • 说清「变量」「数据类型」「表达式」是什么，并正确声明与使用它们。
  • 分清 if / while / for 三种流程控制，写出带条件判断和循环的程序。
  • 在 Keil C51 里新建工程，编译运行一个 LED 闪烁程序，看到真实硬件反应。

需要提前掌握的前置知识：

  • 会用电脑、能安装软件（本课会带你在 Keil 里练习，也可用在线 C 编译器先跑标准 C）。
  • 不需要任何单片机知识——本课就是为零基础准备的，后面的 51 教程会把 C 语法和硬件联系起来。

本课会出现的新名词（下面逐一讲解）：程序、语句、变量、数据类型、运算符、表达式、流程控制、编译、main 函数。

二、基础概念铺垫

1. 程序、语句与 main 函数

生活类比：程序就像一份「做菜的菜谱」，语句就是一行一行的「步骤」，而 main 函数是「厨师开工的入口」——电脑/单片机永远从 main 函数第一行开始执行。

一句话定义：程序 = 一系列按顺序执行的语句；C 程序必须有且只有一个 main 函数，它是程序执行的起点。每条语句以分号 ; 结尾。

例子：LED = 0; 是一条语句，意思「把 LED 这个引脚置为低电平」；return 0; 表示程序正常结束。

2. 变量：给数据起名字的「储物格」

生活类比：变量就像一个贴了标签的储物格。格子有固定大小（决定能装多大数），标签就是变量名。你往格子里放东西叫赋值，看格子里有什么叫读取。

一句话定义：变量是内存中一块有名字、有类型的存储空间。unsigned char cnt = 0; 表示：开一个叫 cnt 的格子，类型是「无符号字符」（0~255），初始放 0。单片机开发 90% 的变量都是 unsigned char（8 位）和 unsigned int（16 位）。

例子：unsigned char i; 声明变量；i = 3; 赋值；i = i + 1; 把 i 的值加 1 再存回去。

3. 数据类型：格子的「容量规格」

生活类比：储物格有「小格（8 位）」和「大格（16 位）」两种规格。小格最多放 0~255 或 -128~127，放不下会「溢出」（像里程表从 99999 跳回 00000）。

一句话定义：数据类型决定变量占几个字节、能表示什么范围。51 单片机最常用：unsigned char（0~255，8 位）、signed char（-128~127）、unsigned int（0~65535，16 位）、bit（0/1，Keil 特有）、sbit（可位寻址引脚，Keil 特有）。

例子：unsigned int t = 60000; 合法；unsigned char t = 60000; 会溢出成 34496-256×134≈200，结果错误——选错类型是新手写 bug 的高发原因。

谭浩强教材要点：负数在内存里用补码存放。以 signed char（8 位）为例：正数 5 存成 0000 0101；负数 −5 不是直接存「负号+5」，而是「取反加 1」：对 0000 0101 逐位取反得 1111 1010、再加 1 得 1111 1011（0xFB）。这就是为什么 signed char 读 0xFB 会得到 −5 而不是 251。范围 −128~127 的边界：1000 0000 表示 −128，0111 1111 表示 127。DS18B20 负温按补码处理（见对应课）就是同一套原理。unsigned 与 signed 混算时默认按 unsigned 解释，这是 51 程序里有符号数突然变大正数的常见根因。

4. 运算符与表达式

生活类比：运算符就是「加减乘除、比较大小」这些动作符号。由运算符把变量和数字连起来组成的式子叫表达式，它一定算出一个结果。

一句话定义：常见几类：算术 + - * / %；赋值 =、+=；比较 == != > < >= <=；逻辑 && || !。注意：单等号 = 是赋值，双等号 == 才是「相等比较」，写混是新手第一大坑。

例子：a = b + 1; 是「把 b 加 1 的结果存进 a」；if (a == 1) 是「判断 a 是否等于 1」。而 if (a = 1) 会把 1 赋给 a，条件永远成立——程序行为立刻错乱。

教材运算符优先级速记（谭书）：从高到低大致为「单目(!、~、++、−) > 算术(*、/、%) > 算术(+、−) > 关系(<、>、<=、>=) > 关系(==、!=) > 逻辑(&&) > 逻辑(||) > 赋值(=、+=)」。所以 a = b > c && d 实际是 a = ((b > c) && d)。最稳妥的写法：拿不准优先级就加括号，别靠背——这也是嵌入式代码里到处是括号的原因。

5. 流程控制：顺序、分支、循环

生活类比：程序默认从上往下「顺序」执行；if 是「十字路口」——满足条件走 A 路，不满足走 B 路；while/for 是「绕圈跑」——跑到指定圈数或条件不再满足才停。

一句话定义：if (条件) { … } else { … } 做分支；while (条件) { … } 先判断再循环；for (初值; 条件; 步进) { … } 适合「固定次数」的循环。单片机里最经典的就是 while (1) { … }——永远循环执行，这是单片机程序的常态（上电后不停工作）。

例子：LED 闪烁的核心就是 while (1) { 亮; 延时; 灭; 延时; }，永远循环下去。

三、原理介绍：你写的变量和代码，在芯片里各待在哪、又是怎么被跑起来的

C 源码不能直接被单片机执行，要经过：编译(Keil 翻成机器码出 hex) → 烧录(写进 Flash) → 运行(上电从 main 开始一条条取指)。但更值得懂的是：代码和变量在芯片里待在两个不同的地方。

原理 1：编译后程序被拆成「代码段 / 数据段 / 栈」三块

编译链接完成后，你的程序在芯片里是这样分布的：

  • 代码段（Flash）：所有函数指令、code 修饰的常量/段码表——烧进 Flash，掉电不丢，CPU 上电从这里取指。
  • 数据段（RAM）：已赋初值的全局变量，上电时由启动代码从 Flash 复制到 RAM，之后在这里被读写。
  • 栈（RAM）：函数调用、局部变量、返回地址用的临时空间，从栈顶往下生长。

为什么要分清：Flash 慢但不丢、RAM 快但掉电即丢。这决定了——不变的查表数据放 code（省 RAM），要反复改的变量放 RAM。51 内部 RAM 只有 128 字节，栈稍微用狠了就溢出踩坏别的变量，所以嵌入式里「省着用 RAM」是硬约束。

原理 2：变量的生命周期——局部变量为什么出了函数就消失

unsigned char t; 这种写在函数里面的局部变量，存在栈上：进函数时在栈顶腾一块、用；函数一返回，栈就回收，那块空间立刻可被下次调用复用——所以函数外根本读不到它，上次的值也不保留。而写在函数外面的全局变量，存在数据段、整个程序生命周期都在，任何函数都能读写。这就是为什么「想在中断和主循环之间共享一个计数」必须用全局变量——局部变量一出函数就没了，中断里根本见不到主循环那个 cnt。

原理 3：CPU 跑程序的本质——PC 指针一条条往下取指

所谓「程序在跑」，其实是 CPU 里一个叫 PC（程序计数器） 的寄存器：它存着「下一条指令在 Flash 的哪个地址」，CPU 取出该指令执行，PC 自动加 1 指向下一条。遇到 while(1)，编译出的机器码就是「跳回前面地址」——PC 永远绕回原处，这就是单片机没有「程序结束」、必须死循环的底层原因。遇到 if/for，本质是机器码按条件改不改 PC 的跳转目标。所以「写 C」真正在做两件事：控制数据(变量怎么变)、控制 PC(什么时候跳、做什么)。

记忆点：程序=代码段(Flash,指令+code常量,掉电不丢)+数据段(RAM,全局变量)+栈(RAM,局部变量,函数返回即回收)；局部变量出函数就消失、跨函数共享必须用全局；CPU靠PC指针一条条取指，while(1)=让PC永远跳回、单片机没有「结束」。

方式适合人群说明

五、完整代码

先看一个最简标准 C 程序（在线编译器可跑），理解程序骨架：

/* 示例 1：最简 C 程序——打印一行字 */
#include <stdio.h>              /* 包含标准输入输出头文件，printf 靠它 */

int main(void)                  /* 程序入口，void 表示不接收参数 */
{
    printf("Hello McuStudy!\n"); /* 输出一行文字，\n 表示换行 */
    return 0;                    /* 返回 0，表示程序正常结束 */
}

再看 51 单片机版：用变量 + 流程控制实现 LED 闪烁，这是本课练习的核心（用 P1.0 外接 LED，共地接法，写 0 亮）：

/* 示例 2：51 LED 闪烁——综合运用变量/运算符/流程控制 */
#include <reg52.h>              /* 51 单片机寄存器定义头文件 */
sbit LED = P1^0;                /* 把 P1.0 引脚改名为 LED */

void delay_ms(unsigned int ms)  /* 自定义函数：软件延时 ms 毫秒 */
{
    unsigned int i, j;          /* 局部变量：循环计数器 */
    for (i = 0; i < ms; i++)    /* 外层循环 ms 次 */
        for (j = 0; j < 120; j++); /* 内层空循环约 1ms */
}

void main(void)                 /* 51 程序入口 */
{
    unsigned char count = 0;    /* 变量：记录闪烁次数（0~255） */
    while (1)                   /* 永远循环：单片机程序常态 */
    {
        LED = 0;                /* 赋值语句：低电平点亮 LED */
        delay_ms(500);          /* 函数调用：延时 500ms */
        LED = 1;                /* 高电平熄灭 LED */
        delay_ms(500);
        count = count + 1;      /* 每闪一次计数加 1 */
        if (count >= 10)       /* 分支判断：闪够 10 次后…… */
            LED = 0;            /* 保持常亮（示意，可自行改逻辑） */
    }
}

六、代码逐段讲解

第一段：头文件与引脚改名

#include <reg52.h> 把 51 单片机的「寄存器名字表」包含进来，这样你写 P1 编译器才知道它指端口 1。sbit LED = P1^0; 是 Keil 特有的写法：给 P1 口的第 0 位起一个更形象的名字。如果不写这两行，后面所有 LED 都无法识别。

第二段：延时函数

void delay_ms(unsigned int ms) 定义了一个「空转等待」的函数：双层 for 循环让 CPU 什么也不做地数数，大约每轮 1ms。unsigned int 表示 ms 最大能到 65535。为什么要它：单片机执行语句极快（微秒级），不加延时 LED 亮灭快得看不见；不写会怎样：程序直接崩在肉眼不可见的闪烁上。

第三段：main 里的循环与分支

while (1) 是单片机的「主旋律」：上电后永远在这里面转。LED 赋值 + 延时组成一次闪烁；count = count + 1; 演示变量自增（等价 count++）；if (count >= 10) 演示分支——注意这里用的是 >=（大于等于），如果手滑写成 count = 10，就成了赋值，条件恒成立，程序行为立刻异常。

关于示例 1 与示例 2 的区别

示例 1 是「纯计算型」程序，用 printf 把结果打印到屏幕；示例 2 是「控制型」程序，用赋值语句直接改变硬件引脚电平。单片机世界里 90% 是示例 2 这种「写引脚 + 读引脚 + 循环判断」的写法，这就是为什么变量、if、while 必须学扎实。

七、现象演示与验证

  • 示例 1（标准 C）：编译运行后屏幕输出 Hello McuStudy!。
  • 示例 2（51）：烧录后 P1.0 上的 LED 以约 1Hz 频率闪烁（亮 0.5s 灭 0.5s）；闪够 10 次后保持常亮。

验证方法（强烈建议做）：

  1. 把 delay_ms(500) 改成 delay_ms(100) 重新编译烧录，LED 应变快 5 倍——证明延时函数确实在起作用。
  2. 把 if (count >= 10) 改成 if (count == 10)，行为不变（第 10 次后常亮）；再故意改成 if (count = 10)，程序会立即错乱——亲手踩一次这个坑，比看十遍教程都记得牢。

八、常见报错排查方案

报错现象可能原因解决方法
编译报 undefined identifier 'LED'漏写 #include <reg52.h> 或 sbit 定义在文件开头补上头文件与 sbit LED = P1^0;
程序运行结果完全不对 / 条件永远成立= 与 == 写混检查所有 if 条件，比较一律用 ==
编译报 missing ';'上一条语句漏了分号看报错提示的行号，在该行或上一行末尾补 ;
变量值突然变成奇怪的大数类型太小发生溢出（如 unsigned char 存 300）改用 unsigned int，或先判断数值范围再选类型
LED 常亮不闪延时太短（肉眼看不出来）或 while(1) 里逻辑写错先加大延时到 1000 试；再检查是否 LED 赋值被后面的语句覆盖
学标准 C 时 scanf 输入后程序崩/读不到值scanf("%d", n); 漏了取地址符 &（应为 &n）scanf 要的是变量地址：scanf("%d", &n);；漏 & 会把读到的数写到地址 0 附近，轻则乱码重则崩溃——谭书第一学期经典错

九、课后练习与延伸

练习 1（必做）：把示例 2 的闪烁间隔改成「亮 200ms、灭 800ms」的不对称闪烁，体会延时参数对现象的影响。

练习 2：新增一个变量 unsigned int total，在 while(1) 里让它每循环一次加 1；当 total 超过 1000 时让 LED 反转一次并清零 total。用 if 分支实现。

练习 3（进阶）：写一个函数 unsigned char add(unsigned char a, unsigned char b) 返回两数之和，在 main 里调用并借助 P1 = add(3, 5); 观察 P1 口对应 LED 亮法（3+5=8，对应 P1 输出 0x08）。

延伸学习：下一课学《数组与指针》——流水灯花样数组和字符串处理全靠它；同时可打开 在线工具-进制转换器 边学边换算 0xFE、0x08 这类十六进制数。
