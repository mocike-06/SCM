EEPROM/NVS 掉电存储

系列：ESP32 进阶 更新：2026-10-25

WiFi 密码、设备编号、开机次数、传感器校准值——这些数据断电就丢，每次重启都要重新配网，体验很差。ESP32 有 NVS（非易失存储）分区，专门保存这类「小配置数据」。本课讲透 RAM vs Flash 的区别，教 Preferences 库的读写用法，做一个「开机次数计数器 + 记住配网信息」的完整示例。

一、本课目标与前置知识

学完本课你能做到：

  • 说清 RAM、Flash、EEPROM 的区别，理解「掉电存储」的硬件本质。
  • 会用 Preferences 库（NVS）读写 int/float/String，会删除键。
  • 做开机次数计数器和 WiFi 配网信息持久化。

需要提前掌握的前置知识（对应学习路线阶段 5）：

  • WiFi 基础（esp32-wifi.html）：本课的配网持久化依赖 WiFi.begin(ssid, pwd)。
  • 中断与定时（esp32-interrupt.html）：结合练习会用到 volatile 与按键。
  • C 语言字符串：Preferences 用字符串做键名。

本课会出现的新名词：RAM、Flash、EEPROM、NVS、Preferences、命名空间/键、putInt/getInt、begin/end、擦写寿命。

二、基础概念铺垫

1. RAM vs Flash：记忆的两张桌子

生活类比：RAM 是「白板」（写上去快、擦掉也快、擦黑板=断电全没）；Flash 是「笔记本」（写上去慢、要整页擦、但合上本子=断电内容还在）。程序跑的时候在白板上打草稿，重要的配置抄进笔记本。

一句话定义：RAM（内存）：断电丢失，变量都住这；Flash（闪存）：断电保留，程序本体就存在 Flash 里。ESP32 的 NVS 就是 Flash 里专门划出的一个小分区，用来存配置数据。

例子：你 loop 里的变量 count 放 RAM，断电归零；用 Preferences 存的 count 放 Flash 的 NVS，断电保留。

2. NVS 与 Preferences：ESP32 的「官方笔记本」

一句话定义：NVS（Non-Volatile Storage，非易失存储）是 ESP32 固件里 Flash 的一个分区，专门存键值对数据；Preferences 库 是 Arduino 环境下操作 NVS 的官方库——像一个小型「设置中心」，按「命名空间 + 键」存取任意类型数据。

例子：命名空间 "device" 下存 "bootCount"（整数）和 "ssid"（字符串）——两个键互不干扰。

3. Preferences 的五步法：begin → put → get → 可选 remove → end

一句话定义：preferences.begin("命名空间", 只读模式) 打开一个命名空间；putInt/putFloat/putString(键, 值) 写入；getInt/getFloat/getString(键, 默认值) 读取（键不存在返回默认值）；remove(键) 删除；end() 关闭。写模式用 false（默认），读模式 true。

例子：prefs.begin("cfg", false); prefs.putInt("boot", 3); int b = prefs.getInt("boot", 0); prefs.end();

4. 擦写寿命：笔记本的页数有限

一句话定义：Flash 每个扇区的擦写次数有限（W25Q64 约 10 万次）。虽然 ESP32 的 NVS 有磨损均衡设计，但不要在 loop 里高频 put（每秒写 NVS 会提前耗尽寿命）；配置类数据「变了才写、上电才读」即可。写太频繁还会拖慢程序（一次 NVS 写入几 ms）。

例子：开机计数器每次上电写一次没问题；但如果每秒写一次，一年 3000 万次——几个月就把寿命写没了。

5. NVS vs SPIFFS/FFat：存「小配置」还是存「大文件」

生活类比：NVS 像手机的「设置项」（开关、密码几个字），键值对、小而快；SPIFFS/FFat 像手机的「文件系统」，能存网页、图片、日志这种大块文件——两者都住在 Flash 里，但分工不同。

一句话定义：ESP32 的 Flash 存储空间分两类用法——NVS：键值存储，适合几字节~几百字节的配置（WiFi 密码、开机次数）；SPIFFS / FFat：在 Flash 上跑的小型文件系统，适合存 HTML 网页、CSS、传感器日志等「按文件名读写」的大块数据。课程设计做 Web 服务器时用的网页文件就放在 SPIFFS 里。

例子：存 WiFi 密码用 NVS（Preferences）；存一个 index.html 网页文件给 Web 服务器用，就用 SPIFFS（SPIFFS.open("/index.html")）。两者的底层都是 Flash，也都有磨损均衡，区别只在「键值 vs 文件」的抽象层。

三、原理介绍：一次 NVS 读写到底发生了什么

ESP32 没有独立的 EEPROM 芯片，所谓「掉电存储」其实都写在同一块 Flash 里。Preferences 是乐鑫官方 NVS（Non-Volatile Storage，非易失存储）的 Arduino 封装。理解 Flash「只能整片擦除、写前必须先擦」的物理特性，才能理解 NVS 为什么用键值对、为什么要磨损均衡。

一次保存配置的链路：begin 打开命名空间 → put 写一条键值 → end 提交 → 数据落在 Flash 的 NVS 分区，断电不丢。

原理 1：Flash 的物理限制——为什么不能直接改一个字节

Flash 存储器有个硬特性：写入只能把 1 变成 0，擦除才能把 0 变回 1，而擦除必须按整块（sector，一般 4KB）进行。这意味着你想把已存的 count=7 改成 count=8，不能「原地改一个字节」——那一位从 1→0 可以，从 0→1 就得把整个 4KB 块擦掉重写。NVS 的解法是追加式写入：旧条目标记为废弃，新键值写到旁边的新位置，整个块写满后才擦除回收。

原理 2：键值条目与命名空间——为什么用字符串 key 而不是地址

NVS 里存的是一条条「键名 → 二进制值」的小记录：putInt("count", 7) 就是写一条 count=7；getInt("count", 0) 按键名查回来。命名空间（begin 的第一个参数，≤15 字符）是隔离不同模块的文件夹——WiFi 模块存自己的 key、你的程序存自己的，互不覆盖。这比传统 EEPROM「按字节地址存」友好得多：不用记「配置存在偏移 0x100 还是 0x200」。

原理 3：磨损均衡与写寿命——为什么不能 loop 里高频写

Flash 每个块大约只能擦写 1 万次就会老化。如果每次都擦同一块，这块很快就坏了。NVS 的磨损均衡机制是：把写入均匀分散到 NVS 分区的各个块，轮流擦写，整体寿命被摊薄。但这救不了「高频写」——如果你 loop 里每秒 putInt 一次，理论上几万秒就把分区写穿了。工程规矩：只在配置改变时写一次、写完 end；温度采集这类高频数据不要每条都存 NVS。

记忆点：Flash 写 1→0 容易、0→1 必须整块擦；NVS 用追加式写入+磨损均衡绕开这个限制；存的是「键名→值」条目，命名空间隔离模块；Flash 寿命约 1 万次擦写，别在 loop 高频写。

四、硬件接线说明

本课纯软件功能（NVS 在芯片内部 Flash），只需要观察设备：

模块接线说明
USB 串口板载 CH340/CP210x串口 115200 打印计数与配网状态
按键（练习用）GPIO15 接 GND触发写入动作
LED（可选）GPIO4配网成功指示

为什么不需要额外接线：NVS 是芯片内置 Flash 分区，没有任何外部引脚。你看到的现象全在串口：开机次数递增、配网成功后连上路由器——这正好说明「掉电存储」是纯软件 + 芯片硬件的能力。

避坑 重复烧录会怎样：普通烧录不擦除 NVS 分区，计数器会继续累加；勾选「Erase All Flash Before Upload」或擦除整片后 NVS 清空，计数归零——排查「为什么重启后数据没了」先想到是不是整片擦除过。

五、完整代码

示例 1：开机次数计数器（每次上电 +1）

/* 开机计数器：NVS 持久化，断电不归零 */
#include <Preferences.h>

Preferences prefs;              /* 全局对象 */

void setup() {
  Serial.begin(115200);

  /* 1. 打开命名空间 "device"（false = 读写模式） */
  prefs.begin("device", false);

  /* 2. 读上次计数（不存在则默认 0） */
  int bootCount = prefs.getInt("bootCount", 0);

  /* 3. 计数 +1 并写回 */
  bootCount++;
  prefs.putInt("bootCount", bootCount);

  /* 4. 关闭（把数据真正落进 Flash） */
  prefs.end();

  Serial.printf("Boot count = %d\n", bootCount);
}

void loop() {
  /* 什么都不用做：配置读取都在 setup 完成 */
}

示例 2：WiFi 配网信息持久化（记住 SSID 与密码）

/* WiFi 配置持久化：先读 NVS，没有则用默认值 */
#include <Preferences.h>
#include <WiFi.h>

Preferences prefs;

/* 默认配置（首次上电用；之后以 NVS 里的为准） */
const char *DEF_SSID = "your_wifi";
const char *DEF_PWD  = "your_password";

String ssid, pwd;

void loadConfig() {
  prefs.begin("wifi", false);          /* 打开命名空间 */
  ssid = prefs.getString("ssid", DEF_SSID);  /* 读，缺省用默认 */
  pwd  = prefs.getString("pwd",  DEF_PWD);
  prefs.end();
  Serial.printf("SSID=%s\n", ssid.c_str());
}

void saveConfig(const char *s, const char *p) {
  prefs.begin("wifi", false);
  prefs.putString("ssid", s);          /* 写入新值 */
  prefs.putString("pwd",  p);
  prefs.end();
  Serial.println("Config saved.");
}

void setup() {
  Serial.begin(115200);
  loadConfig();                        /* 上电读配置 */
  WiFi.begin(ssid.c_str(), pwd.c_str());  /* 用存的配置连网 */
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println("\nConnected!");
  /* saveConfig 可放这里演示：把当前配置写回 NVS（改密码场景） */
}

void loop() {
}

六、代码逐段讲解

第一段：getInt 的默认值参数

prefs.getInt("bootCount", 0) 的第二个参数是关键设计：键不存在时返回 0。为什么必须有默认值：首次烧录时 NVS 是空的，没有 bootCount 键——没有默认值就会读到垃圾或崩溃；有了默认值，「首次上电 = 从 0 开始」的语义就清晰了。所有 get 都该给默认值，这是 Preferences 的规范用法。

第二段：putInt + end 的「落盘」时机

bootCount++; prefs.putInt(...); prefs.end(); 三连。为什么先读、改、再写：NVS 是按键覆盖写，不存在「自增」指令——你必须先 get 出来、内存里加 1、再 put 回去（读-改-写）。为什么 end 不能省：end 把缓冲区真正刷进 Flash；不 end 就断电，这次计数可能没存上。

第三段：getString 的 String 对象

prefs.getString("ssid", DEF_SSID) 返回 String 对象，然后 ssid.c_str() 转成 C 字符串给 WiFi.begin。为什么要有 c_str()：WiFi.begin 需要 const char*，而 Preferences 返回的是 String——类型不匹配，必须转。小坑：String 用完注意内存（ESP32 内存够用，但别在循环里频繁拼 String）。

第四段：saveConfig 的「变更才写」思想

示例 2 里 saveConfig 只在你主动改配置时调用——这正是第 2 章「别高频写」的落地。为什么读要频繁、写要克制：读不损耗 Flash，写会；每次上电 loadConfig 一次、改动 saveConfig 一次，就是最优频率。

七、现象演示与验证

  • 计数器：串口每次上电打印 Boot count = 1、2、3… 递增；断电重启不归零。
  • 配网：首次用默认 SSID/密码连网（连不上会一直打点，先改成你自己的 WiFi）；配置存在 NVS，重启后仍用同一配置。

验证方法：

  1. 烧录示例 1 → 重启 3 次 → 计数 1、2、3；点 ESP32 的 Reset 键（软复位）计数继续加——证明 NVS 持久化。
  2. 在 Arduino IDE 勾选「Erase All Flash」再烧录 → 计数从 1 重新开始——理解整片擦除与 NVS 的关系。
  3. 在示例 2 串口里加指令：输入新 SSID/密码调用 saveConfig，重启后用新配置连接——模拟「配网保存」流程。

八、常见报错排查方案

报错现象可能原因解决方法
数据断电后丢了烧录时擦了整片 Flash / 没 end()别勾 Erase All Flash；确保写入后 prefs.end()
getInt 返回乱码/崩溃键不存在且没给默认值get 时总带默认值参数（第二个参数）
写入失败无反应命名空间名超长（≤15 字符）/ 键名超长命名空间 ≤15、键名 ≤15 字符，用简短英文名
loop 里写 NVS 后程序变卡写入耗时长且频繁（每次几 ms）配置「变更才写」，别每秒写；重活放主循环外
数据读到旧值上次写入未 end 就断电 / 多命名空间同名键保证 end；命名空间唯一，别乱复用
重启计数有时不增断电发生在 put 与 end 之间把 put+end 放同一步，尽量靠近逻辑终点

九、课后练习与延伸

练习 1（必做）：把开机计数器改成「累计运行秒数」：loop 里每秒 get+put（注意这是演示，工程上应 30s 才写一次），断电再开看秒数续传。

练习 2：结合 按键中断：按键按一次把 pressCount 存 NVS，重启不归零——中断 + 持久化计数器。

练习 3（进阶）：把示例 2 扩展成「配网模式」：首次上电无有效配置时开 AP 热点，手机连上后通过串口/网页输入 WiFi 密码，saveConfig 保存——这是智能硬件「一键配网」的雏形（结合 WiFi 教程）。

延伸学习：会存数据了，下一课学 Deep Sleep 低功耗——电池供电设备怎么把「数据 + 省电」结合起来，是物联网落地的最后一环。
