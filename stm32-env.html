Keil MDK 环境搭建（STM32F103）

系列：STM32 入门 更新：2026-10-24

学 STM32 的第一步不是写代码，而是把开发环境跑通。本讲从零讲清楚 Keil MDK、STM32CubeMX、HAL 库各自是干什么的，CubeMX 生成的工程文件夹里每个文件是什么，时钟树为什么必须配到 72MHz，3.3V 和 5V 有什么区别，以及 ST-Link 怎么用 SWD 把第一个程序烧进芯片。装好这一套，后面 7 篇实验都不用再动环境。

一、本课目标与前置知识

学完本课你能做到：

  • 说清楚 Keil MDK、STM32CubeMX、HAL 库三件套各自负责什么，不再把它们混成一个软件。
  • 独立完成「CubeMX 选芯片 → 配时钟 → 生成工程 → Keil 编译 → ST-Link 下载」完整流程。
  • 让 PA5 上的 LED 以 1Hz 闪烁，证明整条「写代码—编译—烧录—运行」链路通畅。

需要提前掌握的前置知识：

  • C 语言基础（阶段 1）：认识 main 函数、头文件、while 循环——本讲代码非常短，能读懂即可。
  • 51 单片机基础（阶段 2）：知道什么是编译、烧录、单片机最小系统——STM32 概念类似，只是工具链更现代。

本课会出现的新名词（下面逐一讲解）：Keil MDK、CubeMX、HAL 库、器件包 DFP、工程结构（main.c / stm32f1xx_hal_msp.c）、时钟树、HSE/PLL、72MHz、3.3V 电平、SWD、ST-Link。

二、基础概念铺垫

1. Keil MDK：写代码、编译、下载的「总工作台」

生活类比：Keil MDK 就像 Word——你在里面写稿子（C 代码），点一下「打印」（编译），它把稿子排版印成成品（可烧录的 hex），再通过一根线送到打印机（ST-Link 烧进芯片）。

一句话定义：Keil MDK-ARM（μVision）是 ARM 单片机的集成开发环境（IDE），集编辑器、编译器、下载调试器于一身，你最终双击打开的那个 .uvprojx 工程文件就归它管。

例子：本讲最后我们在 Keil 里按 F7 编译、按 F8 下载，用的就是 MDK。它本体只带编译器，不认识具体芯片，所以要装下一条讲的器件包。

2. STM32CubeMX：点鼠标配引脚的「图形化说明书」

生活类比：CubeMX 像汽车的「中控大屏」——以前配单片机要翻几百页手册、手算寄存器地址（像老车拧机械旋钮），现在在图上点一下 PA9 选成串口发送，它就自动帮你写好初始化代码。

一句话定义：STM32CubeMX 是 ST 官方免费的图形化配置工具，你在芯片引脚图上点选功能、在时钟树图上拖参数，它自动生成一套 HAL 初始化 C 工程骨架，交给 Keil 编译。

例子：本讲我们在 CubeMX 里选 STM32F103C8T6、把时钟配到 72MHz、把 PA5 设为输出，点 GENERATE CODE 就生成了整个工程。

3. HAL 库：带说明书的「遥控器」

生活类比：直接操作寄存器像每个电器都弯腰去墙上拔插头；HAL 库像客厅里的万能遥控器，每个按钮（函数）背后已经接好了对应电路。

一句话定义：HAL 库（Hardware Abstraction Layer，硬件抽象层）是 ST 官方提供的一组 C 函数，把「往某个寄存器地址写某个数」封装成好记的函数，如 HAL_GPIO_TogglePin()、HAL_Init()。

例子：本讲代码里那句 HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5) 就是 HAL 函数，它背后自动去操作 GPIOA 的 ODR 寄存器，我们不用记地址。

4. 工程结构：生成的一堆文件都是啥

生活类比：CubeMX 生成的工程像一套精装修房——你只住客厅（main.c 里的用户代码区），厨房、水电（外设初始化）都已经装好，别乱拆。

一句话定义：CubeMX 生成的工程里，Core/Src/main.c 是你唯一要写代码的地方（且只能写在 USER CODE BEGIN/END 注释之间）；stm32f1xx_hal_msp.c 放底层引脚初始化；stm32f1xx_it.c 放中断服务函数；system 时钟在 main.c 的 SystemClock_Config() 里。

例子：本讲我们只动 main.c 的 while 循环；以后学中断时再去 it.c；千万不要在 USER CODE 区之外手写代码，否则下次重新生成工程会被 CubeMX 覆盖掉。

5. 时钟树：芯片的「心跳频率」

生活类比：晶振是芯片的心脏，时钟树是血管网络——心跳多快（时钟频率），所有外设（串口、定时器）跟着按同一个节拍数拍子。心跳错了，大家对拍子就全乱。

一句话定义：STM32F103 有两个时钟源：内部 HSI 8MHz（RC 振荡，上电默认、精度差）和外部 HSE 8MHz（晶振，精确）。系统时钟 SYSCLK 由 PLL 把 HSE 9 倍频得到：SYSCLK = HSE × PLLMUL(×9) = 72MHz。这个频率决定了串口波特率、HAL_Delay 延时是否准确。

教材式分频链路（野火/正点原子时钟树章节）：SYSCLK=72MHz 先经 AHB 预分频（HPRE）分频系数=1 → HCLK(AHB 总线)=72MHz；HCLK 再经 APB1 预分频（PPRE1）÷2 → PCLK1(APB1 总线)=36MHz（注意 APB1 上限就是 36MHz，超了死机）；经 APB2 预分频（PPRE2）÷1 → PCLK2(APB2 总线)=72MHz。这些分频位都写在 RCC_CFGR 寄存器里（HPRE[7:4]、PPRE1[10:8]、PPRE2[13:11]）。

易错点（教材高频考点）：挂在 APB1 上的定时器（TIM2~TIM4），当 PPRE1 分频系数≠1（这里=2，PCLK1=36MHz）时，定时器内部时钟会自动 ×2 变成 72MHz——所以即使 APB1 只有 36MHz，TIM2 的计数时钟仍是 72MHz，算定时初值时要用 72MHz 而不是 36MHz，否则定时时间差一倍。

例子：CubeMX 时钟树里把 HCLK 填 72 回车，它自动算出 HSE×9=72MHz，并按 HPRE/PPRE1/PPRE2 填好 RCC_CFGR。若偷懒用了内部 HSI 8MHz，后面串口 115200 就会因为时钟不准而全是乱码。

6. 3.3V 与 5V 的区别

生活类比：5V 是「高个子标准」，3.3V 是 STM32 这个「矮个子」的承受极限。把 5V 硬塞进它的输入脚，像让矮个子硬扛高个子的担子——会受伤。

一句话定义：STM32F103 是 3.3V 系统：供电 3.3V，IO 高电平约 3.3V；而经典 51 单片机是 5V 系统。STM32 的引脚不能直接耐受 5V 输入。

例子：本讲 ST-Link 给板子供电选 3.3V；接 USB 转串口模块时也要用 3.3V 电平档，不要用 5V 档。

7. SWD 下载：几根线把程序送进芯片

生活类比：SWD 像一条「两车道专用数据线」——比老式 JTAG 的「八车道」省引脚，只要两根（SWDIO 数据 + SWCLK 时钟）就能完成烧录和在线调试。

一句话定义：SWD（串行线调试）是 ARM 的两线下载调试接口，对应 STM32 的 PA13(SWDIO)、PA14(SWCLK) 两个引脚，配合 ST-Link 调试器把编译好的程序写入芯片内部 Flash。

例子：本讲硬件接线就是把 ST-Link 的 SWDIO/SWCLK/GND 接到最小系统板对应焊点，Keil 里 Port 选 SW 而非 JTAG。

8. 存储器映射与启动：程序到底从哪开始跑

生活类比：存储器映射像城市的「门牌号总表」——芯片把 Flash、RAM、寄存器都编在一条地址大街上，CPU 按门牌号找东西，谁住几号是固定死的。

一句话定义（野火教材「存储器映射」章节）：STM32F103C8T6 的地址空间按区域固定划分：片内 Flash（存程序）起始地址 0x08000000（C8 容量 128KB）；片内 SRAM（运行内存）起始地址 0x20000000（容量 20KB）；系统存储器 0x1FFFF000 是 ST 出厂固化的 Bootloader（串口 ISP 下载用）。复位后 CPU 默认从 0x08000000 取指。

启动文件与中断向量表（教材必考）：工程里 startup_stm32f10x_md.s（C8T6 属中容量密度）就是启动文件，它干两件事：① 把「初始栈指针 SP」放在向量表第 1 项、「复位 Reset_Handler」放在第 2 项；② 把 .data 从 Flash 拷到 SRAM、清零 .bss，再跳进 main。关键规则：中断向量表里每个 ISR 的函数名（如 USART1_IRQHandler）必须和启动文件里写死的名字一字不差，否则即使你写了同名函数，链接时也不会被装进向量表，中断永远进不去——这是教材里「中断写了却不进」的经典坑。

三、原理介绍

本讲不是教你点哪几个按钮，而是先把「Keil、CubeMX、HAL 库、ST-Link 各管哪一层」讲清楚——理解了分层，环境问题自己就能定位。

整条链路：你写 main.c → CubeMX 生成的 HAL 初始化代码配置好芯片 → Keil 编译链接成固件 → ST-Link 经 SWD 把固件写进内部 Flash → 复位后 CPU 从 Flash 0x08000000 启动跑你的程序。

原理 1：HAL 的三层结构——为什么不直接写寄存器

STM32 程序分三层，越往下越贴硬件：用户层（你写的 main.c）→ HAL 驱动层（stm32f1xx_hal_*.c，把操作封装成函数）→ 寄存器层（对 0x40010800 这些地址直接读写）。你调 HAL_GPIO_TogglePin，HAL 内部再去写 BSRR 寄存器。好处是不用记几百个寄存器地址；代价是多一层间接。CubeMX 干的就是「按你的勾选，替你把 HAL 初始化代码写出来」——所以你只能在 USER CODE BEGIN/END 之间写，否则下次重新生成会被覆盖。

原理 2：器件包 DFP——Keil 凭什么认识 STM32F103

Keil MDK 本体只是一个通用 ARM 编译器 + IDE，它不认识任何具体芯片：不知道 F103 有哪些寄存器、启动文件叫什么、内部 Flash 怎么烧。DFP 包（Keil.STM32F1xx_DFP）就是把这份「芯片说明书 + 烧录算法 + 启动文件」装进 Keil。不装它，新建工程根本选不到 STM32F103、Flash Download 页也没有对应的编程算法——这就是「装好了用不了」最常见的根因。

原理 3：时钟启动链——为什么一上电默认慢、要配到 72MHz

芯片上电默认跑内部 HSI（8MHz），这是个「保底频率」。要跑满性能必须手动切到外部 8MHz 晶振 HSE → 经 PLL 9 倍频 → 得到 72MHz 主时钟，再经 AHB/APB 分频分给各总线。CubeMX 的 SystemClock_Config 就是按「先稳 HSE、再开 PLL、最后切源」的顺序写好的。为什么这步错了全乱：USART 波特率、HAL_Delay 时长都由这个 72MHz 推算，主频偏了，串口必乱码、延时必不准。

原理 4：SWD 烧录——两线怎么把程序送进 Flash

SWD 只用两根：SWDIO（数据）、SWCLK（时钟），对应 PA13/PA14。ST-Link 按 SWD 协议先整片擦除内部 Flash，再按页把固件逐个写入，最后回读校验。勾上 Reset and Run，写完硬件自动复位，CPU 从 0x08000000 开始执行——所以「下载成功但 LED 不闪」多半是没勾 Reset and Run，程序其实在跑，只是没被复位启动。

保姆级安装顺序（照着点即可）：

  1. 装 Keil MDK-ARM：双击官方安装包，一路 Next，注意安装路径别带中文和空格；装完先别打开，记好装在哪。
  2. 装器件包 DFP：打开 Keil → 点工具栏 Pack Installer（盒子图标）→ 左侧 Devices 展开 STMicroelectronics → 选 STM32F1 Series → 右侧找到 Keil::STM32F1xx_DFP 点 Install，进度条走完变对勾即成功。
  3. 装 STM32CubeMX：运行 ST 官网的 CubeMX 安装包，一路下一步；若提示缺 Java，按它给的链接先装 JRE 再回来继续。
  4. 装 ST-Link 驱动：用 USB 线把 ST-Link 插到电脑 → 右键「此电脑→管理→设备管理器」→ 在「通用串行总线设备」或「调试器」里应看到 ST-Link Debugger；若带黄色感叹号，去 ST 官网下 ST-Link 驱动重装。
记忆点：三层=你写用户代码→HAL 函数→寄存器；DFP=Keil 认识芯片的前提；默认 HSI 8M 偏慢，必须切 HSE×9=72MHz，错了串口乱码延时不准；SWD=SWDIO/SWCLK 两线擦+写 Flash，勾 Reset and Run 才自动跑。

四、硬件接线说明

把 STM32F103C8T6 最小系统板通过 ST-Link 接到电脑。一共 4~5 根线，按表接好即可。

模块引脚（ST-Link）单片机引脚（最小系统板）说明
SWDIOSWDIO（PA13）数据线，必须接对
SWCLKSWCLK（PA14）时钟线，必须接对
GNDGND共地，否则通信不稳
3.3V3.3V用 ST-Link 给板子供电时接；板子自供电可不接
RST（可选）NRST不接也能烧，接了可在线复位调试

为什么这样接：

  • 为什么 SWDIO/SWCLK 不能接反？ 这两根是烧录的专用通道，数据线和时钟线各有分工，接反了 ST-Link 根本识别不到芯片（报 No target connected）。板子上一般印了丝印，对着接最稳。
  • 为什么必须共地？ ST-Link 和板子各自的「0V」必须是同一个参考点，否则高低电平判断没有基准，通信会乱。GND 这根线哪怕用 ST-Link 供电也要接。
  • 为什么用 3.3V 而不是 5V？ STM32F103 是 3.3V 器件，最小系统板通常自带稳压，你只需给它供 3.3V（或用 5V 经板上稳压）。千万别把 5V 直接接到 3.3V 引脚排针上。
CubeMX 配置要点 新建工程搜索并选择 STM32F103C8T6；在 Clock Configuration 里把 HSE 设为 Crystal/Ceramic Resonator，PLLMUL 选 ×9，HCLK 输入 72 回车让 CubeMX 自动算满 72MHz；把 PA5 设为 GPIO_Output；Project Manager 里选工具链 MDK-ARM V5，点 GENERATE CODE 生成工程。

五、完整代码

工程生成后用 Keil 打开 MDK-ARM/Project.uvprojx。我们只在 main.c 的用户代码区写几行：让 PA5 每隔 500ms 翻转一次，用来验证「编译—烧录—运行」整条链路是通的。PA5 需在 CubeMX 里配成 GPIO_Output。

/* main.c 用户代码区：验证环境的最小程序（零基础注释版） */
int main(void)
{
  HAL_Init();               /* 1. 初始化 HAL 库本身 */
  SystemClock_Config();     /* 2. CubeMX 自动生成：HSE 8M + PLL×9 = 72MHz */
  MX_GPIO_Init();           /* 3. 初始化 GPIO（PA5 推挽输出） */

  while (1)
  {
    HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);  /* 翻转 PA5：亮变灭、灭变亮 */
    HAL_Delay(500);                          /* 阻塞延时 500ms */
  }
}

编译下载设置： Keil 点 Options for Target（魔术棒）→ Debug 选 ST-Link Debugger → Settings 里 Port 选 SW、Max Clock 降到 4MHz；Flash Download 页勾选 Reset and Run，并确认编程算法列表里有 STM32F10x Med-density Flash。

如果想改闪烁快慢，把延时数字调一下即可：

HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);  /* 翻转 PA5 */
HAL_Delay(200);                          /* 改成 200ms：闪得更快，约 2.5Hz */

六、代码逐段讲解

第 1 段：初始化三连（main 开头三行）

在做什么： HAL_Init() 初始化 HAL 库底层；SystemClock_Config() 把主频配到 72MHz；MX_GPIO_Init() 把你在 CubeMX 点的「PA5 输出」写进寄存器。

为什么这么写： 这三句是 STM32 HAL 工程的固定开场白。不先配时钟，芯片跑在默认低速；不初始化 GPIO，引脚还是上电默认状态，写电平无效。

不写会怎样： 漏掉 MX_GPIO_Init()，PA5 保持默认浮空输入，LED 怎么都不亮——这是最常见的「代码没错但没现象」原因。

第 2 段：主循环翻转 + 延时

在做什么： HAL_GPIO_TogglePin 翻转 PA5 电平，HAL_Delay(500) 阻塞等 500 毫秒。翻转一次等 500ms，再翻转一次又等 500ms，所以一个完整亮灭周期是 1 秒，约 1Hz 闪烁。

为什么这么写： 这是验证环境最简单的程序。若 LED 能闪，说明 Keil 编译、器件包、CubeMX、ST-Link 驱动、下载算法全部通畅，再叠加任何实验都好排查。

不写会怎样： 如果不先写这个最小程序，直接上复杂实验，一旦没现象，你无法区分是环境没装好还是代码写错了——先让灯闪是最佳排错起点。

第 3 段：编译下载设置（魔术棒）

在做什么： 选 ST-Link 调试器、Port 改 SW、勾 Reset and Run、确认 Flash 算法。

为什么这么写： Keil 默认 Port 可能是 JTAG（要 5 根线），我们只用 SWD 两线；不勾 Reset and Run，下载完芯片不自动跑，得手动按复位；没有 Flash 算法则根本写不进芯片。

不写会怎样： Port 不改 SW 会连不上；不勾 Reset and Run 会出现「下载成功但 LED 不闪」，要手动复位才跑。

七、现象演示说明

正常结果分三步验证：

  • 编译通过：点 Build（F7），左下角显示 0 Error(s)。
  • 下载成功：点 Download（F8），提示 Application Program Done 或 Flash Load finished。
  • 运行现象：接在 PA5 上的 LED 以约 1Hz 频率亮灭闪烁。板载 LED 若接在 PC13，把代码里的 GPIO_PIN_5 改成 GPIO_PIN_13、端口改 GPIOC 即可。

可量化的验证方法：

  • 数闪烁周期：手机秒表计时，LED 应约每秒翻转一次（亮 0.5 秒、灭 0.5 秒）。10 次翻转约 5 秒——若明显偏快或偏慢，多半是时钟没配到 72MHz，HAL_Delay 就不准。
  • 改延时看变化：把 HAL_Delay(500) 改成 100，闪烁应立刻快 5 倍。如果改了没变化，说明烧进去的不是你刚编译的程序（没下载成功）。
  • 万用表量电平：LED 亮时 PA5 对 GND 约 3.3V，灭时接近 0V——可确认输出电平正确。

看到 LED 闪，说明 Keil、器件包、CubeMX、ST-Link 驱动、下载算法全部就位，可以进入下一篇 GPIO 实验。

八、常见报错排查方案

报错现象可能原因解决方法
下载时报 No target connected / 找不到器件SWDIO/SWCLK 接错、没共地、ST-Link 驱动没装核对 SWDIO↔SWDIO、SWCLK↔SWCLK、GND↔GND；安装 ST-Link 驱动；魔术棒 Settings 里 Port 改 SW
新建工程选不到 STM32F103C8T6，编译报 Device not found没装 Keil.STM32F1xx_DFP 器件包打开 Keil 的 Pack Installer，找到 Keil::STM32F1xx_DFP 点 Install，装完重启 Keil
Error: L6218E: Undefined symbol main工程里没把 main.c 加进去，或 CubeMX 没生成用户代码回到 CubeMX 重新 GENERATE CODE，确认 main.c 在 Application/User 分组下
下载成功但程序不运行 / LED 不闪时钟树配错（用了内部 HSI）或没勾选 Reset and RunCubeMX 时钟树确认 HCLK=72MHz；下载设置里勾 Reset and Run，重新上电
Flash Download 页没有 STM32F10x 下载算法器件包未正确安装，算法缺失Pack Installer 重装 DFP；或手动 Add 选 STM32F10x Med-density Flash
配完时钟后芯片直接「死机」、下载不进、调试连不上（教材常见坑）PLL 倍频配过头，SYSCLK 超过 72MHz 上限（如把 HSE 8MHz ×16=128MHz），或 APB1 超过 36MHzSTM32F103 额定最高就是 72MHz，PLLMUL 最大只能 ×9；APB1 分频后不得超过 36MHz。擦除芯片重新烧：魔术棒 Debug→Settings→Flash Download 勾 Erase Full Chip，或按住 BOOT0 接 3.3V 用串口 ISP 救回

九、课后练习与延伸

练习 1（改闪烁速度）： 把 HAL_Delay(500) 改成 1000，LED 应变成约 0.5Hz（亮 1 秒、灭 1 秒）。提示：直接改数字重新编译下载即可，不需要动 CubeMX。

练习 2（换板载灯）： 如果你的最小系统板板载灯在 PC13 且低电平点亮，把代码改成 HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_13) 并在 CubeMX 里把 PC13 配成 GPIO_Output。提示：注意板载灯常是低电平点亮，现象可能和外接灯相反。

练习 3（数周期验证时钟）： 用秒表测 10 个完整亮灭周期，记录总时长。若接近 10 秒说明时钟正确；若明显偏离，回头检查时钟树是否真的到了 72MHz。
