数组与指针（单片机实战）

系列：C 语言基础 入门 更新：2026-10-25

数组是「一排编号的储物格」，指针是「记录格子位置的小纸条」。本课用流水灯花样和字符串显示两个实战场景，把这两个让新手最头疼的概念讲透。

一、本课目标与前置知识

学完本课你能做到：

  • 用数组存一批数据，用下标访问任意一个元素；用数组定义流水灯「花样表」。
  • 说清「指针存的是地址」这句话，会正确写出 &变量 和 *指针。
  • 看懂并会修改 51 的流水灯花样数组，让 LED 按自定义图案流动。

需要提前掌握的前置知识（上一课）：

  • 变量与数据类型（unsigned char、unsigned int 的范围）。
  • 流程控制（for 循环、while(1)）与函数调用。
  • 能在 Keil 里编译烧录 51 程序。

本课会出现的新名词：数组、下标、越界、字符串、地址、指针、取地址 &、解引用 *。

二、基础概念铺垫

1. 数组：一排编号的储物格

生活类比：药店的药品柜有 8 个抽屉，从左到右编号 0~7。想拿第 3 个抽屉的东西，就喊「抽屉 3」。编号从 0 开始，这是 C 语言的老规矩。

一句话定义：数组是类型相同、内存连续的一组变量，共用一个名字，靠下标区分。unsigned char tab[8] = {0xFE, 0xFD, 0xFB, 0xF7, 0xEF, 0xDF, 0xBF, 0x7F}; 定义了一个 8 元素数组，tab[0] 是第一个，tab[7] 是最后一个。

例子：P1 = tab[0]; 把第一个花样值送到 P1 口（对应 LED 亮法）；tab[3] = 0x00; 修改第 4 个元素。

2. 下标与越界：格子只有 8 个，别拿第 9 个

生活类比：柜台只有 8 个窗口，你偏去第 9 个窗口要东西——工作人员不知道你在跟谁说话，可能把旁边的柜台搞乱。数组越界就是这样：访问了不存在的元素，编译器不一定报错，但会把相邻内存里的数据改坏，程序行为变得诡异难查。

一句话定义：下标范围是 0 ~ 数组长度-1。tab[8] 越界，访问到的是数组后面的未知内存。单片机程序最常见的越界 bug 就是 for 循环次数写多 1 次。

例子：for (i = 0; i <= 8; i++) P1 = tab[i]; 最后 i=8 时越界——应写 i < 8。

3. 地址与指针：小纸条记着格子在哪

生活类比：你有一箱东西放在仓库，管理员给你一张「货位条」（写着货架号+层号）。想取东西时，你凭纸条上的位置去找。这张纸条就是指针，纸条上写的「货架号」就是地址。

一句话定义：内存里的每个变量都有地址（一个数字编号）。指针是专门用来存地址的变量。unsigned char *p; 声明一个「指向 unsigned char 的指针 p」；p = &cnt; 把 cnt 的地址放进 p（& 是取地址符）；*p 表示「p 指向的那个变量」本身（* 是解引用符）。

例子：unsigned char cnt = 5, *p = &cnt; 之后 *p = 9; 等价于 cnt = 9;——通过纸条找到了格子并改了里面的数。

与 51 内存地址的对照（教材衔接）：51 内部 RAM 每个字节都有固定地址（00H~7FH 通用区、80H~FFH SFR 区），指针里存的就是这种 8/16 位地址。例如 P1 在 SFR 区地址 0x90——你写 sbit LED = P1^0; 本质就是操作 0x90 这个字节的最低位；20H~2FH 位寻址区的 128 个位也都能用「位地址 00H~7FH」直接访问。理解了「指针=地址」，回头看 Keil 的 SFR 定义（sfr P1 = 0x90;）就不神秘了：它就是把符号 P1 绑定到地址 0x90 的指针式强映射。

4. 数组名就是地址：两者是一家

一句话定义：数组名 tab 在表达式里代表数组首元素的地址，即 tab == &tab[0]。所以 unsigned char *p = tab; 之后 p[2]、*(p+2)、tab[2] 是同一个元素。这就是为什么指针和数组经常混着用——它们本质是同一件事的两种说法。

例子：P1 = *(tab + 3); 与 P1 = tab[3]; 完全等价。

5. 字符串：以 0 结尾的字符数组

一句话定义：字符串就是字符数组，且最后一个字符一定是 '\0'（值 0，表示结束）。"HELLO" 实际占用 6 个字节：H E L L O \0。字符串常量的首地址可以直接赋给 char * 指针：char *s = "HELLO"; 后面 LCD/串口显示字符全靠它。

例子：s[0] 是 'H'；*(s+4) 是 'O'；写字符串遍历时用 while (*s) { 处理; s++; }——读到 0 就停，这是标准写法。

三、原理介绍：为什么单片机里「数组名」和「指针」其实是同一个地址数字

51 内部 RAM 只有 128~256 字节，「数据怎么放」极讲究。数组和指针在这儿有三大高频用途：花样表(流水灯/数码管段码)、收发缓冲(串口缓冲区)、字符串(LCD/串口文字，\0 结尾)。

它们为什么好用——三个底层机制：

原理 1：指针本质上就是「一个地址数字」

RAM 里每个字节都有个编号（地址），变量就存在某个地址上。指针变量 p 存的不是数据本身，而是另一个变量的地址数字。*p 的意思是「去 p 这个地址上把数据读出来」——这就是「指针找数据」。为什么单片机爱用指针传数组？因为传地址只要 1~2 字节，而整个数组拷一遍又费 RAM 又慢。函数处理数组时只收个首地址、函数内外共用同一块内存，这就是 STM32 HAL 库、Arduino 全在用的套路。

原理 2：编译后「数组名」和「指针」是同一段机器码

tab[i] 被编译器翻译成「基址 tab + i×元素大小」这个地址上的内容；*(p+i) 编译出完全相同的机器码。唯一区别：数组名对应的地址编译期就定死、不能重新赋值（tab = p; 非法）；指针 p 是个真能改的变量（p++; 合法）。所以「数组名当指针用可以，指针当数组名赋值不行」——同一种地址操作，一个只读、一个可写。tab == &tab[0] 就是这个道理。

原理 3：数组越界为什么是「悬案级」隐患——C 不做下标检查

生活类比：你租了 8 号仓库的 8 个格子（数组长度 8），却用钥匙开了第 10 号格——管理员不拦你（C 不查越界），你打开的是隔壁人家的柜子，把别人的东西改写了。表面程序还在跑，某个不相干的变量却突然变值——这种 bug 极难查。

因果链：① 数组在 RAM 里是一段连续格子，编译器根本不记「这数组多长」；② tab[i] 编译后就是「首地址+i」这个格子，编译器只算地址、从不检查 i 出界没；③ 于是长度 8 的数组合法下标只有 0~7，写 tab[8] 会去读写数组后面那几个字节——那里往往正放着别的局部变量、甚至函数返回地址；④ 后果不是立刻崩溃，而是「偶尔乱码、偶尔跑飞、重启又好」——嵌入式最头疼的悬案。防范：长度用 #define N 8 写死、循环条件写 i < N；串口接收留 1 字节给结束符并判满。

记忆点：指针=存一个地址数字、*p=去那个地址取数据，单片机传数组只传首地址省RAM；tab[i]与*(p+i)编译后同一段机器码，差别只是数组名只读、指针可自增；数组越界C不报错、只会偷偷改隔壁变量——循环一律用i<#define的长度。

四、硬件接线说明

本课沿用 51 最小系统 + P1 口 8 个 LED（共地接法，写 0 亮）。接线与《LED 流水灯》教程一致：

模块引脚单片机引脚说明
LED1~LED8 阳极各经 220Ω 电阻接 VCC电阻限流，防止烧灯
LED1~LED8 阴极P1.0 ~ P1.7IO 输出 0 时点亮
供电VCC / GND开发板供电并共地

为什么这样接：51 引脚「灌电流」能力（往引脚灌 0 时吸收电流）比「拉电流」（输出 1 时提供电流）强，所以 LED 共地接法更亮更稳——这正是上一课讲过的准双向口特性。没有 LED 板也能先用 在线工具-进制转换器 手推花样值。

五、完整代码

用数组 + 指针实现「双灯并走」流水灯：数组存 8 种花样，依次送往 P1 口，走完一轮再反向走回来。

/* 数组 + 指针流水灯：8 个 LED 双灯并走 */
#include <reg52.h>

/* 花样表：每个元素对应一种「亮两颗灯」的图案（0 表示该位亮）
   0xFC=1111 1100：P1.0、P1.1 亮；0xF9：P1.0、P1.3 亮…… */
unsigned char tab[8] = {0xFC, 0xF9, 0xF3, 0xE7,
                        0xCF, 0x9F, 0x3F, 0x7E};

void delay_ms(unsigned int ms) {
    unsigned int i, j;
    for (i = 0; i < ms; i++)
        for (j = 0; j < 120; j++);
}

void main(void) {
    unsigned char i;
    unsigned char *p;      /* 指针：指向 unsigned char 的变量 */
    while (1) {
        /* 正向：用指针遍历数组，tab 就是首地址 */
        p = tab;                    /* p 指向数组开头 */
        for (i = 0; i < 8; i++) {
            P1 = *(p + i);          /* 等价于 P1 = tab[i]; */
            delay_ms(200);
        }
        /* 反向：用下标遍历数组 */
        for (i = 7; i < 8; i--) {  /* i 从 7 减到 0，注意 i<8 恒真，靠 i-- 终止 */
            P1 = tab[i];
            delay_ms(200);
            if (i == 0) break;      /* 走到 0 后跳出，避免越界 */
        }
    }
}

第二实例：用指针遍历一个字符串（直到 '\0' 停）。这个变体专门演示「字符串=字符数组+\0」和「指针逐字节走」：不写死长度，靠读到 0 自动停——这正是以后串口/LCD 发文字的底层写法：

void delay_ms(unsigned int t);   /* 声明延时，复用上面的定义 */
void uart_putc(unsigned char c);  /* 复用串口发一个字节 */

/* 用指针从头到尾走一遍字符串，遇到 '\0' 结束 */
void uart_print(char *s) {
    while (*s != '\0') {   /* *s 为 0 就是字符串结尾，停 */
        uart_putc(*s);     /* 发当前字符 */
        s++;               /* 指针后移一格，指向下个字符 */
    }
}

void main(void) {
    char *msg = "HELLO";   /* 字符串末尾自动带一个 \0 */
    uart_print(msg);       /* 串口依次打出 H E L L O */
    while (1);
}

为什么用指针而不是下标：s++ 让指针自己往后走，while(*s) 靠 '\0' 自动判断结束——不用数这个字符串有几个字符。这就是字符串处理的标准范式：while(*p){ 处理*p; p++; }。坑：字符串必须以 '\0' 结尾，漏了它，while(*s) 会一直读下去、越界打出乱码。

六、代码逐段讲解

第一段：花样表数组

unsigned char tab[8] = {...}; 在内存里开出 8 个连续格子，tab[0]=0xFC，……tab[7]=0x7E。为什么这么写：把「图案」和「逻辑」分离，以后想换花样只改这一行数组；不写会怎样：只能用移位硬凑，复杂图案（双灯、间隔跳）写起来非常痛苦。

第二段：指针遍历（正向）

unsigned char *p; 声明指针；p = tab; 把数组首地址交给 p（等价 &tab[0]）；P1 = *(p + i); 每次取「p 往后数 i 格」的那个格子。为什么用指针演示：让你亲眼看到数组名就是地址、指针和下标能互换；实际工程中 tab[i] 更直白，两种都要会。

第三段：反向遍历的两种写法对比

for (i = 7; i < 8; i--) 是从 7 往下走：unsigned char 的 i 减到 0 后再减会回卷成 255，255 < 8 不成立循环才停，所以中间必须用 if (i == 0) break; 提前跳出——否则访问 tab[255] 越界。这是新手最隐蔽的坑：无符号类型减法回卷 + 越界。更安全的写法是 for (i = 7; i > 0; i--) { P1 = tab[i]; }（i 不会走到 0 访问 tab[0]，边界见练习提示）。

七、现象演示与验证

  • 正向：两颗 LED 从 P1.0/P1.1 起按花样依次点亮、右移，8 步走完。
  • 反向：图案从右往左走回起点，如此往复，看起来像两盏灯在 P1 口来回「溜达」。

验证方法：

  1. 改数组：把 tab 换成单灯花样 {0xFE, 0xFD, 0xFB, 0xF7, 0xEF, 0xDF, 0xBF, 0x7F}，现象应变成单灯跑动——证明「只改数据不动逻辑」。
  2. 把反向循环改成 for (i = 7; i > 0; i--) { P1 = tab[i]; delay_ms(200); } 再观察：tab[0] 会少亮一次，体会边界处理对现象的影响。
  3. 把延时改成 50，流动速度变快 4 倍。

八、常见报错排查方案

报错现象可能原因解决方法
程序乱跳 / LED 亮法完全不对数组越界：下标写到了长度以外，改坏了相邻内存检查所有 for 循环边界，数组长度为 N 时下标最大 N-1
编译报 invalid type argument of 'unary *'对非指针变量用了 *p，或声明时忘了 *检查声明是否为 unsigned char *p;；*p 只能用在指针上
指针没赋值就使用，结果随机声明了 *p 却没用 p = &x; 或 p = tab; 初始化指针必须先「指到」有效地址再解引用；常见写法是声明时初始化 unsigned char *p = tab;
字符串显示乱码 / 多出奇怪字符字符数组没有以 '\0' 结尾手写字符数组时留一个位置放 0，如 char s[6] = {'H','E','L','L','O',0};
反向流水灯中途卡死无符号变量 i-- 越过 0 回卷成 255，循环停不下来改用 for (i = 7; i > 0; i--) 或加 if (i == 0) break;

九、课后练习与延伸

练习 1（必做）：把花样表改成 16 个元素（自创 8 个新图案），正向循环次数同步改成 16，观察更长的跑动效果。

练习 2：用指针重写整个流水灯（正向反向都用 p 完成），并故意把反向写成 for (i = 7; i < 8; i--) 不带 break 编译烧录，观察卡死/乱跳现象，理解越界危害。

练习 3（进阶）：定义字符串 unsigned char code msg[] = "McuStudy";（code 表示放 Flash 不占 RAM），用指针逐字节遍历，把每个字符通过串口发出去（波特率 9600，串口配置见 UART 串口通信教程）。
