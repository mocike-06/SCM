定时器原理与定时

系列：51 单片机 进阶 更新：2026-10-24

前面几课我们一直用「空转 for 循环」凑延时——它既不准，又让 CPU 干等。本讲把单片机内部那个自动数心跳的硬件定时器用起来：搞懂它为什么能精确到微秒、初值怎么算、为什么方式 1 要手动重装，最后用中断做出一个无论主循环多忙都准点的 1 秒节拍。

一、本课目标与前置知识

学完本课你能做到：

  • 说清楚定时器/计数器是什么、机器周期和晶振的关系、「溢出」是什么意思。
  • 根据目标定时时间，用公式「初值 = 65536 − 计数值」亲手算出 TH0/TL0。
  • 用定时器 0 方式 1 + 中断，写出精确 50ms 节拍，累计 20 次翻转 LED 得到准 1 秒闪烁。

需要提前掌握的前置知识（对应学习路线阶段 1、阶段 2）：

  • 会 Keil 建工程、会烧录（mcu51-env.html）。
  • 最小系统里的晶振概念（mcu51-minisys.html）：知道板子是 11.0592MHz。
  • sbit、十六进制、位运算（mcu51-led.html）。

本课会出现的新名词：定时器/计数器、机器周期、初值/溢出、TMOD、TH0/TL0、TR0、中断（预告）。

二、基础概念铺垫

1. 什么是定时器 / 计数器

生活类比：想象一个自带节拍器的「自动计数器」，它每听到一次心跳就自己 +1，数满了就举一下手。你不用一直盯着它数，只要事先告诉它「从几开始数、数到多少该举手」就行。

一句话定义：定时器/计数器是单片机内部一个自动加 1 的硬件计数器。当它数的是「内部心跳（机器周期）」时，就是定时器；当它数的是「外部引脚 P3.4/P3.5 的脉冲」时，就成了计数器。数到最大值后回卷到 0，叫溢出。

例子：我们让它每 1.085µs 自动 +1，事先不让它从 0 数到满 65536（那要 71ms 才溢出），而是从 19456 开始数——数 46080 下正好溢出一次，对应 50ms。

2. 机器周期 = 晶振周期的 12 倍

生活类比：晶振每秒敲 1105.92 万下，但单片机干一件小事要 12 下心跳——像老师每 12 次打铃才翻一页书。

一句话定义：机器周期是 51 单片机干一条基本动作所需的时间，等于 12 个晶振时钟周期，即机器周期 = 12 ÷ 晶振频率。

例子：晶振 11.0592MHz，机器周期 = 12 ÷ 11.0592MHz ≈ 1.085µs。这就是为什么定时器「每 1.085µs 加 1」。如果换成 12MHz，机器周期正好 1µs，算题更整。

3. 初值与溢出计算（65536 − 计数值）

生活类比：一个只能数到 65535 的计数器（数完下一个数就变 0，像汽车里程表从 99999 跳到 00000）。你不想等它从 0 数到满，就预先拨到一个起点 X，让它再数 N 下就溢出。

一句话定义：16 位定时器的最大值是 2^16 = 65536（从 0 计到 65535 后溢出）。要它数 N 下就溢出，初值 = 65536 − N；这个数的高 8 位给 TH0、低 8 位给 TL0。

例子：要定时 50ms。先算要数多少个机器周期：50000µs ÷ 1.085µs ≈ 46080。初值 = 65536 − 46080 = 19456 = 0x4C00。于是 TH0 = 0x4C、TL0 = 0x00。从 0x4C00 开始数 46080 下，正好溢出。

教材通用公式（张毅刚《单片机原理及应用》定时器一章）：对方式 n（方式0=13 位、方式1=16 位、方式2=8 位自动重装），满量程 2^n，机器周期 Tcy = 12 / fosc，则定时时间 t = (2^n − X) × Tcy，反解初值即 X = 2^n − t / Tcy = 2^n − t × fosc / 12。课堂考试常给「fosc=12MHz、定时 10ms、方式1」让你手算 TH/TL：X = 65536 − 10000µs×12MHz/12 = 65536−10000 = 55536 = 0xD8F0，TH0=0xD8、TL0=0xF0。计数能力由位宽决定：方式 0 最大计 8192 个数、方式 1 最大 65536 个、方式 2 只有 256 个（所以它只能做短定时/波特率）。

4. 软件延时为何不准

生活类比：让你数「一千下再开灯」，但数数过程中你可能被人打断、多瞟一眼、走神——实际耗时总在飘。CPU 空转延时也是这个道理。

一句话定义：用 for 循环空转凑的延时叫软件延时，它不精确：编译器优化级别、循环里多一条 if、主循环里夹了别的任务，都会让实际时间漂移；而且延时期间 CPU 全程被占死，干不了别的。

例子：前面 delay_ms(500) 用手机秒表掐，10 次可能 10.5 秒也可能 9.4 秒；改用定时器后，10 次正好 10.0 秒。差别就是「硬件自动数心跳」 vs 「软件空转等人」。

5. 中断概念（预告）

生活类比：你正在看书，门铃响了——你立刻在当前页夹个书签、跑去开门，开完门再回书签处接着看。「门铃响 → 跑去开门」这整套自动响应，就是中断。

一句话定义：中断是硬件事件（定时器溢出、外部引脚变化等）发生时，芯片自动暂停当前主程序、跳去执行一段预先写好的「中断服务函数」，执行完再回来继续主程序。下一课会系统讲，本课只要知道：定时器溢出时，我们希望芯片自动喊我们一声（进中断函数重装初值、翻转 LED）。

例子：开了 EA=1、ET0=1 后，T0 每溢出一次，芯片自动跳去 Timer0_ISR 函数——主循环 while(1) 里什么都不用写，1 秒节拍照样准。

三、原理介绍：定时器是怎么「自己数着时间」的

51 内部有 T0/T1 两个加 1 计数器。它和你在主循环里写空转延时最大的不同是：计数这件事由硬件自动完成，CPU 一行代码都不跑。你装好一个初值、拨一下启动开关，它就每个机器周期自己 +1，数满溢出时置起 TF 标志、还能喊你一声（进中断）。

一次定时的完整流程：

  1. 初始化：TMOD 设方式 1、TH0/TL0 装初值、ET0/EA 开中断、TR0=1 启动。
  2. 硬件每 1.085µs 自动把 TH0:TL0 的值 +1，CPU 完全不参与。
  3. 数满 46080 下，计数器从 0xFFFF 再 +1 回卷到 0，硬件置 TF0 申请中断。
  4. 自动跳去 Timer0_ISR：重装初值、cnt++。
  5. cnt 累计到 20（20×50ms=1000ms），翻转 LED。

原理 1：计数脉冲到底从哪儿来——为什么是 1.085µs 加一次

定时器的「每跳一下」接的是机器周期，而不是晶振周期。51 的 CPU 是 12 分频结构：晶振每来 12 个脉冲，内部才走一步。所以在 11.0592MHz 下，一个机器周期 = 12 / 11.0592MHz ≈ 1.085µs，也就是定时器大约每 1.085µs 加一次。这就是它比软件延时准的根本原因：软件空转延时受指令条数、编译器优化影响，实际周期飘忽；定时器数的是固定的硬件时钟脉冲，不管你主程序在干嘛，节拍误差只有晶振本身的 ppm。这也是后面串口波特率能做到 0% 误差的基础。

原理 2：方式 0/1/2 的位宽与初值是怎么推出来的

四种模式的区别本质就是计数器有多少位：

  • 方式 0：13 位（TH8 + TL低5），最大 8192，淘汰不用。
  • 方式 1：16 位（TH8 + TL8），最大 65536，最常用。
  • 方式 2：8 位自动重装（TL 计数、TH 存重装值），串口波特率专用。

初值推导：计数器是「加 1 到溢出」，不是「从 0 数到 N」。要定时 50ms，先算要数几个机器周期：50000µs ÷ 1.085µs ≈ 46080。方式 1 满量程 65536，所以得先从 65536 往前倒推 46080：初值 = 65536 − 46080 = 19456 = 0x4C00。拆开高低字节：TH0 = 19456/256 = 0x4C、TL0 = 19456%256 = 0x00。为什么是 65536 减而不是 0 开始：因为计数器从初值一直 +1，加到 0xFFFF 再 +1 才溢出，中间经过的步数正好是「满量程 − 初值」。这个「65536−计数值」是所有 51 定时初值的通用公式。

原理 3：为什么方式 1 要手动重装、方式 2 却自动

方式 1 溢出后计数器从 0 重新开始数，如果你不在中断里立刻把 TH0/TL0 写回 0x4C00，下一次定时就从 0 数满 65536（约 71ms）——节拍立刻变长。所以方式 1 的中断服务第一件事必须重装初值，晚几微秒都引入误差。方式 2 解决了这个痛：它把 8 位计数专用 TL、把重装值存 TH，一旦 TL 溢出，硬件自动把 TH 的值装进 TL，全程不经过 CPU。正因为「自动重装、不丢节拍」，串口波特率发生器（定时器 1）一律用方式 2——否则每次中断里手动重装那几微秒抖动，会让串口每个字节都歪一点。

原理 4：TMOD / TCON 寄存器位定义（教材必考表）

张毅刚教材把定时器的配置归纳到两个特殊功能寄存器里，考试基本就是考这两张表的位含义。

TMOD（定时器方式寄存器，低 4 位管 T0、高 4 位管 T1，不可位寻址）：

位GATEC/TM1M0（低4位对应 T0）
含义门控：=1 时需 INTx 引脚同时为高才计数（硬件门控）；=0 时软件 TRx 直接启动=0 定时（数机器周期）；=1 计数（数 P3.4/P3.5 外部脉冲）方式高位方式低位M1M0=00 方式0(13位) / 01 方式1(16位) / 10 方式2(8位自动重装) / 11 方式3

本课 TMOD &= 0xF0; TMOD |= 0x01; 即：T0 的 GATE=0（软件启动）、C/T=0（定时）、M1M0=01（方式1）。TCON（定时器控制寄存器，可位寻址）高 4 位 TF1/TR1/TF0/TR0 管溢出标志与启动，低 4 位 IE1/IT1/IE0/IT0 管外部中断：

位TF1TR1TF0TR0IE1/IT1/IE0/IT0
含义T1 溢出标志，硬件置1、进中断后硬件清0T1 运行控制，=1 启动T0 溢出标志，同上T0 运行控制，=1 启动（对应代码里 TR0=1）外部中断1/0 的请求标志与触发方式（下一课详讲）

位操作 vs 直接赋值对照：写 TR0 = 1; 等价于把 TCON 的 bit4 置 1（因为 reg52.h 里 sbit TR0 = 0x88^4）；写 TMOD = 0x01 等价于一次性把 T0 配成「GATE=0、定时、方式1」同时不碰 T1。这就是教材里「位寻址区 + SFR 可位寻址」在定时器上的直接体现。

记忆点：定时器=硬件每机器周期(12÷晶振≈1.085µs)自动加1，CPU 不参与所以准；方式1是16位、初值=65536−要数的个数，溢出后必须在中断里手动重装；方式2是8位自动重装、专门给串口波特率用；数满回卷到0才置TF申请中断。

四、硬件接线说明

本讲只需一个 LED 观察定时是否准确，仍接 P1.0，与流水灯相同。

为什么这样接： 定时器是芯片内部硬件，不需要额外接线——唯一和硬件相关的是晶振频率。如果你把晶振换成 12MHz，初值公式里的 1.085µs 就变成 1µs，50ms 应计 50000 个数，初值要改成 65536−50000=15536。所以「晶振频率」这一栏写错，定时立刻不准。

五、完整代码

用定时器 0 方式 1（16 位），每 50ms 进一次中断，进 20 次（即 1 秒）翻转一次 LED。这样 LED 正好 1 秒一亮一灭。

/* 定时器0方式1：50ms 中断，累计 20 次即 1 秒翻转 LED */
#include <reg52.h>

sbit LED = P1^0;
unsigned char cnt = 0;   /* 中断次数计数：满 20 次 = 1 秒 */

void Timer0_Init(void) {
    TMOD &= 0xF0;        /* 清掉 T0 的低4位，保留 T1 设置 */
    TMOD |= 0x01;        /* T0 方式1，16位定时 */
    TH0 = (65536 - 46080) / 256;   /* 50ms 初值高8位 = 0x4C */
    TL0 = (65536 - 46080) % 256;  /* 低8位 = 0x00 */
    ET0 = 1;             /* 允许 T0 中断 */
    EA  = 1;             /* 开总中断（总电闸） */
    TR0 = 1;             /* 启动 T0：开始计数 */
}

void main(void) {
    Timer0_Init();
    while (1) {
        /* 主循环空转，定时交给中断；这里可以放别的任务 */
    }
}

void Timer0_ISR(void) interrupt 1 {
    TH0 = (65536 - 46080) / 256;   /* 方式1 溢出后不会自动重装，必须手动写回初值 */
    TL0 = (65536 - 46080) % 256;
    cnt++;
    if (cnt >= 20) {     /* 20 × 50ms = 1000ms */
        cnt = 0;
        LED = ~LED;      /* 翻转 LED */
    }
}

改参数变体： 想让 LED 每 0.5 秒翻转一次（周期 1 秒变成亮 0.5 灭 0.5），把中断里的 if (cnt >= 20) 改成 if (cnt >= 10) 即可——这就是「硬件定时 + 软件分频」的威力。

进阶实例：一个定时器中断驱动两颗错相节拍灯

同一个 50ms 节拍里，用两个不同的判断条件让 LED1（P1.0）和 LED2（P1.1）以相同的 1 秒周期、但错开 0.5 秒亮灭——像两个人错拍鼓掌。体会「一次硬件中断、软件分频出多路节拍」。

/* 进阶：T0 50ms 中断，一颗芯片同时驱动两颗错相 LED */
#include <reg52.h>
sbit LED1 = P1^0;
sbit LED2 = P1^1;
unsigned char cnt = 0;

void Timer0_Init(void) {
    TMOD &= 0xF0;
    TMOD |= 0x01;
    TH0 = (65536 - 46080) / 256;
    TL0 = (65536 - 46080) % 256;
    ET0 = 1;
    EA  = 1;
    TR0 = 1;
}

void main(void) {
    Timer0_Init();
    while (1);            /* 主循环空转，节拍全靠中断 */
}

void Timer0_ISR(void) interrupt 1 {
    TH0 = (65536 - 46080) / 256;   /* 方式1 手动重装初值 */
    TL0 = (65536 - 46080) % 256;
    cnt++;
    if (cnt >= 20) {      /* 每 1 秒 */
        cnt = 0;
        LED1 = ~LED1;     /* LED1 在整秒翻转 */
    }
    if (cnt == 10) {      /* 每到 0.5 秒这个时刻 */
        LED2 = ~LED2;     /* LED2 在半秒翻转，于是与 LED1 错相 */
    }
}

烧录后应看到：LED1 亮时 LED2 灭、LED1 灭时 LED2 亮，两者始终错开半拍。若两颗灯同亮同灭，说明 cnt == 10 这个判断没写对。

六、代码逐段讲解

第 1 段：Timer0_Init 初始化（第 7~16 行）

在做什么： 配置 TMOD 选方式 1、装初值、开中断开关、启动定时器。

为什么这么写： TMOD &= 0xF0 先清低 4 位再 |= 0x01，是为了不破坏高 4 位（T1 的设置）——后面串口课要用 T1 做波特率。三个开关 ET0（允许 T0 中断）、EA（总中断）、TR0（启动）缺一不可。

不写会怎样： 漏 EA 则芯片根本不理会 T0 溢出；漏 TR0 则计数器不跑；只写 TMOD = 0x01 而不清位，会把 T1 模式改成意外值，将来串口出错。

第 2 段：main 的 while(1)（第 18~23 行）

在做什么： 初始化完就死循环，主循环里什么都没干。

为什么这么写： 这正是硬件定时器的意义——主程序该干嘛干嘛（甚至空转），定时由硬件在背后数心跳，到点自动喊进中断。不像软件延时，main 里塞别的任务会把延时打乱。

不写会怎样： 如果删掉 while(1)，main 跑完就跑飞。

第 3 段：中断函数 Timer0_ISR（第 25~33 行）

在做什么： 每次溢出自动进来：先手动重装 TH0/TL0，再 cnt++，满 20 次翻转 LED。

为什么这么写： 方式 1 是 16 位，溢出后计数器从 0 重新数，不会自动回到 0x4C00——所以必须在中断里再写一遍初值，否则第二次开始的定时就变成了「从 0 数到满 65536」（约 71ms），越走越偏。interrupt 1 是 51 规定的 T0 中断号，写别的号芯片就找不到这个函数。

不写会怎样： 不重装初值 → 定时越走越慢；cnt 不判满 20 → LED 每 50ms 翻一次，看起来像常亮。

七、现象演示说明

烧录后 P1.0 的 LED 应以精确的 1 秒间隔亮灭（亮 1 秒、灭 1 秒）。它和前面空循环延时版的区别在于：即使主循环里再加别的任务，这个 1 秒节拍依然准。

可量化的验证方法：

  • 秒表掐点： 用手机秒表掐 10 次完整亮灭，应正好约 20 秒（每次完整周期 2 秒）。误差应在百分秒级别，远好于空循环延时。
  • 主循环加干扰： 在 while(1) 里随便加一句空循环或一句没用的运算，重新烧录——LED 节拍应纹丝不动。这就是硬件定时 vs 软件延时最直观的差别。
  • 改分频值： 把 cnt >= 20 改成 >= 10，LED 应变成 0.5 秒翻转一次（亮 0.5 灭 0.5），节拍正好快一倍。

LED 几乎不亮 / 微亮把分频值改太小（如 cnt>=1），翻转太快恢复 cnt>=20，或先用 delay_ms(500) 确认 LED 硬件接线没问题
用方式 0 时定时比预期短一截（教材易错题）方式 0 是 13 位（TH8 + TL 低 5 位，满量程 8192），不是 16 位；有人按 65536 算初值方式 0 满量程按 8192 算：X = 8192 − 计数值，且 TL 只用低 5 位、高 3 位必须为 0；实际工程一律改用方式 1，别用方式 0
TMOD 一写就把后面串口搞坏直接 TMOD = 0x01 把高 4 位（T1 的 GATE/C/T/M1M0）清成 0，T1 方式被意外改成方式 0用「先与后或」：TMOD &= 0xF0; TMOD |= 0x01; 只动低 4 位，保留 T1 原配置

九、课后练习与延伸

练习 1（手算初值）： 若晶振换成 12MHz（机器周期正好 1µs），要定时 50ms，应计多少个机器周期？TH0、TL0 分别是多少？提示：50ms = 50000µs，除以 1µs 得 50000，初值 = 65536 − 50000 = 15536 = 0x3CB0。

练习 2（改节拍）： 把 LED 改成「亮 2 秒、灭 0.5 秒」的不对称闪烁。提示：用 cnt 配合两个阈值——比如 cnt 到 10 翻转一次，再到 50（累计）再翻转一次；或分别用两个变量记录状态。

练习 3（秒表功能）： 主循环里用一个 unsigned int 秒数 sec，每进 20 次中断 sec++，再把 sec 通过串口（下几课学）或数码管显示出来，做个简单秒表。提示：定时器负责「准点 +1」，显示部分等学完串口/LCD 再做。
