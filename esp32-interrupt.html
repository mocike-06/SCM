定时器与中断（事件驱动编程）

系列：ESP32 进阶 更新：2026-10-25

loop() 里轮询按键、轮询时间，能跑但浪费 CPU、响应还慢。中断才是嵌入式「事件驱动」的真相：按键按下、定时到了，芯片自动跳到中断函数处理，处理完回来继续 main。本课讲透轮询 vs 中断、外部中断 attachInterrupt、硬件定时器 Ticker，以及中断里的三大禁忌。

一、本课目标与前置知识

学完本课你能做到：

  • 说清轮询与中断的区别，判断什么场景该用中断。
  • 用 attachInterrupt 写按键外部中断，正确处理抖动与中断上下文。
  • 用 Ticker 库做定时任务（定时采样/定时翻转），理解它和 delay/millis 的差别。

需要提前掌握的前置知识（对应学习路线阶段 5）：

  • GPIO 基础（esp32-gpio.html）：按键输入、INPUT_PULLUP。
  • ADC 采样（esp32-adc.html）：本课的定时采样会复用它。
  • 51 中断概念（阶段 2）：中断优先级、边沿触发这些术语是通用的。

本课会出现的新名词：中断、中断服务函数（ISR）、轮询、边沿触发/电平触发、attachInterrupt、中断上下文、Ticker、回调、volatile。

二、基础概念铺垫

1. 轮询 vs 中断：等 vs 被打断

生活类比：轮询像客服一直盯着门口看有没有人来（忙等）；中断像前台装了个门铃——人来了门铃响，前台立刻放下手头的事去接待，接待完接着干（事件驱动）。

一句话定义：轮询：程序循环里反复查某个状态（if (按键按下)），简单但占 CPU、响应靠循环速度；中断：硬件事件到来时 CPU 暂停当前任务，自动跳去执行中断服务函数（ISR），执行完回来继续——不占 CPU、响应即时。

例子：100 个按键用轮询每圈查一遍，按 10 次/秒没问题；但如果同时要干重活（WiFi 重连），轮询可能漏按键，中断则一次不漏。

2. attachInterrupt：给引脚装门铃

一句话定义：attachInterrupt(引脚, 回调函数, 触发模式) 把某个引脚的跳变「注册」成中断。触发模式：RISING（上升沿：从低到高）、FALLING（下降沿：从高到低）、CHANGE（任何变化）。按键接地接 FALLING 最常用。

例子：attachInterrupt(15, onPress, FALLING); 按键按下（高→低）时自动调用 onPress()。

3. 中断服务函数的三条铁律

一句话定义：ISR 里禁止三件事：不能用 delay()（阻塞中断）、不能 Serial.print（串口在中断里会死锁/卡顿）、不能做复杂计算（中断时间越短越好）。正确姿势：ISR 里只置一个 volatile 标志/计数器，主循环看到标志再处理「重活」。

例子：按键 ISR 里 pressCount++; 就完事，串口打印放到 loop 里。

4. Ticker：硬件定时器的「闹钟」

生活类比：delay() 像「睡着了等」，期间什么都干不了；millis() 像「看表」，主循环自己比对时间；Ticker 像「订闹钟」——闹钟响时自动执行一次回调，主循环不用管。

一句话定义：Ticker 库把 ESP32 的硬件定时器封装成「定时回调」：ticker.attach_ms(500, 函数) 每 500ms 自动调用一次函数（在中断里执行）；detach() 停止。注意：Ticker 回调也在中断上下文，同样遵守 ISR 铁律。

例子：温度每 2 秒采一次、LED 每 1 秒翻转一次，各用一个 Ticker，主循环只管显示。

5. IRAM_ATTR：把中断函数搬进「快车道」

生活类比：普通函数存在 Flash（仓库），用的时候才搬到 RAM 执行；中断要求「门铃一响立刻开门」，若函数还在 Flash 里等着搬运，就会慢半拍——IRAM_ATTR 就是把这个门岗函数提前搬到门口（RAM），随叫随到。

一句话定义：IRAM_ATTR 是一个宏，告诉编译器把这个 ISR 函数编译进 IRAM（指令 RAM）而不是留在 Flash。原因是 ESP32 跑 WiFi/蓝牙时，Flash 总线可能正被占用，若 ISR 还在 Flash 里，中断到来时取指会被 Flash 读取延迟卡住，甚至崩溃——教材（ESP-IDF 文档）明确要求中断处理函数加 IRAM_ATTR。

例子：void IRAM_ATTR onPress() { pressCount++; }——函数本体在 IRAM，中断一来毫秒级响应，不受 Flash 读延迟影响。

三、原理介绍：一次按键中断的完整旅程

轮询是「一直盯着门口等有人来」，中断是「门铃一响再去开门」。理解中断的硬件响应流程（CPU 怎么突然停下手里的活跳去执行你的函数），才能搞懂为什么 ISR 必须极短、为什么不能在里面 Serial.print。

一次按键中断的链路：attachInterrupt 注册 → 引脚电平跳变 → 中断控制器发请求 → CPU 保存现场跳 ISR → ISR 只置个标志 → 回主循环看标志处理。

原理 1：中断 vs 轮询——事件驱动为什么省 CPU

轮询方式是 loop 里不停 digitalRead(btnPin)——按键没按的绝大多数时间 CPU 也在白读。中断方式是把监视工作交给硬件：你用 attachInterrupt(pin, fn, FALLING) 告诉中断控制器「这个引脚出现下降沿时叫我」，之后 CPU 随便干别的，引脚一出现下降沿，硬件自动打断它。对慢事件（按键、传感器数据就绪）这能省掉 99% 的空转。

原理 2：中断响应的硬件流程——CPU 是怎么「突然跳走」的

按键按下引脚拉低 → 外部中断控制器捕获这个跳变 → 向 CPU 发中断请求。CPU 完成当前这条指令后，自动做三件事：保存现场（程序计数器、寄存器压栈）→ 跳转到你注册的 ISR 函数入口 → ISR 跑完后恢复现场出栈，从被打断的那条指令继续——主循环甚至感觉不到「被打断过」。这一切是硬件自动完成的，微秒级。Ticker 定时器中断是同一机制，只是触发源从「引脚跳变」换成「时钟数到」。

原理 3：ISR 三条铁律——为什么不能 delay、不能 print、不能干重活

ISR 运行时主循环被冻结、其他中断被挂起，所以 ISR 里 delay 1 秒 = 整个系统「失聪」1 秒：WiFi 心跳断了、定时采样停了、甚至看门狗超时把你复位。规矩是：

  • 不 delay、不做长任务：ISR 只做最小动作。
  • 不 Serial.print：串口发送本身是另一套中断驱动的机制，在 ISR 里发可能和它自己嵌套、死锁。
  • 只置 volatile 标志位（或发个队列消息）：ISR 里 flag = true 就立刻返回，真正的处理放 loop 里看 flag 做——按键消抖就是「ISR 记下时刻，loop 里延时确认」。
记忆点：轮询=盯门空转，中断=门铃一响再来；响应流程=保存现场→跳 ISR→恢复现场（硬件自动、微秒级）；ISR 三不：不 delay、不 print、不重活，只置 volatile 标志；Ticker=定时闹钟，回调也在中断上下文。

四、硬件接线说明

两个实验：按键中断（GPIO15）+ 定时采样（复用 ADC 光敏或电位器 GPIO34）：

模块引脚ESP32 引脚说明
按键一端GPIO15内部上拉 INPUT_PULLUP
按键另一端GND按下 FALLING 触发
电位器（可选）两端 3.3V/GND、抽头 GPIO34定时采样演示用
LED（可选）GPIO4Ticker 定时翻转演示

为什么按键用内部上拉 + FALLING：GPIO15 配 INPUT_PULLUP，平时读到高；按下接地变低。FALLING（下降沿）只响应「按下」这一下，不会像 CHANGE 那样「按下+松开」触发两次。为什么消抖不在 ISR 里做：抖动发生在按下瞬间的几毫秒内，若在 ISR 里 delay 消抖就违反铁律——标准做法是 ISR 只记时间戳，loop 里确认「稳定低电平超过 20ms」再算一次有效按键。

避坑 ESP32 并非所有引脚都适合做外部中断输入：GPIO6~11 被 Flash 占用不可用；GPIO34~39 只能输入不能输出（可作中断输入，但外接上拉/按键要注意只能下拉或依赖内部上拉的限制）；GPIO0/2/15 是启动模式引脚，按键中断要选不会影响启动电平的接法。日常选 GPIO4/5/15 等常规引脚最稳。

五、完整代码

示例 1：按键外部中断计数（ISR 置标志，loop 处理+打印）

/* 按键中断计数：ISR 只加计数，串口打印放主循环 */
const int keyPin = 15;

volatile unsigned long pressCount = 0;   /* volatile：中断里会改 */
volatile unsigned long lastIsrMs = 0;    /* 上次按下时刻（消抖用） */

/* 中断服务函数：必须短、无参数、无返回值 */
void IRAM_ATTR onPress() {
  /* 消抖：距上次触发不足 30ms 视为抖动，忽略 */
  unsigned long now = millis();
  if (now - lastIsrMs > 30) {
    pressCount++;              /* 只做计数，别 print、别 delay */
    lastIsrMs = now;
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(keyPin, INPUT_PULLUP);
  /* 注册中断：下降沿触发，绑定 onPress */
  attachInterrupt(keyPin, onPress, FALLING);
}

void loop() {
  /* 中断里的事拿到主循环来做 */
  Serial.print("press=");
  Serial.println(pressCount);
  delay(200);
}

示例 2：Ticker 定时任务（每 1s 翻 LED，每 2s 采一次光敏）

/* Ticker：两个定时任务并行跑，主循环空转 */
#include <Ticker.h>

const int ledPin = 4;
const int adcPin = 34;

Ticker tickerLed;      /* 对象1：翻灯 */
Ticker tickerAdc;      /* 对象2：采样 */

volatile bool ledOn = false;
volatile int lastAdc = 0;

void flipLed() {                       /* 每 1 秒被调用一次（中断上下文） */
  ledOn = !ledOn;
  digitalWrite(ledPin, ledOn ? HIGH : LOW);
}

void sampleAdc() {                     /* 每 2 秒被调用一次 */
  lastAdc = analogRead(adcPin);        /* 读光敏，存全局变量 */
}

void setup() {
  pinMode(ledPin, OUTPUT);
  analogSetPinAttenuation(adcPin, ADC_11db);
  tickerLed.attach_ms(1000, flipLed);  /* 1000ms 回调 */
  tickerAdc.attach_ms(2000, sampleAdc);/* 2000ms 回调 */
}

void loop() {
  /* 主循环可以专心做重活（如 WiFi 处理），定时任务由 Ticker 负责 */
}

六、代码逐段讲解

第一段：IRAM_ATTR 与 volatile

IRAM_ATTR 把 ISR 放进 IRAM（内部 RAM），保证中断响应不被 Flash 读取拖慢——ESP32 的官方推荐写法。volatile unsigned long pressCount 是中断与主循环共享变量的标配修饰：编译器不知道 ISR 会改它，不写 volatile 可能优化掉主循环的读取，计数显示不更新。

第二段：ISR 里的软件消抖

millis() - lastIsrMs > 30 判断两次触发间隔。为什么用时间差消抖而不是延时：延时是「睡过去等」，时间差是「记下时刻、下次比对」——后者不阻塞 ISR，符合铁律。抖动（约 5~20ms）在 30ms 窗口内被过滤，而真实连按（间隔几百 ms）正常计数。

第三段：Ticker 的两个独立对象

两个 Ticker 对象 = 两个独立闹钟，各自 attach_ms(间隔, 回调)。回调每 1s/2s 自动执行。为什么两个不用 delay 串起来：delay 只能串行等（先 1s 再 2s，错开混乱）；Ticker 并行计时、互不阻塞，主循环完全空出来。注意：回调也在中断上下文，所以 sampleAdc 只「读值存全局」，显示处理留在主循环（示例简化为空转，工程上在 loop 里用 lastAdc）。

第四段：主循环空转的意义

示例 2 的 loop 是空的——这不是「没写完」，而是演示「定时任务不占主循环」。真实项目里 loop 去跑 WiFi 重连、MQTT 发送、屏幕刷新等重活，1s/2s 的采样翻灯由硬件定时器后台完成。这是「事件驱动」与「时间片」编程的精髓。

七、现象演示与验证

  • 按键计数：串口持续打印 press=N；每按一次键 N+1，快速连按不漏、抖动不误计。
  • Ticker：LED 每 1 秒精确翻转；光敏值每 2 秒更新一次（把 lastAdc 打印出来观察）。

验证方法：

  1. 快速连按 20 次，计数应为 20（证明中断不丢事件）；再用手指「颤着按」（制造抖动），计数不跳（证明 30ms 消抖生效）。
  2. 把 attach_ms 的 1000 改成 300，LED 翻转明显变快（3 倍）——验证定时周期可调。
  3. 在 flipLed 里故意加 delay(2000)，观察按键计数是否明显变卡——亲手体验「ISR 里 delay 的后果」。

八、常见报错排查方案

报错现象可能原因解决方法
attachInterrupt 报错引脚不可用（GPIO6~11 被 Flash 占用）或中断号映射问题换 GPIO4/5/15 等常规引脚；用 digitalPinToInterrupt 显式指定
按一次计数多次没消抖或 CHANGE 触发（按+松两次）ISR 里加 30ms 时间差过滤；改 FALLING
计数不更新/永远 0变量没 volatile，被编译器优化共享变量加 volatile；确认 attachInterrupt 参数顺序
ISR 里 print 后系统卡死违反铁律：串口阻塞在中断里把 print 移到 loop；ISR 只置标志/计数
Ticker 回调不执行attach_ms 后没保持对象存活 / 语法错Ticker 对象放全局；核对 attach_ms(ms, func) 参数
WiFi 连上后定时不规律WiFi 中断优先级高，抢占 Ticker 时间接受轻度抖动；重活尽量移出定时回调

九、课后练习与延伸

练习 1（必做）：把按键计数改成「长按识别」：ISR 记下按下时间，loop 里判断按住超过 1 秒输出 "LONG"——用中断 + 时间戳实现状态判断。

练习 2：用 Ticker 每 500ms 采样一次 ADC，主循环里把最近 10 次采样打印成简易曲线——定时采样 + 数据显示的完整链路。

练习 3（进阶）：把按键 ISR 与 NVS 存储结合：每次按键把 pressCount 写进 NVS，掉电重启不归零——中断 + 持久化的物联网计数器原型。

延伸学习：事件驱动会了，下一课学 EEPROM/NVS 掉电存储——让设备的「记忆」不随断电消失，物联网设备的标配能力。
