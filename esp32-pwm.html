LEDC PWM 调光与舵机控制

系列：ESP32 进阶 更新：2026-10-25

想调 LED 亮度、控电机转速、转舵机角度，都离不开 PWM。ESP32 的 PWM 叫 LEDC：16 个通道 + 4 个定时器，比 Arduino UNO 的 analogWrite 灵活得多。本课把 PWM 的频率、占空比讲透，再给 LED 呼吸灯和舵机控制两个完整示例——这是物联网项目里「执行器控制」的标配技能。

一、本课目标与前置知识

学完本课你能做到：

  • 说清 PWM 的频率、占空比、分辨率三个概念，以及它们各自影响什么。
  • 看懂 ESP32 LEDC 的「定时器 + 通道 + 引脚」三层结构，会用 ledcSetup/ledcAttachPin/ledcWrite。
  • 做出 LED 呼吸灯，并用 PWM 精确控制舵机角度。

需要提前掌握的前置知识（对应学习路线阶段 5）：

  • GPIO 基础（esp32-gpio.html）：PWM 输出也是在 GPIO 引脚上，只是电平不再只有 0/1。
  • 51 或 STM32 的 PWM 概念（阶段 2/4）：占空比、频率是通用概念。
  • C 语言循环与延时：呼吸灯就是循环里改占空比。

本课会出现的新名词：PWM、频率、占空比、分辨率、LEDC、通道、ledcSetup / ledcAttachPin / ledcWrite、呼吸灯、舵机脉宽。

二、基础概念铺垫

1. PWM 是什么：快速开关的「假模拟」

生活类比：LED 要么全亮（3.3V）要么全灭（0V），但快速开关时，人眼和 LED 的「惯性」会把高频开关「平均」成中间亮度——开 90% 时间看起来就是 90% 亮度。PWM 就是用「高速开关的比例」模拟任意中间值。

一句话定义：PWM（脉宽调制）= 让引脚在固定频率下，高电平时间占比（占空比）按需变化。LED 亮度、电机转速、舵机角度都靠占空比控制。

例子：频率 1kHz（每秒开关 1000 次）、占空比 50% → LED 半亮；占空比 0% → 灭；100% → 最亮。

2. 频率与占空比：两个独立的旋钮

生活类比：频率像「快门每秒按几下」，占空比像「每次曝光多久」——两个旋钮各管各的：把快门拧快（频率高），曝光量（占空比）可以不动；调曝光量，快门速度也不变。

一句话定义：频率 = 每秒开关多少次（决定 PWM 周期长短，LED 高频不闪、电机低频会啸叫）；占空比 = 一个周期里高电平占的比例（决定输出「平均大小」）。两者独立可调：改频率不改占空比、改占空比不改频率。

例子：LED 用 5kHz（听不见、不闪）；舵机用 50Hz（周期 20ms，舵机协议规定）；电机用几百 Hz~几十 kHz（避开共振噪声）。

3. 分辨率：占空比能细到什么程度

生活类比：分辨率就是调光旋钮的「刻度密度」——老式旋钮只有 0/1/2/3 四档，拧不出中间亮度；好旋钮有 256 档，过渡才丝滑。

一句话定义：占空比不是无限可调，而是按「分辨率」分成若干档。ESP32 LEDC 分辨率默认 8 位（0~255），即占空比 256 档；舵机想精确到 1°，要用 10~16 位分辨率。分辨率越高，档位越细，但受频率限制（频率越高可用分辨率越低）。

例子：8 位分辨率下 ledcWrite(0, 128) = 占空比 128/255 ≈ 50%；想要 0.1% 的精细调节，就提高分辨率。

4. ESP32 的 LEDC 结构：定时器 + 通道 + 引脚

生活类比：LEDC 像「可编程灯光控制台」——定时器是节拍器（定快慢），通道是灯光回路（16 路独立输出），引脚是接灯泡的插座：节拍器定好速度，哪路通道接哪个插座，都由你分配。

一句话定义：ESP32 的 PWM 分三层：定时器（决定频率与分辨率，共 4 个，可分组）、通道（16 个，绑定定时器，负责输出占空比）、引脚（把通道接到具体 GPIO）。配置三步：ledcSetup(通道, 频率, 分辨率) → ledcAttachPin(引脚, 通道) → ledcWrite(通道, 占空比)。

例子：ledcSetup(0, 5000, 8); ledcAttachPin(4, 0); ledcWrite(0, 200); 让 GPIO4 输出 5kHz、占空比 200/255 的 PWM。

5. LEDC 的两个时钟源：高频 APB 与低频 REF_TICK

生活类比：LEDC 的节拍器有两档发条——快档（80MHz，转得飞快，能出高频 PWM）和慢档（1MHz，省电，能出超低频 PWM）。不同应用选不同档。

一句话定义：ESP32 LEDC 定时器可选两种时钟源——APB_CLK（80MHz，高速时钟）用于普通高频 PWM（LED 调光、电机）；REF_TICK（1MHz，低频基准）用于需要极低频的场合。Arduino-ESP32 的 ledcSetup 会根据你给的频率和分辨率自动选合适的时钟源与分频比。

例子：LED 呼吸灯用 5kHz（走 80MHz 分频）；若要 1Hz 的极慢 PWM，80MHz 分频不够细时就自动切到 1MHz 时钟源。教材考点：频率越高、能做到的分辨率越低（分频比有限），这是频率-分辨率取舍的根因。

三、原理介绍：呼吸灯与舵机为什么都要 PWM

ESP32 的 PWM 叫 LEDC，是一块硬件 PWM 发生器。理解它内部「分频器 → 计数器 → 比较器」三级电路，才能搞懂为什么 ledcSetup 三个参数各自管什么、为什么舵机频率不能乱改。

一次「改一次占空比」的链路：ledcWrite 写比较值 → LEDC 硬件在计数器计到该值时翻转引脚 → 引脚自动输出方波，CPU 完全不用管。

原理 1：PWM 的本质——用时间平均「合成」模拟量

LED 只有 0V 和 3.3V 两档，但高速开关时，人眼和 LED 的惯性会把高频方波平均成中间亮度：高电平占 90% 时间，平均电压就是 3.3V×90%≈2.97V，看起来就是 90% 亮。频率决定每秒开关多少次（太低人眼可见闪烁），占空比决定高电平占的比例（决定平均输出大小）。呼吸灯就是占空比从 0 平滑扫到 255 再扫回来。

原理 2：LEDC 内部——分频器、计数器、比较器三级电路

LEDC 不靠软件翻转引脚，而是全硬件自动输出：

  1. 分频器：把 80MHz 主时钟分频，得到「计数时钟」——它决定 PWM 频率（这就是 ledcSetup 第二参频率的来历）。
  2. 计数器：每个计数时钟沿 +1，数到分辨率上限（8 位 = 数到 255）就回 0，循环往复。
  3. 比较器：引脚电平 = 「计数值 < 你写的占空比」为真则高、否则低——你写的占空比越大，每个周期里高电平越久。

这套电路全自动运行，不占 CPU：你一旦 ledcWrite 设好值，引脚自己不停输出方波，loop 随便跑别的。这就是为什么不能用 digitalWrite+delay 模拟——软件翻转会阻塞主循环、频率还被别的任务打断。16 个通道共享分频器：所以 16 路能同频率、各自不同占空比（不同亮度）。

原理 3：舵机为什么必须 50Hz——脉宽才是指令

舵机（SG90）不靠平均电压定位角度，而是读一个周期里高电平的宽度：0.5ms=0°、1.5ms=90°、2.5ms=180°，周期固定 20ms（即 50Hz）。换算：8 位分辨率下 1ms 脉宽 = 255/20 ≈ 12.75 档，所以 0.5ms≈6、1.5ms≈19、2.5ms≈32。为什么不能改频率：频率太高（1kHz），0.5~2.5ms 的脉宽在一个周期里占比太小，舵机识别不出；太低（1Hz）舵机会在两次指令间隔里松手抖动——所以 ledcSetup(0, 50, 8) 的 50 是舵机协议的硬约束。

记忆点：PWM=高频开关的时间平均（频率管闪不闪、占空比管大小）；LEDC=分频器→计数器→比较器三级硬件，全自动不占 CPU；16 通道共享分频器；舵机读脉宽不读平均，必须 50Hz/20ms，0.5ms=0°、2.5ms=180°。

四、硬件接线说明

两个实验共用一块板，先做呼吸灯（LED），再做舵机（SG90）：

模块引脚ESP32 引脚说明
LED 阳极GPIO4经 220Ω 限流电阻接 PWM 输出
LED 阴极GND共地
舵机信号线（橙）GPIO4（换线重接）PWM 信号 50Hz
舵机电源线（红）5V 外接电源SG90 堵转电流大，别只靠板子 3.3V
舵机地线（棕）GND（与外接电源共地）必须与 ESP32 共地

为什么舵机要外接 5V 电源：SG90 工作时电流 200mA+，堵转能到 700mA，ESP32 的 3.3V 引脚扛不住，供电不足会导致舵机抖动、复位移位。为什么必须共地：舵机和 ESP32 的「地」必须连一起，PWM 信号才有参考电平——这是所有「外接电源 + 信号控制」接线的铁律。

避坑 GPIO4 是安全 PWM 引脚；避开 GPIO0/2/12（影响启动/烧录）与 GPIO6~11（Flash 占用）。舵机 5V 电源不要直接灌进 ESP32 的 3.3V 引脚——只供舵机、与 ESP32 共地即可。

五、完整代码

示例 1：LED 呼吸灯（占空比 0→255→0 循环）

/* LED 呼吸灯：PWM 占空比循环渐变 */
const int ledPin = 4;       /* PWM 输出引脚 */

void setup() {
  // 1. 配置 PWM：通道 0、频率 5000Hz、分辨率 8 位（0~255）
  ledcSetup(0, 5000, 8);
  // 2. 把 GPIO4 绑定到通道 0
  ledcAttachPin(ledPin, 0);
}

void loop() {
  // 渐亮：占空比从 0 加到 255
  for (int duty = 0; duty <= 255; duty++) {
    ledcWrite(0, duty);        // 输出当前占空比
    delay(5);                  // 每档停留 5ms → 一个循环约 1.3s
  }
  // 渐灭：占空比从 255 减到 0
  for (int duty = 255; duty >= 0; duty--) {
    ledcWrite(0, duty);
    delay(5);
  }
}

示例 2：舵机角度控制（SG90，频率 50Hz，脉宽换算占空比）

/* 舵机控制：0°~180° 往返摆动 */
const int servoPin = 4;

/* 角度 → 占空比（8 位分辨率，周期 20ms）：
   0.5ms=0°、1.5ms=90°、2.5ms=180°；1ms = 255/20 = 12.75 档 */
int angleToDuty(int angle) {
  // 脉宽(ms) = 0.5 + angle / 180.0 * 2.0，再换算成 0~255 档
  return (int)((0.5 + angle * 2.0 / 180.0) * 12.75);
}

void setup() {
  ledcSetup(0, 50, 8);         /* 舵机必须 50Hz（周期 20ms） */
  ledcAttachPin(servoPin, 0);
  ledcWrite(0, angleToDuty(90));  /* 先回中 */
  delay(500);
}

void loop() {
  for (int a = 0; a <= 180; a += 10) {   /* 0°→180°，每 10° 一档 */
    ledcWrite(0, angleToDuty(a));
    delay(200);
  }
  for (int a = 180; a >= 0; a -= 10) {   /* 180°→0° 回程 */
    ledcWrite(0, angleToDuty(a));
    delay(200);
  }
}

六、代码逐段讲解

第一段：呼吸灯的两层 for

外层两段 for 分别负责「渐亮」和「渐灭」，内层 ledcWrite(0, duty) 每次输出一档占空比、delay(5) 停留 5ms。为什么每档要延时：不延时，255 档一毫秒跑完，眼睛只看到「亮一下灭一下」的闪烁，看不到渐变——延时决定了呼吸的节奏（快慢）。为什么 5ms：255 档 × 5ms ≈ 1.3 秒一个呼吸周期，观感自然，可按喜好调整。

第二段：angleToDuty 的换算

(0.5 + angle * 2.0 / 180.0) 把角度映射成脉宽毫秒（0°→0.5ms、180°→2.5ms），再乘 12.75 换成 8 位占空比档。为什么这么麻烦：ledcWrite 只认「档位」不认「毫秒」，而舵机协议规定的是「毫秒脉宽」——中间必须做一次单位换算。注意：这是近似换算，实际舵机可能在 0.4~2.4ms 之间，跑起来角度偏了用「脉宽上下限微调」修正。

第三段：为什么 setup 里先回中

ledcWrite(0, angleToDuty(90)); delay(500); 让舵机先转到中间位置再开始循环。为什么先回中：舵机上电瞬间位置未知，若直接开始往返，可能从某个极端角度猛转——回中既保护舵机，也让现象可预期（从 90° 开始摆）。这是执行器控制的工程习惯。

第四段：寄存器 ↔ 驱动 API ↔ Arduino 函数三层对照

教材要求看懂 LEDC 的三层关系：

你写的 Arduino 函数底层 ESP-IDF API最终操作的硬件寄存器
ledcSetup(0,5000,8)ledc_timer_config()LEDC 定时器分频/位宽寄存器
ledcAttachPin(4,0)ledc_bind_channel_timer()LEDC 通道与 GPIO 的映射（经 GPIO Matrix）
ledcWrite(0,duty)ledc_set_duty()LEDC_DUTY 通道占空比寄存器

为什么重要：ledcWrite 看似简单，实际是写 LEDC_DUTY 寄存器，硬件比较器自动按计数值翻转引脚——这就是「不占 CPU」的硬件 PWM 本质。

七、现象演示与验证

  • 呼吸灯：LED 亮度缓慢增强再减弱，循环不断，无闪烁。
  • 舵机：先停在 90°，然后从 0° 摆到 180°、再摆回 0°，每 10° 一停。

验证方法：

  1. 把频率从 5000Hz 改成 50Hz 接 LED——LED 会明显闪烁，体会「频率太低会闪」。
  2. 把分辨率从 8 改成 16（ledcSetup 第三参），但呼吸循环仍用 0~255——现象不变但占空比范围变 0~65535，注意循环要配套改。
  3. 舵机接 3.3V（不接外接电源）再跑，观察抖动与无力——验证「舵机必须外接 5V」的结论。

八、常见报错排查方案

报错现象可能原因解决方法
LED 不亮引脚没 attach / 通道号冲突确认 ledcAttachPin 与 ledcWrite 用同一通道号；换空闲通道
LED 闪烁明显频率太低（<1kHz）LED 用 5kHz 以上；400Hz 以下人眼可辨闪
舵机不动或抖动频率不是 50Hz / 供电不足ledcSetup 第二参必须 50；舵机接外接 5V 并共地
舵机角度偏脉宽换算近似、个体差异实测 0°/180° 对应占空比，改 angleToDuty 上下限
烧录失败 / 上电异常用了 GPIO6~11 或 GPIO0/2/12换 GPIO4/5/15/16 等安全引脚（看开发板引脚图）
ledcWrite 没效果忘了 ledcSetup（通道未初始化）三步缺一不可：Setup → AttachPin → Write

九、课后练习与延伸

练习 1（必做）：把呼吸灯循环改成「先快后慢」的变节奏呼吸（每档延时随占空比变化），体会延时对节奏的控制。

练习 2：把舵机角度改成串口输入：Serial.readString() 读角度数字，解析后 ledcWrite 到对应占空比——把 PWM 与 串口/WiFi 控制衔接起来。

练习 3（进阶）：用两个 LEDC 通道同时驱动两个舵机，做一个「点头摇头」的小机器人头部——理解多通道独立配置。

延伸学习：PWM 是「输出模拟量」，下一课学 ADC 模拟读取——ESP32 读「模拟量输入」的另一半技能，合起来就能做「传感器+执行器」的完整闭环。
