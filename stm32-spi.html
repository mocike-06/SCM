SPI 通信与 W25Q64 Flash 存储

系列：STM32 进阶 更新：2026-10-25

I2C 用 2 根线、SPI 用 4 根线，但速度更快、一次传更多数据——教材把 SPI 叫「高速串行总线」。本课以 W25Q64 Flash 芯片（8Mbit，开发板标配）为例，讲透四线协议、主从角色、时序模式，并写出读 ID、页写、扇区擦除、读数据的完整代码，学会给单片机加一块「掉电不丢的大仓库」。

一、本课目标与前置知识

学完本课你能做到：

  • 说清 SPI 四根线（SCK/MOSI/MISO/CS）各干什么，主从模式怎么分工。
  • 理解 CPOL/CPHA 与时序模式（Mode 0~3），能看懂芯片手册的时序图。
  • 用 HAL 读写 W25Q64：读 ID 验证通信、写入并读回数据。

需要提前掌握的前置知识（对应学习路线阶段 4）：

  • 寄存器与地址（stm32-register.html）：SPI 外设也在固定地址上，只是 HAL 帮你封装了。
  • 时钟配置（stm32-clock.html）：SPI1 挂在 APB2，SPI2/3 挂在 APB1。
  • I2C 概念（stm32-i2c-oled.html，可选）：同为串行总线，对照着学更容易。

本课会出现的新名词：SPI、SCK/MOSI/MISO/CS、主从模式、CPOL/CPHA、全双工、W25Q64、页编程、扇区擦除、指令集、状态寄存器。

二、基础概念铺垫

1. SPI 的 4 根线：分工明确的快递通道

生活类比：SPI 像一套人工快递流程：CS（片选）= 给哪个收件人派单（拉低表示「这单是你的」）；SCK（时钟）= 收发双方的节拍器（每跳一次传一位）；MOSI = 主机→从机方向的车道（Master Out Slave In）；MISO = 从机→主机方向的车道。

一句话定义：SPI（串行外设接口）是主从式全双工串行总线：主机控制时钟 SCK 和片选 CS，通过 MOSI 发数据、MISO 收数据，四根线同时工作，速度远高于 I2C（F103 SPI 可达 18MHz）。

例子：给 W25Q64 发「读 ID」命令：CS 拉低选中它 → SCK 打节拍 → MOSI 发命令字节 → MISO 回读 2 个字节 ID → CS 拉高结束。

2. 主从模式与片选 CS

生活类比：总线上只有一个「发号施令的老板」（主机=STM32）和很多「听令的员工」（从机=Flash、SD 卡等），老板喊谁（CS 拉低谁）谁应答，其它员工保持沉默（MISO 高阻）。

一句话定义：SPI 是主从结构，时钟永远由主机产生；每个从机一根独立 CS 线，CS 低电平 = 被选中。一根 SPI 总线可挂多个从机（各一根 CS），但同一时刻只能选中一个。

例子：W25Q64 的 CS 接 PA4，SD 卡的 CS 接 PA3——两个都挂在 SPI1 上，靠 CS 区分谁说话。

3. CPOL/CPHA：时钟的「性格」与时序模式

生活类比：同一个节拍器，有的器件喜欢「高电平休息」（空闲高）、有的喜欢「低电平休息」（空闲低）；数据采样有的在上升沿、有的在下降沿。CPOL（时钟极性）= 空闲时 SCK 是高还是低；CPHA（时钟相位）= 数据在哪个边沿采样。

一句话定义：CPOL=0 空闲低、CPOL=1 空闲高；CPHA=0 第一个边沿采样、CPHA=1 第二个边沿采样。组合出 Mode 0~3。W25Q64 支持 Mode 0 和 Mode 3（常用 Mode 0：CPOL=0、CPHA=0）。

例子：CubeMX 里 SPI 配置页面选 Mode 0（CPOL Low、CPHA 1Edge）；配错模式，读回来的数据全是 0xFF 或错位——这是 SPI 新手第一大坑。

4. W25Q64 的组织结构：256 字节一页、4096 字节一扇区

生活类比：Flash 像一本「只能整块擦、不能单个改字」的涂改本：写之前必须把那一块擦成空白（全 0xFF），而且擦的最小单位是扇区（4KB），不是字节。

一句话定义：W25Q64 = 64Mbit = 8MB 的 SPI Nor Flash。页：256 字节（一次最多写 256 字节，页编程）；扇区：4KB（擦除的最小单位）；块：32KB/64KB。写数据前必须先擦除所在扇区，否则写不进去。

例子：往地址 0x1000 写数据 → 先擦除 0x1000 所在的扇区（地址 0x1000~0x1FFF）→ 再发「页编程」命令写入。

三、原理介绍：W25Q64 的一条完整指令流程

SPI 比 I2C 快得多，靠的是「一根时钟线同步、两根数据线收发同时进行」。三个机制讲清它。

整条链路：主机拉低 CS 选中 → SCK 打 8 个脉冲 → MOSI 出一位同时 MISO 进一位 → 一个字节收发完成 → 拉 CS 结束。

原理 1：四线与同步移位——为什么发一字节必同时收一字节

SPI 有四根线：SCK 时钟（主机出）、MOSI 主机发、MISO 从机发、CS 片选（低有效）。主机和从机内部各有一个 8 位移位寄存器，且在 SCK 下同步串联成一个 16 位环：主机打一个脉冲，把自己寄存器的一位推到 MOSI，同时把 MISO 的一位拉进自己寄存器。打满 8 个脉冲，双方寄存器恰好交换完一个字节。所以 SPI 没有单独的「读」操作——读 ID 本质是边发 0x90 + 哑字节、边借同样的时钟把 MISO 读回来。

原理 2：CPOL/CPHA——SCL 空闲电平和采样沿怎么定

「什么时候采样」有两种自由：SCK 空闲是高还是低（CPOL）、在第一个沿还是第二个沿采样（CPHA），组合成 4 种模式。两端必须一致。W25Q64 用最常见的 Mode0（CPOL=0、CPHA=0）：SCK 空闲为低，第一个下降沿移位、上升沿采样。模式不匹配，读回来的 ID 全错——这是 SPI 调不通第一大原因。

教材标准四模式对照表（野火/SPI 时序图）：

模式CPOLCPHASCK 空闲电平数据采样沿移位沿
Mode 000低上升沿下降沿
Mode 101低下降沿上升沿
Mode 210高下降沿上升沿
Mode 311高上升沿下降沿

总线归属决定最高速度：SPI1 挂在 APB2(72MHz)，最高 SCK = fPCLK2/2 = 36MHz；SPI2/SPI3 挂在 APB1(36MHz)，最高 SCK = fPCLK1/2 = 18MHz——所以同样是 SPI，用 SPI1 能跑得更快。W25Q64 手册上限约 50/80MHz，F103 这边受总线限制，实际分频选 fPCLK/4 左右（18MHz）最稳。

原理 3：W25Q64 命令流——为什么必须写使能+查忙

读器件 ID 的一条指令：CS 拉低 → 发 0x90 → 发 3 字节地址 → MISO 返回厂商 ID(0xEF) 与器件 ID → CS 拉高。写还要多两步：

  1. 先 写使能 0x06（Flash 默认禁写，防止误改）。
  2. 发页编程 0x02 + 24 位地址 + 数据，然后 读状态寄存器 0x05 查 BUSY 位，等它变 0。

为什么必须查忙：Flash 内部擦/写是慢操作（几 ms），状态机没忙完就发下一条命令，数据必丢。擦除最小单位是扇区 4KB（0x20 命令）。这套「写使能→操作→查忙」是所有 SPI Flash 的固定套路。

记忆点：SPI=CS 片选+SCK 时钟+MOSI/MISO 同步移位，发一字节必收一字节；CPOL/CPHA 两端要一致，W25Q64 用 Mode0；W25Q64 套路=写使能 0x06→发指令+地址→查忙 0x05；擦除最小 4KB 扇区。

四、硬件接线说明

W25Q64 模块（8 脚）接 STM32 的 SPI1（PA5=SCK、PA6=MISO、PA7=MOSI、PA4=CS，正点原子等开发板的标准接法）：

模块引脚单片机引脚说明
CSPA4片选（软件 GPIO 控制）
CLK (SCK)PA5SPI1_SCK，时钟输出
DO (MISO)PA6SPI1_MISO，芯片→主机
DI (MOSI)PA7SPI1_MOSI，主机→芯片
VCC / GND3.3V / GNDW25Q64 是 3.3V 器件，不能接 5V
WP、HOLDVCC写保护与保持，接高电平禁用保护

为什么 CS 用普通 GPIO 而不是 SPI 硬件自动控制：CS 逻辑简单（通信前拉低、结束拉高），用 GPIO 控制更灵活，还能随时选中/释放；硬件 NSS 模式反而容易误触发。这也是教材和开发板例程的常见做法。

为什么 W25Q64 必须 3.3V：W25Q64 是 3.3V 逻辑器件，接 5V 会损坏；STM32 引脚正好 3.3V，无需电平转换——这也是 SPI 接法「直连即可」的原因。

避坑 买模块时注意是「W25Q64」（8MB）还是「W25Q128」（16MB）——容量不同，器件 ID 和扇区规划不同；仿真里 Proteus 的 SPI FLASH 元件型号选对应 W25Q64。

五、完整代码

CubeMX 配置要点：SPI1 全双工主机、Mode 0（CPOL Low / CPHA 1Edge）、速率 ≤18MHz；PA4 配 GPIO 输出。以下为核心读写代码。

示例 1：读取 W25Q64 的厂商与器件 ID（验证通信）

/* SPI 读写 W25Q64：读 ID 验证通信 */
#include "main.h"

extern SPI_HandleTypeDef hspi1;

#define W25_CS_LOW()   HAL_GPIO_WritePin(GPIOA, GPIO_PIN_4, GPIO_PIN_RESET)
#define W25_CS_HIGH()  HAL_GPIO_WritePin(GPIOA, GPIO_PIN_4, GPIO_PIN_SET)

/* 写使能（0x06）：每次写/擦除前必须调用 */
void w25_write_enable(void)
{
    uint8_t cmd = 0x06;
    W25_CS_LOW();
    HAL_SPI_Transmit(&hspi1, &cmd, 1, 100);
    W25_CS_HIGH();
}

/* 查忙：读状态寄存器（0x05），返回 1=忙 */
uint8_t w25_busy(void)
{
    uint8_t cmd = 0x05, sr = 0xFF;
    W25_CS_LOW();
    HAL_SPI_Transmit(&hspi1, &cmd, 1, 100);
    HAL_SPI_Receive(&hspi1, &sr, 1, 100);  /* 读回状态字节 */
    W25_CS_HIGH();
    return sr & 0x01;                /* bit0 = BUSY */
}

/* 读 ID：返回 16 位（厂商|器件） */
uint16_t w25_read_id(void)
{
    uint8_t cmd[4] = {0x90, 0x00, 0x00, 0x00};  /* 指令 + 3 哑地址 */
    uint8_t buf[2] = {0, 0};
    W25_CS_LOW();
    HAL_SPI_Transmit(&hspi1, cmd, 4, 100);      /* 发指令 + 哑字节 */
    HAL_SPI_Receive(&hspi1, buf, 2, 100);       /* 读 2 字节 ID */
    W25_CS_HIGH();
    return (uint16_t)(buf[0] << 8 | buf[1]);
}

示例 2：扇区擦除 + 页写 + 随机读（完整写读流程）

/* 擦除指定扇区（0x20），扇区地址按 4KB 对齐 */
void w25_erase_sector(uint32_t addr)
{
    uint8_t cmd[4] = {0x20,
                      (addr >> 16) & 0xFF, (addr >> 8) & 0xFF, addr & 0xFF};
    w25_write_enable();             /* 1. 写使能 */
    W25_CS_LOW();
    HAL_SPI_Transmit(&hspi1, cmd, 4, 100);      /* 2. 擦除指令 + 24 位地址 */
    W25_CS_HIGH();
    while (w25_busy());             /* 3. 等擦除完成 */
}

/* 页编程（0x02）：一次最多写 256 字节 */
void w25_page_program(uint32_t addr, uint8_t *data, uint16_t len)
{
    uint8_t cmd[4] = {0x02,
                      (addr >> 16) & 0xFF, (addr >> 8) & 0xFF, addr & 0xFF};
    w25_write_enable();
    W25_CS_LOW();
    HAL_SPI_Transmit(&hspi1, cmd, 4, 100);
    HAL_SPI_Transmit(&hspi1, data, len, 100);  /* 写数据 */
    W25_CS_HIGH();
    while (w25_busy());
}

/* 读数据（0x03）：任意地址任意长度 */
void w25_read_data(uint32_t addr, uint8_t *buf, uint16_t len)
{
    uint8_t cmd[4] = {0x03,
                      (addr >> 16) & 0xFF, (addr >> 8) & 0xFF, addr & 0xFF};
    W25_CS_LOW();
    HAL_SPI_Transmit(&hspi1, cmd, 4, 100);
    HAL_SPI_Receive(&hspi1, buf, len, 100);    /* 读数据 */
    W25_CS_HIGH();
}

int main(void)
{
    uint8_t wbuf[16] = "McuStudy SPI ok";
    uint8_t rbuf[16] = {0};
    HAL_Init();
    SystemClock_Config();
    /* MX_GPIO_Init / MX_SPI1_Init 由 CubeMX 生成 */

    uint16_t id = w25_read_id();            /* 应为 0xEF14 左右 */
    w25_erase_sector(0x0000);               /* 先擦除 0 扇区 */
    w25_page_program(0x0000, wbuf, 16);     /* 写入 16 字节 */
    w25_read_data(0x0000, rbuf, 16);        /* 读回验证 */
    /* rbuf 应与 wbuf 相同，串口打印 "McuStudy SPI ok" */
    while (1);
}

六、代码逐段讲解

第一段：三个基础函数——指令帧的标准结构

每个 W25Q64 命令都是「CS 拉低 → 发指令（可含地址）→ 收发数据 → CS 拉高」。w25_read_id() 里 cmd[4]={0x90,0,0,0} 就是「指令 + 3 个哑地址字节」——为什么发 0 也要打时钟：SPI 是同步全双工，主机必须提供时钟芯片才能回数据，发哑字节就是「借时钟」。

第二段：写使能与查忙的顺序

w25_write_enable() 必须先于任何写/擦操作，因为 W25Q64 上电后默认「写保护」；while (w25_busy()); 死等内部操作完成。为什么不能省：省了写使能 → 写入静默失败（数据还是 FF）；省了查忙 → 下一次命令撞上内部操作，数据丢失。这两个坑教材反复强调。

第三段：24 位地址怎么拆

(addr >> 16) & 0xFF 取高 8 位、(addr >> 8) & 0xFF 取中 8 位、addr & 0xFF 取低 8 位。为什么拆成 3 字节：W25Q64 最大 8MB 需要 23 位地址（0x000000~0x7FFFFF），SPI 每次只传一字节，所以按 24 位拆开发——这正是位运算课「拆字节」在真实外设上的应用。

第四段：erase → program → read 的完整链路

main 里的三步顺序是 Flash 编程的「铁律」：先擦后写再读。擦扇区把地址 0x0000~0x0FFF 全部置 0xFF；页编程把 16 字节写进去（不足 256 字节也没问题）；读回比较。为什么不擦直接写：Flash 只能把 1 变 0，不能把 0 变 1（写 0 可以、写 1 不行）——所以必须先擦（全变 1）再写。

七、现象演示与验证

  • 读 ID：串口打印厂商 ID 0xEF、器件 ID（W25Q64 约 0x40，W25Q128 约 0x18），与芯片丝印对应。
  • 写读验证：串口打印读回的 16 字节，应为 McuStudy SPI ok。

验证方法：

  1. 把写的内容改成递增数字（0x00~0x0F），读回逐字节比对——发现错位即时序模式（Mode）选错。
  2. 把 w25_write_enable() 注释掉再写，读回全 FF——亲手验证写使能的必要性。
  3. 在模式 0 与模式 3（CPOL/CPHA 各组合）之间切换，观察读 ID 结果——体会 CPOL/CPHA 对通信的决定性影响。

八、常见报错排查方案

报错现象可能原因解决方法
读 ID 全 FF 或全 00时序模式不对（Mode 选错）/ CS 没拉低 / 接线错改 Mode 0；确认 CS 时序与引脚；核对 MOSI/MISO 是否接反
写入后读回全 FF没写使能 / 没擦除写前先 w25_write_enable()；先擦扇区再页编程

九、课后练习与延伸

练习 1（必做）：把写读地址从 0x0000 换到 0x2000（跨一个扇区），先擦对应扇区再写读，验证地址拆分正确。

练习 2：实现「掉电记忆」：上电先读 0x0000 处的次数值，+1 后写回（先擦后写），串口打印——做一个小计数器，重启不归零。

练习 3（进阶）：结合 DMA 教程，把页编程的数据传输改成 DMA 模式，对比普通模式与 DMA 模式的主循环占用差异。

延伸学习：SPI 是「高速搬数据」，下一课学 DMA 直接存储器访问——让数据搬运不再占用 CPU，串口、ADC、SPI 全都能提速。
