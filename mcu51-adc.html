ADC0832 模拟量采集（电压表）

系列：51 单片机 进阶 更新：2026-10-25

单片机只会处理 0/1 数字，但温度、电压、光照都是连续变化的模拟量。本课用教材经典 ADC0832（8 位、双通道、SPI 风格串行接口）把模拟电压变成数字，做一台电位器电压表。

一、本课目标与前置知识

学完本课你能做到：

  • 说清 ADC 的「分辨率、参考电压、量化」三个概念，会算 8 位 ADC 的分辨率。
  • 看懂 ADC0832 的启动时序与两次读（MSB 先行、LSB 后行）流程。
  • 采集电位器电压，换算成真实电压值显示出来。

需要提前掌握的前置知识（对应学习路线阶段 2）：

  • 定时器（可选）：定时采样做平滑滤波。
  • 位运算：逐位收发数据。
  • LCD1602（可选）：显示电压值。

本课会出现的新名词：模拟量/数字量、ADC、分辨率、参考电压 Vref、量化、通道选择、SPI 时序、MSB/LSB。

二、基础概念铺垫

1. 模拟量 vs 数字量：连续 vs 台阶

生活类比：温度计的水银柱是连续变化的（模拟量）；电子表只显示整数温度（数字量）。ADC 就是「把水银柱高度读成数字」的翻译官。

一句话定义：模拟量是连续变化的物理量（电压 0~5V 任意值）；数字量是离散的二进制数。单片机只能处理数字量，所以采集模拟电压必须经过 ADC（模数转换器）。

例子：电位器旋到中间，输出电压约 2.5V——51 读不到这个「约 2.5V」，只能让 ADC 芯片把它换成某个数字。

2. 分辨率与量化：一个数字代表多大电压

一句话定义：8 位 ADC 的输出是 0~255 共 256 个台阶。若参考电压 Vref = 5V，每个台阶代表 5V / 256 ≈ 0.0195V（≈19.5mV），这就是分辨率（最小可分辨的电压变化）。输入 2.5V → 数字值 ≈ 2.5 / 5 × 256 ≈ 128。

例子：电压换算公式 电压 = 数字值 × Vref / 256。想量 0~5V 就用 Vref=5V；参考电压不准，量出来的数全都不准——所以 Vref 必须稳定。

3. ADC0832：8 位、双通道、串行输出

一句话定义：ADC0832 是教材常见的 8 位 ADC：两个输入通道（CH0/CH1，可选单端或差分）、参考电压 5V、结果经 3 根线（CS/CLK/DO-DI）串行输出。它是 SPI 风格时序：主机给 CLK 脉冲，芯片在时钟边沿逐位吐出数据。

例子：把电位器中间抽头接 CH0，转动电位器，读到的数字在 0~255 之间变化。

4. MSB 先行 / LSB 后行：一次转换吐两遍

一句话定义：ADC0832 完成一次转换后，先从高位到低位（MSB first）吐 8 位，再从低位到高位（LSB first）吐 8 位——两次读同一结果。程序把两次读到的值平均/比较，能提高抗干扰可靠性（教材都这样教）。

例子：读回第一次 10010110，第二次 01101001（反过来），取第一次作结果即可。

5. 教材通用换算公式与 ADC0809 对照（张毅刚教材 ADC 一节）

一句话定义：8 位 ADC 输出数字量 D（0~255）与输入模拟电压 Vin 的关系为 Vin = Vref × D / 256，反解 D = Vin × 256 / Vref。量化误差固定为 ±1/2 LSB（即 ±Vref/512 ≈ ±9.8mV@5V），这是 ADC 位数决定的、软件无法消除——想更细只能换 10/12 位 ADC。教材里另一颗经典芯片是 ADC0809（8 通道并行输出、逐次逼近型、典型转换时间 100µs@640kHz 时钟），与本课 ADC0832 同属 8 位逐次逼近家族，区别只是 ADC0809 走 8 位并行总线、ADC0832 走 SPI 串行；换算公式完全一样。

采样定理（奈奎斯特）：要无失真还原一个最高频率为 fmax 的信号，采样频率必须 ≥ 2×fmax；否则高频成分会「混叠」成低频假信号。入门阶段直接用 10 倍以上采样率（如测缓慢变化的电位器，每 50~200ms 采一次），完全够用。

三、原理介绍：连续变化的电压，怎么变成一个 0~255 的数字

单片机只认数字（0/1），但现实世界的温度、音量、电压都是连续模拟量。ADC（模数转换器）就是中间那座桥。ADC0832 是 8 位、双通道、SPI 风格串行输出的教材型 ADC。

一次完整读取流程：

  1. 片选拉低：CS 高变低使能芯片、启动转换。
  2. 送配置位：CLK 上升沿依次发 3 位（起始1+单端1+通道0）= 110 选 CH0。
  3. 读数据：配置后逐位输出，先 MSB 8 位、再 LSB 8 位。
  4. 片选拉高：结束本次转换。

原理 1：8 位是什么意思——量化与分辨率

ADC 把 0~VREF（这里 5V）这段连续电压切成 256 档（2⁸=256），每档给一个数字。每一档代表的电压 = VREF/256 = 5000mV/256 ≈ 19.5mV。所以读到数字 N，对应电压 ≈ N×19.5mV = N×5000/256 mV。「量化」就是「电压落在某一档就记那个档号」——电压 2.5V 正好落在第 128 档附近，读到 128。不可避免的代价是量化误差：落在两档之间的电压会被就近归一档，最大误差 ±半档 ≈ ±10mV，这是 8 位 ADC 的固有限制（想更准就换 10/12 位 ADC）。

原理 2：转换那几个 CLK 里，芯片内部在做什么——逐次逼近

ADC0832 用的是 SAR（逐次逼近）算法，本质是二分搜索：从最高位开始，先把试探值的最高位设 1、其它位 0（即 128 档对应的电压），芯片内部一个 DAC 把这个试探值变回电压，和输入电压比——输入更高就保留这位 1、更低就清 0；然后次高位重复……8 位要比 8 次，每次缩一半范围，8 次就锁定到具体档号。这就是为什么转换需要好几个 CLK 周期、而不是一拍出结果：它在内部做 8 次二分比较。理解这点就明白：配置位送完后，你不能立刻读数据，得等它逐次逼近走完。

原理 3：为什么 DI/DO 共用一根线、还得切换方向

ADC0832 为省引脚，把「主机送配置进去」的 DI 和「芯片吐结果出来」的 DO 内部接在同一根脚(DIO)上。一根线两个方向怎么不打架？靠 CS/CLK 时序分时：前半段这根线由主机驱动、往里送 3 位配置（输出方向）；后半段主机松手（DIO 写 1 变输入），芯片在 CLK 边沿往外吐数据。这就是代码里要「先把 DIO 当输出写配置、再当输入读电平」的原因——一根线轮流当两个方向用。电压换算时记得用 unsigned long 承接中间乘积，否则 adc×5000 会溢出（见代码讲解段）。

记忆点：ADC=把0~5V切成256档、每档≈19.5mV，数字N×5000/256=毫伏；8位SAR逐次逼近=内部8次二分比较、所以要等几个CLK才出结果；DI/DO共用DIO一根脚，前半段主机送配置、后半段松手让芯片吐数据；电压换算用unsigned long防溢出。

为什么 DI/DO 共用一根脚：ADC0832 的 DI 与 DO 在芯片内部接到同一引脚（标注为 DI/DO 或 DIO），由 CS/CLK 时序决定方向——先当输出送配置，后当输入读数据。所以代码里要把这根 IO 在「输出配置」和「输入读值」之间切换方向。

避坑 电位器接法：两端接 5V 与 GND、中间抽头接 CH0。VREF 必须稳定（直接接 VCC 即可），别用电阻分压当参考，否则换算全是错的。Proteus 里 ADC0832 是现成元件，电位器用 POT-HG。

五、完整代码

核心是 adc_read() 函数：送配置（CH0）→ 读 MSB 8 位 → 读 LSB 8 位 → 换算电压。结果经串口输出（或接 LCD1602）。

/* ADC0832 采集 CH0 电压，串口输出，9600 */
#include <reg52.h>

sbit ADC_CS  = P1^0;             /* 片选 */
sbit ADC_CLK = P1^1;             /* 时钟 */
sbit ADC_DIO = P1^2;             /* 数据：先输出配置、后输入结果 */

void delay_us(unsigned int us) { while (us--); }

/* 读取 ADC0832 通道 0 的数字值（0~255） */
unsigned char adc_read_ch0(void) {
    unsigned char i, dat = 0;

    ADC_CS = 1; ADC_CLK = 0;     /* 复位时序：先让 CS 高、CLK 低 */
    ADC_CS = 0;                  /* 片选拉低，芯片使能 */
    ADC_DIO = 1;                 /* 起始位 = 1 */
    ADC_CLK = 1; ADC_CLK = 0;

    ADC_DIO = 1;                 /* 单端模式 SGL/DIFF = 1 */
    ADC_CLK = 1; ADC_CLK = 0;

    ADC_DIO = 0;                 /* 通道 0（ODD/SIGN = 0） */
    ADC_CLK = 1; ADC_CLK = 0;

    /* 数据输出：先读 MSB（8 位），第一个下降沿后开始 */
    for (i = 0; i < 8; i++) {
        ADC_CLK = 1;
        ADC_CLK = 0;             /* 下降沿后芯片输出下一位 */
        dat = (dat << 1) | ADC_DIO;  /* 逐位移入 */
    }

    /* 再读 LSB（8 位，从低位到高位），用于校验/平均 */
    for (i = 0; i < 8; i++) {
        ADC_CLK = 1;
        ADC_CLK = 0;
        /* LSB 通道数据，可忽略或与 MSB 结果比对 */
    }

    ADC_CS = 1;                  /* 片选拉高，结束转换 */
    return dat;
}

void uart_init(void) {           /* 9600 @11.0592MHz */
    SCON = 0x50;
    TMOD |= 0x20;
    TH1 = 0xFD; TL1 = 0xFD;
    TR1 = 1;
}

/* 输出 3 位数字（000~255） */
void uart_putnum(unsigned char n) {
    SBUF = '0' + n / 100; while (!TI); TI = 0;
    SBUF = '0' + (n / 10) % 10; while (!TI); TI = 0;
    SBUF = '0' + n % 10; while (!TI); TI = 0;
}

void main(void) {
    unsigned char adc;
    unsigned long mv;          /* 用 32 位 long：adc*5000 最大 127 万，16 位会溢出 */
    uart_init();
    while (1) {
        adc = adc_read_ch0();    /* 读取数字值 0~255 */
        /* 电压(mV) = adc × 5000 / 256，先转 long 再乘，避免 16 位溢出 */
        mv = (unsigned long)adc * 5000UL / 256UL;
        /* 串口输出数字值 */
        uart_putnum(adc);
        SBUF = ' '; while (!TI); TI = 0;
        /* 输出毫伏值（示例：只输出高 2 位做演示） */
        SBUF = '0' + mv / 1000; while (!TI); TI = 0;
        SBUF = '.'; while (!TI); TI = 0;
        SBUF = '0' + (mv / 100) % 10; while (!TI); TI = 0;
        SBUF = 'V'; while (!TI); TI = 0;
        /* 每 200ms 采样一次：延时省略，可加 delay_ms(200) */
    }
}

变体：不用串口，做一个「电量条」电压表。把采样值 0~255 平均分成 8 档，映射到 P2 口 8 颗 LED——电位器转得越大，亮的灯越多，像手机电量格一样。这个版本去掉了串口，Proteus 里接好电位器+8 颗 LED 直接能看：

/* ADC0832 采样值 -> P2 口 8 灯电量条（共地接法：写 0 亮） */
#include <reg52.h>

sbit ADC_CS  = P1^0;
sbit ADC_CLK = P1^1;
sbit ADC_DIO = P1^2;

void delay_ms(unsigned int ms) {
    unsigned int i, j;
    for (i = 0; i < ms; i++)
        for (j = 0; j < 120; j++);
}

/* 与上面相同的 ADC 读取，此处从略，工程里复用同一个 adc_read_ch0() */
unsigned char adc_read_ch0(void);

void main(void) {
    unsigned char adc, level;
    while (1) {
        adc = adc_read_ch0();
        /* 256 分成 8 档，每档约 32：level = 应亮的灯数 0~8 */
        level = adc / 32 + 1;
        if (level > 8) level = 8;
        /* 共地写 0 亮：先全灭(0xFF)，再把最低 level 位写 0 点亮 */
        P2 = 0xFF;
        P2 &= ~((1 << level) - 1);   /* 低 level 个清 0 = 点亮 */
        delay_ms(50);
    }
}

为什么这样写：adc/32 把 0~255 压到 0~7，+1 是为了「有点电压就先亮第一盏」。(1 << level)-1 算出低 level 个全 1 的掩码，再用 &~ 把这几位清 0——共地接法写 0 才亮，所以掩码要取反。把这个 main 与上面的 adc_read_ch0() 拼在一个工程里即可跑，改 /32 的除数能调灵敏度。

六、代码逐段讲解

第一段：送配置的三拍

起始位（1）、单端选择（1）、通道号（0=CH0、1=CH1）各占一拍，每拍都是「先置 DIO 电平 → CLK 上升沿 → 下降沿」。为什么通道配置要在读数据之前送：ADC0832 不知道你要读哪个通道，这 3 个位就是它选通道的「指令」。改读 CH1 只需把最后一个 ADC_DIO = 0 改成 1。

第二段：MSB 读入的边沿时机

循环里 dat = (dat << 1) | ADC_DIO; 每拍先移出高位再并入新位。为什么读在下降沿后：数据手册规定芯片在 CLK 下降沿后把下一位放到 DIO 上，所以「先给下降沿、再采样」顺序不能反——这与你平时「先读后移」的习惯相反，是 SPI 时序最容易错的地方。

第三段：LSB 第二遍读取的意义

同一转换结果芯片会再以 LSB 先行吐一遍。工程做法：把两次结果比对，若一致则数据可信（抗干扰）。入门先忽略它只留循环骨架，注释里已说明用途——代码既完整可跑，又留了进阶接口。

第四段：电压换算的整数技巧与溢出

mv = (unsigned long)adc * 5000UL / 256UL; 用整数算毫伏（0~5000），避免浮点库。为什么先乘后除：先除会丢精度（adc/256 直接得 0 或 1）；先乘后除保留中间精度。为什么必须用 unsigned long：adc×5000 最大 = 255×5000 = 1,275,000，远超 16 位无符号的 65535，若用 unsigned int 中间乘积溢出，高压段换算会乱跳——这是 ADC 电压表最隐蔽的 bug，务必用 32 位 long 承接中间乘积。

七、现象演示与验证

  • 数字值变化：转动电位器，串口输出的数字值在 000~255 之间变化。
  • 电压换算：输出如 128 2.5V，与万用表实测电位器抽头电压接近。

验证方法：

  1. 电位器旋到最左（抽头 0V），数字应接近 0；旋到最右（5V），数字应接近 255。
  2. 用万用表量抽头电压 V，对比 数字值 × 5000 / 256 计算值，误差应在 ±30mV 内。
  3. CH0 换成 CH1（改配置位），验证双通道切换正确。
