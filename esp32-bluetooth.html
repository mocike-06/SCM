ESP32 蓝牙串口通信（经典蓝牙 SPP 透传）

系列：ESP32 进阶 更新：2026-10-25

利用 ESP32 内置的经典蓝牙，把它模拟成一个「无线串口」：手机装个蓝牙串口助手 App，配对后即可双向收发文字，无需路由器、无需联网。本讲从零讲清经典蓝牙与 BLE 的区别、SPP 透传是什么、配对流程怎么走、为什么它叫「透传」。

一、本课目标与前置知识

学完本课你能做到：

  • 分清经典蓝牙（BR/EDR）和 BLE 两种模式，知道本课用的是哪一种。
  • 用 BluetoothSerial 库把 ESP32 变成一块「无线串口」，手机 App 配对后双向收发数据。
  • 理解「透传」的含义：发什么字节过来，应用层就收到什么字节，不做任何加工。

需要提前掌握的前置知识（对应学习路线阶段 5）：

  • 环境搭建（esp32-env.html）：能烧录、会开串口监视器。
  • 串口概念（51 UART 那篇）：知道 Serial.read/available 是什么——蓝牙 SPP 用法和它几乎一样。
  • 一部安卓/苹果手机，装任意「蓝牙串口助手」App。

本课会出现的新名词：经典蓝牙（BR/EDR）、BLE（低功耗蓝牙）、SPP（串口仿真协议）、BluetoothSerial、配对/绑定、透传、SerialBT。

二、基础概念铺垫

1. 经典蓝牙 vs BLE：两种「无线串口」的分工

生活类比：经典蓝牙像「对讲机」，一接通就持续占着信道、耗电但带宽足，适合传音频、串口透传；BLE 像「短信精灵」，平时睡觉、有数据才醒，超低功耗但每次传一点点，适合心率手环、传感器。

一句话定义：经典蓝牙（BR/EDR，蓝牙 2.0/3.0）带宽高、连接持续；BLE（Bluetooth Low Energy，4.0+）功耗极低、按事件唤醒。ESP32 两种都支持，但 ESP32-C3 等小芯片不支持经典蓝牙。

例子：本课用经典蓝牙 SPP，因为它能把串口字节连续透传给手机；如果做心率手环电池能用一年，那才用 BLE。

2. SPP 透传：在蓝牙线上虚拟一条「串口线」

生活类比：SPP（Serial Port Profile）就像在两台设备之间隔空拉了一根看不见的串口线——你在这头发一个字节，那头原封不动收到一个字节，中间蓝牙怎么调制解调、怎么纠错，你完全不用管。

一句话定义：SPP 是经典蓝牙里的一个协议档，作用就是在蓝牙链路上虚拟出一条标准串口：对端手机看到的是一个「蓝牙串口」，发什么字节过来，应用层就收到什么字节，这种「不加工、原样搬」就叫透传。

例子：手机 App 发 "hello" 6 个字节过来，ESP32 的 SerialBT.read() 会依次读到 'h'、'e'、'l'、'l'、'o'——和从 USB 串口读字符一模一样。

3. BluetoothSerial：Arduino 把 SPP 封装成 Serial 的样子

生活类比：你已经会用 Serial（USB 串口）收发字节了。BluetoothSerial 就像给你第二个 Serial——只是它不接 USB 线，而是走蓝牙。API 名字几乎一样：begin、print、println、read、available。

一句话定义：BluetoothSerial 是 Arduino-ESP32 Core 提供的 SPP 封装类，用法与硬件串口 Serial 高度相似，SerialBT.begin("设备名") 开启广播，SerialBT.read/write/available 收发字节。

例子：SerialBT.begin("ESP32_BT"); 后，手机蓝牙列表里就能看到一个叫 ESP32_BT 的设备。

4. 配对与绑定：第一次认识要「握手」

生活类比：两台蓝牙设备第一次见面像两个陌生人交换名片——要互相确认「我们是一伙的」，这个交换过程叫配对。配对一次后系统会记住对方，下次自动连接，叫绑定。

一句话定义：配对（Pairing）是首次连接时的密钥交换流程；多数 ESP32 SPP 固件不需要 PIN 码，若要求输入默认是 1234 或 0000。绑定后手机和 ESP32 之间就有了信任关系。

例子：手机蓝牙设置里点「ESP32_BT」→ 配对成功 → 下次打开蓝牙串口助手直接点连接即可，不用再输密码。

5. 串口透传：为什么叫「桥」

生活类比：本课代码做的事像一座桥——USB 这头过来的字节，搬到蓝牙那头；蓝牙那头过来的字节，搬回 USB 这头。桥本身不改变任何字节，只负责「过路费全免地搬运」。

一句话定义：串口透传 = 把一个串口收到的字节原样转发到另一个串口，不解析、不加工。本课就是「USB 串口 ↔ 蓝牙串口」双向桥。

例子：电脑串口监视器发 "hi"，手机 App 收到 "hi"；手机 App 发 "hello"，电脑串口监视器收到 "hello"——完全对称。

6. 蓝牙协议栈分层：SPP 底下还压着几层

生活类比：和 WiFi 一样，蓝牙也是分层协议栈——最底下是射频跳频，往上是链路管理，再往上才是「串口仿真」。你直接用的 SPP，其实坐在好几层肩膀上。

一句话定义：经典蓝牙协议栈自下而上为 射频/基带 → L2CAP（逻辑链路）→ RFCOMM（串口仿真，在蓝牙上虚拟出 RS-232 口） → SPP（基于 RFCOMM 的串口 Profile）。所以 SPP 不是凭空来的，它本质是「在 RFCOMM 虚拟串口上跑的一个应用档」。

例子：手机发 "hello"，应用层字节 → SPP → RFCOMM 帧 → L2CAP → 跳频射频 → ESP32 反向拆包到 SerialBT.read()。理解这层后，你就明白为什么 SPP 透传的是「字节流」而不是「数据包」——因为 RFCOMM 本来就是按串口字节流设计的。

三、原理介绍

ESP32 同时支持经典蓝牙（BR/EDR）和 BLE。经典蓝牙里最常用的协议档叫 SPP（Serial Port Profile，串口仿真协议）——它在蓝牙无线链路上虚拟出一条「串口线」，让手机 App 像读串口一样收发字节。Arduino-ESP32 Core 把 SPP 封装成 BluetoothSerial 类，用法和硬件串口 Serial 几乎一样。

一次「手机发指令 → ESP32 收到」的链路：射频跳频通信 → 蓝牙协议栈建链 → SPP 把字节流交给 BluetoothSerial → loop 里 available()/read() 读到。

原理 1：经典蓝牙链路——配对到底在配对什么

经典蓝牙工作在 2.4GHz ISM 频段，把整个频段切成 79 个 1MHz 信道，通信双方按约定的伪随机序列每秒跳频 1600 次——这就是它抗干扰强的原因（被干扰的信道跳走就好）。配对的实质是：双方交换并记住一个 128 位链路密钥，之后每次连接都用它加密。所以「第一次要 PIN、之后不用」——PIN 只是首次交换密钥时的口令，配对成功后系统记住密钥，下次直连即可。

原理 2：SPP 透传协议——为什么 SerialBT 和 Serial 用法一模一样

SPP 本身不规定数据内容，只干一件事：在已建好的蓝牙链路两端无损透传一串字节。对上层来说，这串字节和 USB 串口收到的字节毫无区别——所以 Core 直接把它做成 BluetoothSerial，begin/available/read/write/println 这些 API 名和 Serial 完全同名。本课的「双向桥」就是两个流之间的搬运工：USB 有字节写给蓝牙、蓝牙有字节写给 USB。

原理 3：为什么 loop 里要轮询 available()

蓝牙链路是异步的：字节随时可能到达。BluetoothSerial 内部有一个小缓冲区（环形队列），到达的字节先排队；available() 告诉你队列里还剩几个字节没读，read() 取一个。如果 loop 不及时读，缓冲区满了新字节就被丢弃——这就是后面蓝牙遥控项目里解析指令要「快进快出」、不能塞长 delay 的原因。

配对说明 首次在手机上搜索到 ESP32_BT 后点击配对，多数固件不需要 PIN 码；若要求输入，默认是 1234 或 0000。配对一次后系统会记住，下次自动连接。
记忆点：经典蓝牙=79 信道每秒跳频 1600 次（抗干扰）；配对=交换并记住加密密钥；SPP=字节流透传，所以 SerialBT 与 Serial 同 API；字节先进环形缓冲区，要轮询 available() 读走，满了就丢。

四、硬件接线说明

蓝牙为片上外设，不需要任何外部接线，仅 USB 供电即可。手机需安装任意「蓝牙串口助手」类 App（如 Serial Bluetooth Terminal 等）。

模块引脚单片机引脚说明
USB 供电板载 USB 口蓝牙发射峰值电流约 200mA，建议用稳定 5V 电源
板载天线PCB 天线无需外接，距离手机 5~10 米内稳定
手机蓝牙2.4GHz 射频对端在 App 中扫描并配对 "ESP32_BT"

为什么这样接：

  • 为什么不用接线？ 蓝牙射频和天线都在芯片/PCB 上，软件 begin 后直接用。
  • 为什么强调供电？ 蓝牙发射瞬间电流大，供电不稳会导致芯片重启、连接断开。
  • 为什么距离 5~10 米？ PCB 天线增益小，穿墙后信号衰减明显；实验室距离内稳定，隔墙可能断连。

五、完整代码

/* ESP32 经典蓝牙 SPP：USB 串口 <-> 蓝牙 双向透传（零基础注释版） */
#include "BluetoothSerial.h"

BluetoothSerial SerialBT;   // 实例化蓝牙串口对象

void setup() {
  Serial.begin(115200);                  // 打开 USB 串口
  SerialBT.begin("ESP32_BT");            // 开启蓝牙广播，设备名 ESP32_BT
  Serial.println("蓝牙串口已启动，设备名：ESP32_BT");
}

void loop() {
  // 方向 1：USB 串口收到 -> 原样转发给蓝牙
  if (Serial.available()) {               // 如果 USB 串口有数据
    SerialBT.write(Serial.read());        // 读一个字节，写给蓝牙
  }
  // 方向 2：蓝牙收到 -> 原样转发回 USB 串口
  if (SerialBT.available()) {             // 如果蓝牙有数据
    Serial.write(SerialBT.read());        // 读一个字节，写给 USB 串口
  }
}

第二个实例：按行解析指令（解决「半个命令/乱码粘包」问题）——主程序是原样透传，这个变体等手机 App 发完一整行（带换行）再处理，收到 ON/OFF 就回一条结果：

/* 蓝牙变体：按行解析文本指令 */
#include "BluetoothSerial.h"
BluetoothSerial SerialBT;
String input = "";                    // 指令缓冲区

void setup() {
  Serial.begin(115200);
  SerialBT.begin("ESP32_BT");          // 手机蓝牙列表里的名字
}

void loop() {
  while (SerialBT.available()) {
    char c = SerialBT.read();
    if (c == '\n' || c == '\r') {      // 遇到换行 = 一条指令结束
      if (input.length() > 0) {
        Serial.print("收到指令: ");
        Serial.println(input);
        if (input == "ON")  SerialBT.println("LED 已开");
        if (input == "OFF") SerialBT.println("LED 已关");
        input = "";                    // 清空缓冲区，防粘包
      }
    } else {
      input += c;                       // 拼接字符
    }
  }
}

想改设备名？把 SerialBT.begin("ESP32_BT") 里的字符串改成你想要的名字（如 "MyCar"），手机蓝牙列表里就会显示新名字。

六、代码逐段讲解

第 1 段：引入库并实例化（第 2~4 行）

在做什么： include BluetoothSerial.h，再创建一个叫 SerialBT 的蓝牙串口对象。

为什么这么写： BluetoothSerial 是个类，必须先实例化一个对象才能调它的方法；起个类似 Serial 的名字，是为了让代码读起来直观。

不写会怎样： 漏 include 报编译错；不实例化直接调 SerialBT.begin 也会报未定义。

第 2 段：setup() 开两个串口（第 6~10 行）

在做什么： USB 串口以 115200 打开，蓝牙以 "ESP32_BT" 为名字开始广播，然后打印一行启动提示。

为什么这么写： Serial.begin 让电脑串口监视器能看到启动信息；SerialBT.begin 是让 ESP32 进入「可被发现」状态，手机才能在蓝牙列表里扫到它。

不写会怎样： 漏 SerialBT.begin，手机蓝牙列表根本搜不到 ESP32；漏 Serial.begin，电脑端看不到任何启动信息。

第 3 段：loop() 双向透传（第 12~20 行）

在做什么： 每轮循环检查两个串口的 available()：USB 有数据就 write 给蓝牙，蓝牙有数据就 write 给 USB。

为什么这么写： available() 返回待读字节数，>0 表示有数据；read() 每次只读 1 字节，write() 写 1 字节。这种「一字节一搬」最简单可靠，不会粘包。

不写会怎样： 两个 if 缺一不可——只写一个方向，桥就断了一半；不调 available() 直接 read，会阻塞或读到空字节。

七、现象演示说明

  • 现象 1：上电后串口监视器（115200）打印「蓝牙串口已启动，设备名：ESP32_BT」。
  • 现象 2：手机打开蓝牙设置，能在列表里扫描到 ESP32_BT；在蓝牙串口助手中点击连接，状态变为「已连接」。
  • 现象 3：在手机 App 发送框输入 "hello" 并发送，电脑串口监视器立刻打印 "hello"；反过来在串口监视器发送 "hi"，手机 App 收到 "hi"。
  • 现象 4（验证独立性）：拔掉 USB 线（改用充电宝供电），手机与 ESP32 仍能正常收发，说明蓝牙链路独立于 USB 工作。

可量化的验证方法：

  • 数字节：手机发 "12345"，电脑串口应恰好打印 "12345" 5 个字符，不多不少——验证透传无丢字节。
  • 测距离：从 ESP32 旁边逐步走远，到约 8~10 米或隔一堵墙时连接可能断开，走近后自动重连。

九、课后练习与延伸

练习 1（改设备名）： 把 SerialBT.begin 的参数改成你的名字（如 "LJB_ESP32"），手机重新扫描验证新名字出现。

练习 2（加回显）： 手机发一个字符，ESP32 收到后立刻回一个 "A" 给手机——提示：在 SerialBT.available() 分支里读完字节后，加一行 SerialBT.write('A');。

练习 3（进阶预告）： 把「读到的字节原样转发」改成「读到 'L' 就点亮板载 LED，读到 'O' 就熄灭」——这就是下一篇蓝牙遥控器的雏形。
