DS18B20 单总线温度采集

系列：51 单片机 进阶 更新：2026-10-25

DS18B20 是教材「传感器接口」的经典器件：一颗测温芯片只用一根数据线就能和单片机通信（单总线），还能挂多颗在一条线上。本课把复位、读时隙、写时隙三条时序讲透，写出可用的温度读取代码。

一、本课目标与前置知识

学完本课你能做到：

  • 看懂单总线的复位、写 0/写 1、读 0/读 1 时序图，并说出每步的时间要求。
  • 用 C 代码实现 DS18B20 复位、写字节、读字节三个函数。
  • 把 16 位温度原始值换算成带一位小数的摄氏度，并在 LCD/串口上显示。

需要提前掌握的前置知识（对应学习路线阶段 2）：

  • IO 口输出/输入：单总线靠 IO 方向切换模拟双向通信。
  • 位运算：移位收发数据位、拆温度字节。
  • DHT11 温湿度（可选）：都是单总线时序器件，可对照。

本课会出现的新名词：单总线（1-Wire）、复位/存在脉冲、读时隙、写时隙、ROM 指令、功能指令、12 位温度分辨率、CRC。

二、基础概念铺垫

1. 单总线（1-Wire）：一根线又供电又传数据

生活类比：普通串口像「双向两车道」（TX 发、RX 收）；单总线像「一条很窄的单行道」——同一时刻只能一个方向走，靠严格的时间段（时隙）轮换方向，还要靠线的状态变化来分时。

一句话定义：DS18B20 只有 3 个引脚（VCC、GND、DQ），数据就靠 DQ 一根线：主机（单片机）和从机（DS18B20）分时占用这条线，每一比特的传输都发生在固定长度的时隙里。DQ 平时由上拉电阻保持高电平，谁想发数据就把它拉低再按时序释放。

例子：4.7kΩ 上拉电阻把 DQ 拉到 VCC，单片机拉低 DQ 表示「开始一次通信」。

2. 复位与存在脉冲：先「握手」再说话

生活类比：打电话前先「喂，有人在吗？」——主机拉低总线 480µs 以上再释放，DS18B20 检测到这个信号后，会主动把总线拉低 60~240µs 作为「我在」的回答，这个回答叫存在脉冲。

一句话定义：复位 = 主机拉低 ≥480µs 后释放总线；随后主机去读总线，读到低电平说明 DS18B20 存在（握手成功）。这是每次通信的第一步，握手失败后面全是空谈。

例子：代码里 ds18b20_reset() 返回 0 表示存在、1 表示没检测到器件。

3. 写时隙与读时隙：一个时隙传一个位

一句话定义：写 1：主机拉低总线约 1~15µs 后释放（线被上拉回高），持续整个 60µs 时隙；写 0：主机把总线拉低并保持整个 60µs 时隙。写完之后必须留 ≥1µs 恢复时间。读时隙：主机拉低 1~15µs 后释放，然后立即采样总线——DS18B20 若想传 1 就释放线（读到高），想传 0 就继续拉低（读到低）。所有时隙必须 ≥60µs。

例子：发送字节 0xA5 = 逐位调用「写 1/写 0」8 次；读取温度 = 逐位调用「读位」8 次拼成一个字节。这 8 次循环就是单总线通信的全部。

4. ROM 指令与功能指令：先点名、再下令

一句话定义：通信分两步。ROM 指令（先发）：0xCC 跳过 ROM（只接一颗时用）、0x55 匹配 ROM（多颗时按 64 位地址点名）。功能指令（后发）：0x44 启动温度转换（需等 750ms）、0xBE 读暂存器（取温度数据）。

例子：标准读取流程 = 复位 → 0xCC → 0x44（启动转换）→ 等 750ms → 复位 → 0xCC → 0xBE（读 9 字节，取前 2 字节温度）。

三、原理介绍：温度怎么变成一串数字、单总线又凭什么一根线搞定

DS18B20 内部是一个 12 位 ADC 温度传感器（默认分辨率 0.0625°C/位）。它和 DHT11 一样是单总线器件：一根 DQ 线、开漏结构、靠 4.7kΩ 上拉。但它的通信是严格的「时隙制」——所有数据都在一个个固定时长的时间槽里传。

转换结果存在暂存器第 0、1 字节（LSB 在前）：

  • 正温度：12 位有符号数，如 0x0191 = 401，温度 = 401×0.0625 = 25.0625°C。
  • 负温度：补码，如 0xFFFE，取反加 1 得 2，温度 = −2×0.0625 = −0.125°C。

整数换算：温度值(0.1°C单位) = 原始值 × 625 / 10——单片机没浮点单元，放大成整数算更快。

原理 1：单总线的「时隙」机制——一个时间槽传一位

DS18B20 没有时钟线，双方靠时间槽（time slot）对齐：每个槽固定约 60µs，一位数据就在这个槽里靠「线被拉多久」编码。

  • 复位+存在脉冲（每次通信开头）：主机拉低总线 ≥480µs，再释放；DS18B20 检测到上升沿后，主动拉低 60~240µs ——这就是它的「应答信号」，主机读到这一拉才知道总线上有芯片。
  • 写时隙：主机拉低总线。写 0=拉低保持满 60µs；写 1=拉低 1~15µs 就释放（线被上拉回高）。
  • 读时隙：主机拉低 1~15µs 后立刻释放，紧接着采样总线——芯片要传 1 就放手让上拉拉高（读到 1），要传 0 就继续按住拉低（读到 0）。

为什么时序要求微秒级严格：读/写全靠「在时间窗的哪个点采样」，早几微秒或晚几微秒，0 和 1 就判反。所以代码里 delay_us 要按 11.0592MHz 校准，且通信过程中不能被别的中断打断——这是单总线最难调的地方。

原理 2：ROM 指令 + 功能指令——先点名再下令

一根单总线理论上能挂很多颗 DS18B20，每颗有唯一 64 位序列号。所以通信要分两层：先发 ROM 指令决定「跟哪颗说话」——只挂一颗时用 0xCC（Skip ROM）跳过点名；再发功能指令下令做事——0x44 启动温度转换（要等约 750ms 它才转完）、0xBE 读暂存器（把那两字节温度读出来）。为什么分两次握手：启动转换(0x44)和读结果(0xBE)之间芯片要花 750ms 做 ADC，这段时间总线空闲，必须重新「复位+0xCC」才能再读——这就是为什么记忆点流程里出现两遍「复位→跳过ROM」。

原理 3：温度为什么是 0.0625——12 位 ADC 的分辨率

芯片内部 ADC 把 −55~+125°C 量化成 12 位、共 4096 个等级。每一位代表的温度 = 量程里最小步进 = 1/16 = 0.0625°C。所以「原始值 × 0.0625」就是温度。负温用补码是因为 ADC 要表示零下，用最高位当符号位、负数以补码存放——读到 0xFFxx 这种高位全 F 的值，就知道是负温，得先取反加 1 才能算出绝对值。这套「ADC 量化 + 二进制补码」和后面 ADC0832 课是一脉相承的。

记忆点：单总线=开漏+上拉、靠时间槽传位，复位(拉低≥480µs)等芯片存在脉冲(拉低60~240µs)握手；写0=拉满槽、写1=拉一下就放，读=拉一下立刻采样；流程=复位→0xCC→0x44→等750ms→复位→0xCC→0xBE 取2字节；温度=原始值×0.0625、负温按补码。

四、硬件接线说明

DS18B20 只有 3 根线，核心是 DQ 数据线 + 4.7kΩ 上拉：

模块引脚单片机引脚说明
DQ（数据）P3.7必须经 4.7kΩ 上拉电阻接 VCC
VCC5V（实物）/ 仿真接电源也可用「寄生供电」只接两根线（进阶）
GNDGND与单片机共地

为什么必须上拉电阻：单总线是「开漏式」通信——器件只能主动拉低，高电平全靠外部上拉电阻提供。没有 4.7kΩ 上拉，总线永远被拉到低，通信直接失败。这是单总线接线的第一要素。

引脚选择：P3.7 是 51 里好用的通用 IO（未占用特殊功能），实物开发板常见接法；也可换任意空闲引脚，代码里改 sbit 定义即可。

避坑 DS18B20 引脚方向（正面字朝你，左边 GND、中间 DQ、右边 VCC），插反会发热烧毁；实物先查模块丝印再接线。Proteus 仿真元件 DS18B20 需带模型才能出数据。

五、完整代码

完整流程：握手 → 启动转换 → 等待 → 读温度 → 换算 → 串口输出。单总线函数是核心，务必配合注释理解时序。

/* DS18B20 单总线温度读取（串口输出，9600） */
#include <reg52.h>

sbit DQ = P3^7;                  /* 数据线 */

void delay_us(unsigned int us) {  /* 微秒级延时（11.0592MHz 粗调） */
    while (us--);
}
void delay_ms(unsigned int ms) {  /* 毫秒级延时 */
    unsigned int i, j;
    for (i = 0; i < ms; i++)
        for (j = 0; j < 120; j++);
}

/* 1. 复位：拉低 ≥480µs，检测存在脉冲。返回 0=器件存在 */
unsigned char ds_reset(void) {
    unsigned char presence;
    DQ = 0;                       /* 主机拉低总线 */
    delay_us(480);                /* 保持 480µs+ */
    DQ = 1;                       /* 释放总线 */
    delay_us(60);                 /* 等待器件响应窗口 */
    presence = DQ;                /* 采样：器件存在时会拉低（读到 0） */
    delay_us(420);                /* 收尾，等整个复位时隙结束 */
    return presence;              /* 返回 1 表示没检测到 */
}

/* 2. 写一个位：bit=1 拉低后快速释放；bit=0 拉低保持 */
void ds_write_bit(unsigned char bit) {
    DQ = 0;
    if (bit) { delay_us(5); DQ = 1; delay_us(55); }  /* 写 1 */
    else     { delay_us(55); DQ = 1; delay_us(5); }  /* 写 0 */
}

/* 3. 读一个位：主机拉低 1µs 后释放，采样器件电平 */
unsigned char ds_read_bit(void) {
    unsigned char bit;
    DQ = 0;
    delay_us(2);                  /* 拉低 2µs */
    DQ = 1;
    delay_us(5);                  /* 释放后等器件驱动 */
    bit = DQ;                     /* 采样 */
    delay_us(50);                 /* 填满时隙 */
    return bit;
}

/* 4. 写一字节：低位先发 */
void ds_write_byte(unsigned char dat) {
    unsigned char i;
    for (i = 0; i < 8; i++) {
        ds_write_bit(dat & 0x01);  /* 取最低位发送 */
        dat >>= 1;                 /* 右移取下一位 */
    }
}

/* 5. 读一字节：低位先收 */
unsigned char ds_read_byte(void) {
    unsigned char i, dat = 0;
    for (i = 0; i < 8; i++) {
        dat >>= 1;                 /* 先让出最低位 */
        if (ds_read_bit()) dat |= 0x80; /* 读到 1 就置最高位 */
    }
    return dat;
}

/* 6. 读取温度原始值（低字节 + 高字节） */
unsigned int ds_get_temp(void) {
    unsigned char low, high;
    ds_reset();
    ds_write_byte(0xCC);          /* 跳过 ROM：单颗器件 */
    ds_write_byte(0x44);          /* 启动温度转换 */
    delay_ms(750);                /* 12 位转换最多需 750ms，必须等够再读 */
    ds_reset();
    ds_write_byte(0xCC);
    ds_write_byte(0xBE);          /* 读暂存器 */
    low  = ds_read_byte();        /* 温度低字节 */
    high = ds_read_byte();        /* 温度高字节 */
    return (unsigned int)high << 8 | low;
}

/* 换算并输出：温度 = 原始值 × 0.0625，用整数算（×625 / 10 出 1 位小数） */
void uart_show_temp(unsigned int raw) {
    /* 正温度路径（含 0）：简化处理，负温度用补码另算 */
    unsigned int t = (raw * 625) / 10;   /* 例：25.06°C → 2506 */
    /* 串口输出函数省略：发 2506 的千/百/十/个位与小数点 */
}

void uart_init(void) {           /* 9600 @11.0592MHz（同前课） */
    SCON = 0x50;
    TMOD |= 0x20;
    TH1 = 0xFD; TL1 = 0xFD;
    TR1 = 1;
}

void main(void) {
    unsigned int temp;
    uart_init();
    while (1) {
        if (ds_reset() == 0) {    /* 先握手一次，失败则跳过 */
            temp = ds_get_temp();
            uart_show_temp(temp);
        }
        delay_ms(2000);           /* 每 2 秒采一次，给转换留足时间 */
    }
}

第二实例：温度超限亮灯报警（不用串口）。复用上面的 ds_reset/ds_write_byte/ds_read_byte/ds_get_temp，把 main 换成这个版本：温度超过 30°C（原始值 30/0.0625 = 480）就点亮 P1.0 报警 LED，低于则熄灭——不依赖串口，Proteus 里对着仿真模型改温度就能看到灯随温变：

/* 温度报警：超过 30°C 点亮 P1.0 的 LED（共地写 0 亮） */
#include <reg52.h>
sbit DQ  = P3^7;
sbit ALARM = P1^0;             /* 报警 LED */

/* 此处直接复用上面的 ds_reset/ds_write_byte/ds_read_byte/ds_get_temp */

void main(void) {
    unsigned int raw;
    ALARM = 1;                 /* 先熄灭报警灯 */
    while (1) {
        if (ds_reset() == 0) {        /* 握手成功才读 */
            raw = ds_get_temp();       /* 1 位 = 0.0625°C */
            /* 30°C = 30/0.0625 = 480，用整数比较避免浮点 */
            if (raw >= 480) ALARM = 0; /* 超 30°C 亮灯 */
            else            ALARM = 1; /* 否则熄灭 */
        }
        delay_ms(2000);
    }
}

为什么用 raw >= 480 而不换算成摄氏小数：30°C 对应的原始值就是 30÷0.0625 = 480，直接拿整数原始值和阈值比，省掉浮点换算，又快又准。这是嵌入式「比较阈值」的常用技巧——能在原始量化值上比，就别绕一圈去换物理量。

六、代码逐段讲解

第一段：复位函数的三段式

DQ = 0; delay_us(480); 拉低总线发出复位信号；DQ = 1; delay_us(60); 释放并等器件应答窗口；presence = DQ; 采样。为什么采样要在释放后 60µs 左右：DS18B20 在主机释放后 15~60µs 内把线拉低应答，太早采样会读到还没释放完的高电平、太晚会错过——时序窗口是单总线的命门。

第二段：写位与读位的对称性

写 1 是「拉低 5µs 就松手」（线被上拉回高），写 0 是「一直拉低 55µs」。读位是「拉低 2µs 松手，5µs 后采样」。为什么读 1 不采样在拉低瞬间：器件需要时间把线拉低或释放，采样点必须落在「器件已响应」之后——这也是数据手册给的时间窗，照着抄即可，别自己发明时序。

第三段：字节收发的小端序细节

写字节 dat & 0x01 取最低位、dat >>= 1 逐个发送；读字节反过来 dat |= 0x80 把高位放进来。DS18B20 规定低位先传，所以读回的温度低字节在前——合并时 high << 8 | low，别写反，写反温度会差 256 倍。

第四段：转换等待与负温度处理

发完 0x44 启动转换后，12 位分辨率最多要 750ms 才能转完，所以用 delay_ms(750) 死等——等不够就读到旧值或默认 85°C。负温度用补码处理：if (raw & 0x8000) raw = ~raw + 1; 再乘 0.0625 并加负号。uart_show_temp 这里只给出换算骨架，真实项目把 t 的千/百/十/个位通过串口逐字节发出即可。

七、现象演示与验证

  • 握手正常：ds_reset 返回 0，程序继续读温度。
  • 温度显示：串口输出如 25.0，与室内温度计偏差 <1°C。
  • 响应变化：用手指捏住 DS18B20，温度在 2 秒内上升；放开后回落。

验证方法：

  1. 拔掉数据线（或仿真中断开 DQ），ds_reset 返回 1，程序不再输出——证明握手检测生效。
  2. 把 12 位分辨率改为 9 位（写 0x4E 配置），转换时间降为 93.75ms，温度精度变 0.5°C——体会分辨率与速度的取舍。
  3. 在 Proteus 里用虚拟示波器看 DQ 线上的时序：复位拉低 480µs、每个时隙约 60µs，对照数据手册核对。

九、课后练习与延伸
