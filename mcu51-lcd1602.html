LCD1602 液晶驱动

系列：51 单片机 进阶 更新：2026-10-24

LED 只会亮灭，串口只能在电脑上看——本讲让数据直接显示在一块小液晶屏上。LCD1602 能显示 2 行 × 16 个字符，是学习「并行通信时序」最好的入门器件。本讲从 RS/RW/E 三根控制线的时序讲起，再封装出显示字符串、显示数字的函数。

一、本课目标与前置知识

学完本课你能做到：

  • 说清楚并行通信、RS/RW/E 三根控制线的作用、指令与数据的区别。
  • 理解 LCD1602 内部 RAM 地址和两行显示位置的关系（第一行 0x00、第二行 0x40）。
  • 写出完整驱动：第一行显示字符串、第二行用 sprintf 显示数字，并能调对比度看到清晰字符。

需要提前掌握的前置知识（对应学习路线阶段 2）：

  • 高低电平、sbit、8 位端口写值（mcu51-led.html）。
  • Keil 工程里能加 #include <stdio.h>（用 sprintf）。

本课会出现的新名词：并行通信、RS/RW/E、指令 vs 数据、ASCII 码、DDRAM 地址、E 使能脉冲。

二、基础概念铺垫

1. 并行通信

生活类比：串口是一个人搬箱子一次搬一个；并行是 8 个人同时搬，一次搬 8 个。LCD1602 用 8 根数据线（D0~D7）一次传一个完整字节，所以快，但要占 8 根 IO。

一句话定义：并行通信用多根数据线同时传送多位（这里是 8 根线一次传 8 位 = 一个字节），配合几根控制线告诉对方「现在传的是什么」。

例子：51 的 P0 口 8 根线正好接 LCD1602 的 D0~D7，往 P0 写一个数（如 0x38），LCD 就在 8 根线上同时收到这 8 个电平。

2. RS / RW / E 三根控制线时序

生活类比：去快递柜取件，要先告诉柜子「我要存件还是取件」（RS）、「我现在要写还是读」（RW）、最后按一下「确认键」（E）柜子才动作。

一句话定义：RS=0 表示接下来送的是「命令」、=1 是「要显示的数据」；RW=0 表示写、=1 表示读（本讲只写，RW 接地或恒 0）；E 是使能脉冲——数据放到线上后，E 给一个高脉冲，LCD 在 E 下降沿锁存这字节。完整节奏：先摆好 RS/RW → 再把字节放到 D0~D7 → 拉高 E → 稍等 → 拉低 E。

例子：要发命令 0x38：RS=0、RW=0、P0=0x38、E=1、等几微秒、E=0。LCD 就在 E 变低那一瞬间把 0x38 读进去，理解为「8 位接口、2 行显示」。

3. 指令 vs 数据

生活类比：同一个显示屏，你发「清屏」是指挥它干活（指令），你发「A」是告诉它显示什么（数据）。区分这两类的就是 RS 引脚。

一句话定义：指令是控制 LCD 的命令（清屏、开显示、设光标位置等），用 RS=0 发送；显示数据是要显示字符的编码，用 RS=1 发送。

例子：0x01 是清屏指令（RS=0 发）；字母 'A' 的 ASCII 码 0x41 是数据（RS=1 发）——前者让屏幕清空，后者让屏幕上出现一个 A。

4. ASCII 码

生活类比：电脑/液晶屏怎么知道 0x41 要显示成字母 A？因为全世界约定了一张「字符→数字」对照表，就是 ASCII 码。

一句话定义：ASCII 码是英文字符与数字的标准对应表：'0'=0x30、'A'=0x41、'a'=0x61、空格=0x20。LCD1602 内部固化了 ASCII 字模，你送哪个编码，它就显示哪个字符。

例子：想显示数字「3」，不能直接写 3（LCD 会显示一个控制符号），要送 ASCII 码 0x33（即字符 '3'）。这就是为什么显示数字要用 sprintf 把 123 转成 "123" 字符串再逐字符送——每个字符已经是 ASCII 码。

5. 液晶内部 RAM 地址（DDRAM）

生活类比：LCD1602 内部有 32 个小格子（第一行 16 个、第二行 16 个），每个格子存一个字符的编码。你要往某个位置写字，得先告诉液晶「下一个字写到哪个格子」。

一句话定义：LCD 的显示数据存在内部 DDRAM，地址是 7 位的。第一行首地址 0x00，第二行首地址 0x40。设地址指令要「或上 0x80」：第一行第 col 列 = 0x80 + col；第二行 = 0x80 + 0x40 + col。

例子：想在第二行第 3 列显示字符，先发命令 0x80 + 0x40 + 2 = 0xC2（注意列从 0 开始数），再发要显示的字符。第二行不是 0x80+16，而是 0x80+0x40，这是新手最常写错的地方。

三、原理介绍：单片机只发一个字节，液晶怎么知道这是「命令」还是「字」

LCD1602 能显示 2 行×16 个 ASCII 字符，和单片机之间用 8 位并口 D0~D7 通信，外加 RS/RW/E 三根控制线。它和你直接控 IO 不一样——它内部自带一个控制器（HD44780），你不是逐点刷液晶，而是给控制器发命令和字符，控制器自己去点阵屏上画。

初始化到显示的完整流程：

  1. 上电先发 0x38（设 8 位、2 行、5×7 点阵）。
  2. 发 0x0C（开显示、关光标）。
  3. 发 0x06（写入后地址自增）。
  4. 发 0x01（清屏）。
  5. 发位置指令（0x80=第一行开头、0xC0=第二行开头）。
  6. 逐个发字符数据，内部地址自动 +1，字符依次右排。

必记命令：0x38 功能设置、0x0C 开显示关光标、0x06 地址自增、0x01 清屏、0x80|地址 定位。

原理 1：RS/RW/E 三根线是怎么完成一次「握手」的

同一个 D0~D7 口线上，可能传的是命令、也可能是字符——液晶靠 RS 这根线来区分：RS=0 表示「口线上是命令」，RS=1 表示「口线上是要显示的数据」。RW 选择读还是写（本讲只读，直接把 RW 接地一直写）。E（使能）是同步脉冲：你不能把字节放在口线上液晶就自动收——它要等你给一个「取货信号」。标准动作是：先把 RS 摆好、把字节放到 D0~D7 → 拉高 E → 等几微秒 → 拉低 E，液晶在 E 的下降沿才把口线上的数据锁进去。为什么要「先摆好数据再给脉冲」而不是边给边看：因为口线电平在切换瞬间是不稳定的，E 脉冲这一刻它认定的数据才有效——这和后面 I2C「时钟高电平期间数据必须稳定」是同一种同步思想。

教材式时序参数（HD44780 数据手册）：E 高电平脉宽 ≥ 450ns；RS/RW 在 E 下降沿前要稳定（建立时间 tsu ≈ 几十 ns）；数据 D0~D7 相对 E 下降沿的建立时间 ≥ 195ns、保持时间 ≥ 10ns。51 在 11.0592MHz 下一个机器周期就 1.085µs≈1085ns，所以「E=1; E=0;」两条语句之间哪怕空一条 NOP 也远大于这些参数，软件延时不用写太长。更规范的做法是读忙标志 BF（D7）：RW=1、RS=0 时读 D0~D7，D7=1 表示液晶还在忙、不能发下一条——入门阶段用 2~5ms 软件延时代替即可。

原理 2：为什么要先「写命令定位」再「写字符」——DDRAM 地址指针

液晶内部有一块 DDRAM（显示数据 RAM），每个字节对应屏幕上一个格子，并有一个地址指针指向下一个要写入的格子。你发 0x80|地址 命令，本质就是移动这个指针。两个坑点：

  • 第二行不是紧接第一行：第一行首地址是 0x00，第二行首地址是 0x40（中间空了一段）。所以定位第二行开头要写 0x80|0x40 = 0xC0，而不是想当然的 0x10。
  • 写完一个字符指针自动 +1（这就是 0x06 命令设的）：所以你定位一次后，连续发 N 个字符就自动从左往右排，不用每个都重新定位。

「先命令后数据」的分工由此清楚：命令（RS=0）管的是「指针移到哪、开不开显示、清不清屏」；数据（RS=1）管的是「往当前指针那个格子塞什么字符」。上层的 lcd_show_string 就是「先写一条定位命令、再循环写字符数据」的封装。

原理 3：为什么初始化那一串命令不能省、顺序不能乱

液晶上电后内部控制器是默认未知状态：几位接口？几行？光标闪不闪？写入后地址加还是减？全要靠初始化命令一个个定下来。0x38 必须第一个发，因为它定「8 位并口」——在它生效前，控制器还不知道你口线一次给它 8 位还是 4 位，后面命令全会被读错。这就是为什么 LCD1602「偶尔显示乱码花屏」多半是初始化时序不够（命令之间没留够等待时间）或顺序错了，而不是接线问题。

记忆点：RS=0 命令/1 数据，E 下降沿锁存（先摆好数据再给脉冲）；液晶内部有 DDRAM 地址指针，0x80|地址=移动指针，第二行首地址是 0x40 所以定位写 0xC0，写一个字符指针自动 +1；初始化 0x38→0x0C→0x06→0x01 顺序不能乱，否则花屏。

四、硬件接线说明

数据口 D0~D7 接 P0，控制线 RS/RW/E 接 P2.0/P2.1/P2.2。VO 脚接电位器中间抽头调节对比度。

模块引脚单片机引脚说明
RSP2.00 命令 / 1 数据
RWP2.1恒接地（只写不读），这里仍接 IO 便于演示
EP2.2使能脉冲
D0~D7P0.0 ~ P0.78 位数据口
VSS/VDD/VOGND / 5V / 电位器VO 调对比度，调到字符清晰可见

为什么这样接：

  • 为什么数据口用 P0？ P0 是 8 位口，一次写一个字节正好匹配 LCD 的 8 位并口；换 P1 也行，只要改代码里的 #define LCD_DATA P0。
  • 为什么要有电位器调 VO？ VO 控制液晶驱动电压，调不到合适值时一片白或一片黑，什么都看不见——这是新手「烧录成功但屏幕没字」第一个要查的点。
  • 为什么 RW 可以接地？ 本讲只写不读（不查忙标志），RW 恒为 0 即可，省一根 IO；接 IO 是为了代码更通用。

五、完整代码

第一行显示字符串，第二行显示一个数字（用 sprintf 把数字转字符串再送显示）。

/* LCD1602 显示：第一行字符串，第二行数字 */
#include <reg52.h>
#include <stdio.h>          /* 用 sprintf 把数字转成字符串 */

#define LCD_DATA P0         /* 数据口接到 P0 */

sbit RS = P2^0;
sbit RW = P2^1;
sbit E  = P2^2;

void delay_us(unsigned int us) { while(us--); }   /* 粗略微秒延时 */

/* 写命令：RS=0 */
void Lcd_Write_Cmd(unsigned char cmd) {
    RS = 0;
    RW = 0;
    LCD_DATA = cmd;     /* 命令字节放到数据口 */
    E = 1; delay_us(10);
    E = 0;              /* E 下降沿锁存 */
    delay_us(100);
}

/* 写数据：RS=1 */
void Lcd_Write_Data(unsigned char dat) {
    RS = 1;
    RW = 0;
    LCD_DATA = dat;     /* 要显示的字符（ASCII 码） */
    E = 1; delay_us(10);
    E = 0;
    delay_us(100);
}

void Lcd_Init(void) {
    Lcd_Write_Cmd(0x38);  /* 8位，2行，5x7 点阵 */
    Lcd_Write_Cmd(0x0C);  /* 开显示，关光标 */
    Lcd_Write_Cmd(0x06);  /* 写入后地址自动加一 */
    Lcd_Write_Cmd(0x01);  /* 清屏 */
}

/* 在指定行(row 0/1)、列(col 0~15)开始显示字符串 */
void Lcd_Show_Str(unsigned char row, unsigned char col, unsigned char *s) {
    if (row == 0) Lcd_Write_Cmd(0x80 + col);          /* 第一行 */
    else          Lcd_Write_Cmd(0x80 + 0x40 + col);     /* 第二行 */
    while (*s) Lcd_Write_Data(*s++);
}

void main(void) {
    unsigned char buf[16];
    unsigned char n = 123;
    Lcd_Init();
    Lcd_Show_Str(0, 0, "McuStudy 51");     /* 第一行第0列开始 */
    sprintf(buf, "Num = %d", n);            /* 把数字 123 转成 "Num = 123" */
    Lcd_Show_Str(1, 0, buf);               /* 第二行显示 */
    while (1);                             /* 显示完就停住 */
}

进阶实例：第二行数字每秒自增走动

在上面驱动函数不变的前提下，把 main 改成「数字每秒 +1 并刷新」，让屏幕像个秒表计数器。注意每次刷新前要清掉旧数字的残影（用固定宽度 %5d 右对齐补空格即可）。

/* 进阶：在上面所有驱动函数保留的前提下，把 main 替换成本段 */
void delay_ms(unsigned int ms) {
    unsigned int i, j;
    for (i = 0; i < ms; i++)
        for (j = 0; j < 120; j++);
}

void main(void) {
    unsigned char buf[16];
    unsigned int n = 0;
    Lcd_Init();
    Lcd_Show_Str(0, 0, "Counter:");
    while (1) {
        sprintf(buf, "%5d", n++);   /* %5d：占 5 位宽，旧位被空格覆盖，不留残影 */
        Lcd_Show_Str(1, 0, buf);
        delay_ms(1000);
    }
}

烧录后第一行 Counter: 不动，第二行数字应从 0 开始每秒往上跳一个。若数字左侧残留旧字符，说明格式化宽度不够，把 %5d 改成 %6d。

六、代码逐段讲解

第 1 段：两个底层函数 Lcd_Write_Cmd / Lcd_Write_Data（第 12~31 行）

在做什么： 把「摆 RS → 放数据 → E 脉冲」这三步封装成两个函数：一个发命令（RS=0），一个发数据（RS=1）。

为什么这么写： 时序细节（E 拉高再拉低、中间延时）只写一遍，上层调用就不用关心时序。E=1 后 delay_us(10) 再 E=0，是因为 LCD 锁存需要稳定的高脉冲宽度，太短会丢字节。

不写会怎样： 把 RS 忘设成 0（发命令时 RS=1），LCD 会把命令当字符显示出来，出现乱码。

第 2 段：Lcd_Init 初始化（第 33~38 行）

在做什么： 上电后依次发 0x38、0x0C、0x06、0x01 四条命令。

为什么这么写： LCD1602 上电后内部状态是未知的，必须按手册顺序初始化：先设接口格式（0x38），再开显示（0x0C），再设自增方式（0x06），最后清屏（0x01）。顺序不能乱，漏发就会显示异常。

不写会怎样： 漏 0x38 → 初始化不完整，显示乱码；漏 0x01 → 屏幕上残留上电随机字符。

第 3 段：Lcd_Show_Str 定位显示（第 40~44 行）

在做什么： 先按行/列发「设地址」命令（0x80+col 或 0x80+0x40+col），再逐个发字符数据。

为什么这么写： 发完位置命令后，LCD 内部地址指针会在每个字符发送后自动 +1（这是 0x06 设好的），所以字符串能从指定位置依次往右排，不用每发一个字符都重设地址。

不写会怎样： 第二行地址错写成 0x80+16+col → 字符跑到奇怪位置或换行错乱；不设地址直接发数据 → 显示在上次位置，可能接在上一行末尾。

第 4 段：main 里 sprintf 显示数字（第 46~56 行）

在做什么： 用 sprintf 把数字 n=123 格式化成字符串 "Num = 123"，再交给 Lcd_Show_Str 显示。

为什么这么写： LCD 只认 ASCII 码，直接送 123 这个数字会显示成控制符号。sprintf 把 123 拆成 '1'、'2'、'3' 三个 ASCII 字符放进 buf，再逐字符送显示。

不写会怎样： 直接 Lcd_Write_Data(123) → 屏幕显示一个奇怪符号，而不是数字 123。

七、现象演示说明

烧录后，LCD1602 第一行显示 McuStudy 51，第二行显示 Num = 123。如果一片白看不到字，先调 VO 对比度电位器。

可量化的验证方法：

  • 调对比度： 慢拧 VO 电位器，应从全白 → 出现黑块（对比度过强）→ 清晰显示字符 → 字符变淡消失，找到最清晰的位置。
  • 改数字： 把 n = 123 改成 n = 4567 重新烧录，第二行应变成 Num = 4567——证明 sprintf 数字显示链路正常。
  • 改位置： 把 Lcd_Show_Str(0, 0, ...) 的 col 从 0 改成 5，字符串应从第 6 列开始显示，前面空 5 格。

八、常见报错排查方案

报错现象可能原因解决方法
屏幕全白或全黑，一个字都没有对比度 VO 没调好调电位器 VO，直到背景与字符对比清晰
显示乱码、字符错位初始化命令没发全 / E 脉冲太短确认先发 0x38、0x0C、0x06、0x01，适当加大 delay_us
字符显示到第二行跑到很后面第二行地址写错第二行地址是 0x80 + 0x40 + col，不要写成 0x80+16+col
数字显示成奇怪符号直接把数字当 ASCII 送了先用 sprintf 转成字符串再逐字符送 Lcd_Write_Data
第一行正常、第二行完全不显示接线中 P0 某根线松动 / 初始化漏 2 行设置重插 D0~D7 杜邦线；确认 0x38 已发（含 2 行设置）
