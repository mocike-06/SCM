OTA 无线升级（不插线更新固件）

系列：ESP32 进阶 更新：2026-10-25

设备装在墙里、吊在天花板上，改个 bug 还要拆下来插线烧录？量产 IoT 设备的标准答案是 OTA：固件通过网络远程升级。ESP32 内置双分区（A/B）机制，升级失败还能自动回滚。本课讲透 OTA 原理、分区表、ArduinoOTA 网页升级与 HTTP OTA，做出「浏览器打开就能刷固件」的 ESP32。

一、本课目标与前置知识

学完本课你能做到：

  • 说清 OTA 的原理与双分区 A/B 回滚机制。
  • 用 ArduinoOTA 实现浏览器网页升级（最简单方式）。
  • 用 HTTP OTA 从服务器下载固件自动升级，并处理失败回滚。

需要提前掌握的前置知识（对应学习路线阶段 5）：

  • WiFi（esp32-wifi.html）：OTA 依赖网络。
  • NVS/存储（esp32-storage.html）：OTA 状态记录。
  • FreeRTOS（esp32-freertos.html）：ArduinoOTA 在后台任务运行。

本课会出现的新名词：OTA、分区表（Partition）、app0/app1（A/B）、ArduinoOTA、HTTPUpdate、固件哈希、回滚、标志位。

二、基础概念铺垫

1. OTA 是什么：给设备「远程刷机」

生活类比：手机系统更新就是 OTA——不用去维修店，WiFi 下个包就换新系统。ESP32 的 OTA 同理：把编译好的 .bin 固件通过网络写入 Flash 的备用分区，重启后运行新固件。

一句话定义：OTA（Over-The-Air）通过无线网络下载并更新固件。ESP32 的 Flash 按分区表划分：app0、app1（两个应用区）、spiffs（文件系统）、nvs 等。OTA 写入的是「当前没运行的」那个 app 分区，写完后切换启动目标并重启。

例子：固件跑在 app0，OTA 下载的新固件写入 app1 → 设置启动 app1 → 重启 → 跑新固件。

2. 为什么必须有 app0 + app1 两个分区

一句话定义：双分区（A/B）是「保险丝」：新固件写进备用区、校验成功后标记为可启动。如果新固件崩溃/校验失败，启动器检测到后回滚到旧分区——设备不会变砖。代价：Flash 一半给固件用（256KB 分区 ×2，还有 128KB 多的剩余）。

例子：新固件烧录后反复重启（崩溃循环），esp-idf 启动器数到 N 次失败自动切回旧固件——设备「自动复活」。

3. ArduinoOTA：5 分钟上手的网页升级

一句话定义：ArduinoOTA 库让 ESP32 成为一个「可被 Arduino IDE 直接无线烧录」的设备：IDE 端口列表里出现它，选端口就能像插线一样烧录。它本身只支持 IDE 无线烧录，不提供网页上传页面；想要「浏览器打开网页上传 .bin」需要另装 WebUpdate / AsyncElegantOTA 这类库。开发调试最方便，但适合局域网（设备发现靠 mDNS）。

例子：烧录带 ArduinoOTA 的固件后，Arduino IDE「工具→端口」里多出「esp32-xxxx at IP」——选它即可无线上传。

4. HTTP OTA：量产设备的升级通道

一句话定义：HTTP OTA 是「主动拉取」模式：设备启动后（或定时）访问服务器上的固件 URL（如 http://server/fw.bin），下载、校验、写入、重启。适合远程批量升级——配合版本号判断「有没有新版本」。

例子：设备每 24 小时 GET 一次 /api/fw/latest，比对版本号，有新版就下载升级。

5. 启动链怎么知道该跑 app0 还是 app1

生活类比：bootloader 像宿舍管理员，手里有一张「当前住哪间」的登记表（OTA 数据分区）。每次开门先看表：登记 app1 就去 app1 那间，登记 app0 就回 app0。

一句话定义：沿「ROM Bootloader（一级）→ 二级 Bootloader（0x1000，读分区表）→ App」的启动链，二级 Bootloader 决定跳哪个 app 分区：它读 Flash 里 OTA 数据分区（ota_data）记录的启动标志，决定跳 ota_0 还是 ota_1。OTA 升级就是「把新固件写进另一个 app 区 + 改写这个启动标志」。

例子：现在跑 ota_0，OTA 写新固件到 ota_1、把启动标志改成 ota_1 → 重启后二级 bootloader 跳 ota_1；新固件崩溃几次后标志自动改回 ota_0——这就是 A/B 回滚的机制。

三、原理介绍：一次 OTA 升级的完整流程

OTA 能「变砖也不怕」，全靠 ESP32 Flash 的双分区（A/B）设计。理解 Flash 怎么切成 app0/app1 两块、为什么写备用区再切换、启动器怎么回滚，才能讲清 OTA 的安全性从哪来。

一次升级的链路：联网 → 下载固件 → 流式写入备用 app 区 → 校验通过 → 标记启动目标 → 重启跑新固件（崩溃则自动回滚）。

原理 1：分区表——Flash 为什么切成 app0/app1 两块

ESP32 的 Flash 不是一整块随便写，而是按分区表切好几块：bootloader（引导程序）、app0（应用区 A）、app1（应用区 B）、nvs（参数）、spiffs（文件系统）。普通烧录只写 app0；OTA 升级时把新固件写进当前没在跑的那个 app 区（比如正在跑 app0，就写 app1）。两块 app 区互为备份——这就是「A/B 升级」。代价：Flash 留给单个固件的空间减半，所以 Tools→Partition Scheme 必须选带 OTA 的方案（Huge APP），否则根本没有 app1 分区。

原理 2：流式写入与校验——为什么内存装不下整个固件

固件 .bin 可达 1~2MB，而 ESP32 可用内存只有几百 KB——不可能把整个固件下载进内存再写 Flash。OTA 库的做法是流式写入：HTTP 数据按块读出来（每次几 KB），读一块就 Update.write 写一块到 Flash，内存里只留一个小缓冲区。写完后 Update.end() 校验总大小和 MD5——对不上就整个丢弃，旧固件照常跑。这就是「写入中途断电也不怕」：半截固件根本没被标记为可启动，重启照旧进旧分区。

原理 3：启动链与回滚——新固件崩溃了怎么办

校验通过后，启动器把「下次启动跑 app1」记下来，重启。如果新固件跑起来正常，它在启动后会主动标记自己为「有效」；如果新固件一启动就崩溃重启，启动器数到失败次数（默认几次）后自动回滚、下次又跑回旧 app 区——设备「自动复活」。所以 OTA 的真正风险不是写一半断电，而是「写完切换了、新固件自己有 bug」——回滚机制就是为这个兜底的。ArduinoOTA 只是把「谁来触发下载」做成了 IDE 无线烧录（局域网 mDNS）；HTTP OTA 则是设备主动拉服务器——两者底层都是上面这套双分区机制。

记忆点：Flash 按分区表切 app0/app1+nvs+spiffs；OTA 写「没在跑的」备用区；流式写入（内存装不下整个固件）；MD5 校验不过就丢弃；新固件崩溃由启动器失败计数自动回滚；所以 OTA 不会变砖。

四、硬件接线说明

OTA 是纯软件 + 网络功能，无额外接线：

资源用途说明
ESP32 开发板被升级目标USB 供电（首次烧录需插线）
路由器局域网 + 外网ArduinoOTA 用局域网，HTTP OTA 需外网
电脑Arduino IDE / 浏览器上传 .bin 固件

为什么第一次还是要插线：设备出厂时空机没有 OTA 程序——必须先用 USB 烧录一个「带 OTA 功能的引导固件」，之后才可能无线升级。量产流程：产线烧引导固件 → 之后全部 OTA。

避坑 OTA 烧录前先确认分区表方案：Arduino IDE 的「Tools → Partition Scheme」要选 Huge APP (3MB APP/1MB SPIFFS) 或默认带 OTA 的方案——选错（如 Minimal SPIFFS）没有 app1 分区，OTA 会失败。换分区方案后必须重新插线烧一次。

五、完整代码

示例 1 ArduinoOTA（IDE/网页升级）；示例 2 HTTP OTA（服务器拉取）。

示例 1：ArduinoOTA——浏览器网页升级

/* ArduinoOTA：启动后可用 Arduino IDE 无线烧录（局域网内）
   IDE「工具→端口」里选 esp32-ota 对应的网络端口即可上传 */
#include <WiFi.h>
#include <ArduinoOTA.h>

const char *ssid     = "你的WiFi";
const char *password = "你的密码";

void setup() {
  Serial.begin(115200);

  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) { delay(500); Serial.print("."); }
  Serial.println("WiFi OK");

  /* 配置 OTA：设备名 + 密码（防局域网内别人乱刷） */
  ArduinoOTA.setHostname("esp32-ota");
  ArduinoOTA.setPassword("123456");

  ArduinoOTA.onStart([]() {          /* 开始升级 */
    Serial.println("OTA Start");
  });
  ArduinoOTA.onEnd([]() {            /* 升级完成 */
    Serial.println("OTA End");
  });
  ArduinoOTA.onProgress([](unsigned int p, unsigned int total) {
    Serial.printf("Progress: %u%%\r\n", p / (total / 100));
  });
  ArduinoOTA.onError([](ota_error_t err) {
    Serial.printf("OTA Error %d\r\n", err);
  });

  ArduinoOTA.begin();                /* 启动 OTA 服务 */
  Serial.println("OTA ready");
  Serial.print("IP: ");
  Serial.println(WiFi.localIP());
}

void loop() {
  ArduinoOTA.handle();               /* 必须周期性调用：处理升级请求 */
  delay(10);
}

示例 2：HTTP OTA——从服务器下载固件自动升级

/* HTTP OTA：访问 URL 下载固件并升级（量产远程升级模式） */
#include <WiFi.h>
#include <HTTPClient.h>
#include <Update.h>

const char *ssid     = "你的WiFi";
const char *password = "你的密码";
const char *fw_url   = "http://192.168.1.100/firmware/esp32.bin";

void do_http_ota(void)
{
  HTTPClient http;
  http.begin(fw_url);
  int code = http.GET();              /* 发起下载请求 */
  Serial.printf("HTTP %d, size=%d\r\n", code, http.getSize());

  if (code == HTTP_CODE_OK) {
    /* 流式写入 Flash：Update 返回总字节数 */
    size_t written = Update.writeStream(http.getStream());
    if (written == http.getSize() && Update.end()) {
      Serial.printf("OTA done %u bytes, rebooting...\r\n", written);
      ESP.restart();                  /* 校验通过：重启切换 */
    } else {
      Serial.printf("OTA fail written=%u err=%d\r\n",
                    written, Update.getError());
    }
  }
  http.end();
}

void setup() {
  Serial.begin(115200);
  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) { delay(500); Serial.print("."); }
  Serial.println("WiFi OK");

  do_http_ota();                      /* 启动即检查升级 */
}

void loop() {
  /* 正常业务代码：升级只在上电/定时触发 */
  delay(1000);
}

六、代码逐段讲解

第一段：onStart/onProgress 等回调

ArduinoOTA 提供四个状态回调：onStart（升级开始，可在此停止业务）、onEnd（完成）、onProgress（百分比进度）、onError（出错类型）。为什么用 lambda（[](){}）：C++11 简洁写法；也可以传普通函数。注意：onStart 里如果要关 WiFi/Flash 相关操作，文档建议 Update.abort() 处理——本课演示最简用法。

第二段：handle() 为什么必须在 loop 里周期调用

ArduinoOTA.handle() 是 OTA 服务的「心跳」：它负责监听升级请求、接收数据。漏了它 = 设备永远不响应 OTA。为什么不能 delay 太久：如果 loop 里 delay(10000)，浏览器上传数据时 handle 10 秒才处理一次，接收会超时——工程上把 OTA 放进高优先级任务或用较短延迟。

第三段：HTTP OTA 的 writeStream 流式写入

Update.writeStream(http.getStream())：HTTP 响应流边读边写进 Flash 备用区，返回写入字节数。为什么比较 written == getSize()：写入量必须等于下载总量，否则说明下载中途断了——校验不通过不重启。Update.end()：完成 + 校验（MD5 在 begin 时可设置），通过才真正切换分区。顺序：写 → 校验 → 重启，缺一不可。

第四段：为什么启动就检查升级

示例 2 在 setup 里直接升级：简单直接，适合「上电升级」场景。量产更稳的写法：先跑业务，定时（或收到服务器推送指令后）再升级——避免每次开机都要下载固件、升级失败影响业务启动。版本判断：先 GET 版本接口比对，再决定是否下载固件。

七、现象演示与验证

  • IDE 无线烧录：Arduino IDE「工具→端口」列表出现 esp32-ota（局域网内），选中后直接点上传（不插线）→ 串口打印 OTA Start/Progress/End → 自动重启运行新固件。
  • 提示：ArduinoOTA 本身没有网页上传页；浏览器网页传 .bin 需另装 WebUpdate 库（见练习 2 思路）。
  • HTTP OTA：启动串口打印 HTTP 200, size=xxxx → OTA done → 重启运行新固件。

验证方法：

  1. 升级前后改一下固件里的打印内容（如加个版本号），确认重启后确实运行了新固件。
  2. 用错误密码连 OTA（setPassword 设了 123456），升级被拒——验证密码保护。
  3. 把 HTTP OTA 的 URL 改成一个不存在的路径，观察 HTTP 404 后设备继续正常运行（不崩溃）——验证失败兜底。

九、课后练习与延伸

练习 1（必做）：编译两个版本的固件（打印内容不同），用 OTA 来回升级 3 次，观察串口确认切换。

练习 2：给 HTTP OTA 加「版本号检查」：先 GET /version.txt 比对 #define FW_VERSION，不一致才升级。

练习 3（进阶）：把 HTTP OTA 放进 FreeRTOS 任务（esp32-freertos.html）：后台每 6 小时检查一次升级，业务任务不受影响。
