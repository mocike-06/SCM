SysTick 系统定时器与 HAL_Delay 原理

系列：STM32 进阶 更新：2026-10-25

每个 HAL 工程都在用 HAL_Delay()，但你知道它是怎么算出 1 毫秒的吗？答案藏在 SysTick——一个藏在 Cortex-M3 内核里、所有 STM32 都有的 24 位定时器。本课讲透 SysTick 的结构、HAL 的时基（Tick）机制、HAL_Delay 的源码逻辑，以及为什么在中断里调用 HAL_Delay 会出大事。

一、本课目标与前置知识

学完本课你能做到：

  • 说清 SysTick 是什么、HAL 用它的哪三个寄存器建立「系统时基」。
  • 读懂 HAL_Delay 的源码：为什么它依赖中断、为什么不能在中断里用。
  • 自己实现基于 SysTick 的精确延时（不走 HAL_Delay 的替代方案）。

需要提前掌握的前置知识（对应学习路线阶段 4）：

  • 系统时钟（stm32-clock.html）：SysTick 的计数节拍来自系统时钟 72MHz。
  • 寄存器操作（stm32-register.html）：SysTick 也有寄存器，只是地址在内核区。
  • 定时器基础（stm32-pwm.html）：倒计时、重载这些概念通用。

本课会出现的新名词：SysTick、时基（Tick）、HAL_Delay、SysTick 控制/重载/当前值寄存器、HAL_IncTick、uwTick、中断里禁 delay。

二、基础概念铺垫

1. SysTick 是什么：内核自带的「节拍器」

生活类比：每栋办公楼（芯片）都标配一个「总节拍钟」（SysTick）——不用自己买（不用占通用定时器资源），钟摆每响一次就过一个节拍。

一句话定义：SysTick（系统滴答定时器）是 Cortex-M3 内核内置的 24 位倒计时定时器：从重载值（最大 16777215）开始每来一个时钟脉冲减 1，减到 0 触发中断并自动重新装载。每个 STM32 都有，专为操作系统时基和延时而生。

例子：72MHz 主频下，每 1µs 减 1 次；重载值设为 71999，则 72000µs = 72ms 中断一次——不对，是 71999 次计数 = 72000 个时钟 = 1ms。等等，重载值 71999 表示计数 72000 次（含 0），= 1ms。

2. 时基（Tick）：软件里的「心跳计数器」

生活类比：SysTick 是「钟」，软件还需要一个「日历」（一个不断累加的计数器）记录「今天是第几秒」。HAL 的做法：SysTick 每 1ms 中断一次，中断里执行 HAL_IncTick()，让全局变量 uwTick 加 1——这个 uwTick 就是全工程的「心跳计数器」。

一句话定义：时基 = 周期性中断里递增的计数器，为系统提供「当前时间」的参考。HAL_GetTick() 返回当前 uwTick（毫秒）。HAL_Delay、HAL_UART 超时判断全靠它。

例子：uint32_t t = HAL_GetTick(); 拿到「上电后第几毫秒」，可以用来做非阻塞延时、超时检测。

3. HAL_Delay 的真相：它依赖中断

一句话定义：HAL_Delay 不是「空转等时间」，而是「记下开始时刻，循环查询 uwTick 是否到了目标时刻」。因为 uwTick 由 SysTick 中断维护，所以 HAL_Delay 必须在中断开启（且 SysTick 中断正常）时才能工作。

例子：HAL_Delay(1000) = 记录 start=uwTick，然后 while (uwTick - start < 1000) 空转，直到 uwTick 涨了 1000。

4. 为什么中断里不能调 HAL_Delay

生活类比：你在接待重要客人（执行中断），却打开日历等 1 秒——但日历是靠「每 1 秒响一次铃」来翻页的，你正占着铃（中断优先级可能高于 SysTick），铃响不了，日历永远停在原地——于是你永远等不到 1 秒，程序卡死。

一句话定义：若 SysTick 中断优先级低于当前中断，当前中断里调 HAL_Delay 时 SysTick 中断无法抢占，uwTick 不再递增，while (uwTick - start < delay) 永远为真 → 死循环卡死。所以中断 ISR 里禁用 HAL_Delay。

例子：EXTI 回调里写 HAL_Delay(10)，中断卡死、系统假死——新手高频翻车点。

三、原理介绍：HAL 的时基是怎么建立起来的

HAL_Delay(1000) 凭什么真的等一秒？答案藏在 SysTick 这个内核自带的小定时器和一个全局计数里。

整条链路：SysTick 每 1ms 中断一次 → 中断里 uwTick++ → HAL_Delay 反复查 uwTick 差值，到点就返回。

原理 1：SysTick 倒计时——1ms 节拍怎么产生

SysTick 是 Cortex-M 内核内置的 24 位倒计时器。HAL_Init() 把它配成：72MHz 下重载值写 71999，数到 0 就触发一次中断并自动重装。为什么是 71999 不是 72000：计数器从「重载值」减到 0 才算一次，共减了「重载值+1」次。要 72000 个时钟（=1ms），重载值 = 72000−1 = 71999。这是含 0 计数的经典陷阱。

教材必背：SysTick 时钟源由 CTRL 的 CLKSOURCE 位决定。CLKSOURCE=1 → 直接用内核时钟 AHB（72MHz）；CLKSOURCE=0 → 用 AHB/8（9MHz）。HAL 默认选 AHB 72MHz，所以 LOAD=71999 才是 1ms；若你手动改成 AHB/8，同样的 71999 会变成 8ms——这是教材实验里「延时莫名慢 8 倍」的隐藏原因。另外 SysTick 是 Cortex-M3 内核的一部分（三级流水线：取指→译码→执行），它的中断优先级在 SHPR 寄存器里配，默认较低；RTOS 里它就是系统节拍中断，优先级要比一般外设中断高、但不能高过必须即时响应的硬实时中断。

原理 2：uwTick 心跳——uwTick++ 怎么变成时间轴

每次 1ms 中断进 SysTick_Handler，它调 HAL_IncTick() 执行 uwTick++。于是 uwTick 就是「上电以来第多少毫秒」。任何地方调 HAL_GetTick() 读它，就拿到当前时间。HAL_Delay 本质是：记下起点 t0，while 里反复查 uwTick−t0 ≥ 等待值 就返回——它不主动「睡」，只是忙等这个差值。SysTick 一旦停（中断被关），uwTick 不涨，HAL_Delay 就永远等不到。

原理 3：volatile——为什么 uwTick 必须加 volatile

uwTick 在中断里被写、在主循环里被读。若不声明 volatile，编译器优化时可能把它读进寄存器缓存，主循环一直用缓存的旧值、看不到中断里的自增——HAL_Delay 就永远不到点。所以 HAL 把它定义成 volatile uint32_t uwTick。通用原则：凡是「中断写、主循环读」的共享变量，都要 volatile 防优化。同理，中断里绝不能调 HAL_Delay（它依赖 SysTick 中断，会互相死锁）。

记忆点：SysTick=内核 24 位倒计时器，重载 71999=1ms@72M（减一因为含 0）；中断里 uwTick++ 作心跳；HAL_Delay=忙等 uwTick 差值；共享时间变量必须 volatile；中断里禁 delay。

四、硬件接线说明

SysTick 是内核内部定时器，无外部引脚。硬件只用于观察现象：

模块接线说明
LED板载（如 PC13）验证 1s 精确翻转
串口PA9/PA10打印 HAL_GetTick 值验证时间轴
按键PA0 接 GND触发「中断里 delay」演示卡死

为什么不需要接线：SysTick 在芯片内核里，物理上无引脚、无外部电路——你看到的延时现象全是软件行为。接线只是用来「观察现象」：LED 每 1 秒翻转一次，验证 HAL_Delay(1000) 精确。

避坑 CubeMX 生成的工程默认用 SysTick 做时基（HAL_TICK_FREQ_1KHZ）。如果你后来把 SysTick 挪给 FreeRTOS 用，HAL_Delay/HAL_GetTick 会失效——RTOS 工程要把时基改成 TIM6/TIM7（CubeMX 里 SYS 选项卡设置），这是移植 RTOS 时必查的配置。

五、完整代码

示例 1：读懂 HAL 的 SysTick 与 HAL_Delay 源码

/* 这是 HAL 库源码的核心逻辑（简化展示，实际在 stm32f1xx_hal.c） */

/* HAL_Init 里初始化 SysTick：以系统时钟为节拍，1ms 中断一次 */
HAL_StatusTypeDef HAL_InitTick(uint32_t TickPriority)
{
    /* 重载值 = 时钟频率 / 1000 - 1：72MHz → 71999 */
    SysTick->LOAD = (SysTick->LOAD & SysTick_LOAD_FMSK) |
                    (uint32_t)(SystemCoreClock / 1000U - 1U);
    SysTick->VAL  = 0UL;                  /* 清当前值，从 0 重新数 */
    SysTick->CTRL = SysTick_CTRL_CLKSOURCE_Msk |  /* 使用内核时钟 */
                    SysTick_CTRL_TICKINT_Msk   |  /* 开中断 */
                    SysTick_CTRL_ENABLE_Msk;      /* 启动 */
    return HAL_OK;
}

/* SysTick_Handler 在 stm32f1xx_it.c 里，每 1ms 进一次 */
void SysTick_Handler(void)
{
    HAL_IncTick();                 /* uwTick++ */
}

/* HAL_IncTick 与 HAL_GetTick */
volatile uint32_t uwTick = 0;      /* 全局心跳（毫秒） */
void HAL_IncTick(void)  { uwTick++; }
uint32_t HAL_GetTick(void) { return uwTick; }

/* HAL_Delay 的核心：查询差值而非空等 */
void HAL_Delay(uint32_t Delay)
{
    uint32_t tickstart = HAL_GetTick();     /* 记下开始时刻 */
    while ((HAL_GetTick() - tickstart) < Delay)   /* 等到差值达标 */
    { }
}

示例 2：不用 HAL_Delay 的非阻塞延时（中断里安全）

/* 非阻塞延时：不空转、不依赖 HAL_Delay，中断里也安全 */
#include "main.h"

/* 检查「自 t0 起是否过了 ms 毫秒」，用 u32 无符号回绕处理 */
uint8_t time_elapsed(uint32_t t0, uint32_t ms)
{
    return (uint32_t)(HAL_GetTick() - t0) >= ms;
}

int main(void)
{
    uint32_t last = HAL_GetTick();   /* 记开始时刻 */
    HAL_Init();
    SystemClock_Config();

    while (1)
    {
        if (time_elapsed(last, 1000)) {      /* 每 1 秒 */
            HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
            last = HAL_GetTick();            /* 更新基准 */
        }
        /* 主循环还能做别的事——非阻塞的关键 */
    }
}

六、代码逐段讲解

第一段：LOAD 重载值的计算

SystemCoreClock / 1000U - 1U：72,000,000 / 1000 - 1 = 71,999。为什么减 1：SysTick 从 LOAD 数到 0 共 LOAD+1 次才中断，要 1000 次/秒（1ms），就设 LOAD = 1000 - 1。为什么是 SystemCoreClock 而不是写死 72M：主频变了（如 64MHz）自动适配——HAL 刻意不写死，这也是换时钟树后延时仍然准确的原因。

第二段：CTRL 的三个位

CLKSOURCE 选内核时钟（72MHz）；TICKINT 使能中断（没有它 uwTick 不会加，HAL_Delay 永等不到）；ENABLE 启动。三个位缺一不可：缺 ENABLE 定时器不跑、缺 TICKINT 中断不触发——很多人移植时把中断关了，结果 HAL_Delay 卡死。

第三段：HAL_Delay 的「差值法」

(HAL_GetTick() - tickstart) < Delay 用无符号减法算差值——为什么不用 >= 比较：u32 计数 49 天会回绕到 0，差值法天然处理回绕（0 - 大数 = 正确差值），而「当前值 > 目标值」在回绕后会永远不成立。这是嵌入式时间的标准写法。

第四段：非阻塞 time_elapsed 的意义

示例 2 的主循环里「每 1 秒翻转」用的是查询差值，循环没有空转等 1 秒——检查时间、干活、再检查。为什么比 HAL_Delay 好：HAL_Delay 阻塞期间 CPU 只能空转，非阻塞写法让 CPU 在等待时还能处理按键、通信等任务——这是「单线程事件驱动」的核心技巧，也是中断安全的替代方案。

七、现象演示与验证

  • 精确延时：LED 每 1 秒精确翻转，用秒表对照无明显漂移（72MHz 晶振下误差 <1ms/分钟）。
  • 时间轴：串口每秒打印 tick=xxxx，数值递增 1000，验证 uwTick 是毫秒心跳。

验证方法：

  1. 在 SysTick_Handler 里加断点，观察它每 1ms 触发一次——用调试器数 10 次断点的间隔。
  2. 把主频改成 64MHz（时钟树 PLL ×8），LED 翻转仍 1 秒——验证 LOAD 用 SystemCoreClock 自动适配。
  3. 在 EXTI 回调里写 HAL_Delay(100) 并触发按键——观察系统卡死，验证「中断里禁 delay」。

九、课后练习与延伸

练习 1（必做）：用 HAL_GetTick() 实现「每 3 秒打印一次当前 tick」的非阻塞定时任务，主循环同时翻转另一个 LED——两个任务并行不卡。

练习 2：读一下你工程里 stm32f1xx_it.c 的 SysTick_Handler，确认它调用 HAL_IncTick；把它注释掉，观察 HAL_Delay 卡死——亲眼验证依赖关系。

练习 3（进阶）：把 SysTick 的 LOAD 改成 SystemCoreClock / 1000U * 2U（2ms 时基），观察 HAL_Delay(1000) 变成约 2 秒——理解「时基粒度决定延时精度」。
