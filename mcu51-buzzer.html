蜂鸣器发声（提示音与音乐）

系列：51 单片机 入门 更新：2026-10-25

蜂鸣器是单片机最常用的「发声输出」：按键反馈、报警、音乐都能靠它。本课讲清有源/无源的区别、驱动电路为什么加三极管，并用定时器精确产生音调，播放一段音乐。

一、本课目标与前置知识

学完本课你能做到：

  • 分清有源/无源蜂鸣器，并选对驱动电路（三极管/ULN2003）。
  • 用延时法或定时器产生指定频率的方波，让蜂鸣器发出指定音调。
  • 用音符频率表 + 节拍表写一首音乐。

需要提前掌握的前置知识（对应学习路线阶段 2）：

  • IO 口输出：蜂鸣器就是「一个需要大电流的 LED」。
  • 定时器（进阶玩法用）：精确产生频率。
  • 数组：音符表就是数组。

本课会出现的新名词：有源/无源蜂鸣器、方波、频率/周期、占空比、三极管驱动、音符频率表、节拍。

二、基础概念铺垫

1. 有源 vs 无源蜂鸣器：一字之差，驱动完全不同

生活类比：有源蜂鸣器像「自带闹钟的喇叭」——只要通电就响（内部有振荡电路）；无源蜂鸣器像「需要自己敲的钟」——给它通直流电它不响，必须给高低变化的方波才会响。

一句话定义：有源：内部集成振荡源，通电即响，只能「响/不响」，不能变调；无源：需要外部提供一定频率的方波才发声，频率决定音调，能播放音乐。开发板上的蜂鸣器大多是无源。

例子：想发「嘟——」提示音用有源省事；想弹《小星星》必须无源。

2. 方波、频率与周期

生活类比：声音是空气的振动，振动越快音调越高。方波是「高电平一段时间、低电平一段时间、不断交替」的电信号，交替一次叫一个周期；每秒交替多少次叫频率（Hz）。

一句话定义：无源蜂鸣器需要 高 → 低 → 高 → 低 的方波。频率 1000Hz = 每秒交替 1000 次 = 周期 1ms（高 0.5ms + 低 0.5ms）。音调 C 调 do（C4）约 262Hz，la（A4）440Hz。

例子：让 IO 每 0.5ms 翻转一次，输出就是 1kHz 方波，蜂鸣器发出 1kHz 的音。

教材式定时器方波频率公式：让 IO 在定时器中断里翻转，翻转周期 = 2×定时时间，则输出方波频率 f = 1 / (2 × T)。用定时器方式 2（8 位自动重装）时，定时时间 T = (256−TH0)×12/fosc，所以 f = fosc / (24×(256−TH0))。例：11.0592MHz 下想发 1kHz，代入得 256−TH0 = 11059200/(24×1000) = 460.8——8 位装不下，所以发中音常改用方式 1 或直接延时翻转；低音（几百 Hz 以下）方式 2 才够用。这是教材「用定时器产生方波音调」的标准推导。

3. 为什么驱动要加三极管/驱动芯片

生活类比：蜂鸣器是「大胃王」，要几十毫安电流；51 的引脚是「小水管」，最多几毫安。直接接，蜂鸣器响不亮、引脚还容易烧——中间加一个「大管家」（三极管）用小电流控制大电流。

一句话定义：51 IO 输出能力有限（灌电流约 10mA、拉电流更小），蜂鸣器工作电流常 20~40mA，必须经 NPN 三极管（如 8050）或驱动芯片（ULN2003）放大：IO 输出高 → 三极管导通 → 蜂鸣器通电发声。

例子：接法（无源、NPN 驱动）：IO → 1kΩ 电阻 → 三极管基极；蜂鸣器正极接 VCC、负极接三极管集电极；发射极接地。IO 高电平时导通发声。

4. 音符频率表：把简谱翻译成频率

一句话定义：每个音符对应一个固定频率（国际标准 A4=440Hz，其它按十二平均律推算）。写音乐 = 一个「音符序列」+ 一个「每个音时长（节拍）序列」。常用中音：do(523Hz) re(587) mi(659) fa(698) sol(784) la(880) si(988) 高音 do(1047)。

例子：《小星星》开头「do do sol sol la la sol」对应频率 523 523 784 784 880 880 784。

三、原理介绍：蜂鸣器凭什么「通电」就响、又怎么调出准音调

发一个指定频率的方波，关键是精确控制高/低电平各持续多久。两种做法：

  1. 软件延时法：BEEP=0;delay(半周期);BEEP=1;delay(半周期); 循环。简单但受延时函数精度影响。
  2. 定时器中断法（推荐）：定时器每半周期触发一次中断、在里面翻转 IO，频率由初值精确决定。

原理 1：有源 vs 无源——为什么有的给电就响、有的必须给方波

这是蜂鸣器最根本的分野：

  • 有源蜂鸣器：内部自带振荡电路，一通电就以固定频率（常见 2kHz 左右）自己响。你只要给高电平它就响，给的方波反而让它变成断续「哒哒」声。适合做简单提示音。
  • 无源蜂鸣器：内部就是一片压电陶瓷片，没有振荡器——你不给它交变电压，它就不振动不发声。你必须给它一定频率的方波，它才按这个频率振动出声音。正因为振动频率由外加方波决定，无源蜂鸣器才能奏出不同音高的音乐——这是本课用无源的原因。

所以「程序写方波、蜂鸣器却不响」多半是接了有源件（它不需要方波）；「给电就响、想停也停不住」多半也是有源件。先确认板子是哪种，再决定程序写法。

原理 2：频率为什么等于音调——半周期翻转的初值怎么算

蜂鸣器振动片每秒被方波推拉多少次，人耳就听到多高的音——方波频率直接=音高。一个完整周期=一次高+一次低，所以在定时器中断里每次翻转 IO，翻转间隔就是半周期。要发 f Hz 的音，半周期 = 1/(2f) 秒。换算成机器周期数（51 一个机器周期=12/11.0592MHz≈1.085µs）：

半周期机器数 = 11059200 / (12 × 2 × f)，方式1初值 = 65536 − 该数。

例：523Hz（中音 do）→ 11059200/(12×2×523) ≈ 881 → 初值 = 65536−881 = 64655 = 0xFC8F。为什么人耳对跑调这么敏感：音高差几个赫兹就听得出，软件空转延时受编译优化、中断打断影响，频率会飘；定时器数的是固定硬件脉冲，频率准——所以播音乐一律用定时器中断，把当前音符频率换算成初值装进 TH0/TL0 即可切换音高。

原理 3：为什么 IO 不能直接驱动蜂鸣器——三极管的电流放大

51 引脚灌电流约十几毫安、拉电流更小，而无源蜂鸣器工作要 20~40mA。直接接：电流不够、声音小，引脚还可能过载。中间加一颗 NPN 三极管（8050）做电流放大开关：IO 只需给基极几毫安小电流，三极管就能让几十毫安大电流从 VCC 经蜂鸣器流过它到地。IO 是「小水管拧阀门」、三极管是「大管家开大管子」——这是所有「IO 控制大电流负载」（蜂鸣器、继电器、电机）的通用套路，后面步进电机用的 ULN2003 就是七颗这样的管子做在一起。

记忆点：有源蜂鸣器内部有振荡器、通电就响不能变调；无源靠外加方波振动、频率=音高才能奏乐；半周期翻转 IO，初值=65536−11059200/(12×2×频率)；IO 电流小、蜂鸣器要大电流，必须三极管/ULN2003 放大。

四、硬件接线说明

无源蜂鸣器经 NPN 三极管（8050）驱动，接 P2.5：

模块引脚单片机引脚说明
IO 控制P2.5经 1kΩ 电阻接三极管基极
蜂鸣器正极VCC无源蜂鸣器无正负（线圈），接电源
蜂鸣器负极三极管集电极发射极接地；可并联续流二极管
三极管8050（NPN）IO 高电平导通，蜂鸣器通电

为什么这样接：NPN 三极管「基极高导通」：IO 输出 1 → 基极有电流 → 集电极-发射极导通 → 蜂鸣器下端接地形成回路发声。1kΩ 基极电阻限制基极电流保护 IO。Proteus 仿真里蜂鸣器元件 SOUNDER 可直接接 IO，但要选对极性；实物务必加三极管。

避坑 先确认板子上蜂鸣器是有源还是无源：有源给高电平就响，程序写方波反而会「哒哒哒」；无源不写方波则永远不响。开发板原理图都会标注。

五、完整代码

示例 1：定时器中断产生 523Hz（C 调 do）持续响

/* 定时器 0 中断翻转 IO：蜂鸣器发 523Hz */
#include <reg52.h>

sbit BEEP = P2^5;

void timer0_init(void) {
    TMOD |= 0x01;                 /* T0 方式 1 */
    TH0 = 0xFC;                   /* 半周期初值（约 881 个机器周期） */
    TL0 = 0x8F;
    ET0 = 1;  EA = 1;  TR0 = 1;
}

void timer0_isr(void) interrupt 1 {
    TH0 = 0xFC;                   /* 重装初值 */
    TL0 = 0x8F;
    BEEP = !BEEP;                 /* 翻转 IO：高变低、低变高 */
}

void main(void) {
    timer0_init();
    while (1);                    /* 中断自动发声 */
}

示例 2：播放《小星星》前两句（音符表 + 节拍表）

/* 音乐播放：音符频率表 + 节拍时长表 */
#include <reg52.h>

sbit BEEP = P2^5;

/* 音符频率：中音 do re mi fa sol la si 高音 do、休止 0 */
unsigned int code tone[] = {0, 523,587,659,698,784,880,988, 1047};
/* 简谱音符（1~7 表示 do~si，0 休止），《小星星》前两句 */
unsigned char code song[] = {1,1,5,5,6,6,5,  4,4,3,3,2,2,1,  0};
/* 每个音符的节拍（0.5 秒为 1 拍：1=0.5s，2=1s） */
unsigned char code beat[] = {1,1,1,1,1,1,2,  1,1,1,1,1,1,2,  1};

void delay_ms(unsigned int ms) {
    unsigned int i, j;
    for (i = 0; i < ms; i++)
        for (j = 0; j < 120; j++);
}

/* 按频率启动定时器发声；freq=0 时静音 */
unsigned char th_save, tl_save;   /* 当前音符的初值，供中断重装 */
void beep_freq(unsigned int freq) {
    unsigned int th;
    if (freq == 0) {              /* 休止：关定时器、IO 拉低 */
        TR0 = 0;  BEEP = 0;
        return;
    }
    th = (unsigned int)(65536 - 11059200UL / (12UL * 2 * freq));
    th_save = th / 256;           /* 高 8 位暂存 */
    tl_save = th % 256;           /* 低 8 位暂存 */
    TH0 = th_save;                /* 立即装入并启动 */
    TL0 = tl_save;
    TR0 = 1;                      /* 启动 */
}

void timer0_isr(void) interrupt 1 {
    TH0 = th_save;                /* 用暂存的初值重装（方式1不自动重装） */
    TL0 = tl_save;
    BEEP = !BEEP;
}

void main(void) {
    unsigned char i;
    TMOD |= 0x01;                 /* T0 方式 1 */
    ET0 = 1;  EA = 1;
    while (1) {
        for (i = 0; song[i] != 0 || i < 15; i++) {
            beep_freq(tone[song[i]]);      /* 按音符设置频率 */
            delay_ms(beat[i] * 500);       /* 持续该音时长 */
            beep_freq(0);                  /* 音符间短暂静音 */
            delay_ms(30);
        }
    }
}

六、代码逐段讲解

第一段：半周期翻转原理

定时器每经过「半个周期」触发一次中断，中断里 BEEP = !BEEP; 翻转电平。为什么半周期而不是整周期：一个完整方波需要高电平一段 + 低电平一段，两次翻转才凑成一个周期，所以中断周期 = 半周期。初值怎么算：机器周期 1.085µs，半周期时长 = 1/(2×523) ≈ 0.956ms ≈ 881 个机器周期，初值 = 65536 - 881 ≈ 0xFC8F。

第二段：音符表与节拍表

tone[] 用下标对应音符：song[i] 是简谱数字（1=do），tone[song[i]] 查频率。beat[i] 是每个音的拍数，乘以 500ms 得到时长。为什么用两个表：数据与逻辑分离——换歌只改 song/beat 两个数组，代码一行不动；这是数组在工程里的标准用法。

第三段：beep_freq 的频率初值计算

公式 65536 - 11059200/(12×2×freq) 里 12 是机器周期系数、2 是半周期、11059200UL 加 UL 防止 16 位乘法溢出（unsigned long）。th/256 和 th%256 把 16 位初值拆成高 8 位 TH0、低 8 位 TL0——正是位运算课讲过的「拆字节」。

第四段：中断里为什么要暂存初值

每个音符频率不同、初值也不同。beep_freq 算出初值后，先把高/低字节存进全局变量 th_save/tl_save，再让定时器跑起来；进中断时就用这两个变量重装——这样换音符后，中断重装的永远是「当前这个音」的初值，而不是写死的某个值。这就是为什么中断里不能写死 TH0=0xFC：那只对 523Hz 一个音准，换音就跑调。

七、现象演示与验证

  • 示例 1：蜂鸣器发出稳定的 523Hz「do」音，用手机频率计 App 测应在 520~526Hz。
  • 示例 2（修复中断重装后）：播放《小星星》前两句「do do sol sol la la sol / fa fa mi mi re re do」。

验证方法：

  1. 把频率改成 880Hz（la），音调应明显变高——验证频率-音调关系。
  2. 把节拍表全部改 2（慢一倍），节奏变慢——验证节拍表生效。
  3. 把晶振改为 12MHz 重新算初值（机器周期 1µs），对比音高差异，体会晶振对频率计算的影响。

九、课后练习与延伸

练习 1（必做）：把示例 1 频率改为 880Hz、然后 1318Hz（高音 mi），对比音高变化。

练习 2：修复示例 2——把 beep_freq 算出的初值存入全局变量 th_save/tl_save，中断里重装这两个变量，烧录后音准应正常。

练习 3（进阶）：给上一课秒表加「到 10 秒响一声」的提示音（调 beep_freq(880) 响 0.2s），把显示、按键、发声三块合起来。
