Deep Sleep 低功耗

系列：ESP32 进阶 更新：2026-10-25

温度传感器节点、智能门锁、野外监测——电池供电的设备动辄要撑几个月，而 ESP32 正常跑着 WiFi 就要 100mA+，一节电池撑不过几天。Deep Sleep 是官方给出的答案：没事就「深度睡眠」只留 10µA，定时醒来干活几十秒再睡回去。本课讲透功耗模式、唤醒源、RTC 机制，做一个「定时醒来→采集→上报→再睡」的完整低功耗节点。

一、本课目标与前置知识

学完本课你能做到：

  • 说清 ESP32 的功耗模式阶梯（Active/Modem/Light/Deep）和各自电流量级。
  • 理解 Deep Sleep 后 CPU 停了但 RTC 还在跑，能定时/GPIO/触摸唤醒。
  • 写出「唤醒→采集→存 NVS→上报→再睡」的完整低功耗节点程序。

需要提前掌握的前置知识（对应学习路线阶段 5）：

  • ADC 采集（esp32-adc.html）：低功耗节点要读传感器/电池电压。
  • NVS 存储（esp32-storage.html）：睡眠期间的数据靠 Flash 保存。
  • WiFi/MQTT（可选）：上报数据用（低功耗下 WiFi 只在醒来时开）。

本课会出现的新名词：低功耗、Active/Modem Sleep/Light Sleep/Deep Sleep、RTC、唤醒源（定时/GPIO/触摸）、esp_sleep_enable_timer_wakeup、esp_deep_sleep_start、µA 量级。

二、基础概念铺垫

1. 为什么要低功耗：电池容量的数学题

生活类比：一块 18650 锂电池约 3000mAh。设备持续耗 100mA → 30 小时就没电；若平时睡觉只耗 10µA、每小时醒来 3 秒耗 100mA → 一个月平均不到 5mA，能用 600 小时——差出两个数量级。

一句话定义：低功耗不是「降低性能」，而是「无事时让芯片尽可能不干活」。ESP32 这种 SoC 的优势：Deep Sleep 时大部分电路断电，只留 RTC 域计时，电流降到 10µA 级。

例子：环境监测节点每 10 分钟采一次温湿度并上报，其余 9 分 57 秒都在 Deep Sleep——这是电池设备的标准工作模式。

2. ESP32 的功耗模式阶梯

一句话定义（典型电流，实测因板而异）：Active（CPU 全速 + WiFi 开，100~240mA）；Modem Sleep（CPU 跑、WiFi 关闭，20~50mA）；Light Sleep（CPU 暂停、可定时唤醒，1~5mA）；Deep Sleep（CPU 和大部分 SRAM 断电，只留 RTC，10µA 级）。选哪级看需求：要频繁响应选 Light，要极致续航选 Deep。

例子：要省电又要秒回消息 → Light Sleep；定时采集上报 → Deep Sleep 足够。

3. RTC 域与唤醒源：睡着了谁叫你

生活类比：Deep Sleep 时 CPU 和主内存全关机，但一块「独立小闹钟」（RTC 电路）还开着电——闹钟响（唤醒源触发），整机才重新开机。

一句话定义：Deep Sleep 期间只有 RTC 域（RTC 定时器、RTC 存储器、部分 RTC GPIO、UART 等）带电。唤醒源：① 定时器（esp_sleep_enable_timer_wakeup(微秒)）；② 外部 GPIO（ext0 单脚 / ext1 多脚，esp_sleep_enable_ext0_wakeup）；③ 触摸传感器。唤醒后：程序从 setup() 重新开始执行（相当于重启，但复位原因是 Deep Sleep 唤醒）。

例子：门上传感器用 GPIO 唤醒（开门→唤醒→拍照）；环境节点用定时唤醒（每 10 分钟醒一次）。

4. 唤醒后怎么知道「我是谁」：复位原因与 RTC 内存

一句话定义：唤醒 = 重启，所以要用 esp_sleep_get_wakeup_cause() 判断这次是「上电 / Deep Sleep 唤醒 / GPIO 唤醒」，走不同逻辑；跨睡眠保存少量数据可以用 RTC_DATA_ATTR 修饰的全局变量（存在 RTC 内存，Deep Sleep 不清空）——比 NVS 快，但容量小（约 8KB）。

例子：RTC_DATA_ATTR int wakeCount; 每次唤醒 +1，断电才清零——不磨损 Flash，适合高频计数。

5. ULP 协处理器：深睡时还能「悄悄干活」的小工

生活类比：Deep Sleep 把主 CPU 关了，但 RTC 域里还养着一个超省电的小工——ULP（超低功耗协处理器）。它不会开 WiFi，只会极慢地读 ADC、查触摸，一旦发现「温度超标/有人摸」，才把主 CPU 叫醒。

一句话定义：ULP（Ultra Low-Power coprocessor）是 ESP32 RTC 域里的一个 8 位小协处理器，Deep Sleep 期间仍能以微安级功耗运行，可定时采样 ADC、比较阈值，满足条件再唤醒主 CPU。它适合「长期守着阈值、偶尔才上报」的场景，比每次都唤醒主 CPU 再省一个量级。

例子：野外土壤监测——ULP 每几秒偷偷读一次湿度，只有跌破阈值才唤醒主 CPU 开 WiFi 上报一次；平时主 CPU 全程深睡，电池撑半年以上。

三、原理介绍：低功耗节点的一次完整循环

ESP32 的功耗是分域管理的：CPU、WiFi 射频、内部 RAM 分属不同电源域，可以单独断电。Deep Sleep 就是把除 RTC 域之外全部断电——电流从运行时的约 100mA 降到约 10µA，差一万倍。理解「哪些域保留、哪些断电」，才能解释为什么唤醒等于重启、什么数据能跨睡眠保留。

一次低功耗循环：醒来（=冷启动跑 setup）→ 判断唤醒原因 → 读传感器+上报 → 配置唤醒源 → esp_deep_sleep_start()（不返回）→ 睡到下次触发。

原理 1：功耗域——Deep Sleep 到底关了什么

ESP32 芯片内部电源分域：数字域（CPU、SRAM、WiFi/蓝牙射频）功耗最大；RTC 域（实时时钟、低速外设）功耗极小。Deep Sleep 做的事是：切断数字域电源，只保留 RTC 域。结果就是——CPU 停了、WiFi 断了、主 RAM 里的变量全部丢失，只有 RTC 计数器还在走。这就是为什么 Deep Sleep 电流能降到微安级。

原理 2：三种唤醒源——谁能把断电的芯片叫醒

  • Timer（定时唤醒）：RTC 计数器数到你设的微秒数自动唤醒——esp_sleep_enable_timer_wakeup(600e6) 里 600 秒=6 亿微秒。
  • EXT0（引脚唤醒）：指定某一个 RTC 引脚，电平到设定值就唤醒——适合按键。
  • EXT1（多引脚唤醒）：一组 RTC 引脚按「全低」或「全高」唤醒——适合多个按键任意一个触发。

三种唤醒源都属于 RTC 域，所以睡眠期间它们一直在耗电值守——这是用 10µA 换「能随时醒来」。

原理 3：为什么唤醒=重启，什么数据能跨睡保留

因为主 RAM 被断电了，唤醒时 CPU 的寄存器、栈、变量全没了——程序只能像刚上电一样从 setup 冷启动。esp_sleep_get_wakeup_cause() 告诉你这次是「真上电」还是「睡眠唤醒」，据此跳过重复初始化。想跨睡眠保留的小数据（比如计数），要放进 RTC_DATA_ATTR 修饰的变量——它被链接到 RTC 域内存，睡眠时不掉电；大块数据则存 NVS Flash。WiFi 为什么要短连快断：WiFi 射频开机就 100mA+，是功耗大头；醒来→连网→几秒发完→立刻睡，把开机时间压到最短，平均电流才能真降下来。

记忆点：Deep Sleep=切断数字域、只留 RTC 域（100mA→10µA）；唤醒源=Timer/EXT0/EXT1，都属 RTC 域值守；唤醒=冷启动跑 setup，用 wakeup_cause 区分；RTC_DATA_ATTR 跨睡留小变量、大的存 NVS；WiFi 短连快断。

四、硬件接线说明

低功耗节点示例（带光敏/电位器 ADC 输入与板载 LED 指示）：

模块引脚ESP32 引脚说明
传感器（光敏/电位器）GPIO34（ADC1）采集模拟量；用 RTC GPIO 唤醒可另行接 GPIO4
按键（GPIO 唤醒练习）GPIO4（RTC GPIO）esp_sleep_enable_ext0_wakeup 用
LED 指示GPIO2 或板载唤醒期间点亮一下，肉眼可见「醒来又睡了」
串口板载 USB打印唤醒原因与采集值（睡眠时串口也断电）

为什么传感器接 ADC1（GPIO32~39）：Deep Sleep 唤醒后要马上采样，ADC1 不需要 RTC 配合、用起来简单；ADC2 在 WiFi 使用时又不稳——保持上一课的原则。为什么 GPIO 唤醒要接 RTC GPIO：只有部分引脚（如 GPIO2/4/12~15/32~39 等）属于 RTC 域，Deep Sleep 时只有它们能感知外部电平变化，普通 GPIO 在深睡时根本不工作——查 ESP32 数据手册的 RTC GPIO 表。

避坑 板上 USB 串口芯片（CH340 等）本身也耗电（几 mA），测功耗时要用电池/外接电源并拔掉 USB——开发板测量 Deep Sleep 电流常见「测不准」就是因为 USB 芯片还在耗电。

五、完整代码

示例 1：定时唤醒 + 采集 + 计数 + 再睡（10 秒一醒）

/* Deep Sleep 节点：每 10 秒唤醒一次，采样 + 计数，再睡 */
#include <esp_sleep.h>

const int adcPin = 34;
RTC_DATA_ATTR int wakeCount = 0;   /* RTC 内存：Deep Sleep 不清空 */

void printWakeCause() {
  switch (esp_sleep_get_wakeup_cause()) {
    case ESP_SLEEP_WAKEUP_UNDEFINED:   /* 首次上电 */
      Serial.println("Cause: power-on");
      break;
    case ESP_SLEEP_WAKEUP_TIMER:
      Serial.println("Cause: timer");
      break;
    default:
      Serial.println("Cause: other");
  }
}

void setup() {
  Serial.begin(115200);
  delay(100);                        /* 等串口稳定 */

  wakeCount++;                       /* 唤醒次数 +1（跨睡保存） */
  printWakeCause();
  Serial.printf("wakeCount=%d\n", wakeCount);

  /* 干活：读一次 ADC（低功耗节点醒来才开外设） */
  analogSetPinAttenuation(adcPin, ADC_11db);
  int n = analogRead(adcPin);
  Serial.printf("sensor=%d\n", n);

  /* 配置唤醒：10 秒（微秒单位） */
  esp_sleep_enable_timer_wakeup(10 * 1000000ULL);

  Serial.println("Entering Deep Sleep...");
  esp_deep_sleep_start();            /* 此函数不返回，直接睡 */
}

void loop() {                        /* Deep Sleep 程序里 loop 用不到 */
}

示例 2：GPIO 唤醒（按一下 GPIO4 才醒）

/* 外部 GPIO 唤醒：平时深睡，按键按下（下降沿）唤醒 */
#include <esp_sleep.h>

const int wakePin = 4;      /* 必须是 RTC GPIO */

void setup() {
  Serial.begin(115200);
  delay(100);

  if (esp_sleep_get_wakeup_cause() == ESP_SLEEP_WAKEUP_EXT0) {
    Serial.println("Woken by GPIO!");
  } else {
    Serial.println("Power-on");
  }

  /* ext0：单脚低电平唤醒；HIGH/LOW 可选触发电平 */
  esp_sleep_enable_ext0_wakeup((gpio_num_t)wakePin, 0);  /* 0=LOW 唤醒 */

  Serial.println("Sleeping...");
  esp_deep_sleep_start();
}

void loop() { }

六、代码逐段讲解

第一段：RTC_DATA_ATTR 的跨睡计数

RTC_DATA_ATTR int wakeCount 把变量放进 RTC 内存——Deep Sleep 断电时它还在，唤醒后值保留。为什么不用普通变量：普通变量在主内存里，深睡断电全丢，每次唤醒都从 0 开始。为什么不用 NVS：NVS 写一次擦写一次 Flash（有寿命），RTC 内存没有擦写损耗且速度快——高频计数用 RTC 变量更合适，低频配置才用 NVS。

第二段：printWakeCause 的分支处理

ESP_SLEEP_WAKEUP_UNDEFINED 表示「不是任何唤醒源」= 首次上电或复位。为什么必须区分：首次上电需要完整初始化（校准、清空临时状态），定时唤醒则直接干活——不区分会导致每次唤醒都重置计数或重复初始化。工程习惯：低功耗程序的第一步永远是判断唤醒原因。

第三段：esp_sleep_enable_timer_wakeup 的单位

参数是微秒：10 * 1000000ULL = 10 秒（加 ULL 防 32 位溢出）。为什么容易错：很多人按毫秒写（10000）结果 10 毫秒就醒一次，串口疯狂刷——单位换算错误是低功耗代码第一坑。

第四段：esp_deep_sleep_start 不返回

这个函数「一去不回」——芯片立即进入深睡。所以它必须放在 setup 的最后一行，后面写的任何代码都执行不到。loop 为什么空着：程序根本到不了 loop——睡眠前就停了；这也解释了为什么低功耗程序的逻辑可以全放 setup。

第五段：ext0 唤醒的电平参数

esp_sleep_enable_ext0_wakeup(pin, 0) 第二个参数 0=LOW 电平唤醒（引脚被拉低时唤醒）、1=HIGH。按键怎么配合：GPIO4 平时靠外部上拉为高，按键按下接地变低 → LOW 唤醒；松开后恢复高，下次再按再醒。

七、现象演示与验证

  • 示例 1：串口每 10 秒打印一组 Cause: timer / wakeCount=N / sensor=xxx，然后进深睡；LED 无持续工作。
  • 示例 2：上电打印 Power-on 后睡；按一下 GPIO4 按键，串口打印 Woken by GPIO。

验证方法：

  1. 用万用表电流档串联测功耗：深睡期间电流应从 mA 级掉到 µA 级（几十~几百 µA 含板载芯片，属正常）。
  2. 把定时从 10 秒改成 60 秒（60×10⁶ µs），观察唤醒间隔拉长 6 倍——验证定时单位。
  3. 示例 1 里把 wakeCount 改用普通 int，重启后计数归零——对比 RTC_DATA_ATTR 的作用。
