存储器映射与寄存器本质

系列：STM32 进阶 更新：2026-10-25

为什么 51 用 sbit LED = P1^0，STM32 却写 HAL_GPIO_WritePin(...)？它们背后都是同一件事：往某个固定内存地址写 0 或 1。本课把 STM32 的「地址地图」讲透——Flash 在哪、SRAM 在哪、GPIO 的寄存器住在哪个地址、HAL 函数只是这些地址的「翻译官」。

一、本课目标与前置知识

学完本课你能做到：

  • 说清 F103 的 Flash / SRAM / 外设三个地址区，以及 GPIOA 等外设的基地址。
  • 理解「寄存器 = 有固定地址的内存单元」，会用结构体指针直接操作寄存器点灯。
  • 看懂 HAL 宏与函数背后的寄存器读写，排查「为什么我改寄存器没用」。

需要提前掌握的前置知识（对应学习路线阶段 4）：

  • 时钟配置（stm32-clock.html）：操作寄存器前必须先开外设时钟。
  • GPIO 教程（stm32-gpio.html）：本课解释它里面 HAL 函数的底层。
  • C 语言指针（阶段 1）：*(指针) 解引用、结构体成员访问。

本课会出现的新名词：存储器映射、外设基地址、寄存器偏移、volatile、BSRR/ODR/IDR、结构体指针、位带操作、地址总线。

二、基础概念铺垫

1. 存储器映射：一张「城市地图」

生活类比：芯片内部就像一个城市，每栋楼（内存块）有固定门牌号（地址）。Flash 是「档案馆」（存程序，掉电不丢），SRAM 是「办公室」（跑程序时放变量，掉电就清空），外设是「各政府部门」（GPIO、串口、定时器，办不同的事）。存储器映射 = 芯片出厂时定好的「城市地图」，所有功能住在固定门牌号上。

一句话定义：存储器映射指芯片把不同功能的存储/寄存器区安排在一张统一地址表上。F103 地图（0x0000_0000 起）：0x0800_0000 Flash（程序）、0x2000_0000 SRAM（变量）、0x4000_0000 起外设区。

例子：你烧录的程序存在 Flash（0x08000000 开始），程序里的变量存在 SRAM（0x20000000 开始）——烧录失败/程序不跑先查 Flash，变量莫名其妙被清零先想 SRAM。

2. 外设基地址与寄存器偏移：楼号 + 房间号

生活类比：每个外设是一栋楼（基地址），楼里每个寄存器是一间房（偏移量）。GPIOA 楼在 0x40010800，楼里的「ODR 房」（输出数据寄存器）在第 0x0C 号房间——所以 GPIOA 的 ODR 完整地址 = 0x40010800 + 0x0C。

一句话定义：外设寄存器的完整地址 = 外设基地址 + 寄存器偏移。F103 常用：GPIOA 基址 0x40010800、USART1 基址 0x40013800、RCC 基址 0x40021000。头文件里 GPIOA->ODR 就是「基地址 + 偏移」的封装。

例子：GPIOA->ODR = 0x0001; 等价于往地址 0x4001080C 写 1——点亮 PA0。

3. volatile：告诉编译器「这地址会自己变」

生活类比：编译器像个爱偷懒的秘书——你反复读同一个变量的值，它可能自作主张用上次记的（缓存优化）。volatile 就是贴一张「此值随时可能变」的便签，让每次读写都真的去内存。

一句话定义：寄存器值由硬件随时改变（如中断标志位），必须用 volatile 修饰指针，防止编译器优化掉关键读写。这也是为什么所有寄存器访问都是 volatile unsigned long *。

例子：读 UART 的接收标志 RXNE 用 volatile 修饰，否则编译器可能一直读到旧值，导致数据接收判断失效。

4. BSRR 与 ODR：点灯为什么有两个寄存器

一句话定义：ODR（输出数据寄存器）：直接写整个 16 位引脚电平（0x0001 表示 PA0 高）；BSRR（置位/复位寄存器）：低 16 位写 1 = 对应引脚置高、高 16 位写 1 = 对应引脚拉低，只影响写到的位，其它位不动。所以操作单个引脚推荐 BSRR——不需要「读-改-写」，天然无冲突。

例子：GPIOA->BSRR = (1 << 5); 只把 PA5 拉高，其它引脚不变；GPIOA->BSRR = (1 << (16+5)); 把 PA5 拉低。HAL_GPIO_WritePin 内部就是操作 BSRR/ODR。

5. 总线矩阵与 AHB-APB 桥：CPU 怎么找到外设

一句话定义（野火教材「总线架构」章节）：Cortex-M3 内核并不是直接踩在外设上的，它前面有一组总线：ICode 总线（取指，把 Flash 里的指令搬进内核）、DCode 总线（读 Flash 里的常量/向量表）、System 总线（访问 SRAM 和外设）。这些总线汇到总线矩阵(bus matrix)，再经 AHB 总线，由两座 AHB-APB 桥 分频挂出 APB1(36MHz) 和 APB2(72MHz) 两条外设总线——GPIOA 在 APB2、TIM3 在 APB1，就是这么来的。

存储器地图补全（教材必背三块）：除了 Flash 0x08000000(128KB)、SRAM 0x20000000(20KB)，还有第三块系统存储器 0x1FFFF000——这是 ST 出厂固化的 Bootloader，STM32 把 BOOT0 拉高时就从这里启动，通过串口 ISP 烧录程序而不用 ST-Link。记牢这三个基址，寄存器和启动问题都能对上号。

三、原理介绍：从 HAL 函数到寄存器的一条链

这一篇揭开最后一层窗户纸：所谓「操作单片机」，本质就是对一串固定地址做读写。

整条链路：C 指针 = 外设基地址 → 结构体把寄存器按偏移排好 → GPIOA->BSRR 被编译成「往 0x40010810 写一个数」。

原理 1：存储器映射——外设其实是一排内存地址

ARM Cortex-M 采用统一编址：外设寄存器和 RAM 共用同一根地址总线，CPU 读写外设寄存器和读写一个变量用的是同一条指令。GPIOA 挂在 APB2，基地址固定 0x40010800。头文件把它强转成结构体指针：

/* GPIOA 基地址 = APB2 上的 0x40010800，强转成结构体指针 */
#define GPIOA_BASE  (0x40010800UL)
#define GPIOA       ((GPIO_TypeDef *)GPIOA_BASE)

GPIO_TypeDef 按手册把寄存器排成：CRL(0x00)、CRH(0x04)、IDR(0x08)、ODR(0x0C)、BSRR(0x10)、BRR(0x14)。编译器保证成员地址 = 基地址 + 偏移——所以 GPIOA->ODR 就是地址 0x4001080C。

原理 2：HAL_GPIO_WritePin 底层到底做了什么

打开 stm32f1xx_hal_gpio.c，那个函数实质就三句：

  1. SET → GPIOx->BSRR = PinMask;（对应位置 1）
  2. RESET → GPIOx->BRR = PinMask;（BRR 置 1 拉低）
  3. Toggle → GPIOx->ODR ^= PinMask;（异或翻转）

为什么置高用 BSRR 而不是直接改 ODR：改 ODR 是读-改-写，中途若中断也改 ODR 就会互相覆盖（竞态）。BSRR/BRR 是只写置位寄存器，写 1 对应位原子生效、绝不动其他位——线程安全。这就是 HAL 一律走 BSRR/BRR 的原因。

原理 3：volatile 与时钟——为什么寄存器必须 volatile、用前先开时钟

寄存器值会被硬件随时改变（如 IDR 随引脚电平变），若不加 volatile，编译器可能把「连续读 IDR」优化成「只读一次放寄存器」，读到旧值。所以所有外设结构体都用 volatile 修饰，强制每次真去地址读。另外，外设没开时钟时寄存器地址是空的，先 RCC->APB2ENR |= (1 << 2); 开 GPIOA 时钟才能写动——这就是「用前先开 RCC」的寄存器写法。

记忆点：统一编址=外设即内存；GPIOA=0x40010800，ODR=+0x0C、BSRR=+0x10；HAL 底层=BSRR/BRR/ODR；寄存器必须 volatile 防优化；用前先 RCC->APB2ENR 开时钟。

四、硬件接线说明

本课用寄存器直接驱动 PA5 上的 LED（F103 最小系统板板载 LED 常见接 PA5 或 PC13，先看原理图确认）：

模块引脚单片机引脚说明
LED 阳极PA5（先查板子原理图）经 330Ω 限流电阻
LED 阴极GND推挽输出高电平点亮
ST-LinkSWDIO/SWCLK/GND下载与调试（烧录用）

为什么 PA5 需要配置模式才能输出：STM32 每个引脚默认是输入浮空，必须先写 CRL/CRH 配置寄存器把引脚设为「推挽输出 50MHz」，ODR 才有意义。HAL 的 HAL_GPIO_Init() 做这件事；本课代码用寄存器方式手动配置，让你看见 HAL 隐藏的步骤。

避坑 不同开发板板载 LED 引脚不同（F103C8T6 蓝板常在 PC13，正点原子在 PB0/PB5 等）——先看你的板子原理图再改代码里的引脚号，否则点了没反应会误以为寄存器操作错了。

五、完整代码

示例 1：纯寄存器点灯（不开 HAL 外设，直接操作 RCC/CRH/ODR/BSRR）；示例 2：对比 HAL 写法与寄存器写法。

示例 1：寄存器直接操作点亮 PA5（LED 闪烁）

/* 纯寄存器点灯：不调 HAL_GPIO 函数，直接写地址 */
#include "stm32f1xx.h"

/* 便捷宏：把某地址强转成 volatile 指针再读写 */
#define REG(addr)  (*(volatile unsigned long *)(addr))

void delay(void) {
    volatile unsigned long i;
    for (i = 0; i < 500000UL; i++);   /* 粗略软件延时 */
}

int main(void)
{
    /* 1. 开 GPIOA 时钟：RCC->APB2ENR 的 bit2 = GPIOAEN */
    REG(0x40021000 + 0x18) |= (1UL << 2);

    /* 2. 配置 PA5 为推挽输出：CRH(偏移0x04) 管 PA8~PA15，每脚 4 位 */
    /*    PA5 在 CRL(偏移0x00)，MODE5[1:0]=11(50MHz), CNF5=00(推挽) */
    /*    CRL bit[23:20] = 0x3  → 写入 0011 */
    REG(0x40010800 + 0x00) &= ~(0xFUL << 20);   /* 清掉 PA5 原配置 */
    REG(0x40010800 + 0x00) |=  (0x3UL << 20);   /* 推挽输出 50MHz */

    while (1) {
        /* 3a. 点亮：BSRR(偏移0x10) 低16位 bit5 置 1 → PA5 高 */
        REG(0x40010800 + 0x10) = (1UL << 5);
        delay();
        /* 3b. 熄灭：BRR(偏移0x14) bit5 置 1 → PA5 低 */
        REG(0x40010800 + 0x14) = (1UL << 5);
        delay();
    }
}

示例 2：同功能的两种写法对比

/* 写法 A：HAL 库（工程里常用） */
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);    /* PA5 高 */
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_RESET);  /* PA5 低 */

/* 写法 B：直接寄存器（原理等价，本课学的） */
GPIOA->BSRR = GPIO_PIN_5;               /* 置高 */
GPIOA->BRR  = GPIO_PIN_5;               /* 拉低 */

/* 写法 C：指针解引用（最底层，示例 1 用这个） */
(*(volatile unsigned long *)0x40010810UL) = (1UL << 5);  /* BSRR 地址直写 */

六、代码逐段讲解

第一段：REG 宏与 volatile 的意义

#define REG(addr) (*(volatile unsigned long *)(addr)) 把任意地址变成可读写的变量。为什么必须 volatile：编译器看到 REG(x) |= y 可能优化成「只读一次、写一次」；但寄存器会被硬件改变，volatile 强制每次都真实访问地址——丢了这个关键字，很多诡异 bug 由此而来。

第二段：开时钟的地址 0x40021000 + 0x18

RCC 基地址 0x40021000，APB2ENR 的偏移是 0x18，bit2 是 GPIOAEN。|= (1UL << 2) 是「只置第 2 位、不动其它位」的标准写法。为什么不直接写 =1：那样会清掉其它外设的时钟使能（可能关掉串口等已开外设）。「读-改-写」是寄存器操作的黄金习惯。

第三段：CRL 配置的位段计算

PA0~PA7 由 CRL 管理，每个引脚占 4 位：CNF[1:0]（功能）+ MODE[1:0]（速度）。PA5 的 4 位在 bit[23:20]。0xF << 20 清掉这 4 位，0x3 << 20 写入「通用推挽输出、50MHz」。为什么是 0x3：MODE=11（50MHz）、CNF=00（推挽）组合成二进制 0011 = 0x3。这是数据手册 GPIO 章节的标配表格。

第四段：BSRR 与 BRR 的点灯动作

BSRR = (1UL << 5) 让 PA5 输出高；BRR = (1UL << 5) 让 PA5 输出低。与 ODR 不同，这两个寄存器「写 1 生效、写 0 无效」，所以不需要读-改-写，直接赋值即可——这也是 HAL 内部偏爱它们的原因。

七、现象演示与验证

  • 正常现象：PA5 上的 LED 以约 1Hz 频率闪烁（软件延时约 0.5s 一次翻转）。
  • 对照实验：把延时从 500000 改到 50000，闪烁明显变快——验证「CPU 频率 + 循环次数 = 延时时间」。

验证方法：

  1. 用 Debugger（Keil 仿真）在 REG(0x40010810UL) = ... 行加断点，Watch 窗口观察 GPIOA->BSRR/ODR 值变化——亲眼看到寄存器被改写。
  2. 把第 2 步（CRL 配置）注释掉重烧，LED 不亮——证明「必须先配模式才能输出」。
  3. 把开时钟那行删掉重烧，LED 也不亮——证明「先开时钟」的必要性（回顾上一课）。

八、常见报错排查方案

报错现象可能原因解决方法
LED 不亮但程序在跑引脚选错（板载 LED 不在 PA5）/ 模式没配查原理图换引脚；确认 CRL 已写推挽输出
寄存器写了没效果没开外设时钟 / 地址算错先 RCC->APB2ENR |= (1<<2)；核对基地址+偏移
程序行为异常且偶发丢了 volatile，编译器优化了寄存器读写所有寄存器访问用 volatile 指针或结构体
LED 亮度极暗模式写成开漏且无上拉CRL 的 CNF 写成 00（推挽）；开漏只适合总线
想只动一个引脚却全乱了直接写 ODR 覆盖了其它引脚改用 BSRR/BRR 或读-改-写 ODR
编译报错：REG 未定义示例宏没复制 / 头文件路径不对把 #define REG(addr) ... 与 #include "stm32f1xx.h" 放 main.c 顶部

九、课后练习与延伸

练习 1（必做）：把示例 1 的 PA5 改成 PA6（CRL 位段从 bit[23:20] 换成 bit[27:24]），验证寄存器位段计算的通用性。

练习 2：用 BSRR 同时点亮 PA5 和 PA6（BSRR = (1<<5)|(1<<6)），再用 BRR 只灭 PA6——体会「写 1 生效」的独立性。

练习 3（进阶）：读 IDR（输入数据寄存器，偏移 0x08）实现按键检测：配 PA0 为上拉输入（CRL 写 0x8 = 上拉输入），读 IDR bit0 判断按下。
