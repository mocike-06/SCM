传感器读取：DHT11 温湿度 + DS18B20 温度

系列：ESP32 进阶 更新：2026-10-25

用两类最常见的数字温湿度传感器打通「外设数据进单片机」的完整链路：DHT11 用单总线时序读温湿度，DS18B20 用 OneWire 单总线读高精度温度。本讲从零讲清单总线为什么要上拉、40 位数据怎么编码、CRC 校验是什么、库是怎么替你 bit-bang 的。

一、本课目标与前置知识

学完本课你能做到：

  • 理解单总线（1-Wire）的物理含义：一根线既当电源参考又当数据线。
  • 接线 DHT11 和 DS18B20，用 Adafruit DHT 库与 OneWire/DallasTemperature 库读出温湿度。
  • 知道为什么 DS18B20 必须接 4.7kΩ 上拉电阻，为什么 DHT11 至少 2 秒读一次。

需要提前掌握的前置知识（对应学习路线阶段 5）：

  • GPIO 输入输出（esp32-gpio.html）：知道 digitalWrite/digitalRead。
  • 库管理器的使用：会装第三方库。
  • C 语言浮点：知道 float 类型。

本课会出现的新名词：单总线（1-Wire）、DHT11 时序、起始信号、位编码（26~28μs vs 70μs）、校验和、DS18B20、OneWire 库、DallasTemperature 库、4.7kΩ 上拉、CRC 校验。

二、基础概念铺垫

1. 单总线（1-Wire）：一根线干两份活

生活类比：普通通信像双线铁轨（一根发一根收），单总线像一根独木桥——所有设备都挂在同一根线上，大家分时说话、分时听。线平时被电阻拉到高电平，谁要说话就主动把线拉低。

一句话定义：单总线（1-Wire）是 Maxim 公司的串行协议，只用一根数据线（加 GND 和 VCC）就能完成供电与双向通信；多个设备并联在同一根线上，靠每个芯片出厂自带的 64 位唯一地址区分。

例子：DS18B20 的 VCC/GND/DATA 三个脚，DATA 这根线既传温度数据，又决定通信时序。

2. 上拉电阻：让总线「默认回家」

生活类比：总线平时没设备说话时不能飘在空中——像电梯门没按的时候要默认关着。上拉电阻就是把线默认拉到高电平的「橡皮筋」，谁要发信号就主动把它拉低。

一句话定义：单总线空闲时必须靠一个 4.7kΩ 电阻把 DATA 线拉到 VCC（3.3V）；没上拉，线电平悬空，时序完全乱掉。

例子：DS18B20 的 DATA 与 3V3 之间焊一个 4.7kΩ 电阻；DHT11 成品模块板上一般已经焊了 10kΩ 上拉，裸片则要自己加。

3. DHT11 时序：用「高电平持续多久」来表示 0 和 1

生活类比：DHT11 不像 UART 那样有固定波特率，而是靠「高电平持续时间长短」来区分 0 和 1——像拍电报，短闪是 0、长闪是 1。

一句话定义：主机先拉低总线 ≥18ms 发起起始信号，释放后 DHT11 回 40 位数据：26~28μs 高电平表示 0，70μs 高电平表示 1；40 位 = 湿度整数 + 湿度小数 + 温度整数 + 温度小数 + 校验和。

例子：Adafruit DHT 库内部就是用微秒级延时去 bit-bang 这个时序的，你不用自己写，调 dht.readHumidity() 即可。

4. OneWire 与 DallasTemperature 库：替你 bit-bang 的发动机

生活类比：手写单总线时序要精确到微秒，像自己造钟表。OneWire 库是「底层发动机」，负责起始/读位/写位；DallasTemperature 是「方向盘」，把温度换算、CRC 校验都包好。

一句话定义：OneWire 库实现 1-Wire 底层时序；DallasTemperature 库在其上封装「发起温度转换」「读温度」等高层 API，两行代码即可拿到 float 温度。

例子：ds18b20.requestTemperatures(); 发起转换，float t = ds18b20.getTempCByIndex(0); 读第 0 号传感器温度。

5. CRC 校验和：检查数据有没有传错

生活类比：快递单上的「重量校验」——寄件时称一次重量写在单子上，收件时再称一次，对不上就说明途中被人换过。CRC 就是数据末尾的一段校验码，接收方重算一遍对不上就丢弃。

一句话定义：DHT11 的 40 位最后 8 位是前面 4 字节的算术和；DS18B20 用 CRC-8 校验暂存器。库内部会自动检查，对不上返回 NaN 或 -127。

例子：DHT11 若接线不良，dht.readHumidity() 返回 NaN，代码里用 isnan(h) 就能判断并打印「读取失败」。

三、原理介绍

DHT11 和 DS18B20 都是「单总线」器件：一根 DATA 线既供电通信又传数据。它们的共同点是——线平时为高电平，谁想说话就主动拉低，说完松开、靠上拉电阻回到高电平。理解这个「开漏 + 上拉」的硬件模型，才能理解时序和上拉电阻为什么缺一不可。

一次读取的链路：主机发起起始信号 → 传感器响应 → 按位回送数据 → 主机按高电平宽度（DHT11）或时隙（DS18B20）逐位解码 → 校验。

原理 1：DHT11 时序——用「高电平宽度」区分 0 和 1

DHT11 没有时钟线，全靠每一位高电平持续多久来编码：

  1. 起始信号：主机把 DATA 拉低 ≥18ms，再松开——这是「我要读了」的发令枪。
  2. 响应：DHT11 拉低 80μs、再拉高 80μs，表示「我准备好了」。
  3. 数据位：之后每位先拉低 50μs 作间隔，再拉高——高电平 26~28μs 表示 0，高电平约 70μs 表示 1。主机在拉高期间测宽度就能解出 0/1。

一次共回 40 位：湿度整数 + 湿度小数 + 温度整数 + 温度小数 + 校验和。为什么要用库而不自己写：整套时序是微秒级精确时序，ESP32 跑 FreeRTOS 时随时可能被别的任务打断，自己 bit-bang 极易读错——库内部关中断精确延时，才稳。

DHT11 一次完整通信时序表（数据手册口径）：

阶段方向电平与时长
起始信号主机 → 传感器DATA 拉低 ≥18ms，再拉高 20~40μs
响应传感器 → 主机拉低 80μs → 拉高 80μs
数据位「0」传感器 → 主机先拉低 50μs，再拉高 26~28μs
数据位「1」传感器 → 主机先拉低 50μs，再拉高约 70μs

教材判读要点：每位都以「主机/传感器拉低 50μs 间隔」开头，区别只在随后高电平的宽度——26~28μs 是 0，70μs 是 1。这就是示波器上看到的「宽窄脉冲串」波形。

原理 2：开漏线与 4.7kΩ 上拉——为什么必须有上拉电阻

单总线器件的 DATA 脚是开漏输出：内部只能把线拉低（接 GND），没有能力输出高电平。所以「空闲为高」必须靠外部 4.7kΩ 电阻把线拉到 3.3V；任一设备想发信号就拉低、松开后电阻又把线拽回高。为什么是 4.7kΩ：太大，线充放电太慢、边沿变钝采样错；太小，拉低时灌电流太大烧脚——4.7kΩ 是协议推荐的折中值。这就是 DS18B20 不接上拉会读出 -127 的原因：线一直是浮空乱电平，时序全乱。

原理 3：DS18B20 的 1-Wire——一根线挂几十颗，靠 64 位地址区分

DS18B20 也走开漏单总线，但协议是 Maxim 的 1-Wire：每颗芯片出厂烧录一个 64 位唯一 ROM 地址，所以一条总线上挂 10 颗也能各自寻址。读温度分两步：主机发「Convert T」命令，芯片把模拟量转成 12 位温度存进内部暂存器（约 750ms）；主机再发「Read Scratchpad」把 9 字节读出来。最后一字节是 CRC-8 校验——传输出错时校验不过，库返回 -127 让你知道数据不可信。

记忆点：单总线=开漏+上拉，平时高电平、说话就拉低；DHT11 用高电平宽度编码（26μs=0、70μs=1）；4.7kΩ 上拉是协议硬要求；DS18B20 靠 64 位地址多芯片共线，CRC 校验防错；两个「单总线」协议不兼容，不能共线。

四、硬件接线说明

模块引脚单片机引脚说明
DHT11 VCC3V3DHT11 支持 3.3~5V，ESP32 侧统一用 3V3
DHT11 DATAGPIO4数据脚，模块通常已自带上拉；裸片加 4.7kΩ 到 VCC
DHT11 GNDGND共地
DS18B20 VCC3V3外部供电模式（非寄生电源）
DS18B20 DATAGPIO5数据线与 3V3 之间必须接 4.7kΩ 上拉电阻
DS18B20 GNDGND共地

为什么这样接：

  • 为什么用 3V3 不用 5V？ ESP32 的 GPIO 耐压是 3.3V，DATA 线上拉到 5V 会损坏引脚；统一 3V3 最安全。
  • 为什么 DS18B20 必须 4.7kΩ？ 单总线协议要求空闲电平稳定为高；阻值太大充电太慢、太小拉不动总线，4.7kΩ 是协议推荐值。
  • 为什么 DHT11 接 GPIO4、DS18B20 接 GPIO5？ 两者协议不兼容，不能共线；GPIO4/GPIO5 都是安全引脚（避开 6~11 与 GPIO0/2/12/15 这些启动引脚——上电时这些脚的电平决定启动模式，接了传感器可能被误判）。
上拉电阻 DHT11 的成品模块板上一般已经焊了 10kΩ 上拉，直接插即可；裸 DS18B20 必须自己焊 4.7kΩ 电阻在 DATA 与 VCC 之间，否则读出来是乱码或 -127℃。

五、完整代码

先在库管理器安装 DHT sensor library by Adafruit（会自动装 Adafruit Unified Sensor 依赖），以及 OneWire 与 DallasTemperature 两个库。

/* ESP32 读取 DHT11 温湿度 + DS18B20 温度（零基础注释版） */
#include <DHT.h>
#include <OneWire.h>
#include <DallasTemperature.h>

#define DHTPIN    4
#define DHTTYPE   DHT11
DHT dht(DHTPIN, DHTTYPE);          // 实例化 DHT11 对象

#define ONE_WIRE_BUS 5
OneWire oneWire(ONE_WIRE_BUS);     // 底层单总线
DallasTemperature ds18b20(&oneWire);  // 上层温度库

void setup() {
  Serial.begin(115200);
  dht.begin();                      // 初始化 DHT11
  ds18b20.begin();                 // 扫描单总线上的设备
  Serial.println("传感器初始化完成");
}

void loop() {
  // ---- DHT11：温湿度 ----
  float h = dht.readHumidity();
  float t = dht.readTemperature();
  if (isnan(h) || isnan(t)) {       // 校验失败会返回 NaN
    Serial.println("DHT11 读取失败，请检查接线");
  } else {
    Serial.print("DHT11 温度: ");
    Serial.print(t);
    Serial.print(" °C   湿度: ");
    Serial.print(h);
    Serial.println(" %");
  }

  // ---- DS18B20：温度 ----
  ds18b20.requestTemperatures();     // 发起一次温度转换
  float tempC = ds18b20.getTempCByIndex(0);  // 读第 0 号传感器
  Serial.print("DS18B20 温度: ");
  Serial.print(tempC);
  Serial.println(" °C");

  Serial.println("----------");
  delay(2000);                      // DHT11 建议 2 秒以上读一次
}

第二个实例：一条总线上挂多颗 DS18B20，自动数个数并轮询 + 超温报警（1-Wire 的优势就是多芯片共用一根线）：

/* sensor 变体：多颗 DS18B20 轮询 + 超温报警 */
#include <OneWire.h>
#include <DallasTemperature.h>

#define ONE_WIRE_BUS 5
OneWire oneWire(ONE_WIRE_BUS);
DallasTemperature ds18b20(&oneWire);
#define ALERT_PIN 2                 /* 超温报警灯 */

void setup() {
  Serial.begin(115200);
  ds18b20.begin();                  /* 扫描总线，发现芯片数量 */
  pinMode(ALERT_PIN, OUTPUT);
}

void loop() {
  ds18b20.requestTemperatures();     /* 所有芯片同时转换 */
  int n = ds18b20.getDeviceCount();  /* 总线上挂了几颗 */
  for (int i = 0; i < n; i++) {
    float t = ds18b20.getTempCByIndex(i);   /* 读第 i 颗 */
    Serial.print("传感器#"); Serial.print(i);
    Serial.print(" = "); Serial.print(t); Serial.println(" C");
    if (t > 30.0) digitalWrite(ALERT_PIN, HIGH);   /* 超温报警 */
    else          digitalWrite(ALERT_PIN, LOW);
  }
  delay(2000);
}

想换引脚？把 #define DHTPIN 4 改成别的 GPIO，DS18B20 同理改 ONE_WIRE_BUS，接线同步换即可。

六、代码逐段讲解

第 1 段：头文件与对象实例化（第 2~13 行）

在做什么： 引入三个库，分别创建 dht、oneWire、ds18b20 三个对象，把引脚号宏定义好。

为什么这么写： DallasTemperature 依赖 OneWire 做底层，构造时要把 oneWire 对象的引用传进去（&oneWire）——这是库的设计，不是随便写的。

不写会怎样： 漏 include 编译不过；引脚宏写错，接线对不上读不到数据。

第 2 段：setup() 初始化（第 15~21 行）

在做什么： 打开串口，dht.begin() 和 ds18b20.begin() 分别初始化两个传感器。

为什么这么写： DS18B20 的 begin() 会扫描总线并记录挂了几颗芯片；不调它，getTempCByIndex(0) 不知道 0 号是谁。

不写会怎样： 漏 ds18b20.begin()，读温度一直是 -127。

第 3 段：DHT11 读取与 NaN 检查（第 24~36 行）

在做什么： 读湿度和温度，用 isnan 判断是否有效，无效就打错误提示，有效就打印。

为什么这么写： DHT11 时序对时序敏感，偶尔会读错；库会返回 NaN 表示失败，不检查的话串口会打印「nan」让你一头雾水。

不写会怎样： 不判 NaN，接线不良时串口刷「nan」，你分不清是代码错还是硬件错。

第 4 段：DS18B20 读取（第 39~43 行）

在做什么： requestTemperatures() 发起转换，紧接着 getTempCByIndex(0) 读出第 0 号芯片温度。

为什么这么写： DS18B20 转换需要约 750ms（12 位分辨率），库内部在 getTempC 时会等待；如果你手动加 delay(2000)，更保险。

不写会怎样： 漏 requestTemperatures()，读到的是上次旧值；不按 index 读会取错传感器。

第 5 段：delay(2000) 的频率限制（第 46~48 行）

在做什么： 每轮读完等 2 秒再下一轮。

为什么这么写： DHT11 数据手册建议采样间隔 ≥1~2 秒，频繁读会导致它内部还没刷新、返回错误值。

不写会怎样： 去掉 delay 全速读，DHT11 大量返回 NaN。

七、现象演示说明

  • 现象 1：串口监视器（115200）每 2 秒滚动输出一次，例如：
    DHT11 温度: 26.30 °C 湿度: 55.00 %
    DS18B20 温度: 26.56 °C
  • 现象 2：用手捏住 DS18B20 金属头，温度值应在 10 秒内缓慢上升；对着 DHT11 哈一口气，湿度值应明显变大。
  • 现象 3（对比验证）：两颗传感器读数相差应在 ±1℃ 以内；若 DS18B20 一直显示 -127.00 或 85.00，说明接线/上拉有问题。

可量化的验证方法：

  • 哈气测试：对 DHT11 哈一口气，湿度应从约 50% 跳到 80% 以上，几秒后回落——验证湿度链路通。
  • 手捏测试：捏住 DS18B20 金属头 30 秒，温度应从环境 26℃ 升到 30℃ 以上。
  • 断线上拉：拔掉 DS18B20 的 4.7kΩ 电阻，温度应变成 -127——验证上拉的必要性。
