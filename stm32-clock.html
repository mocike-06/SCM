系统时钟树与 RCC 配置

系列：STM32 进阶 更新：2026-10-25

为什么 CubeMX 里时钟树配错，串口全是乱码、定时器时间全不对、甚至程序直接跑飞？答案就在本课。系统时钟是 STM32 一切外设的「心跳」：从 8MHz 晶振怎么变成 72MHz 主频、AHB/APB1/APB2 怎么分频、哪个外设挂在哪条总线——这些课本必讲、新手必懵的底层知识，本课一次讲透。

一、本课目标与前置知识

学完本课你能做到：

  • 读懂 CubeMX 的 Clock Configuration 页面：HSI/HSE、PLL、SYSCLK、AHB/APB 分频各是什么。
  • 说清 USART 波特率、定时器频率、ADC 采样率为什么都依赖系统时钟。
  • 看懂 HAL 生成的 SystemClock_Config 函数，能自己排查时钟配置导致的异常。

需要提前掌握的前置知识（对应学习路线阶段 4）：

  • 环境搭建（stm32-env.html）：CubeMX 生成工程、Keil 烧录——本课解释 CubeMX 里那个「时钟树」页面。
  • GPIO 与串口基础（stm32-gpio.html、stm32-usart.html）：体会「频率错了外设就错」的后果。
  • 51 单片机的晶振概念（阶段 2）：晶振提供时钟，STM32 只是把时钟玩得更复杂。

本课会出现的新名词：时钟源（HSI/HSE/LSI/LSE）、PLL 锁相环、SYSCLK、AHB/APB1/APB2 总线、分频/倍频、RCC、HCLK、外设时钟使能。

二、基础概念铺垫

1. 时钟是什么：整部机器的节拍器

生活类比：芯片里几百万个晶体管要「步调一致」地干活，靠的就是一个统一节拍器——时钟信号。它每秒跳多少次，芯片就每秒执行多少个动作：主频 72MHz = 节拍器每秒跳 7200 万次。

一句话定义：时钟是单片机内部所有逻辑动作的同步节拍信号，频率越高处理越快。所有外设（串口、定时器、ADC）的「时间感」都由它派生。

例子：串口波特率 9600 的意思是「每秒发 9600 位」，芯片怎么知道「1 秒」多长？靠的就是时钟节拍数出来的——时钟频率差一点，波特率就全错。

2. 时钟源：晶振不是唯一的「心跳」

生活类比：钟表可以挂墙上的大钟（外接晶振），也可以用手表内置的小机芯（内部振荡器）。STM32 的「心跳」可以来自两处：外部晶振 HSE（板上那颗 8MHz 晶振，精度高）和 内部振荡器 HSI（芯片内置 8MHz，省一颗晶振但精度一般）。另有低速的 LSE（32.768kHz 给 RTC）和 LSI（给看门狗）。

一句话定义：HSE = 外部高速晶振（通常 8MHz，主时钟首选）；HSI = 内部高速 RC 振荡器（8MHz，免晶振但温漂大）；LSE = 外部低速晶振（32.768kHz，给实时时钟）；LSI = 内部低速 RC（约 40kHz，给看门狗）。

例子：正点原子/野火最小系统板都焊了 8MHz 晶振，CubeMX 里默认选 HSE 作为主时钟来源。

3. PLL 倍频：把 8MHz 变成 72MHz

生活类比：晶振只会稳定产生一个固定频率（8MHz），但 CPU 想要跑更快——PLL 就像一个「频率放大镜」，能把 8MHz 放大 9 倍变成 72MHz。

一句话定义：PLL（锁相环）是内部电路，能把输入时钟按倍数（倍频系数）放大。F103 标准配置：HSE 8MHz × PLL 9 倍 = SYSCLK 72MHz（主频上限）。

例子：CubeMX 时钟树页面里「HSE → PLL Source Mux → PLLMul x9 → System Clock Mux」一路连下来，得到 72MHz——这就是「把 8 变 72」的那条路径。

4. 总线分频：一颗心脏，多条血管

生活类比：心脏（SYSCLK）跳 72 次/秒，但不同器官的「承受上限」不同：CPU 可以跑满 72MHz，低速外设只能承受一半。所以芯片里设了分频器，把 72MHz 分成几条不同频率的「血管」。

一句话定义：AHB 总线（最高 72MHz，CPU 和内存走它）；APB1 低速总线（F103 上限 36MHz：USART2/3、TIM2~4、I2C1/2、SPI2、RTC 等）；APB2 高速总线（上限 72MHz：GPIO、USART1、SPI1、TIM1、ADC1/2 等）。每个外设必须由它所在总线的时钟「供电」才能工作。

例子：为什么 USART1 能跑 4.5Mbps 而 USART2 最高只 2.25Mbps？因为 USART1 挂在 APB2（72MHz）、USART2 挂在 APB1（36MHz）——总线频率上限决定了外设性能。

5. RCC：时钟的总开关与电表

一句话定义：RCC（Reset and Clock Control）是负责「复位」和「时钟控制」的单元：①决定系统时钟选哪个源、倍频多少；②为每个外设提供「时钟开关」——默认大部分外设时钟是关闭的，用之前必须开（__HAL_RCC_xxx_CLK_ENABLE()）。这也是 HAL 代码里一上来就有一串 CLK_ENABLE 的原因。

例子：写 GPIO 前必见 __HAL_RCC_GPIOA_CLK_ENABLE();——没开时钟，GPIO 寄存器写不进去，LED 死活不亮。

三、原理介绍：一次完整的时钟配置流程

时钟树就是芯片的「配电系统」：一颗 8MHz 晶振是发电机，经过倍频、分频、各路开关，把合适频率送到每一个外设。

整条链路：HSE 8MHz → PLL ×9 → SYSCLK 72MHz → AHB ÷1=72 → APB1 ÷2=36、APB2 ÷1=72 → 各外设时钟门控按需打开。

原理 1：HSE→PLL→72MHz——主频是怎么来的

芯片上电默认跑内部 HSI（8MHz），这是「保底心跳」。要跑满性能必须换外部 8MHz 晶振 HSE，经 PLL 锁相环 ×9 倍频 得到 72MHz 主时钟。PLL 是个反馈倍频电路：它把输入频率自动锁定、稳定放大 9 倍。流程必须「先启 HSE 等 RDY → 配 PLL 等锁定 → 最后才把系统时钟切换到 PLL」——顺序反了，切源时 PLL 还没稳，芯片直接跑飞。

原理 2：AHB / APB1 / APB2 分频——为什么 APB1 只能 36MHz

72MHz 主时钟经 AHB 总线分发，再下挂两条外设总线：APB1 是低速总线（挂 USART2/3、TIM2~7、I2C、CAN），数据手册硬性规定 PCLK1 ≤ 36MHz；APB2 是高速总线（挂 USART1、SPI1、ADC、全部 GPIO），可到 72MHz。所以 AHB=72 分给 APB1 必须 ÷2、APB2 不除。为什么有上限：总线越高频，信号走线和外设的建立保持时间越难满足，这是物理电气极限，不是软件能突破的——CubeMX 时钟树标红就是在拦你越线。

原理 3：外设时钟门控——为什么 GPIO 要用前先开时钟

为省电，每个外设的时钟默认是关的，不喂时钟它就完全不响应寄存器读写。用 GPIOA 前必须 __HAL_RCC_GPIOA_CLK_ENABLE() 写 RCC->APB2ENR 对应位，否则你往 0x40010800 写数据毫无效果——LED 死活不亮。这就是 HAL 代码开头一串 CLK_ENABLE 的原因。为什么错了像「程序坏了」：主频一变，波特率、定时器、PWM、ADC 全部按错的频率算，表现为乱码、延时变快、声音跑调——其实只是心跳频率不对，这也是「先查时钟树」的由来。

原理 4：RCC_CFGR 分频位 ↔ HAL 宏 + 定时器时钟 ×2 易错点

上面三个分频比最终都写在一个寄存器 RCC_CFGR 里，教材要求记住位域位置：

分频级RCC_CFGR 位域本配置取值HAL 宏
AHB 预分频 HPREHPRE[7:4]÷1 → HCLK=72MHzRCC_SYSCLK_DIV1
APB1 预分频 PPRE1PPRE1[10:8]÷2 → PCLK1=36MHzRCC_HCLK_DIV2
APB2 预分频 PPRE2PPRE2[13:11]÷1 → PCLK2=72MHzRCC_HCLK_DIV1

教材高频易错点（必须记住）：当 APB1 预分频 PPRE1 的分频系数 ≠1（这里=2，PCLK1=36MHz）时，挂在 APB1 上的定时器（TIM2~TIM7）内部时钟会被硬件自动 ×2，即定时器实际计数时钟 = 36MHz×2 = 72MHz。所以即使 APB1 只有 36MHz，TIM3 的定时/PWM 计算仍按 72MHz 代入（本系列 PWM 篇公式正是 72M/(PSC+1)/(ARR+1)）；只有当 PPRE1=÷1 时定时器时钟才等于 PCLK1 本身。这条规则是新手算定时初值差一倍的元凶。

记忆点：8MHz 晶振 → PLL ×9 → SYSCLK 72MHz → AHB×1 / APB1÷2(36) / APB2×1(72)；顺序=先稳 HSE、再配 PLL、最后切源；外设默认关时钟，用时先 CLK_ENABLE；时钟错=全外设跟着错。

四、硬件接线说明

时钟配置几乎不涉及额外接线——晶振电路在最小系统板上已焊好：

元件位置说明
8MHz 晶振（HSE）板上 OSC_IN/OSC_OUT 引脚配 2 个 20pF 负载电容，HSE 时钟源
32.768kHz 晶振（LSE）板上（部分板子没有）给 RTC 实时时钟用
VBAT 电池座可选掉电后给 RTC 供电（进阶）

为什么不用额外接线：时钟配置是纯软件行为。你只需要确认板子上有 8MHz 晶振（几乎所有 F103 最小系统板都有），CubeMX 里时钟源选对 HSE 即可。如果你的板子没有外部晶振，就只能用 HSI（内部 8MHz）——那 PLL 倍频仍可到 64MHz，但精度差、USB 等对时钟要求高的外设会出问题。

避坑 CubeMX 时钟树页面右上角如果有红色错误提示（如 PLL 超出范围、APB1 超 36MHz），别硬点生成代码——先按本课原理把分频改对。这是新手最常踩的坑之一。

五、完整代码

以下代码由 CubeMX 自动生成（F103C8T6 + HSE 8MHz → 72MHz），是教材标准配置。示例 1 完整版；示例 2 演示怎么读取和验证当前时钟。

示例 1：标准 SystemClock_Config（HSE 8MHz → 72MHz）

/* 系统时钟配置：CubeMX 自动生成（F103C8T6） */
void SystemClock_Config(void)
{
  RCC_OscInitTypeDef RCC_OscInitStruct = {0};
  RCC_ClkInitTypeDef RCC_ClkInitStruct = {0};

  /* 1. 启动 HSE 外部晶振，并配置 PLL：8MHz × 9 = 72MHz */
  RCC_OscInitStruct.OscillatorType = RCC_OSCILLATORTYPE_HSE;
  RCC_OscInitStruct.HSEState = RCC_HSE_ON;           /* 打开 8MHz 晶振 */
  RCC_OscInitStruct.HSEPredivValue = RCC_HSE_PREDIV_DIV1;  /* 不分频 */
  RCC_OscInitStruct.PLL.PLLState = RCC_PLL_ON;
  RCC_OscInitStruct.PLL.PLLSource = RCC_PLLSOURCE_HSE;  /* PLL 来源 = HSE */
  RCC_OscInitStruct.PLL.PLLMUL = RCC_PLL_MUL9;         /* 倍频 ×9（结构体字段 PLLMUL、HAL 宏 RCC_PLL_MUL9） */
  if (HAL_RCC_OscConfig(&RCC_OscInitStruct) != HAL_OK)
  {
    Error_Handler();              /* 晶振/PLL 配置失败，进入错误处理 */
  }

  /* 2. 配置总线分频：SYSCLK=72MHz, AHB=72MHz, APB1=36MHz, APB2=72MHz */
  RCC_ClkInitStruct.ClockType = RCC_CLOCKTYPE_HCLK |
                                RCC_CLOCKTYPE_SYSCLK |
                                RCC_CLOCKTYPE_PCLK1 | RCC_CLOCKTYPE_PCLK2;
  RCC_ClkInitStruct.SYSCLKSource = RCC_SYSCLKSOURCE_PLLCLK; /* 主时钟切到 PLL */
  RCC_ClkInitStruct.AHBCLKDivider = RCC_SYSCLK_DIV1;        /* AHB ÷1 = 72MHz */
  RCC_ClkInitStruct.APB1CLKDivider = RCC_HCLK_DIV2;         /* APB1 ÷2 = 36MHz */
  RCC_ClkInitStruct.APB2CLKDivider = RCC_HCLK_DIV1;         /* APB2 ÷1 = 72MHz */
  if (HAL_RCC_ClockConfig(&RCC_ClkInitStruct, FLASH_LATENCY_2) != HAL_OK)
  {
    Error_Handler();              /* Flash 等待周期=2（72MHz 必需） */
  }
}

示例 2：读取当前时钟频率（验证配置是否生效）

/* 在主函数里读取当前系统时钟（单位 Hz） */
#include "main.h"

int main(void)
{
  HAL_Init();                     /* 初始化 HAL 库 */
  SystemClock_Config();           /* 配置系统时钟（上面的函数） */

  uint32_t sysclk = HAL_RCC_GetSysClockFreq();   /* 应返回 72000000 */
  uint32_t hclk   = HAL_RCC_GetHCLKFreq();       /* AHB：应 72000000 */
  uint32_t pclk1  = HAL_RCC_GetPCLK1Freq();      /* APB1：应 36000000 */
  uint32_t pclk2  = HAL_RCC_GetPCLK2Freq();      /* APB2：应 72000000 */

  /* 把四个值 printf 到串口（9600），对照数据手册核对 */
  printf("SYSCLK=%lu HCLK=%lu PCLK1=%lu PCLK2=%lu\r\n",
         sysclk, hclk, pclk1, pclk2);
  while (1);
}

六、代码逐段讲解

第一段：RCC_OscInitStruct——换「心脏」

结构体 RCC_OscInitTypeDef 是 HAL 的「配置单」：先把要配的参数填进去，再交给 HAL_RCC_OscConfig() 一次性执行。为什么填 HSEState=ON：告诉 HAL 去启动外部晶振；PLLMULL=×9：8MHz×9=72MHz。为什么不写 PLL 就 72：写 8 就是 64、写 10 就是 80——超上限，芯片不工作，所以倍频系数必须和晶振频率搭配。

第二段：RCC_ClkInitStruct——铺「血管」

SYSCLKSource 选 PLLCLK 表示「主时钟来源切到 PLL 输出」；三个 Divider 分别设置 AHB/APB1/APB2 分频。重点看 APB1CLKDivider = DIV2：为什么 APB1 必须 ÷2——F103 的 APB1 硬件上限 36MHz，72MHz 直接灌进去会超频损坏，所以必须砍一半。这就是「一颗心脏，多条血管」的落地。

第三段：FLASH_LATENCY_2 是什么

Flash 存储器的读取速度跟不上 72MHz 的 CPU——就像仓库管理员搬货速度跟不上流水线。等待周期 = 让 CPU 每取几条指令「等一下」仓库。主频 72MHz 必须 2 个等待周期，写错这个参数程序会随机跑飞，这是课本注释里「72MHz 必需」的真正含义。

第四段：四个 Get 函数的验证价值

HAL_RCC_GetSysClockFreq() 等四个函数从寄存器读回当前频率。为什么用它验证：时钟配置错了不会报编译错，只有「实际频率」才能暴露问题——串口打印这四个数，和 72/72/36/72 对不上，就说明配置或晶振有问题。这是排查「程序莫名跑飞」的第一步。

七、现象演示与验证

  • 正常现象：串口输出 SYSCLK=72000000 HCLK=72000000 PCLK1=36000000 PCLK2=72000000。
  • 对照实验：把 PLLMULL 改成 ×8（64MHz），串口频率跟着变 64M，且用 72MHz 算的延时函数全部变慢——直观看到「时钟影响一切」。

验证方法：

  1. 接好串口，打印四个频率值，与 F103 数据手册的时钟树框图逐项核对。
  2. 把 APB1 分频改成 ÷1（72MHz 超频），观察程序是否异常或复位——理解「上限」的物理意义。
  3. 拔掉外部晶振（或仿真里断开 HSE），程序应进入 Error_Handler 或跑飞——理解「换心失败」的后果。

八、常见报错排查方案

报错现象可能原因解决方法

程序上电后跑飞 / 进 Error_HandlerHSE 没起振（晶振虚焊）/ PLL 配置错示波器量晶振两端波形；检查晶振电容与焊接；改用 HSI 试跑

九、课后练习与延伸

练习 1（必做）：在 CubeMX 里把系统时钟分别配成 72MHz 与 64MHz，各烧录一次，用串口打印 HAL_RCC_GetSysClockFreq() 并对比两次延时函数的速度差异。

练习 2：不开 __HAL_RCC_GPIOA_CLK_ENABLE() 直接操作 GPIO，观察现象并解释原因（提示：寄存器写不进去）。

练习 3（进阶）：结合 USART 教程，把波特率计算公式里的 PCLK1/PCLK2 换成你实际读到的频率，验证 9600 波特率的分频值是否正确——建立「时钟 → 外设参数」的完整链路。
