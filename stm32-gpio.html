STM32 GPIO 输入输出（点灯与按键）

系列：STM32 入门 更新：2026-10-24

用一个引脚点亮 LED、用另一个引脚读按键。本讲从零开始讲透 GPIO：推挽与开漏、上拉与下拉、寄存器与 HAL 封装、3.3V 与 5V 电平的区别，再带你把 CubeMX 配置和 HAL 代码逐段读懂。GPIO 是单片机最基础也最重要的外设，后面所有实验都建立在它之上。

一、本课目标与前置知识

学完本课你能做到：

  • 说清楚推挽输出/上拉输入是什么、为什么 STM32 的引脚是 3.3V 而不是 5V。
  • 在 CubeMX 里把一个引脚配成输出、一个配成上拉输入，并生成工程。
  • 读懂并用好 HAL_GPIO_WritePin / ReadPin / TogglePin，完成「按键控制 LED」并能自己加消抖。

需要提前掌握的前置知识（对应学习路线阶段 2~4 前两篇）：

  • 51 单片机基础（阶段 2）：高/低电平、IO 口输出、按键抖动——这些概念 STM32 同样适用，只是引脚配置更灵活。
  • 环境搭建（stm32-env.html）：Keil MDK 建工程、CubeMX 生成代码、ST-Link 下载流程。
  • C 语言基础（阶段 1）：函数调用、if 判断、while 循环。

本课会出现的新名词（下面逐一讲解）：GPIO、推挽/开漏、上拉/下拉电阻、寄存器、HAL 库、HAL_GPIO_WritePin / ReadPin / TogglePin、机械抖动与软件消抖。

二、基础概念铺垫

1. GPIO 与两种工作方向

生活类比：GPIO 引脚就像大楼门口的门卫——要么负责「对外喊话」（输出），要么负责「听外面动静」（输入），由你给门卫下指令决定他今天是喊话还是听。

一句话定义：GPIO（通用输入输出口）是芯片上一个个既能输出高低电平、又能读取外部电平的引脚，每个引脚通过软件配置成「输出」或「输入」方向。

例子：本课把 PA5 配成输出去点亮 LED，把 PA0 配成输入去读按键。STM32F1 的 GPIO 分为 PA~PG 多个端口，每个端口 16 个引脚（PA0~PA15）。

2. 推挽输出与开漏输出

生活类比：推挽像「一个人又推又拉」——要灯亮时它稳稳送出高电平，要灭时它稳稳拉到地，两头都主动出力。开漏像「只负责往下拽、往上靠别人」——它只能把电平拉到 0V，想输出高电平时必须靠外部电阻拉上去。

一句话定义：推挽输出：内部两个 MOS 管交替导通，引脚能主动输出 3.3V 或 0V，驱动能力强，点灯首选；开漏输出：只能主动拉低，高电平靠外部上拉电阻提供，适合电平转换（如把 3.3V 信号接 5V 器件）和总线场景（I2C）。

例子：驱动 LED 用推挽输出，CubeMX 里选 GPIO_Output 默认即推挽；后面学 I2C 时 SCL/SDA 用开漏。

3. 上拉电阻与下拉电阻

生活类比：一根悬空的绳子，风一吹就乱摆——引脚悬空时电平随机跳变（「浮空」），就像这根绳子。上拉电阻是把绳子的另一头轻轻系在高处（默认拉到 3.3V），按下按键才把它拽到地上。

一句话定义：上拉电阻把引脚「默认电平」拉高到 VCC，下拉电阻把引脚「默认电平」拉低到 GND，让引脚在不被外部驱动时有一个确定的电平。STM32 内部就有可配置的上拉/下拉电阻，不用外接。

例子：按键一端接 PA0、另一端接 GND，CubeMX 里把 PA0 配成 Input + Pull-up（内部上拉）：平时读到的就是高电平（GPIO_PIN_SET），按下时被接地读到低电平（GPIO_PIN_RESET）。

4. 寄存器与 HAL 封装

生活类比：寄存器是芯片内部的「控制旋钮面板」，每个旋钮都有固定编号。直接拧旋钮（操作寄存器）效率最高但容易拧错；HAL 库就是厂商给的一套「带说明的遥控器」，每个按键对应一个函数。

一句话定义：寄存器是单片机内部的存储单元，地址固定，CPU 通过读写寄存器控制硬件；HAL 库（硬件抽象层）把寄存器操作封装成好记的函数和宏，让你写 HAL_GPIO_WritePin(...) 而不是去算一串寄存器地址。

例子：CubeMX 生成代码后，MX_GPIO_Init() 里那些 GPIO_InitStruct.Pin = GPIO_PIN_5 就是「遥控器按键」，背后真正干活的是一堆寄存器写操作。

5. 3.3V 与 5V 电平的区别

生活类比：5V 是「标准身高」，3.3V 是「矮个子」。给矮个子按标准身高的要求强行工作（输入 5V），他承受不了——烧毁。

一句话定义：STM32F103 的供电和 IO 电平是 3.3V：输出高电平约 3.3V，输入高电平只需超过约 2V（TTL 阈值）。51 单片机是 5V 系统。混用时不能把 5V 直接灌进 STM32 引脚。

例子：STM32 的 GPIO 输出高电平时只有 3.3V，点 LED 时用 3.3V 计算限流电阻（3.3V − LED 压降 2V ≈ 1.3V，串 220Ω 电流约 6mA，安全）。给 STM32 引脚输入 5V 信号前必须先做电平转换（分压或电平转换模块），否则可能烧芯片。

6. 三个最常用的 HAL 函数

一句话定义（+ 例子）：

  • HAL_GPIO_WritePin(端口, 引脚, 电平)：直接给引脚写电平。如 HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET) 让 PA5 输出高电平。电平用 GPIO_PIN_SET（高/1）或 GPIO_PIN_RESET（低/0）。
  • HAL_GPIO_ReadPin(端口, 引脚)：读引脚当前电平，返回 SET 或 RESET。如 HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0)。
  • HAL_GPIO_TogglePin(端口, 引脚)：把引脚电平翻转一次（亮变灭、灭变亮），适合做闪烁和按键翻转。

参数规律：端口用 GPIOA/GPIOB/.../GPIOG 宏，引脚用 GPIO_PIN_0 ~ GPIO_PIN_15 宏，必须和 CubeMX 里配置的引脚一致。

三、原理介绍：一个引脚是怎么被程序点亮的

写一行 HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET)，LED 就亮了——这背后其实发生了三件事：把「GPIOA、第 5 脚」翻译成芯片内部某个地址的某一位；让那个引脚的输出电路真正接通；再把电平送到板子上的 LED。下面三个原理小节把这条链路一层层拆到底。

整条链路：写函数 → HAL 驱动层把它翻译成寄存器地址 → 寄存器某一位置 1 → 引脚内部 MOS 管导通 → 引脚对外输出 3.3V → 电流经 LED、220Ω 电阻回 GND，灯亮。

原理 1：寄存器映射——「GPIOA」到底是哪个地址

CPU 根本不知道「GPIOA」这个名字，它只认地址。STM32 把所有外设都挂在片内几条总线上，给每个外设分了一段固定地址，这叫存储器映射：

  • GPIOA 挂在高速总线 APB2 上，基地址是固定的 0x40010800；GPIOB 是 0x40010C00，依次排下去。
  • 每个端口内部又是一排寄存器，按偏移排好队：CRL(0x00) 配 PA0~PA7、CRH(0x04) 配 PA8~PA15、IDR(0x08) 读引脚电平、ODR(0x0C) 写引脚输出、BSRR(0x10) 置位、BRR(0x14) 复位。

所以「让 PA5 输出高」翻译成硬件动作就是：往地址 0x40010800 + 0x10（BSRR）的第 5 位写 1。这也解释了为什么用引脚前必须开时钟：APB2 上的外设默认是断电的，要先写 RCC 的 APB2ENR 寄存器把 GPIOA 的时钟门控打开，它才会响应任何地址读写。

原理 2：推挽输出内部——两个 MOS 管怎么「一推一拉」

引脚电路在输出模式下，是两个 MOS 管上下对接：上管接 3.3V、下管接 GND，中间节点就是引脚。写 SET 时上管导通、下管截止，引脚被主动接到 3.3V；写 RESET 时下管导通、上管截止，引脚被主动拉到 0V。两头都能主动驱动，所以叫「推挽」。

输入模式则相反：两个 MOS 管都断开，引脚经过一个采样缓冲接到 IDR 寄存器，CPU 读 IDR 的对应位就知道引脚上现在是高还是低。内部还有可选的上拉（约 40kΩ 接 3.3V）/下拉（接 GND）电阻，让悬空引脚也有确定电平——这就是 PA0 配 Pull-up 后不按键读得到高电平的原因。

原理 3：为什么 HAL_GPIO_TogglePin 背后用的是 BSRR 而不是 ODR

如果直接改 ODR，得「读出 ODR 原值 → 与/或运算改一位 → 写回」，这是读-改-写。万一改到一半进了中断、中断也改了 ODR，两次写互相覆盖就出错（竞态）。BSRR 是只写置位寄存器：往它低 16 位某 bit 写 1，对应 ODR 位立刻原子地变 1，绝不影响其他位；要拉低就写 BRR。所以 HAL 点灯一律走 BSRR/BRR，既快又线程安全。

记忆点：GPIOA 基地址 0x40010800（APB2），CRL/CRH 配模式、IDR 读、ODR 写、BSRR 置位/BRR 拉低；用前先开 RCC->APB2ENR 时钟；推挽=上下两管主动推拉、开漏=只能拉低靠上拉拉高；置位用 BSRR 原子写，别读改写 ODR。

原理 4：CRL/CRH 位定义 ↔ HAL 函数对照（教材必背表）

STM32F1 每个引脚的模式由 CRL（配 Pin0~7）/ CRH（配 Pin8~15） 里 4 位一组决定：高 2 位 CNF[1:0]（配置）、低 2 位 MODE[1:0]（速度/方向）。这正是野火教材「GPIO 端口配置寄存器」章节的核心：

模式CNF[1:0]MODE[1:0]对应 CubeMX / HAL 配置
浮空输入0100GPIO_Input，No pull-up/pull-down
上拉输入10（输入时配合 IDR 读）00GPIO_Input + Pull-up（本讲 PA0）
下拉输入1000GPIO_Input + Pull-down
模拟输入0000ADC 采集时用（stm32-adc 篇）
推挽输出0001/10（10MHz/2MHz）GPIO_Output Push-pull（本讲 PA5）
开漏输出0101/10GPIO_Output Open-drain（I2C 用）
复用功能推挽/开漏10 / 1101/10USART_TX、SPI_SCK 等片上外设接管引脚

你在 CubeMX 里点的每一下，最终都被 HAL_GPIO_Init() 翻译成上面这 4 位写进 CRL/CRH——所以教材说「先理解 CNF/MODE 四位，再看 HAL 就是查表填位」。

时钟使能也要记一条对照：用 GPIOA 前必须开 APB2 时钟，HAL 里这句宏 __HAL_RCC_GPIOA_CLK_ENABLE() 等价于直接写寄存器 RCC->APB2ENR |= (1<<2)（IOPAEN 位）。GPIOA~GPIOG、USART1、TIM1、ADC1、SPI1、EXTI 都挂在 APB2；而 USART2/3、TIM2~4、I2C、CAN、RTC、PWR 挂在 APB1（36MHz）——开错总线时钟，外设照样不响应。

四、硬件接线说明

模块引脚单片机引脚说明
LED 阳极（长脚）PA5（经 220Ω 电阻）推挽输出高电平点亮；电阻不可省，否则烧灯
LED 阴极（短脚）GND共地
按键一脚PA0CubeMX 配 GPIO_Input + Pull-up（内部上拉）
按键另一脚GND按下时 PA0 接地，读到低电平
供电3.3V / GND板子与 LED、按键共地

为什么这样接：

  • 为什么 LED 要串 220Ω 电阻？ STM32 输出高电平是 3.3V，LED 压降约 2V，电阻两端约 1.3V；串 220Ω 时电流约 6mA，在安全范围内且足够亮。不串电阻电流可超 20mA，长期会损坏 LED 甚至引脚。
  • 为什么必须共地？ 电流要形成回路。LED 回路和按键回路都必须回到 STM32 的 GND，板子、外设、电源三者不共地，信号和电流都「无处可去」。
  • 为什么按键不接外部电阻也能用？ 因为开了 STM32 内部上拉，省掉一颗外部 10kΩ 电阻。若引脚配成浮空输入（无上下拉），悬空时电平随机，按键读数会乱跳。
CubeMX 配置要点 PA5 设为 GPIO_Output，默认输出 Low；PA0 设为 GPIO_Input，Pull-up 选 Pull-up。其余保持默认即可。

五、完整代码

下面代码在 while(1) 里轮询按键：检测到 PA0 为低（按下）后延时 20ms 消抖，确认仍为低就翻转 LED，并等按键松开后再退出，防止一次按下连续触发。

/* main.c 用户代码区：按键控制 LED 翻转（零基础注释版） */
int main(void)
{
  HAL_Init();               /* 1. 初始化 HAL 库本身 */
  SystemClock_Config();     /* 2. 配置系统时钟（CubeMX 自动生成） */
  MX_GPIO_Init();           /* 3. 初始化 GPIO（PA5 输出 / PA0 上拉输入） */

  while (1)
  {
    /* --- 第 1 步：读按键。上拉输入：未按下为高，按下读到 RESET(0) --- */
    if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET)
    {
      /* --- 第 2 步：软件消抖。延时 20ms 跳过机械抖动期 --- */
      HAL_Delay(20);
      /* --- 第 3 步：再读一次，确认电平确实稳定（真按下而非抖动） --- */
      if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET)
      {
        /* --- 第 4 步：翻转 LED：亮变灭、灭变亮 --- */
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
        /* --- 第 5 步：等按键松开，避免一次按下触发多次 --- */
        while (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET);
      }
    }
  }
}

如果只是想让 LED 自动闪烁，把 while 体换成下面两行即可：

HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);  /* 翻转一次 */
HAL_Delay(300);                          /* 每 300ms 翻转一次，约 1.6Hz 闪烁 */

六、代码逐段讲解

第 1 段：初始化三连（第 2~4 行）

在做什么： HAL_Init() 初始化 HAL 库底层的时钟与中断分组；SystemClock_Config() 把芯片主频配到 72MHz（CubeMX 按你在图形界面选的时钟树自动生成）；MX_GPIO_Init() 把你点的「PA5 输出、PA0 上拉输入」真正写进寄存器。

为什么这么写： 这三句是 STM32 HAL 工程的固定开场白——不先配时钟，芯片跑在默认低速状态甚至不工作；不先初始化 GPIO，引脚还是上电默认的浮空输入，写电平无效。

不写会怎样： 漏掉 MX_GPIO_Init()，PA5/PA0 保持默认浮空状态，LED 怎么都不亮、按键读了也乱跳——这是最常见的「代码没问题但没现象」的原因之一。

第 2 段：读按键并消抖（第 10~18 行）

在做什么： 先用 HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET 判断按键是否按下（上拉输入下，按下接地读到低）。检测到按下后延时 20ms，再读一次确认。

为什么这么写： 机械按键按下瞬间会有几毫秒的抖动（通断多次），第一次读到低可能是抖动而不是真按下。延时 20ms 等抖动过去后重读：仍是低=真按下；变高了=刚才只是抖动，忽略。

不写会怎样： 不消抖的话，按一次键 LED 可能跳两三次甚至五六次，现象「很不听话」。

第 3 段：翻转 LED 并等松开（第 19~24 行）

在做什么： HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5) 把 LED 电平翻转；随后 while(...RESET) 空循环一直等到按键松开（电平变高）。

为什么这么写： Toggle 一次对应「按一下变一次」；等待松开的目的是让本次按下只产生一次翻转——如果松手前循环又读到一次低，就会在同一段时间里翻转两次。

不写会怎样： 不等待松开，按住不放时 while(1) 会反复翻转 LED，灯会快速乱闪。

第 4 段：闪烁变体（第二个代码块）

在做什么： 去掉按键逻辑，只用 Toggle + 延时实现自动闪烁。

为什么这么写： 这是验证 GPIO 输出最简单的程序：若闪烁正常，说明时钟、GPIO 输出、下载链路全部通畅，再叠加输入逻辑排错更省事。

不写会怎样： 直接上按键程序，一旦没现象，你无法区分是输出问题、输入问题还是下载问题——先让 LED 闪起来是最佳排错顺序。

七、现象演示说明

保姆级操作顺序（照着做）：

  1. CubeMX 芯片图上点 PA5 → 选 GPIO_Output，右键它 → GPIO settings 把 GPIO output level 默认设 Low；点 PA0 → 选 GPIO_Input，下拉菜单里 GPIO Pull-up/Pull-down 选 Pull-up。
  2. 切到 Clock Configuration 把 HCLK 填 72 回车；Project Manager 选 MDK-ARM V5，点 GENERATE CODE，弹窗显示生成完成即成功。
  3. Keil 打开工程 → 在 main.c 的 USER CODE BEGIN WHILE 区贴入本讲代码 → 按 F7 编译，左下角应看到 0 Error(s), 0 Warning(s)。
  4. 魔术棒 → Debug 选 ST-Link、Port 改 SW、勾 Reset and Run → 按 F8 下载，提示 Application Done。
  5. 接好 LED(PA5+220Ω) 与按键(PA0↔GND)，按一下按键，PA5 的 LED 应翻转一次。
  • 上电初始：PA5 默认低电平，外接 LED 熄灭。
  • 按一次按键：LED 状态翻转（灭变亮，再按变灭），每按一次只变一次，不会连续跳。
  • 验证消抖：快速「咔哒」按一下，LED 也只翻转一次；如果没加消抖，按一下通常会跳两三次。

可量化的验证方法：

  • 数次数：用手按 10 次按键，LED 应正好翻转 10 次（亮灭交替 10 次）。每按一下数一下，若某次按出两次翻转，说明消抖延时不够，把 20ms 改大到 50ms 再试。
  • 换闪烁代码验证输出：临时把主循环换成 Toggle+HAL_Delay(300)，用手机秒表数 10 次闪烁应为约 6 秒（每次翻转间隔 300ms，亮+灭各 300ms 为一个周期 600ms，10 次翻转≈6s），确认输出通路正常。
  • 万用表量电平：LED 亮时 PA5 对 GND 电压约 3.3V，灭时接近 0V；按住按键时 PA0 对 GND 约 0V，松开约 3.3V——用电压表可直观验证两个引脚工作状态。

八、常见报错排查方案

报错现象可能原因解决方法
LED 怎么都不亮引脚配成了输入；或 LED 是共阳接法（高电平灭）极性反了；或漏了 MX_GPIO_Init()CubeMX 确认 PA5 为 GPIO_Output；试着用 WritePin 输出 RESET 看是否点亮，判断是高电平亮还是低电平亮；确认生成代码里 main 调用了 MX_GPIO_Init()
按键按了完全没反应PA0 配成了浮空输入（无上拉），电平不确定；或按键另一端没接 GNDCubeMX 把 PA0 改成 GPIO_Input + Pull-up；按键另一端确认接 GND
按一次 LED 跳两三次没有做软件消抖，机械抖动被当成多次按下检测到低电平后 HAL_Delay(20~50) 再读一次确认
TogglePin 没反应 / 编译报未定义端口或引脚宏写错（如写成 GPIOB、PIN_13）对照 CubeMX 里实际引脚：端口 GPIOA，引脚 GPIO_PIN_5；宏名大小写必须一致
下载失败：No target connected / 找不到 ST-Link驱动没装、下载器接线错（SWDIO/SWCLK/GND 接反）、板子没供电重装 ST-Link 驱动；核对 SWDIO→PA13、SWCLK→PA14、GND→GND；确认板子 3.3V 供电正常
把引脚配成开漏输出后，永远输出不了高电平（教材常见坑）开漏只能主动拉低，高电平必须靠外部上拉电阻（或内部上拉）提供；忘了加上拉，输出高时引脚悬空开漏模式外接上拉电阻（典型 4.7kΩ~10kΩ 到 3.3V），或在 CubeMX 给开漏脚同时开 Pull-up。普通点灯别用开漏，用推挽（Push-pull）才能主动出 3.3V

九、课后练习与延伸

练习 1（改引脚）： 把 LED 改到 PB0、按键改到 PB1，完成同样的「按键翻转 LED」功能。提示：CubeMX 里重新选引脚并重新生成代码，main.c 里把 GPIOA 改成 GPIOB、GPIO_PIN_5 改成 GPIO_PIN_0 / GPIO_PIN_1，接线同步更换。

练习 2（改功能）： 改成「按下点亮、松开熄灭」而不是翻转。提示：把 TogglePin 换成 WritePin，按条件写 SET（亮）或 RESET（灭），注意消抖和等松开的逻辑要保留。

练习 3（扩展功能）： 两个按键控制两颗 LED 独立翻转（PA0 控制 PA5、PA1 控制 PB0）。提示：两路逻辑可以复制同样的结构，注意端口引脚宏都要改对。
