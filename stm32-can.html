CAN 总线通信（双机收发）

系列：STM32 进阶 更新：2026-10-25

汽车里上百个 ECU（发动机、ABS、车窗…）怎么互相通信？靠 CAN 总线——一条双绞线挂几十个节点，抗干扰、远距离、自带仲裁。教材「现场总线」章节与车载电子毕设的核心。本课讲透 CAN 的物理层（差分信号、终端电阻）、报文结构、ID 仲裁，用两块 STM32 通过 HAL_CAN 实现双机收发。

一、本课目标与前置知识

学完本课你能做到：

  • 说清 CAN 为什么用两根线差分传输、为什么两端要 120Ω 终端电阻。
  • 理解 CAN 报文（帧）结构：ID、数据、DLC，以及 ID 仲裁机制。
  • 用 CubeMX + HAL_CAN 配置收发，两块板子互通数据。

需要提前掌握的前置知识（对应学习路线阶段 4）：

  • 串口（stm32-usart.html）：点对点通信 vs 总线通信的对比基础。
  • 时钟（stm32-clock.html）：CAN 挂在 APB1（36MHz），波特率由分频决定。
  • 中断与回调（stm32-exti.html）：CAN 接收中断与回调模式。

本课会出现的新名词：CAN 总线、CANH/CANL 差分、终端电阻 120Ω、报文/帧、ID（标识符）、数据帧、仲裁、波特率、bxCAN、过滤器、收发邮箱、HAL_CAN。

二、基础概念铺垫

1. CAN 是什么：一条「会议室总线」

生活类比：CAN 像会议室：谁发言都通过同一条扩音线（总线）传给所有人，但每次只能一个人发言（同一时刻一个帧）；大家按「优先级」抢麦（仲裁），最紧急的先说。所有人听到全部内容（广播），按需取用。

一句话定义：CAN（控制器局域网）是多主机的差分串行总线：多个节点共享两根线（CANH/CANL），以报文为单位广播，按 ID 仲裁决定谁先发，最高速率 1Mbps（高速 CAN）、最远约 1km（低速）。

例子：车窗节点发出「车窗状态」报文，全车节点都能收，只有仪表盘节点关心并显示。

2. 差分信号：为什么抗干扰强

一句话定义：CAN 用 CANH/CANL 两根线传差分信号：显性位 = CANH 高 + CANL 低（2.5V 上下各摆 1V 左右），隐性位 = 两线同电平。接收端看两线之差而不是单线对地——外界的共模干扰同时加在两根线上，差值不变，所以抗干扰极强（汽车点火、电机旁也能用）。

例子：串口 TTL 是单线对地，地线抖动就错码；CAN 的差分管脚（CANH/CANL）对地噪声免疫。

3. 报文与 ID：广播式的「带编号的信件」

一句话定义：CAN 传输单元是报文（帧）：包含 ID（11 位标准帧 / 29 位扩展帧）、DLC（数据长度 0~8 字节）、数据体、CRC、ACK 等字段。ID 越小优先级越高（仲裁时显性位优先）。任何节点都能发、都能收——用过滤器只接收关心的 ID。

例子：报文「ID=0x123，DLC=8，数据=温度值」——一个帧就能传 8 字节，够仪表盘用了。

4. 终端电阻：消除反射的「消声器」

一句话定义：CAN 总线两端必须各接一个 120Ω 终端电阻：匹配传输线阻抗，吸收信号到达末端时的反射——没有它，高速信号在末端反弹产生振铃，通信直接错乱。只有两端接，中间的节点不接。

例子：两块板子互连 = 总线两端，每块板 CANH-CANL 间接 120Ω（有的开发板已焊，跳线确认）。

三、原理介绍：STM32 bxCAN 的收发流程

CAN 是汽车/工业总线：两根差分线挂一堆节点、没有主机、谁紧急谁先发。它的底层全靠「位时序」和「ID 仲裁」两个机制。

整条链路：填报文(ID+DLC+数据)→AddTxMessage 进发送邮箱→总线仲裁→发出；对端采样点收到→进 FIFO0 接收中断→GetRxMessage 取出。

原理 1：位时序 SYNC+BS1+BS2——为什么一个位要拆三段

CAN 没有时钟线，接收方只能靠位边沿自己对齐。一个位时间被切成若干时间片 tq：开头 SYNC_SEG(1tq) 用来对齐边沿，BS1、BS2 是两个相位段，采样点设在 BS1 与 BS2 之间。为什么要拆：总线有传播延迟，把采样点放在一位的 75~80% 处，就能容忍这点延迟、采到稳定电平。波特率 = APB1(36M) / (Prescaler × (1+BS1+BS2))，例 Prescaler=4、BS1=9、BS2=6 → 36M/(4×16)=562.5kbps。两端这套参数必须完全一致，否则采样错位、全是错误帧、最终 Bus-Off。

原理 2：差分线与 120Ω——为什么抗干扰

CAN 用 CANH/CANL 两根线差分传信号：显性位时两线压差约 2V、隐性位压差≈0。干扰是同时耦合到两根线上的「共模噪声」，接收端只看两线之差，共模噪声被抵消——这就是 CAN 抗干扰强、能跑几十米的原因。总线两端各并一个 120Ω 终端电阻做阻抗匹配，中间节点不用加。

原理 3：ID 仲裁与收发流程——为什么漏 Start 就没反应

多个节点同时发时，按 报文 ID 仲裁：ID 越小优先级越高（发 0 的节点能压住发 1 的），谁也不破坏对方数据。HAL 流程是：先 HAL_CAN_Start 让外设进入正常态，再 HAL_CAN_AddTxMessage 填发送邮箱发数据；接收要先开 FIFO0 中断，帧到了进 HAL_CAN_RxFifo0MsgPendingCallback 再 HAL_CAN_GetRxMessage 取。头号坑：漏调 HAL_CAN_Start，状态停在初始化态、收发全无——这是 CAN 调不通最常见原因。

记忆点：CAN=差分双线+广播+ID 小优先；位时序=SYNC+BS1+BS2，采样点放 75~80%，波特率=36M/(Prescaler×(1+BS1+BS2))，两端必须一致；120Ω 只在总线两端；流程=先 Start 再 AddTx/GetRx，漏 Start 收发全无。

原理 4：bxCAN 寄存器 ↔ HAL 对照（教材查表）

关键时钟前提：bxCAN 挂在 APB1(36MHz)，所以上面位时序公式分母用的是 36MHz 而不是 72MHz——别拿 72MHz 去配 Prescaler，否则实际波特率正好差一倍，两端对不上、全是错误帧。

四、硬件接线说明

两块 F103 板互连（或一块 + USB-CAN 分析仪）：

节点 A节点 B说明
CAN_TX (PA12)CAN_RX (PA11)交叉连接：发端接收端
CAN_RX (PA11)CAN_TX (PA12)交叉连接
GNDGND共地（差分也要共地）
CANH-CANL 间 120ΩCANH-CANL 间 120Ω总线两端各一只（若板载已有可跳过）

为什么 TX/RX 要交叉：和串口一样，发送端必须接到对方的接收端。为什么共地仍必要：CAN 差分能免疫共模干扰，但收发器内部仍需参考地——不共地会烧收发器或通信不稳。

避坑 F103 的 CAN 引脚不是随便复用的：标准是 PA11/PA12，也可复用 PB8/PB9（重映射）。CubeMX 里别把「复用」选成「普通推挽输出」——CAN 收发器需要开漏+复用，配错则总线一直显性（错误帧风暴）。另外注意部分最小系统板没有板载 CAN 收发器（TJA1050），需要外接收发模块才能连总线。

五、完整代码

CubeMX 配置：CAN 引脚 PA11/PA12、Prescaler=4、BS1=9、BS2=6、Mode Normal、使能 FIFO0 中断、勾选 Activate the reception interrupt。示例 1 发送；示例 2 中断接收。

示例 1：CAN 发送（板 A：每秒发一帧）

/* CAN 发送：ID=0x123，每 1 秒发一帧 8 字节递增数据 */
#include "main.h"
#include <stdio.h>

extern CAN_HandleTypeDef hcan;
extern UART_HandleTypeDef huart1;

/* printf 重定向到串口 1（标准写法，需包含 stdio.h） */
int fputc(int ch, FILE *f)
{
    HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, 100);
    return ch;
}

void can_send_test(void)
{
    CAN_TxHeaderTypeDef tx;
    uint8_t data[8];
    uint32_t mailbox = 0;
    uint8_t i;

    tx.ExtId = 0;
    tx.IDE = CAN_ID_STD;          /* 标准帧：11 位 ID */
    tx.RTR = CAN_RTR_DATA;        /* 数据帧 */
    tx.DLC = 8;                   /* 8 字节 */
    tx.StdId = 0x123;

    for (i = 0; i < 8; i++) data[i] = i;   /* 数据：0,1,2,...7 */

    if (HAL_CAN_AddTxMessage(&hcan, &tx, data, &mailbox) != HAL_OK) {
        printf("CAN send fail\r\n");
    } else {
        printf("CAN send OK, mailbox=%lu\r\n", mailbox);
    }
}

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_CAN_Init();            /* CubeMX 生成：Normal 模式 */
    MX_USART1_UART_Init();

    HAL_CAN_Start(&hcan);     /* 关键：启动 CAN 外设 */

    while (1) {
        can_send_test();
        HAL_Delay(1000);
    }
}

示例 2：CAN 中断接收（板 B：收到即打印）

/* CAN 接收：FIFO0 中断，回调里取帧并串口打印 */
#include "main.h"
#include <stdio.h>

extern CAN_HandleTypeDef hcan;
extern UART_HandleTypeDef huart1;

/* printf 重定向到串口 1 */
int fputc(int ch, FILE *f)
{
    HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, 100);
    return ch;
}

/* 接收回调：帧到达 FIFO0 时自动进入（函数名固定） */
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan)
{
    CAN_RxHeaderTypeDef rx;
    uint8_t data[8];
    uint8_t i;

    if (HAL_CAN_GetRxMessage(hcan, CAN_RX_FIFO0, &rx, data) == HAL_OK) {
        printf("ID=0x%03lX DLC=%u data=", rx.StdId, rx.DLC);
        for (i = 0; i < rx.DLC; i++) printf("%02X ", data[i]);
        printf("\r\n");
    }
}

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_CAN_Init();
    MX_USART1_UART_Init();

    HAL_CAN_Start(&hcan);

    /* 使能 FIFO0 接收中断通知（配合 CubeMX 的中断勾选） */
    HAL_CAN_ActivateNotification(&hcan, CAN_IT_RX_FIFO0_MSG_PENDING);

    while (1) {
        HAL_Delay(1000);
        /* 主循环空闲：接收全靠中断 */
    }
}

六、代码逐段讲解

第一段：TxHeader 的四个关键字段

IDE = CAN_ID_STD 选标准帧（11 位 ID）；RTR = CAN_RTR_DATA 表示数据帧（另一类是远程请求帧 RTR）；DLC = 8 数据长度；StdId = 0x123 帧 ID。为什么 ID 重要：接收端过滤器按它筛选、仲裁按它定优先级（0x123 比 0x456 优先）。扩展帧（29 位）：IDE 换 CAN_ID_EXT、填 ExtId——汽车 OBD 诊断常用扩展帧。

第二段：AddTxMessage 的邮箱机制

HAL_CAN_AddTxMessage(&hcan, &tx, data, &mailbox)：把帧放进三个发送邮箱之一（硬件有 3 个邮箱排队）。返回 HAL_OK 说明入队成功，不等于已发出——发出由硬件仲裁完成。邮箱满（3 个都忙）：函数返回 BUSY，重试或等中断回调。mailbox 输出参数告诉你用了几号邮箱。

第三段：接收回调 + GetRxMessage

HAL_CAN_RxFifo0MsgPendingCallback 是固定回调名，帧进 FIFO0 时 HAL 调用它；在回调里 HAL_CAN_GetRxMessage 把帧取到 rx 与 data。为什么必须及时取：FIFO 深度有限（3 帧），不及时取会溢出丢帧——回调里做轻量处理（取帧+标记），重活放主循环。

第四段：ActivateNotification 与 CubeMX 的关系

HAL_CAN_ActivateNotification(&hcan, CAN_IT_RX_FIFO0_MSG_PENDING) 使能中断通知；CubeMX 里同时要勾选「Activate the reception interrupt」。两步缺一不可：CubeMX 生成 NVIC 使能，HAL 调用挂回调——漏了任一步，帧到了也没人通知。

七、现象演示与验证

  • 发送：板 A 串口每秒打印 CAN send OK, mailbox=0。
  • 接收：板 B 串口打印 ID=0x123 DLC=8 data=00 01 02 03 04 05 06 07。
  • 对端无响应：只开板 A，AddTxMessage 一直返回 OK（CAN 单发成功不要求对方在线），但对方没打印——理解 CAN「发了不代表对方收到」。

验证方法：

  1. 拔掉一根 CAN 线：板 A 仍打印 send OK（硬件能发出）；但示波器/分析仪上看总线报错——理解总线状态。
  2. 把板 B 波特率改成 250k（Prescaler=9），两板通信中断、出现错误帧——亲眼验证「波特率必须一致」。
  3. 用 USB-CAN 分析仪（如 PCAN）抓包，确认帧 ID/数据与代码一致。

八、常见报错排查方案

报错现象可能原因解决方法
收发完全无反应漏了 HAL_CAN_Start启动 CAN 外设再收发
通信错乱/错误帧两端波特率不一致核对 Prescaler/BS1/BS2 两板一致
总线上大量错误帧没终端电阻 / 引脚复用错两端加 120Ω；核对 PA11/PA12 复用配置
接收回调不触发ActivateNotification 漏调 / NVIC 没开补 ActivateNotification；CubeMX 勾接收中断
Bus-Off（外设锁死）总线严重故障累积 256 次错误检查接线/波特率/终端电阻；HAL_CAN_ResetError
只收不到自己发的过滤器被配成只收特定 ID默认过滤器设为全接收（掩码 0）先跑通
加上接收功能后发送变慢回调里做串口阻塞打印回调只存帧，打印放主循环
开发板无收发器F103 引脚不是 CAN 电平，需外接 TJA1050加 CAN 收发器模块再连总线

九、课后练习与延伸

练习 1（必做）：把发送数据改成「温湿度模拟值」（两字节温度 + 两字节湿度打包），接收端解析并串口打印——学会多字节打包。

练习 2：配过滤器：板 B 只接收 ID=0x123，发 0x456 的帧应被丢弃——理解掩码筛选。

练习 3（进阶）：三节点组网（两发一收），用不同 ID 区分数据源，收端按 ID 显示「来自谁」——体会多主机广播。

延伸学习：CAN 会收发后，下一课学 内部 Flash 读写——给 CAN 收到的参数找个「掉电不丢」的存储地。
