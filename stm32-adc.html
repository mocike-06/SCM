ADC 模拟采集（多通道电压测量）

系列：STM32 进阶 更新：2026-10-24

单片机只会读 0 和 1，但真实世界是模拟的。ADC 把引脚上的连续电压变成数字，STM32 才能「感知」电位器、传感器、电池电量。本讲从零讲透采样、量化、分辨率、12 位为什么对应 4095、参考电压与换算公式，再用扫描+连续+DMA 三件套把两路电压自动采进内存数组。

一、本课目标与前置知识

学完本课你能做到：

  • 说清楚 ADC 把电压变成数字的三个步骤（采样、保持、量化），理解 12 位分辨率意味着什么。
  • 会用公式「电压 = 采样值 × 3.3 / 4095」把读到的 0~4095 换算成真实电压。
  • 用 ADC1 扫描 + DMA 循环，自动采集两路电压并通过串口打印出来。

需要提前掌握的前置知识：

  • 串口（stm32-usart.html）：本讲复用上一篇的 printf 打印电压。
  • GPIO 复用：ADC 引脚要配成模拟输入（Analog）而不是普通 GPIO。
  • 基础数学：乘法、除法、小数（float）。

本课新名词：ADC、采样/量化、分辨率、12 位、4095、参考电压 Vref、换算公式、通道、扫描模式、连续转换、DMA。

二、基础概念铺垫

1. ADC 是什么：把「连续电压」变成「数字」

生活类比：单片机只会数整数，像一个只会数「格」的量尺。ADC 就是这把量尺——把引脚上连续变化的电压（如 1.234V），对齐到最近的刻度，报回一个整数格数。

一句话定义：ADC（模数转换器）把引脚上连续变化的模拟电压，按固定档位量化成一个整数数字。STM32F103 的 ADC 是 12 位的，能把 0~3.3V 分成 4096 个等级。

例子：输入 0V 读到 0，输入 3.3V 读到 4095，输入约 1.65V 读到约 2048。

2. 采样、量化、分辨率：量尺的三个动作

生活类比：采样像「拍快照」——每隔一小段时间给电压拍一张；量化像「把快照对齐到最近的刻度线」；分辨率就是这把尺的最小刻度有多细。刻度越细（位数越多），量得越准。

一句话定义：采样是定时读取某一瞬间的电压；量化是把这个电压就近归入某个整数档位；分辨率由位数决定：12 位 = 2¹² = 4096 档（0~4095）。

例子：12 位 ADC 每一档代表 3.3V÷4095 ≈ 0.8mV，即分辨率约 0.8mV——这也是为什么后面电压表每一步约 0.8mV。

3. 参考电压：量尺的「满量程」基准

生活类比：量尺要有总长度才能读数。参考电压 Vref 就是这把尺的「满刻度」——本尺从 0V 量到 3.3V，超过 3.3V 就「量不下了」（饱和在 4095）。

一句话定义：参考电压是 ADC 量化的上限基准，STM32F103 用 VDDA = 3.3V 作参考。输入电压范围必须在 0~3.3V 之间，超过会读到顶格 4095 且可能伤引脚。

例子：想测 5V 电池不能直接接，必须先用电阻分压把它降到 3.3V 以内——这是最后一个电压表项目的核心。

4. 电压换算公式：从整数变回真实电压

生活类比：ADC 报回的是「格数」，你要按「每格多少伏」乘回去才是真实电压。每格 = 3.3V÷4095，所以真实电压 = 格数 × 每格电压。

一句话定义：换算公式 电压 = ADC 采样值 × 3.3V / 4095。例如读回 2048，电压 ≈ 2048×3.3/4095 ≈ 1.65V。注意是除以 4095（最大值），不是 4096。

例子：本讲代码里 v0 = adc_buf[0] * 3.3f / 4095.0f; 就是这行换算。

5. DMA：ADC 忙时自动把结果搬进内存，不劳 CPU

生活类比：没有 DMA 时，ADC 每转完一次，CPU 都要亲自跑一趟去「取快递」（读结果寄存器），很耽误事。DMA 像一个专职快递员——ADC 一有结果，DMA 自动搬进指定数组，CPU 完全不管，需要时直接看数组。

一句话定义：DMA（直接存储器访问）是一个能不经过 CPU、在外设和内存之间直接搬运数据的硬件。本讲用它把 ADC 结果自动循环写进 adc_buf[2]，CPU 只管读数组。

例子：调一次 HAL_ADC_Start_DMA(&hadc1, (uint32_t*)adc_buf, 2)，之后 ADC 自动反复采 IN0、IN1 填进数组，主循环直接读即可。

三、原理介绍

ADC 是把「连续的模拟电压」变成「离散数字」的桥梁。它内部不是一根万用表，而是一套采样-比较-量化的硬件流水线。

整条链路：引脚上的模拟电压 → 采样保持电容 → 逐次逼近 SAR 比较出 12 位数字 → 结果寄存器 → DMA 自动搬进内存数组，CPU 只在要显示时读数组。

原理 1：12 位逐次逼近——0~3.3V 怎么变成 0~4095

F103 的 ADC 是 12 位逐次逼近型（SAR）：12 位能表示 2¹²=4096 个等级，把 0~3.3V 参考电压等分成 4096 份。转换时 SAR 像二分查找一样从最高位到最低位逐位试探比较，一次出 0~4095 的整数。反算电压：

电压 = ADC 值 × 3.3V / 4095。读回 2048 ≈ 1.65V。

参考电压 VREF 是这一切的基准：F103 的 VREF+ 一般直接接 3.3V，所以满量程=3.3V。外部电压超过 3.3V 不能直接进引脚（会损坏），所以电压表要加分压电阻——这是下一篇项目的关键。

原理 2：采样保持与扫描——多路是怎么轮流采的

ADC 一次只能测一路。F103 有多通道：PA0=ADC1_IN0、PA1=ADC1_IN1。同时要测多路就得开 Scan 扫描模式，让 ADC 按通道表自动把 IN0、IN1 轮流采一遍；再开 Continuous 连续转换，采完一轮自动下一轮，不用软件每次触发。每路转换前还有一小段「采样保持」时间给内部电容充到外部电压——采样时间设太短，高阻抗源会采不准。

原理 3：DMA 自动搬运——CPU 为什么不用管读数

传统做法每转完一路 CPU 都得跑去读结果寄存器，既慢又被打断。配 DMA 循环模式后：ADC 一转换完，DMA 硬件自动把结果写进 adc_buf[0]、adc_buf[1]，指针绕回继续。CPU 全程不参与，要数据时直接读数组即可。「扫描+连续+DMA 循环」就是电压表、采集器的标准三件套。

保姆级 CubeMX 配 ADC1+DMA（照着点即可）：

  1. 左侧 Analog → ADC1，把 IN0、IN1 勾选为 Independent；Settings 里 Scan Conversion Mode = Enable、Continuous Conversion Mode = Enable、Number of Conversions = 2。
  2. 切到 DMA Settings → Add，选 ADC1，DMA 模式选 Circular（采完自动重头填 adc_buf）。
  3. PA0/PA1 自动变模拟输入，不用手配 GPIO；点 GENERATE CODE 生成工程。
  4. 编译下载后串口每 300ms 刷新两路电压；用手摸 PA0 杜邦线，读数应随之小幅跳动。
记忆点：12 位 = 4096 份，电压 = raw×3.3/4095，基准是 VREF≈3.3V、超压要分压；多路靠 Scan 扫描、连续转换自动轮转；DMA 循环自动填数组，CPU 不参与读数。

原理 4：ADC 寄存器 ↔ HAL 函数对照（RM0008 查表）

野火教材讲 ADC 时一定对照 RM0008 的三个寄存器：CR2（控制）、SQR（规则组序列）、DR（数据）。本讲动作对应如下：

你做的事对应寄存器 / 位HAL 函数 / CubeMX
开启 ADC 并唤醒校准CR2 的 ADON 位（首次写=唤醒，再写=开始转换）HAL_ADC_Start() / HAL_ADCEx_Calibration_Start()
选转换通道与顺序SQR3/SQR1 的 SQ1/SQ2…（规则组序列，第几转换采哪通道）CubeMX 里 Rank 0=IN0、Rank 1=IN1
扫描多通道CR1 的 SCAN 位=1Scan Conversion Mode = Enable
连续自动转换CR2 的 CONT 位=1Continuous Conversion Mode = Enable
读转换结果DR（16 位数据寄存器，高 12 位有效）HAL_ADC_GetValue() / DMA 自动搬
开 ADC1 时钟RCC->APB2ENR 里 ADC1EN 位__HAL_RCC_ADC1_CLK_ENABLE()

为什么 ADC 挂在 APB2 还要分频：ADC1 时钟来自 APB2(72MHz) 经 ADCPRE 分频，而 RM0008 规定 ADC 时钟最高不得超过 14MHz。CubeMX 默认给 /6 → 72/6 = 12MHz，正好安全；如果你手动把 ADCPRE 配成 /2 或 /4，ADC 会跑在 36/18MHz 超规格，结果漂移甚至失真——这是教材实验里「读数莫名其妙不准」的隐藏原因。

四、硬件接线说明

模块引脚单片机引脚说明
电位器中间滑动脚PA0（ADC1_IN0）转动时输出 0~3.3V 可调电压
电位器两端3.3V / GND给电位器供上满幅电压
第二路测试信号PA1（ADC1_IN1）可再接一个电位器或直接接 GND/3.3V 看满量程
供电 / 共地3.3V / GND待测电压不要超过 3.3V，否则伤 ADC 引脚

为什么这样接：

  • 为什么电位器两端接 3.3V 和 GND？ 电位器是一个可变分压电阻，两端供满 0~3.3V，中间滑动脚才能在整个量程内连续调压。
  • 为什么待测电压不能超 3.3V？ ADC 的参考上限是 3.3V，输入更高电压不仅读到顶格 4095，还可能损伤引脚。测高压必须先分压（最后一个项目专门讲）。
  • 为什么不用的 ADC 引脚要接地？ 悬空引脚会感应周围电磁干扰，读数乱跳——这正好是一个验证点（见第七节）。
CubeMX 配置要点 Analog → ADC1，把 IN0、IN1 都 Enable；Parameter Settings 里把 Scan Conversion Mode 设 Enable、Continuous Conversion Mode 设 Enable；在 DMA Settings 点 Add 选 ADC1，模式选 Circular（循环）。右下方 Rank 0=Channel0、Rank1=Channel1。

五、完整代码

下面代码启动 ADC + DMA，结果自动循环写入 adc_buf；主循环按公式换算两路电压并 printf（复用上一篇串口）。

/* main.c：ADC1 两路扫描 + DMA，串口打印电压（零基础注释版） */
ADC_HandleTypeDef hadc1;
DMA_HandleTypeDef hdma_adc1;

uint16_t adc_buf[2];   /* adc_buf[0]=IN0, adc_buf[1]=IN1 */

int main(void)
{
  HAL_Init();
  SystemClock_Config();
  MX_GPIO_Init();
  MX_DMA_Init();
  MX_ADC1_Init();
  MX_USART1_UART_Init();   /* 复用上一篇的串口打印 */

  /* 启动 ADC + DMA：结果自动循环写入 adc_buf */
  HAL_ADC_Start_DMA(&hadc1, (uint32_t *)adc_buf, 2);

  float v0, v1;
  while (1)
  {
    /* 直接按公式换算电压：raw * 3.3 / 4095 */
    v0 = adc_buf[0] * 3.3f / 4095.0f;
    v1 = adc_buf[1] * 3.3f / 4095.0f;

    printf("IN0=%.2f V   IN1=%.2f V\r\n", v0, v1);
    HAL_Delay(300);
  }
}

如果不想用 DMA，最简单的轮询写法（一次采一路）是：

HAL_ADC_Start(&hadc1);
HAL_ADC_PollForConversion(&hadc1, 10);      /* 等转换完成 */
uint16_t raw = HAL_ADC_GetValue(&hadc1);    /* 读结果 */
float v = raw * 3.3f / 4095.0f;              /* 换算成电压 */
HAL_ADC_Stop(&hadc1);

六、代码逐段讲解

第 1 段：启动 DMA 采集

在做什么： HAL_ADC_Start_DMA(&hadc1, (uint32_t*)adc_buf, 2) 启动 ADC，并让 DMA 把 2 个结果循环搬进 adc_buf。

为什么这么写： 扫描两路就要告诉 DMA 搬 2 个数据、目标是 adc_buf。配了 Circular 模式后采完一轮自动再来一轮，不需要程序反复触发。

不写会怎样： 不调 Start_DMA，adc_buf 里一直是 0，串口打印 0.00V——配了 DMA 却忘了启动是常见坑。

第 2 段：公式换算电压

在做什么： adc_buf[0] * 3.3f / 4095.0f 把 0~4095 的整数换算成 0~3.3V 的浮点电压。

为什么这么写： adc_buf 是 uint16_t 整数，乘 3.3f 转成浮点再除以 4095.0f，得到真实电压。除以 4095 而非 4096，因为量程是 0~4095 共 4096 档。

不写会怎样： 不换算就直接打印 adc_buf，看到的是 0~4095 的原始整数，不是电压；若误除以 4096，量程会差一点点。

第 3 段：轮询写法对比

在做什么： 不用 DMA 时，手动 Start → 等转换 → GetValue 读结果。

为什么这么写： 适合只采一路、不频繁采集的简单场景，容易看懂。但多路高频采集时 CPU 要一直等待，效率低。

不写会怎样： 没等 PollForConversion 就读值，结果可能是上一次的旧值或不确定值。

七、现象演示说明

  • 打开串口助手（115200），每 300ms 打印两路电压。
  • 转动 PA0 上的电位器旋钮，IN0 电压应在 0.00 V 到 3.30 V 之间连续变化。
  • 把电位器拧到两端极限：应分别读到接近 0.00 和 3.30（略微有误差属正常）。
  • PA1 悬空时读数会乱跳——这正说明：不用的 ADC 引脚不能悬空，要接地或接确定电压。

可量化的验证方法：

  • 万用表对比：万用表量 PA0 对 GND 的实际电压，应与串口打印的 IN0 电压几乎一致（误差在几 mV 内）。若差很多，检查分压/换算公式。
  • 拧到两端验证量程：电位器拧到最左应 ≈0.00V，拧到最右应 ≈3.30V。读到顶格 3.30 说明量程正确。
  • 悬空测干扰：把 PA1 什么都不接，观察 IN1 读数乱跳；再把 PA1 接 GND，IN1 立刻稳定在 0.00V——直观验证「悬空会乱跳」。

九、课后练习与延伸

练习 1（测电池电压）： 把一节干电池（1.5V）正极接 PA0、负极接 GND，串口应打印约 1.50V。提示：1.5V 在 3.3V 量程内，可直接测。

练习 2（加第三通道）： 再加一路 PA2(IN2) 采样，adc_buf 改成 [3]，串口多打印一路。提示：CubeMX 里把 IN2 也 Enable，DMA 长度改成 3。

练习 3（阈值报警）： 当 IN0 电压超过 2.0V 时让 PA5 LED 亮，低于 1.0V 时灭。提示：读 v0 后用 if 判断，调 HAL_GPIO_WritePin 控制 LED。
