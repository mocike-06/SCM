LED 点阵屏显示（8×8 扫描与取模）

系列：51 单片机 进阶 更新：2026-10-25

公交车的滚动字幕、点阵广告屏、毕设的汉字显示——LED 点阵是最直观的「显示扩展」。本课讲透 8×8 点阵的结构（16 个引脚、行列共用）、动态扫描原理（人眼视觉暂留），用 P0/P2 直接驱动显示图形，再用 74HC595 级联扩展多块屏——从单屏到「点阵墙」的完整路径。

一、本课目标与前置知识

学完本课你能做到：

  • 看懂 8×8 点阵模块的引脚：8 行 + 8 列，LED 在交叉点。
  • 理解动态扫描：为什么一次只亮一行、人眼却看到整屏。
  • 会用手工取模 + 程序显示图形/汉字，并用 74HC595 扩展。

需要提前掌握的前置知识（对应学习路线阶段 2）：

  • IO 口输出（mcu51-led.html）：点阵就是 16 个可控 LED 的组合。
  • 延时（mcu51-timer.html）：扫描刷新要精确延时。
  • 数组与位运算（c-array-pointer.html / c-bitwise-macro.html）：字模是字节数组。

本课会出现的新名词：点阵模块、行选/列选、共阳/共阴、动态扫描、视觉暂留、字模（取模）、74HC595 移位寄存器、级联、OE。

二、基础概念铺垫

1. 8×8 点阵：64 个 LED 共用 16 根线

生活类比：电影院座位（64 个 LED）——你不能给每个座位单独拉一条电线（要 64 根线），而是「排号选座」：先指定第几排（行选），再指定哪几个座位亮（列数据）。行列一交叉，座位就定位了。

一句话定义：8×8 点阵 = 64 个 LED 按行列矩阵排列，同行的阳极（或阴极）连一起、同列的阴极（或阳极）连一起，引出 8+8=16 根引脚。亮一个点 = 对应行和列同时有效。

例子：共阳点阵：行接 +5V（行选），列接低电平（列数据）——第 2 行第 3 列亮 = 行 2 高 + 列 3 低。

2. 动态扫描：一次只亮一行

生活类比：走马灯/翻页动画：一帧帧快速翻，人眼看到的是连贯动画。点阵也是：轮流点亮第 1 行、第 2 行、直到第 8 行，每行只亮 1~2ms，刷新够快（50Hz 以上）时视觉暂留让 64 个点「看起来同时亮着」。

一句话定义：动态扫描 = 分时点亮各行（每次只驱动一行），靠视觉暂留（人眼对消失的图像约保留 0.1s）合成完整画面。优点：一行只需 8 个数据位，64 个点只用 16 根线。

例子：每行亮 1ms，8 行一轮 = 8ms/帧 = 125 帧/秒——远超 50Hz，画面稳定无闪烁。

3. 字模：把图形变成字节数组

一句话定义：显示内容预先取模成 8 个字节（每行 1 字节，1=亮 0=灭）：第 0 字节 = 第 0 行的 8 个点。手工取模：画出 8×8 格子，逐行把点转成二进制。取模软件（字模精灵等）一键生成。字节第几位对应哪个列由硬件接法决定（行/列、共阳/共阴），取模参数必须匹配。

例子：字母「H」字模 = 第 0 行 0xFF，中间行 0x81，最后一行 0xFF。

教材取模的两种组织方式（经典坑）：横向取模（逐行）：每行 1 字节、8 行共 8 字节，适合行扫描；纵向取模（逐列）：每列 1 字节、8 列共 8 字节，适合列扫描。还要选高位在前还是低位在前（字节最高位对应最左列还是最右列）。取模软件这几个参数必须和硬件扫描方向一致，否则显示的图形会上下颠倒或左右镜像——这是点阵显示"字模花屏"的头号原因。

4. 74HC595：用 3 根线扩展 8 根线

一句话定义：74HC595 是串入并出移位寄存器：3 根线（数据 DS、时钟 SH_CP、锁存 ST_CP）串行送入 8 位数据，一次并行输出 8 位。多片级联（第一片 Q7' 接第二片 DS）可无限扩展输出口——点阵墙、数码管大屏全靠它。

例子：两片 595 = 16 个并行输出，驱动 16×16 点阵的列；51 只用 P1.0~P1.2 三根线。

三、原理介绍：64 个小灯，怎么只用 16 根线就拼出一整幅图

8×8 点阵内部是 64 个 LED 排成 8 行×8 列的交叉阵列——每个交叉点一个灯。和数码管动态扫描同源：任何时刻只亮一行，快速轮流，人眼就看成完整画面。

一帧画面的扫描流程：

  1. 字模 led_tab[8] 共 8 字节，每字节一行。
  2. 选第 0 行有效（共阳 P2.0=1 其余=0），P0=led_tab[0]（该行哪几列亮）。
  3. 保持 1ms，切到第 1 行、P0=led_tab[1]……循环 8 行。
  4. 循环刷新：8ms 一轮，人眼看到完整图案。

原理 1：点阵为什么是「行列交叉」结构——扫描怎么省下 48 根线

64 个灯如果每个独立控制要 64 根线。点阵把它们排成矩阵：同行 8 个灯的阳极接在一起(行线)、同列 8 个灯的阴极接在一起(列线)。这样一个灯亮 =「它所在行通电 + 它所在列接通」两者同时成立。动态扫描就是利用这一点省线：某一时刻只选通一行（这一行所有灯的阳极都有电），列线上送「这一行该哪几列亮」——这一行里指定的灯亮，其它行阳极没电不亮。1ms 后切下一行。8 行×8 列只要 16 根线就管住了 64 个灯——代价是每个灯只有 1/8 时间通电（占空比 12.5%），所以点阵亮度偏低、大电流驱动是常态。

原理 2：字模到底是什么——一个字节就是一行的亮灭图

8×8 一行正好 8 列 = 一个字节 8 位。字模的本质就是「把 8 行各写成一个字节」：某位=1 表示该列的灯要点（共阳接法列低电平亮，所以实际取反）。比如要显示左上角亮、右半暗，第 0 行字节就对应成 11110000。取模工具（如 PCtoLCD2002）帮你画好图、自动算出这 8 个字节，但「行序从哪行开始、位序从哪列开始、共阴还是共阳」必须和硬件接法一致——取模参数不对，图案就是歪的/反的。

原理 3：74HC595 怎么用 3 根线顶 8 根——移位寄存器

点阵大了列线就多（16×16 要 16 列），51 IO 不够。74HC595 是「串入并出移位寄存器」：它内部有 8 个触发器排成一排。你只需 3 根线——数据线(DS)一位一位往里送、时钟(SH_CP)每来一个脉冲所有位往后挤一格、新位补进最前面；送满 8 位后，锁存线(ST_CP)打个脉冲把这 8 位一次性并行输出。于是 3 根线就变出 8 根并行输出。多片级联（第一片最后一位 Q7' 接第二片 DS）= 送的位一路往后传，两片一起吐出 16 位——大屏点阵墙就是这么把 IO 需求压到最低的。

记忆点：8×8点阵=行列交叉二极管阵列，同行为阳极、同列为阴极；动态扫描=任一时刻只通一行、列送该行亮哪几列，16根线管64灯、代价是1/8占空比偏暗；字模=8字节一行一位对应一列，取模参数必须和硬件阴阳/位序一致；595移位寄存器=3线送8位串转并、Q7'级联扩更多。

四、硬件接线说明

常见 8×8 模块（如 1088BS 共阳）：

点阵引脚接 51说明
行 1~8（阳极组）P2.0~P2.7行选：高电平选中该行
列 1~8（阴极组）P0.0~P0.7列数据：低电平点亮该列
（扩展方案）列数据595 DS/SH/ST列 16 位经两片 595 级联

为什么直接驱动用 P2 行 + P0 列：16 个 IO 正好够；注意 P0 是开漏口，直接接点阵列需要上拉电阻（常见模块内置）。为什么大屏必须用 595：IO 有限（51 只有 32 个口），两片 595 出 16 位列数据 + P2 行选 = 16×16 点阵；点阵越多级联越多。

避坑 不同厂家模块的引脚顺序和「行阳/列阴」标法五花八门——先看模块背面丝印或 datasheet 确认，别按 1088BS 标准盲接。方向接错最常见的现象：字是「镜像」或「上下颠倒」——这时候改取模参数而不是改电路。

五、完整代码

示例 1 P0/P2 直接驱动显示图形；示例 2 595 扩展扫描。

示例 1：P0 列数据 + P2 行选，显示「心形」

/* 8x8 共阳点阵：P2 行选（高有效），P0 列数据（低电平点亮）
   显示心形图案：手工取模，每字节=一行，1=灭 0=亮 */
#include "reg52.h"

/* 心形字模：8 行 x 8 列，字节位=列（bit0=最左） */
unsigned char code heart[8] = {
    0xE7,   /* 第0行：1100 0111，中间两列亮（心形顶部凹槽） */
    0xC3,   /* 第1行：1100 0011 */
    0x81,   /* 第2行：1000 0001 */
    0x81,   /* 第3行 */
    0x81,   /* 第4行 */
    0x42,   /* 第5行：0100 0010 */
    0x24,   /* 第6行：0010 0100 */
    0x18    /* 第7行：0001 1000 */
};

void delay_ms(unsigned int ms);

void main(void)
{
    unsigned char row;

    while (1) {
        for (row = 0; row < 8; row++) {
            P2 = (1 << row);        /* 选中第 row 行（高电平） */
            P0 = heart[row];        /* 该行列数据 */
            delay_ms(1);            /* 亮 1ms */
        }
        P2 = 0;                     /* 帧末消隐：防拖影 */
        P0 = 0xFF;
    }
}

示例 2：74HC595 驱动列（两片级联 16 位）

/* 两片 595 级联输出 16 位列数据，P2 行选
   接线：P1.0=DS, P1.1=SH_CP, P1.2=ST_CP */
#include "reg52.h"

sbit DS   = P1^0;   /* 串行数据 */
sbit SHCP = P1^1;   /* 移位时钟 */
sbit STCP = P1^2;   /* 输出锁存 */

/* 送 16 位数据到两片 595（先送高位字节，即第二片） */
void hc595_send16(unsigned int dat)
{
    unsigned char i;
    for (i = 0; i < 16; i++) {
        DS = (dat & 0x8000) ? 1 : 0;   /* 取最高位 */
        SHCP = 0; SHCP = 1;            /* 上升沿移入一位 */
        dat <<= 1;
    }
    STCP = 0; STCP = 1;                /* 锁存：并行输出 */
}

void delay_ms(unsigned int ms);

void main(void)
{
    unsigned char row;

    while (1) {
        for (row = 0; row < 8; row++) {
            hc595_send16(0x8000 >> row);  /* 演示：一条亮线扫过 */
            P2 = 0xFF;                    /* 全行使能（示意） */
            delay_ms(1);
        }
        P2 = 0;
    }
}

六、代码逐段讲解

第一段：取模的「1 灭 0 亮」方向

心形第 0 行 0xE7 = 1110 0111：bit3、bit4 是 0 → 这两列低电平 → LED 亮——中间两个点亮，构成心形顶部凹槽。为什么方向反直觉：共阳模块列是阴极，低电平才亮，所以取模软件要选「共阳、列低有效」参数。手工取模口诀：先把图案画到 8×8 格纸，逐行读「亮=0 灭=1」转成二进制再转 16 进制。

第二段：P2 = (1 << row) 的行选

1 << row：row=0 → 0x01（第 0 行高电平），row=1 → 0x02。为什么是位操作：P2 的 8 位正好对应 8 行，一次置一行高。为什么帧末 P2=0、P0=0xFF：切换行瞬间若不清除，上一行的点亮状态会在下一行「串行」出现——这叫消隐，防止拖影/鬼影。

第三段：595 的移位时序

DS = (dat & 0x8000) ? 1 : 0 取最高位 → SHCP 0→1 上升沿把该位移入内部寄存器 → dat <<= 1 处理下一位。16 次后：第一片存低 8 位、第二片存高 8 位。最后 STCP 锁存：所有位一次性并行输出——这是 595 的标准「移入 8 位 + 锁存」时序。为什么锁存很重要：没有锁存，输出会随移位「逐个亮灭」闪烁；锁存让 16 位同时更新。

七、现象演示与验证

  • 心形：8×8 屏显示一颗心，稳定无闪烁。
  • 亮线：595 示例里一条亮线从左扫到右（动态效果）。
  • 对比：把每行延时改成 10ms，能看到明显闪烁——验证视觉暂留的临界点。

验证方法：

  1. 延时 1ms、5ms、10ms 逐步加大，记录「开始闪烁」的临界值（一般 4~5ms）——理解刷新率要求。
  2. 把取模字节按位取反（0xE7 → 0x18），心形变成取反图形——验证位序理解。
  3. 交换两行字节，图形上下颠倒——验证「字节=行、位=列」的映射。

八、常见报错排查方案

报错现象可能原因解决方法
整屏不亮共阳/共阴接反 / 电源没接确认模块阴阳；供电 VCC/GND
只有一行亮行选循环没跑完 / 延时太长检查 for 循环 0~7；每行延时不超过 2ms
字是镜像/颠倒取模参数与硬件方向不符改取模方向（从左/右、从上/下）或位序
画面闪烁刷新率太低（每行延时大）每行 1ms；总帧时不超过 8ms
有拖影/鬼影行切换没消隐帧内切换行前先 P0=0xFF、P2=0
595 输出乱SHCP/STCP 顺序错 / 字节顺序反核对时序：移 16 位后锁存；高低字节顺序
亮度太暗占空比 1/8 正常但偏暗加大电流（减小限流）/ 提高 VCC / 增大刷新
某行某列恒亮/恒灭引脚虚焊或模块坏点万用表测该行列；换模块验证

九、课后练习与延伸

练习 1（必做）：用字模软件或手工取模显示字母「M」和数字「5」——换两个内容验证流程。

练习 2：做「上下跳动的小球」动画：三帧图案轮流刷新，间隔 200ms——体会动画 = 多帧切换。

练习 3（进阶）：两片 595 + P2 实现 16×16 点阵，用取模软件生成汉字「电」显示——从 8×8 升级到汉字级。

延伸学习：显示与驱动都齐了，回到 学习路线 阶段 2 收官：把数码管（segment）、点阵、步进电机组合成「电子广告屏」或「电梯楼层显示」综合项目。下一步建议进入 Proteus 仿真深化（proteus-simulate.html）或直接进入 STM32 阶段。
