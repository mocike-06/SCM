数码管显示（静态与动态扫描）

系列：51 单片机 进阶 更新：2026-10-25

数码管是高校单片机教材「显示接口」章节的标配外设。本课讲清共阴/共阳、段码表、静态与动态扫描，并完成课表要求的「定时器计时：数码管显示秒表」综合练习。

一、本课目标与前置知识

学完本课你能做到：

  • 看懂共阴/共阳数码管的内部结构，能写出任意数字与字母的段码。
  • 实现 1 位数码管静态显示、8 位数码管动态扫描显示。
  • 结合 定时器 做出「秒表」，完成课表练习项目。

需要提前掌握的前置知识（对应学习路线阶段 2）：

  • IO 口输出：sbit、P 口赋值——数码管本质就是「控制多路 LED」。
  • 位运算与宏定义：段码本质是位组合，动态扫描要拆分个位/十位。
  • 定时器（可选，做秒表时用）。

本课会出现的新名词：数码管、共阴/共阳、段选、位选、段码表、静态显示、动态扫描、视觉暂留、消隐。

二、基础概念铺垫

1. 数码管：7 段 LED + 一个小数点

生活类比：数码管就是 8 个 LED 排成「日」字形：七段（a~g）组成数字笔画，加一个小数点 dp，共 8 个发光段。想让哪段亮就点亮哪个 LED。

一句话定义：一位数码管有 10 个引脚：8 个段（a、b、c、d、e、f、g、dp）+ 2 个公共端。公共端接 GND 叫共阴（段给高电平点亮），公共端接 VCC 叫共阳（段给低电平点亮，51 板最常见）。

例子：共阴数码管显示数字「1」：b、c 两段点亮，即段数据 0x06（b=1、c=1，其余 0）。

2. 段码表：数字 ↔ 段数据的对照字典

一句话定义：把「某一位应该输出什么电平」预计算好存在数组里，显示时直接查表取用，就是段码表。共阴数字 0~9 的段码是 {0x3F,0x06,0x5B,0x4F,0x66,0x6D,0x7D,0x07,0x7F,0x6F}。段 a 对应数据最低位 D0，b 对应 D1，依此类推——这是厂商引脚定义约定的。

例子：显示数字 5：查表得 0x6D，共阴时 P0 = 0x6D; 即可。共阳段码 = 共阴段码按位取反（如 5 的共阳是 ~0x6D = 0x92）。

3. 静态显示 vs 动态扫描

生活类比：静态显示像「每人一个专属台灯，想亮多久亮多久」——一位数码管占一组 IO，一直点亮；动态扫描像「一个手电筒轮流照 8 个人，照得够快，人眼以为都亮着」。

一句话定义：静态：每位数码管独占一组段选线，同时点亮，驱动简单但占 IO 多。动态扫描：所有数码管共用一组段选线，靠位选线逐位轮流点亮，靠视觉暂留（人眼余晖约 0.1s）让整体看起来同时亮，IO 省、成本低——绝大多数产品用动态。

例子：8 位动态显示只要 8 根段选 + 8 根位选 = 16 根线（配合锁存器更少），而静态要 8×8=64 根线。

4. 段选与位选：显示「谁」和「亮什么」

一句话定义：段选线决定某一位数码管显示什么字符（数字/字母）；位选线决定当前哪一位数码管被点亮。动态扫描循环体：先选位（位选=1），再送段码（段选=段码），延时几毫秒，换下一位。

例子：显示「3.7」两位：第 1 位位选打开，送段码 0x4F（3）；第 2 位位选打开，送段码 0x07|0x80（7 + 小数点）。每秒轮流几十次。

5. 消隐：防止「串位重影」

一句话定义：换位瞬间，上一位的段码还没切走、下一位的位选已打开，会出现「重影」——解决办法是先关闭所有位选（或清段码），再切换，叫消隐。正确顺序：关位选 → 送段码 → 开位选 → 延时。

三、原理介绍：数码管为什么靠「轮流点亮」就能同时显示多位

数码管内部就是 8 个 LED（a~g 七段 + dp 小数点）拼成「日」字。要点亮某个数字，就是选通对应那几段——这靠一张段码表。多位数码管共用同一组段线，靠位选决定此刻哪一位通电。

动态扫描一次刷新的流程：

  1. 程序让第 1 位亮 2~5ms（送它的段码、开它的位选）。
  2. 切到第 2 位、送段码、开位选，同样亮 2~5ms。
  3. 8 位轮流一遍，总耗时约 16~40ms。
  4. 循环远快于人眼 0.1s 残像，看到的是「多位同时亮」。

原理 1：段码表是怎么排出来的——一个字节管 8 段

一个字节 8 位正好对应 8 个段（b0=a、b1=b…b6=g、b7=dp）。共阴数码管，段引脚接高电平的那一段就点亮，所以想让数字「0」亮 a~g 中除 f 外的七段，对应字节就是 0b00111111 = 0x3F。于是形成一张表：seg[0]=0x3F、seg[1]=0x06……共阳则正好相反——段接低电平才亮，段码是共阴的按位取反（如 0 变成 0xC0）。这就是「换了共阳数码管，整段码表要取反重写」的原因，也是接反段/位选会出现「所有位同显一个字」的根因。

原理 2：动态扫描为什么不闪——视觉暂留与人眼极限

多位数码管如果每位都独立占一组段线，引脚根本不够。硬件做法是所有位的段线并联在一起，同一时刻只让「一位」的公共端通电。某一瞬间其实只有一位在亮——但程序用 2~5ms 的速度快速轮流，一圈刷新周期 <50ms。人眼有视觉暂留（约 100ms），前一位的残像还没消失、下一位已经点亮，大脑就把它们合成成「多位同时亮」。刷新慢了就闪：一圈超过 50ms，残像断开，肉眼能看到一位位轮流跳。

教材式刷新频率计算：整圈周期 = 位数 × 每位点亮时间。4 位每位亮 2ms → 整圈 8ms → 刷新频率 = 1/8ms = 125Hz；工程上要求整圈刷新频率 ≥50Hz（即整圈 ≤20ms）人眼才完全不觉得闪，每位延时 = 20ms / 位数 是起步值。注意：每位点亮时间太短会变暗（占空比小），太长会闪——4 位时每位 1~5ms 是经验区间，8 位则要压到 1~2ms。

原理 3：为什么切位前要先「消隐」——防残影拖影

如果直接「送新段码 → 切到下一位」，在段码刚送到、新位选还没建立的那几微秒，旧位选可能还通着，新段码会短暂映到旧位上，形成残影/拖影。所以标准顺序是先关位选（消隐）→ 再送新段码 → 再开新位选：先把要显示的这一位彻底熄灭，段码在没人通电的情况下悄悄换好，再点亮新位——每一位只映自己的段码，不串台。这就是记忆点里「先消隐、再送段、后开位选」的物理原因。

记忆点：段码表=一个字节管 a~dp 八段，共阴高电平点亮（0=0x3F）、共阳取反；多位共用段线、靠位选轮流通电，一圈<50ms 借视觉暂留看起来同时亮；切位前先关位选消隐，否则新旧段码串台出现拖影。

四、硬件接线说明

本课用 4 位共阴数码管（元件 7SEG-MPX4-CC，Proteus 可直接仿真）：段选 a~dp 接 P0.0~P0.7（P0 需接上拉，开发板已有），位选 1~4 接 P2.0~P2.3。

模块引脚单片机引脚说明
段 a~g、dp（8 根）P0.0 ~ P0.7段码输出；每段串 220Ω 电阻
位选 1（千位）P2.0高电平选中第 1 位
位选 2~4P2.1 ~ P2.3依次对应百位、十位、个位
公共端共阴接 GND / 共阳接 VCC本课用共阴，位选输出高电平点亮

为什么这样接：P0 口不带内部上拉（51 准双向口中唯一特殊的口），段码必须依赖外部上拉电阻或锁存器驱动——这也是下一课《总线扩展》用 74HC573 锁存段码的动机；P2 作位选则直接可驱动。Proteus 仿真中把段选经 220Ω 电阻接 P0，位选直接接 P2。

避坑 段码与位选千万别接反：段选送「显示什么」，位选决定「哪一位亮」。接反了现象是「所有位显示同一个字符」或「只有一位亮」。先用 1 位数码管（7SEG-COM-CATHODE）验证段码，再加位选做动态。

五、完整代码

示例 1：静态显示单个数字（1 位共阴数码管，段选接 P0）：

/* 静态显示：P0 输出段码，数码管显示数字 5 */
#include <reg52.h>

/* 共阴段码表：下标 0~9 对应数字 0~9 */
unsigned char code seg[10] = {0x3F,0x06,0x5B,0x4F,0x66,
                              0x6D,0x7D,0x07,0x7F,0x6F};

void main(void) {
    P0 = seg[5];        /* 显示 5：查表取段码送 P0 */
    while (1);          /* 保持显示（静态） */
}

示例 2：4 位动态扫描 + 定时器秒表（完成课表练习项目）：

/* 秒表：定时器 0 每 50ms 中断一次，20 次=1 秒，4 位数码管动态显示 */
#include <reg52.h>

unsigned char code seg[10] = {0x3F,0x06,0x5B,0x4F,0x66,
                              0x6D,0x7D,0x07,0x7F,0x6F};
unsigned char sec = 0;              /* 秒计数 0~59 */
unsigned char cnt50 = 0;            /* 50ms 累计计数 */

void delay_ms(unsigned int ms) {    /* 软件延时，供显示扫描用 */
    unsigned int i, j;
    for (i = 0; i < ms; i++)
        for (j = 0; j < 120; j++);
}

void timer0_init(void) {
    TMOD |= 0x01;                   /* T0 方式 1：16 位定时 */
    TH0 = 0x4C;                     /* 初值 19456：定时 50ms @11.0592MHz */
    TL0 = 0x00;
    ET0 = 1;                        /* 开 T0 中断 */
    EA  = 1;                        /* 开总中断 */
    TR0 = 1;                        /* 启动 T0 */
}

/* 显示函数：把千/百/十/个位轮流扫描一遍 */
void display(void) {
    unsigned char i;
    unsigned char pos = 0x01;       /* 位选初值：先选第 1 位 */
    for (i = 0; i < 4; i++) {
        P0 = 0x00;                  /* 消隐：先清段码 */
        P2 = pos;                   /* 开当前位 */
        switch (i) {                /* 送对应位的段码 */
            case 0: P0 = seg[sec / 1000]; break;      /* 千位 */
            case 1: P0 = seg[sec / 100 % 10]; break;  /* 百位 */
            case 2: P0 = seg[sec / 10 % 10]; break;   /* 十位 */
            case 3: P0 = seg[sec % 10]; break;        /* 个位 */
        }
        delay_ms(2);               /* 保持点亮约 2ms */
        pos = pos << 1;             /* 位选左移，选中下一位 */
    }
}

void main(void) {
    timer0_init();
    while (1) {
        display();                  /* 主循环不断刷新显示 */
    }
}

/* 定时器 0 中断：每 50ms 进一次 */
void timer0_isr(void) interrupt 1 {
    TH0 = 0x4C;                     /* 重装初值 */
    TL0 = 0x00;
    cnt50++;
    if (cnt50 >= 20) {             /* 20×50ms = 1 秒 */
        cnt50 = 0;
        sec++;
        if (sec >= 60) sec = 0;    /* 满 60 归零 */
    }
}

六、代码逐段讲解

第一段：段码表

unsigned char code seg[10] = {...}; 里的 code 是 Keil 关键字，表示把数组放程序存储区（Flash）而不是宝贵的内部 RAM——查表只读不改，就该放 Flash。为什么用查表：显示逻辑和段码数据分离，改显示内容只改下标，段码烧错一眼能看出；不写 code：8 字节数组会白白占 RAM，大工程里 RAM 会不够。

第二段：display 扫描循环

四步走：P0 = 0x00 消隐（防止上一位段码串到下一位）→ P2 = pos 开位选 → switch 送段码 → 延时 2ms 保持点亮。pos << 1 让位选从 0x01、0x02、0x04、0x08 依次移动。为什么顺序必须是消隐→送码→开选：若先开位选再送码，切位瞬间会出现「下一位短暂显示上一位的段码」——动态扫描最经典的重影 bug 就是这么来的。

第三段：秒表数据拆分

sec / 1000 取千位、sec / 100 % 10 取百位……这是「把一个数拆成各位数字」的标准手法（整除 + 取余）。秒表逻辑在中断里：50ms 加一次初值计数，20 次凑 1 秒——这就是课表里「定时器计时」与「数码管显示」的结合点。

第四段：中断重装初值

interrupt 1 是 Keil 的中断函数声明（1 号中断 = 定时器 0）。进中断先重装 TH0/TL0——16 位定时器溢出后不重装，下次定时就是 65536 个机器周期（约 71ms），秒表立刻失准；这是定时器中断的头号坑，务必养成「进中断先重装」的习惯。

七、现象演示与验证

  • 示例 1：数码管稳定显示数字「5」，不闪烁。
  • 示例 2：4 位数码管从 0000 开始每秒加 1，59 秒后归零；显示整体稳定不闪，亮度均匀。

验证方法：

  1. 把段码表第 5 项临时改成 0x00，显示会缺笔画——验证段码与显示一一对应。
  2. 把延时 2ms 改成 30ms，观察明显闪烁——验证刷新周期 <50ms 的结论。
  3. 删掉消隐行 P0 = 0x00;，观察「重影」——亲手复现教材上说的消隐必要性。

八、常见报错排查方案

报错现象可能原因解决方法
显示的数字笔画错乱共阴/共阳接反，或段码表用错极性共阳用 ~seg[n]；对照数据手册确认公共端接法
所有位显示同一个数字位选没接对 / 位选一直打开检查 P2 位选接线与 pos 移位逻辑
数字之间「串位」出现重影切换时没先消隐按顺序：P0=0x00（消隐）→ P2=位选 → P0=段码
显示闪烁明显扫描太慢（整圈 >50ms）缩短每位延时到 2~5ms；或改用定时器中断刷新
某一位特别暗 / 亮度不均单次点亮时间不足或限流电阻过大提高每位点亮时间，电阻取 220Ω 附近；确认 8 位轮换均匀
秒表走不准 / 跳数定时器中断里没重装初值中断第一件事重装 TH0/TL0；核对 11.0592MHz 对应初值 0x4C00

九、课后练习与延伸

练习 1（必做）：把秒表改成「0.1 秒位」显示（显示 00.0 格式，小数点 dp 置位），体会 seg[n] | 0x80 点亮小数点的写法。

练习 2：增加两个按键：一个「启动/暂停」，一个「清零」（配合 按键教程），做一个完整秒表。

练习 3（进阶）：让数字像跑马灯一样滚动显示「2026」循环（每 200ms 整体左移一位），核心是把 4 位显示内容放进数组轮换。

延伸学习：数码管只解决了「显示」，接下来学 独立按键与矩阵键盘 解决「输入」——人机交互的两半就齐了；想做 8 位以上显示且省 IO，看 总线扩展（74HC573）。
