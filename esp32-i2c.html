I2C 通信与 OLED 显示

系列：ESP32 进阶 更新：2026-10-25

OLED 屏、温湿度传感器、陀螺仪、EEPROM——物联网设备里一半的外设都挂在 I2C 总线上：只占两根线，却能挂几十个器件。本课在 ESP32 上用 Arduino 的 Wire 库驱动 SSD1306 OLED 显示 + AHT20 温湿度读取，并对照 51 里手搓的软件 I2C，把「两线总线」彻底看懂。

一、本课目标与前置知识

学完本课你能做到：

  • 说清 I2C 总线机制：两根线、7 位地址、主从关系、应答位。
  • 用 Wire 库往 OLED 写数据、从 AHT20 读数据。
  • 看懂器件 datasheet 的寄存器表，自己读任意 I2C 传感器。

需要提前掌握的前置知识（对应学习路线阶段 5）：

  • GPIO（esp32-gpio.html）：SDA/SCL 就是两根 GPIO 的复用。
  • 串口（esp32-bluetooth.html 或 stm32-usart.html）：了解「总线 + 协议」的通信思维。
  • 可选：51 的软件模拟 I2C（mcu51-i2c-eeprom.html）对照学习。

本课会出现的新名词：I2C 总线、SDA/SCL、7 位从机地址、起始/停止条件、应答 ACK/NACK、Wire 库、SSD1306、寄存器地址、AHT20。

二、基础概念铺垫

1. I2C 是什么：一条「门牌号总线」

生活类比：I2C 像小区里一条共享通道：每个器件（从机）有门牌号（7 位地址），主机喊「3 号楼，把窗户打开」（写地址+命令），器件应答并执行。所有器件共用两根线（SDA 数据线、SCL 时钟线），靠地址区分彼此。

一句话定义：I2C 是 两线制同步串行总线：主机用 SCL 产生时钟、SDA 传数据，通过 7 位从机地址 选目标器件，每次传输以「起始条件→地址→数据→停止条件」组织，接收方回 应答位 确认。

例子：SSD1306 OLED 的 I2C 地址常见 0x3C，AHT20 温湿度是 0x38——不同器件地址不同，地址表写在各芯片 datasheet。

2. 为什么 SDA/SCL 要接上拉电阻

一句话定义：I2C 是 开漏输出：器件只能把线拉低，拉高靠外接 上拉电阻（4.7kΩ 常见）。多主机/多从机才能安全共享同一根线。ESP32 开发板的 I2C 引脚（默认 GPIO21=SDA、GPIO22=SCL）一般已带上拉。

例子：如果 SDA 电压一直被拉低、波形像一条平线——大概率漏接上拉（或线序接反）。

3. Wire 库：Arduino 封装好的 I2C 工具箱

一句话定义：Wire 是 Arduino 官方 I2C 库：Wire.begin() 初始化、Wire.beginTransmission(addr) 开始发、Wire.write() 写字节、Wire.endTransmission() 发送、Wire.requestFrom(addr, n) 向从机要 n 字节、Wire.read() 读。五六个函数就能和任意 I2C 器件对话。

例子：给 OLED 发一个命令：beginTransmission(0x3C) → write(0x00) → write(0xAE) → endTransmission。

4. 寄存器：和器件说话先查「地址簿」

一句话定义：每个 I2C 器件内部有一组 寄存器（编号地址），写入特定寄存器=发命令，读取特定寄存器=拿数据。数据手册的寄存器表就是「地址簿」：AHT20 先写 0xBE 触发测量、再等 80ms、读 6 个字节（湿度 20bit + 温度 20bit）。

例子：读 OLED 不需要（纯显示器件只写不读）；读 AHT20 要「写命令→延时→读数据」三步——教材「读传感器」都是这个套路。

三、原理介绍：一次 I2C 读写的完整时序

I2C 只用两根线（SDA 数据、SCL 时钟）就能挂多个器件，是最简单的「板上总线」。它的精髓在于开漏线 + 地址寻址 + 每字节应答三件事——理解了，扫描器和 OLED/AHT20 的代码就都通了。

一次读传感器的链路：起始条件 → 发 7 位地址+读写位 → 从机 ACK → 发寄存器命令 → 重起始 → 读回数据字节 → 停止条件。

原理 1：开漏线与上拉——为什么 SDA/SCL 都要上拉电阻

I2C 的两根线都是开漏：任何设备都只能把线拉低，不能主动输出高电平——平时的高电平全靠 4.7kΩ 上拉电阻拉到 3.3V。好处是线与：任何设备拉低，整根线就变低，不会出现两个器件一个输出高、一个输出低互相打架的情况。这就是「一条总线挂多个器件」能成立的硬件基础——也是为什么 OLED 和 AHT20 模块上必须看到上拉、裸板不接就不通。

原理 2：起始/停止条件与 ACK——协议怎么框住一帧

I2C 靠两个特殊电平变化框住一次传输：起始条件是 SCL 高电平时 SDA 从高跳低，停止条件是 SCL 高电平时 SDA 从低跳高——这两种跳变在正常数据传输里不会出现，所以是明确的「开始/结束」信号。每发完 8 位（1 字节），接收方必须在第 9 个时钟把 SDA 拉低回 ACK；没拉低（NACK）就说明没这个地址或传输出错。这就是 I2C 扫描器的原理：从 0 扫到 127，挨个发地址，谁回 ACK 谁就在线上。

I2C 关键时序参数（教材波形口径）：

条件SCL 状态SDA 动作
起始 START高电平期间SDA 由高→低（唯一允许的跳变）
停止 STOP高电平期间SDA 由低→高
数据位有效高电平期间SDA 必须稳定（此时跳变=START/STOP）
应答 ACK第 9 个时钟高电平接收方把 SDA 拉低

教材判读要点：「SCL 高电平时 SDA 不允许变化」是数据位的铁律——只有 START/STOP 例外。SDA 上的数据必须在 SCL 低电平期间改变（建立时间），等 SCL 变高再被采样（保持时间），这就是「建立时间/保持时间」的由来。

原理 3：读传感器为什么要「先写命令、再读数据」

传感器内部有很多寄存器（温度寄存器、湿度寄存器、配置寄存器……）。主机不能直接读温度——得先告诉器件「我要读哪个寄存器」：发地址（写）→ 发寄存器号 → 再发「重起始 + 地址（读）」→ 器件才把对应寄存器的值放到 SDA 上。这套「写命令→等转换→读数据」的三步事务是所有 I2C 传感器的通用模式——OLED 的初始化（写一堆命令字节）、AHT20 的读温湿度，底层都是它。ESP32 有硬件 I2C 外设，Wire 库把这些时序全替你做了；51 没硬件 I2C，只能 GPIO 软件翻转模拟——但协议思维完全一样。

记忆点：I2C=两线开漏总线（SDA/SCL 都靠上拉到 3.3V，线与不打架）；起始=SCL 高时 SDA 高→低、停止=低→高；每字节后第 9 时钟回 ACK（扫描器就是挨个试地址）；读传感器=先发寄存器命令再读数据；地址查 datasheet（0x3C=OLED、0x38=AHT20）。

四、硬件接线说明

模块接线说明
SSD1306 OLEDVCC→3V3、GND→GND、SCL→GPIO22、SDA→GPIO21默认 I2C 引脚；地址 0x3C
AHT20 模块VCC→3V3、GND→GND、SCL→GPIO22、SDA→GPIO21与 OLED 共用总线（同地址才冲突，它们不同地址）
（可选）0.96 寸 OLED 四针同上1.3 寸地址可能 0x3D，先扫描

为什么多个器件能并在一起：I2C 总线共享：只要地址不同，挂多少器件都行（受总线电容限制，一般 ≤8 个）。OLED 0x3C 和 AHT20 0x38 不冲突，可以直接并联。

怎么确认地址：第一次接新器件先跑「I2C 扫描」例程（Arduino 自带 i2c_scanner），串口打印出所有在线地址——这是排查一切 I2C 问题的第一动作。

避坑 板子上有些 OLED 模块 VCC 标 5V 也写着能兼容，但优先接 3V3；接 5V 时确认模块带电平转换（很多模块只有稳压没有双向电平转换，长期使用可能烧 ESP32 引脚）。

五、完整代码

示例 1：I2C 设备扫描（新手必跑）

/* I2C 扫描：打印总线上所有设备的 7 位地址 */
#include <Wire.h>

void setup() {
  Serial.begin(115200);
  Wire.begin();                // 默认 GPIO21(SDA) / GPIO22(SCL)
  Serial.println("\nI2C Scanner");
}

void loop() {
  byte error, address;
  int nDevices = 0;

  Serial.println("Scanning...");
  for (address = 1; address < 127; address++) {
    Wire.beginTransmission(address);
    error = Wire.endTransmission();
    if (error == 0) {          // 0 = 有器件 ACK
      Serial.print("Found at 0x");
      if (address < 16) Serial.print("0");
      Serial.println(address, HEX);
      nDevices++;
    }
  }
  Serial.print("Done. Found ");
  Serial.println(nDevices);
  delay(2000);
}

示例 2：OLED 显示 + AHT20 温湿度（需要安装 Adafruit_SSD1306 库与 Adafruit_AHTX0 库）

/* OLED 实时显示温湿度 */
#include <Wire.h>
#include <Adafruit_SSD1306.h>
#include <Adafruit_AHTX0.h>

#define OLED_ADDR 0x3C

Adafruit_SSD1306 oled(128, 64, &Wire, -1);   // 128x64，软复位
Adafruit_AHTX0 aht;

void setup() {
  Serial.begin(115200);
  Wire.begin();                       // 同一总线上挂 OLED + AHT20

  if (!oled.begin(SSD1306_SWITCHCAPVCC, OLED_ADDR)) {
    Serial.println("OLED init fail");
    while (1);                        // OLED 失败就停在这
  }
  oled.clearDisplay();
  oled.setTextSize(1);
  oled.setTextColor(SSD1306_WHITE);
  oled.display();

  if (!aht.begin()) {
    Serial.println("AHT20 init fail");
    while (1);
  }
  Serial.println("Sensors OK");
}

void loop() {
  /* 读 AHT20：getEvent 读取一次传感器并返回是否成功（true=读到有效数据） */
  sensors_event_t hum, temp;
  if (aht.getEvent(&hum, &temp)) {

    /* OLED 显示两行文字 */
    oled.clearDisplay();
    oled.setCursor(0, 0);
    oled.print("Temp: ");
    oled.print(temp.temperature);
    oled.println(" C");
    oled.setCursor(0, 16);
    oled.print("Hum : ");
    oled.print(hum.relative_humidity);
    oled.println(" %");
    oled.display();
  }
  delay(1000);                        // 每秒刷新一次
}

六、代码逐段讲解

第一段：扫描器的 error==0 判断

Wire.endTransmission() 返回一个状态码：0 表示有器件 ACK（在线）、2 表示 NACK（无器件）。为什么先跑扫描：接线错、地址记错、器件坏了——扫描器一次性暴露所有 I2C 问题。看到打印的地址再去查 datasheet 对不对，是标准排障流程。

第二段：Adafruit 库的封装逻辑

Adafruit_SSD1306 oled(128, 64, &Wire, -1) 构造时指定尺寸、总线、复位脚（-1 表示不接复位）。oled.begin(SSD1306_SWITCHCAPVCC, OLED_ADDR) 完成初始化。为什么库函数里已经包含「写寄存器」：库把「发 0x00 控制字节 + 命令/数据」全封装了，你看到的是高层 API——但底层仍是 beginTransmission/write/endTransmission 那套。

第三段：getEvent 拿到的是结构体

sensors_event_t 是 Adafruit 统一传感器格式：temp.temperature 与 hum.relative_humidity 直接是 float 摄氏度与百分比。为什么不用自己拼字节：AHT20 的 20bit 原始数据换算公式（湿度=raw/2²⁰×100）库已经算好——理解换算存在，但日常开发直接用库。想亲手抠原始字节，参考 51 课的 DHT11/I2C 思路。

第四段：oled.print 与 C++ 重载

oled.print(temp.temperature) 直接把 float 打印上屏——Arduino 的 print 是重载函数，整数、浮点、字符串都能打。为什么先 clearDisplay 再 setCursor：OLED 不清屏会叠字；cursor 定位到 (0,0) 和 (0,16) 两行，对应屏幕两行文字。

第五段：寄存器 ↔ 时序 ↔ Wire 库三层对照

教材要求看懂「硬件外设 ↔ 软件模拟 ↔ 库」三层：

你写的 Arduino 函数底层方式最底层
Wire.beginTransmission(0x3C)ESP32 硬件 I2C 外发起始+地址I2C 外设数据/命令寄存器
Wire.write(0x00)硬件移位寄存器发 1 字节I2C 数据寄存器
51 里的软件模拟 I2CGPIO 翻转 SDA/SCL 模拟时序纯软件延时位操作，无硬件外设

为什么重要：ESP32 有硬件 I2C 外设定时发 SCL，所以你只调 Wire 库函数；51 没硬件 I2C，要自己用 GPIO 翻转模拟同样的 START/STOP/ACK 时序——协议本身一样，只是「硬件帮你做」还是「软件手搓」的区别。

七、现象演示与验证

  • 扫描：串口打印 Found at 0x38（AHT20）与 Found at 0x3C（OLED）。
  • 显示：OLED 显示 Temp: 26.5 C、Hum : 55.2 %，每秒刷新。
  • 响应：手指捏住传感器，温度读数升高、湿度变化。

验证方法：

  1. 拔掉 AHT20 单独跑 OLED——OLED 仍正常（总线断一个器件不影响另一个）。
  2. 把 OLED 地址从 0x3C 改成 0x3D（部分屏实际地址），观察 begin 失败提示——理解地址的重要性。
  3. 只接 OLED 不接 AHT20 跑完整例程：aht.begin() 返回 false，串口报错不卡死——理解初始化失败的容错写法。

八、常见报错排查方案

报错现象可能原因解决方法
扫描不到任何设备接线错 / 没共地 / 上拉缺失核对 SDA/SCL/VCC/GND；确保与板子共地；补 4.7k 上拉
扫到地址但 OLED 黑屏地址/尺寸参数不对，或 Reset 引脚接了 -1 但模块需要试 0x3D；构造改 64/128 尺寸；接上复位引脚
温度读数恒定不变AHT20 初始化失败 / 读取时序没等够查 aht.begin() 返回；库版本升级；换例程对照
接了 OLED 后 AHT20 也失效两个器件地址相同（罕见）或总线被占扫描确认地址不同；不同地址还冲突就查 VCC 电压

九、课后练习与延伸

练习 1（必做）：跑扫描例程，确认你手头所有 I2C 器件的真实地址，并记录到注释里。

练习 2：不用 Adafruit_AHTX0 库，改用 Wire 原始函数（beginTransmission/write/requestFrom）读 AHT20 原始字节并自己换算——动手前先查 AHT20 datasheet 寄存器表。

练习 3（进阶）：把 OLED 从 Adafruit 库换成「裸 Wire 驱动」（网上有 SSD1306 裸驱动代码），看懂它的命令序列——彻底告别「只会用库」。
