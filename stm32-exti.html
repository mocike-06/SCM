外部中断 EXTI（按键中断）

系列：STM32 进阶 更新：2026-10-24

第二回读按键是「轮询」，单片机不停去问「按了没」。这回用中断：平时主循环该干嘛干嘛，按键一按硬件立刻自动跳进来处理。本讲从零讲透 EXTI 是什么、轮询和中断的区别、上升沿/下降沿怎么选、NVIC 为什么必须使能、以及为什么我们只需要改写 HAL_GPIO_EXTI_Callback 这个回调函数而不用自己写中断服务函数。

一、本课目标与前置知识

学完本课你能做到：

  • 说清楚 EXTI 外部中断是什么，以及它和轮询读按键的本质区别。
  • 会在 CubeMX 把 PA0 配成 EXTI 下降沿中断、上拉输入，并在 NVIC 里使能。
  • 改写 HAL_GPIO_EXTI_Callback 完成按键翻转 LED，并理解回调机制为什么比手写中断函数好。

需要提前掌握的前置知识：

  • GPIO（stm32-gpio.html）：上拉输入、按键消抖——本讲按键接法和消抖逻辑沿用。
  • 中断概念（51 单片机阶段）：知道什么是中断、中断会打断主程序。

本课新名词：EXTI、外部中断、轮询、上升沿/下降沿、中断线、NVIC、抢占优先级、回调函数 Callback、weak 弱定义。

二、基础概念铺垫

1. EXTI 是什么：引脚电平跳变的「报警器」

生活类比：轮询像你每隔一秒就抬头看一眼门铃有没有人按；外部中断 EXTI 像门铃本身会响——没人按你专心干活，门一被按（引脚电平跳变），门铃立刻「嘟嘟」叫你去开门。

一句话定义：EXTI（外部中断/事件控制器）监听指定引脚上的电平跳变，一旦发生跳变就自动打断 CPU 当前的事，跳去执行中断处理函数。

例子：本讲把 PA0 配成 EXTI 中断，按键按下（高→低跳变）时自动触发回调，翻转 LED，主循环完全不用管按键。

2. 轮询 vs 中断：主动问 vs 被动等

生活类比：轮询是「每隔一分钟去门口看快递」，浪费时间还可能看漏；中断是「快递到了按门铃」，你该工作工作，门铃响了才去取。

一句话定义：轮询是主循环反复读引脚电平判断事件；中断是硬件在事件发生时自动通知 CPU。中断不浪费 CPU、响应快（微秒级），还能在主循环闲着时进入低功耗。

例子：GPIO 那篇用 while(1) 轮询读 PA0；本讲主循环是空的，按键照样即时响应——对比鲜明。

3. 上升沿与下降沿：在哪个跳变上报警

生活类比：报警器可以设定成「门被推开（高→低）时响」，也可以「门被关上（低→高）时响」。要看你关心哪个动作。

一句话定义：下降沿触发在电平从高变低时报警；上升沿触发在从低变高时报警。本讲按键内部上拉、平时高电平、按下接地变低，所以选下降沿。

例子：CubeMX 里选 Falling edge trigger detection，按下瞬间那一下高→低跳变就触发中断。

4. NVIC 与抢占优先级：中断的「总开关 + 排队规则」

生活类比：EXTI 配好只是装好了门铃，NVIC 是门铃墙上的总电闸。不拉闸，门铃按了也不响。多个中断同时来时，抢占优先级高的可以打断低的。

一句话定义：NVIC（嵌套向量中断控制器）是芯片统一管理所有中断的部件。光配 EXTI 不够，必须在 NVIC 里把这条中断「使能」（打开开关）它才响应。抢占优先级决定多个中断同时到来时谁先、谁能打断谁。

例子：本讲 CubeMX 的 NVIC Settings 里要勾 EXTI line0 interrupt，否则回调永远不执行。

5. 回调机制：为什么改写 Callback 而不手写中断函数

生活类比：HAL 库已经把「接电话、记来电显示」这些杂事全包了（中断服务函数），只留一个「通话键（Callback）」给你按——你只管按通话键说你要说的话，不用学会怎么接电话。

一句话定义：HAL 库的中断服务函数（如 EXTI_IRQHandler）已经写好并自动清中断标志，它末尾会调用一个weak（弱定义）的回调 HAL_GPIO_EXTI_Callback。我们重写这个回调，就能插入自己的处理逻辑，不用碰底层的标志位清理。

例子：本讲只需写 void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin){ ... }，CubeMX 生成的 EXTI_IRQHandler 会自动调用它。

三、原理介绍

第 2 篇我们在 while(1) 里反复读 PA0 判断按键——这叫轮询：CPU 一直在空转等按键，主循环任务多时按键还会被「卡住」几毫秒。EXTI 把这件事反过来做，让硬件主动喊人。

整条链路：引脚电平跳变 → EXTI 边沿检测线捕捉 → NVIC 裁决并抢占 CPU → 硬件跳到固定中断向量 → HAL 清标志 → 调 weak 回调 HAL_GPIO_EXTI_Callback。

原理 1：边沿检测——硬件怎么知道「按下了」

EXTI 内部对每条中断线做边沿监视：可设上升沿（低→高）、下降沿（高→低）或双边沿。按键内部上拉、按下接地，松开是高、按下瞬间是高→低跳变，所以选下降沿。关键是「引脚 ↔ 中断线」不是随便连的：PA0/PB0/PC0 共用 EXTI0，PA1/PB1 共用 EXTI1……同编号引脚同一时刻只能选一个。所以「为什么 PB0 配了 EXTI0 又想用 PA0」会冲突——它们挤在同一条线上。

原理 2：NVIC——事件来了凭什么能打断主循环

光让 EXTI 检测到跳变还不够，必须在 NVIC（嵌套向量中断控制器）里把 EXTI0 这条中断「使能」，它才有权打断 CPU。NVIC 还管优先级：高优先级可打断低优先级（嵌套）。中断一旦触发，CPU 自动停下手头指令、压栈、跳到固定地址的中断向量——这就是为什么中断响应是微秒级、且与主循环在干什么无关。

原理 3：weak 回调钩子——为什么只要重写一个函数就行

启动文件里有 EXTI0 的中断向量，它指向 CubeMX 写好的 EXTI0_IRQHandler，里面调 HAL_GPIO_EXTI_IRQHandler：自动清中断标志位、再调用 HAL_GPIO_EXTI_Callback。这个 Callback 在 HAL 库里是 weak（弱定义）的空函数——你在 main.c 里重写它，链接器就优先用你的版本。这就是 HAL 的「钩子」思想：框架把脏活（清标志）包了，留一个干净钩子给用户填业务。坑点：中断里别写长代码、别用 HAL_Delay（它靠 SysTick 中断，被中断打断会卡死），只置标志、主循环里慢慢处理。

记忆点：EXTI 监视边沿（按下=下降沿），PA0/PB0/PC0 共用 EXTI0；必须在 NVIC 使能才能打断 CPU；IRQHandler 清标志后调 weak Callback，重写即接管；中断里只置标志、别延时。

原理 4：EXTI/NVIC 寄存器 ↔ HAL 对照 + 抢占与子优先级（教材核心）

野火教材讲中断必背「优先级分两层」：Cortex-M3 的 NVIC 把每个中断优先级切成高几位=抢占优先级、低几位=响应(子)优先级。抢占优先级高的中断可以打断正在执行的低抢占中断（嵌套）；子优先级只决定两个同抢占级中断同时来时谁先，谁也不能打断谁。CubeMX 里 Priority Group 选 NVIC_PRIORITYGROUP_4 表示全 4 位都当抢占优先级。

你做的事对应寄存器 / 位HAL 函数 / CubeMX
选 PA0 触发线（引脚→EXTI 映射）AFIO_EXTICR1 的 EXTIn 位（PA/PB/PC 选择）CubeMX 点 PA0 选 GPIO_EXTI0
允许/禁止某条线产生中断EXTI_IMR（中断屏蔽寄存器，MRx=1 放行）CubeMX 配 EXTI 中断即置 IMR
选上升沿/下降沿EXTI_RTSR / EXTI_FTSRFalling edge trigger detection
NVIC 真正使能这条中断NVIC_ISER（中断置位使能寄存器，写 1 使能）CubeMX NVIC Settings 勾 EXTI line0
清中断挂起标志EXTI_PR（挂起寄存器，写 1 清）HAL_GPIO_EXTI_IRQHandler 自动清

Cortex-M3 背景一句话：M3 采用三级流水线（取指→译码→执行），中断响应时硬件自动把 xPSR、PC、LR、R0~R3、R12 压进栈，进入 ISR；ISR 末尾硬件自动出栈恢复——所以你写回调时完全不用手动保护现场，这是 M3 比 51 省心的地方。

四、硬件接线说明

模块引脚单片机引脚说明
按键一脚PA0（GPIO_EXTI0）内部上拉，按下接地产生下降沿
按键另一脚GND按下时 PA0 被拉低
LED 阳极PA5（经 220Ω 电阻）用来指示中断是否触发成功
LED 阴极 / 供电GND / 3.3V共地供电

为什么这样接：

  • 为什么按键接 PA0 而不是任意脚？ EXTI 线号和引脚编号对应：PA0~15 分别对应 EXTI0~15。选 PA0 走 EXTI0，方便对应 NVIC 里的「EXTI line0」。
  • 为什么用下降沿 + 上拉？ 内部上拉让平时 PA0 为高，按下接地拉低，产生高→低下降沿——正好对应我们选的下降沿触发。
  • 为什么 LED 用来指示？ 主循环是空的，必须靠 LED 翻转才能证明「是中断在响应」，而不是别的什么在干活。
CubeMX 配置要点 点 PA0 选 GPIO_EXTI0；在 PA0 的 GPIO 设置里 GPIO mode 选 External Interrupt Mode with Falling edge trigger detection，Pull-up/Pull-down 选 Pull-up；切到 NVIC Settings，勾选 EXTI line0 interrupt 把它使能。

五、完整代码

中断服务函数 HAL_GPIO_EXTI_IRQHandler 由 CubeMX 自动生成在 stm32f1xx_it.c 里，我们只需要重写回调函数。主循环故意留空，以此证明按键是被中断响应的。

/* main.c：EXTI0 按键中断回调（零基础注释版） */

/* 中断回调：EXTI 引脚产生跳变时自动调用 */
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
  if (GPIO_Pin == GPIO_PIN_0)          /* 确认是 PA0 触发的 */
  {
    HAL_Delay(20);                     /* 简单消抖，等机械抖动结束 */
    /* 再确认一次确实按下去了 */
    if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET)
    {
      HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);   /* 翻转 LED */
    }
  }
}

int main(void)
{
  HAL_Init();
  SystemClock_Config();
  MX_GPIO_Init();

  while (1)
  {
    /* 主循环什么都不做：所有事情都在中断里完成 */
    /* 这里完全可以去执行低优先级任务或进低功耗模式 */
  }
}
注意 中断回调里应尽量短，别写大段延时或死循环——它一卡住，整个芯片别的中断都进不来。上面 HAL_Delay(20) 只是教学演示，项目里建议用「进中断记录时间戳，主循环里再消抖处理」的写法。

进阶写法（推荐用于真实项目）： 中断里只置一个标志位就立刻退出，把消抖和翻转挪到主循环——这样中断里没有任何耗时函数，响应最快、最稳。共享变量必须加 volatile，否则编译器优化会把它缓存进寄存器，主循环读不到中断里的更新。

/* 进阶写法：中断里只置标志，主循环统一消抖处理（不在中断里 HAL_Delay） */
volatile uint8_t key_pressed = 0;   /* 中断与主循环共享，必须加 volatile */

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
  if (GPIO_Pin == GPIO_PIN_0) {
    key_pressed = 1;                 /* 只记一笔就立刻退出中断，不耗时 */
  }
}

int main(void)
{
  HAL_Init();
  SystemClock_Config();
  MX_GPIO_Init();

  while (1)
  {
    if (key_pressed)                 /* 主循环发现「被按过」 */
    {
      HAL_Delay(20);                 /* 在主循环里消抖，安全 */
      if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) {
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);   /* 真按下才翻转 LED */
      }
      key_pressed = 0;               /* 清标志，等下一次按下 */
    }
  }
}

六、代码逐段讲解

第 1 段：回调函数开头判断来源

在做什么： HAL_GPIO_EXTI_Callback 是所有 EXTI 引脚共用的回调，用 if (GPIO_Pin == GPIO_PIN_0) 判断是不是 PA0 触发的。

为什么这么写： 一个回调可能服务多个 EXTI 引脚（EXTI0~EXTI15 共用一个 Callback），必须靠传入的 GPIO_Pin 区分是谁触发的，只处理 PA0 的事件。

不写会怎样： 多个中断脚时不判断来源，会误把别的引脚事件当成 PA0 处理。

第 2 段：中断里的消抖

在做什么： 进回调后 HAL_Delay(20) 等抖动过去，再 ReadPin 确认仍为低才翻转 LED。

为什么这么写： 机械按键按下瞬间会抖动出多次跳变，可能触发好几次中断。等 20ms 再确认，只认一次有效按下。

不写会怎样： 不消抖，按一下 LED 可能翻转两三次，甚至因为抖动反复触发。

第 3 段：主循环留空

在做什么： while(1) 里什么都不做。

为什么这么写： 故意留空是为了证明按键翻转 LED 完全靠中断，而不是轮询——主循环没读过按键，LED 照样翻。

不写会怎样： 若主循环还在读按键，就分不清是轮询还是中断在起作用，演示效果打折。

七、现象演示说明

  • 下载后主循环是空的，但按下 PA0 上的按键，LED 照样翻转——说明是中断在响应，不是轮询。
  • 对比轮询：把主循环故意加一个 HAL_Delay(500) 的长任务，轮询方式下按键会明显「迟钝」，中断方式下按键依然即时响应。
  • 验证消抖：快速按一下，LED 只翻转一次；如果把回调里的 20ms 消抖删掉，按一下通常会跳两三次。

可量化的验证方法：

  • 验证中断 vs 轮询延迟：主循环加 HAL_Delay(1000) 模拟长任务，按按键 LED 几乎立即翻转——若改成轮询读键，按下后要等最长 1 秒才反应，对比明显。
  • 数翻转次数：按 10 次按键，LED 应正好翻转 10 次。若某次按出两次翻转，说明消抖延时不够，把 20ms 加到 50ms。
  • 按住不放：按住按键不放，LED 不应连续乱翻——因为只在按下瞬间的下降沿触发一次。若按住反复触发，说明边沿配置有误。

八、常见报错排查方案

报错现象可能原因解决方法

按一次触发很多次 / 一直触发没有消抖；或上下拉/触发边沿配反回调里加 20ms 消抖；确认是 Falling edge + Pull-up

九、课后练习与延伸

练习 1（加第二个中断按键）： 用 PB1(EXTI1) 再接一个按键，按下翻转另一颗 LED。提示：CubeMX 配 PB1 为 EXTI1 下降沿上拉、NVIC 勾 EXTI line1；回调里加 if(GPIO_Pin==GPIO_PIN_1) 分支。

练习 2（中断计数）： 每按一次按键，一个 count 变量加 1，并通过串口打印 count 值。提示：回调里 count++ 后 printf——注意中断里别做太长的事。
