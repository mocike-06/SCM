DAC0832 模拟量输出（波形发生器）

系列：51 单片机 进阶 更新：2026-10-25

上节课学了「读模拟量」（ADC0832），这节学「写模拟量」：单片机只有 0/1 数字信号，怎么输出 1.5V、2.7V 这样的连续电压？答案是用 DAC（数模转换器）。DAC0832 是教材「模拟量输出接口」的经典芯片，本课讲透 D/A 原理、芯片三种工作模式，并用它做出三角波、正弦波发生器——示波器上看得见的「电压画画」。

一、本课目标与前置知识

学完本课你能做到：

  • 说清 DAC 的工作原理：数字码 → R-2R 网络 → 电流 → 运放变电压。
  • 理解 DAC0832 的直通/单缓冲/双缓冲模式差别。
  • 写代码输出直流电压、三角波、正弦波（查表法）。

需要提前掌握的前置知识（对应学习路线阶段 2 + 4）：

  • 片外扩展总线（mcu51-exram.html）：DAC0832 也是挂在总线上的器件。
  • ADC 概念（mcu51-adc.html）：DAC 是 ADC 的逆过程。
  • C 语言数组与循环（c-basics.html）：波形查表要遍历数组。

本课会出现的新名词：DAC、分辨率、R-2R 电阻网络、运算放大器、直通/单缓冲/双缓冲、ILE/CS/WR1/WR2/XFER、查表法、阶梯波。

二、基础概念铺垫

1. DAC 是什么：把数字「翻译」成电压

生活类比：音量旋钮有 256 格（数字量 0~255），每一格对应一个固定的音量（模拟电压）。DAC 就是一个「自动旋钮」：给它数字 100，它就输出对应的电压。

一句话定义：DAC（数模转换器）把 n 位二进制数转换为成比例的模拟电压/电流。分辨率 = 位数（8 位 DAC 有 256 级）；满量程 = 参考电压 VREF；最小电压步进 = VREF/256。DAC0832 是 8 位、电流输出型 DAC。

例子：VREF=5V 时，数字 128 → 2.5V，数字 255 → 约 4.98V。

2. R-2R 网络：DAC 的「电阻梯子」

一句话定义：DAC0832 内部用 R-2R 电阻网络：每位数码控制一个开关，把 2R 电阻接到基准电压或地。因为电阻比例是 2:1，每低一位贡献的电流恰好减半——各支路电流按二进制权叠加，总电流就正比于数字量。这是 DAC 芯片的物理核心。

例子：bit7（最高位）贡献 VREF/2 电流，bit0 贡献 VREF/256——数字 0b10000000 的输出正好是半量程。

3. 运放的作用：把电流变成「能用的电压」

一句话定义：DAC0832 输出的是电流（Iout1/Iout2），要变成电压必须外接运算放大器（如 LM358）：反馈电阻把电流转成电压，输出 Vout = -Iout × Rfb。教材电路图里那个运放不是摆设——没有它你只能量到电流。

例子：Iout1 最大 ≈ VREF×(255/256)/R，经运放 10k 反馈电阻 → 满量程约 -5V（反相）。

4. 三种工作模式：直通 / 单缓冲 / 双缓冲

一句话定义：DAC0832 内部有两级锁存器（输入寄存器 + DAC 寄存器），由 ILE/CS/WR1/WR2/XFER 控制：直通：所有控制全有效，数据直接进 DAC，输出实时跟随 P0（最常用教学）；单缓冲：一级直通一级锁存，常用（写一次输出一次）；双缓冲：两级都锁存，可「先收数据、后同时更新」——多片 DAC 同步输出用。

例子：本课用单缓冲：把 WR2/XFER 接低电平（DAC 寄存器直通），只控制输入寄存器——写 P0 即输出。

5. 教材通用输出公式（张毅刚教材 DAC 一节）

一句话定义：DAC0832 经运放后的输出电压为 Vout = -Vref × D / 256（D=0~255，负号来自运放反相输入），若把运放接成同相或对调 Iout1/Iout2 则取正。最小输出步进（1LSB）= Vref/256 ≈ 19.5mV@5V，这就是 DAC 的分辨率。教材还要求掌握两个指标：建立时间（输出从 0 到满量程稳定所需时间，DAC0832 约 1µs 量级）、绝对精度（实际输出与理想值之差，受 Vref 精度和电阻网络误差限制）。波形发生器频率公式：f = 刷新频率 / 每周期点数（本课 256 点）。

三、原理介绍：一个数字怎么变成示波器上的一条波形

DAC 是 ADC 的反过程：你给它一个 0~255 的数字，它输出对应电压。DAC0832 是 8 位、电流输出型、带两级锁存的教材型 DAC。

从数字到波形的流程：

  1. D0~D7 挂 P0 数据总线，CS 接译码片选(如0x2000)，ILE 接高。
  2. CPU 向 0x2000 写一字节：P0 出数据→WR1 写脉冲→输入寄存器锁存→DAC 寄存器直通→电流输出。
  3. 电流经运放转电压，接示波器。
  4. 循环写 0→255→0 得三角波；按正弦表依次写得正弦波。

原理 1：R-2R 电阻网络——每一位按权重贡献一份电流

DAC0832 内部核心是一套 R-2R 梯形电阻网络。8 位数字的每一位控制一个开关：该位为 1，就把对应那路电流接到输出。关键是——这些支路的电阻成2 倍递进，于是最高位开关贡献的电流是最低位的 128 倍（2⁷:2⁰）。把所有为 1 的位的电流加起来，总电流就和数字大小成正比：写 128 时输出约为写 255 时的一半。这就是「数字→成比例电流」的物理本质——256 档对应 0~满量程，输出电压 ≈ 数字/255 × VREF。和 ADC 正好相反：ADC 是把电压切成 256 档读数，DAC 是拿数字选一档输出电压。

原理 2：为什么电流型 DAC 后面必须跟一颗运放

DAC0832 输出的是电流(Iout1/Iout2)，不是电压——示波器/万用表量的是电压，直接量没有意义。所以后面接一颗运算放大器(LM358)做电流→电压转换：流出的电流流过反馈电阻(片内 Rfb)，在运放输出端变成电压 Vout = 数字/255 × VREF。这就是「电流型 DAC 必须外接运放」的原因——芯片本身只出电流，电压是运放转出来的。VREF 越稳，波形越干净；用纹波大的 5V 当基准，波形会毛糙。

原理 3：为什么波形要用「查表」而不是实时算 sin

要出正弦波，理想是每个输出点算一次 sin(x)。但 51 没浮点单元，调 sin 库函数算一个点要几十微秒甚至更久——波形会卡顿、失真。嵌入式标准做法是查表法：编译时在电脑上把正弦波 256 个点的数值算好、写成一个数组 code sin_tab[256] 烧进 Flash；运行时只做 P0=sin_tab[i++]——几个指令出一个点，刷新飞快。波形频率 = 每秒输出点数 / 256。这和数码管段码表是同一思路：把复杂计算挪到编译期，运行时只查表。

记忆点：DAC=数字转电压、8位256档，内部R-2R网络让每位按2的幂权重贡献电流、总和∝数字；它是电流输出、必须外接运放才变成电压；波形用查表法——编译期算好sin表、运行期只P0=tab[i++]，频率=刷新速度/点数；0832两级锁存，教学用单缓冲(WR2/XFER接地直通)。

四、硬件接线说明

DAC0832 引脚接法说明
D0~D7P0.0~P0.7数据输入
CS74LS138 Y1片选，地址 0x2000（取决于译码接法）
ILE+5V输入锁存使能，常高
WR1WR（P3.6）写输入寄存器
WR2 / XFERGND接地 = DAC 寄存器直通（单缓冲）
Iout1 / Iout2运放反相端 / 地电流输出
Rfb运放输出→反馈片内反馈电阻
VREF+5V（或 TL431 基准）参考电压

为什么 CS 接 138 的 Y1 而不是 Y0：Y0 被 6264（上节课）占了；Y1 对应地址 0x2000~0x3FFF——两个器件不打架。这也演示了「地址空间怎么分给多个外设」的完整套路。

避坑 运放供电要看清：LM358 可单电源（+5V/GND）工作，输出 0~4.x V；如果输出是反相的（数字越大电压越低），把 Iout1/Iout2 接法对调或换同相接法。Proteus 里仿真运放要选对型号，LM358 别选成理想放大器（会省掉反馈的物理意义）。

五、完整代码

示例 1 直流与三角波；示例 2 正弦波查表。

示例 1：单缓冲输出直流 + 三角波

/* DAC0832 单缓冲模式：CS=Y1 → 地址 0x2000；WR2/XFER 接地 */
#include "reg52.h"
#include <absacc.h>        /* XBYTE 宏：按地址访问外部空间 */

#define DAC0832  XBYTE[0x2000]   /* 定义 DAC 端口地址 */

/* 软延时（约 1ms，可调） */
void delay_ms(unsigned int ms)
{
    unsigned int i, j;
    for (i = 0; i < ms; i++)
        for (j = 0; j < 120; j++);
}

void main(void)
{
    unsigned char v;

    /* 1. 直流输出：写 128 → 输出约 2.5V（VREF=5V） */
    DAC0832 = 128;
    delay_ms(1000);

    /* 2. 三角波：0 爬到 255 再降回 0，循环 */
    while (1) {
        for (v = 0; v < 255; v++) { DAC0832 = v; }   /* 上升沿 */
        for (v = 255; v > 0; v--) { DAC0832 = v; }   /* 下降沿 */
    }
}

六、代码逐段讲解

第一段：XBYTE 宏的意义

XBYTE[0x2000] 是 Keil 提供的宏：按给定地址访问 xdata 空间的一个字节。写 DAC0832 = 128 编译成一条 MOVX 写指令——产生完整的「P0 数据 + WR 脉冲」时序。为什么地址是 0x2000：138 的 Y1 区段起点；低 8 位地址写多少都行（0832 没有地址线，靠片选选中即可，惯例写 0x00）。

第二段：三角波的循环边界

for (v = 0; v < 255; v++) 与 for (v = 255; v > 0; v--)：上升沿输出 0~254，下降沿 255~1，循环衔接——为什么上下不对称：255 这个最大值只出现一次（峰），0 也只出现一次（谷），波形在峰谷处略有停留，看起来仍是对称三角波。如果想精确：两个循环都用 0~255 然后反向，但会重复端点，波形更抖。

第三段：查表法的两个关键

code 关键字把表放程序存储器（省 RAM，8KB 表占 Flash 不占片内）；128 + 127×sin 把 -1~+1 的正弦平移到 0~255 整数。为什么本课直接给出 256 项完整表：让你能直接编译运行看到波形；换点数/换波形时按公式 int(128 + 127*sin(2*PI*i/N)) 重新生成即可。频率公式：f = 1/(点数×每点耗时)，点数 256、每点 20µs → 约 195Hz。

七、现象演示与验证

  • 直流：写 128，万用表量输出 ≈ 2.5V（VREF=5V 时）。
  • 三角波：示波器看到 0~5V 三角波；调延时能看到频率变化。
  • 正弦波：示波器看到正弦；周期与 delay_us 对应。

验证方法：

  1. 写 0 和 255，量输出电压应约 0V 和 4.9V（反相接法则相反）——验证线性关系。
  2. 依次写 0、64、128、192、255，记录电压：应近似等间隔（0、1.25、2.5、3.75、4.9V）。
  3. 把 delay_us 从 20 改成 100，示波器频率变低 5 倍——验证「点数×延时=周期」。

九、课后练习与延伸
