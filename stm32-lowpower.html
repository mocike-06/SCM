低功耗模式（睡眠/停止/待机）

系列：STM32 进阶 更新：2026-10-25

电池设备（遥控器、传感器节点、手表）最怕「待机也耗电」。STM32 的功耗管理有三档：睡眠、停止、待机——越省电代价越大（唤醒越慢、能保住的状态越少）。本课对照 ESP32 的 Deep Sleep（esp32-deepsleep.html），讲透三档模式的功耗/唤醒/状态保留，做出「每 10 秒醒来报一次温湿度再睡」的低功耗节点。

一、本课目标与前置知识

学完本课你能做到：

  • 分清睡眠/停止/待机三档：功耗、唤醒源、RAM/寄存器保留情况的差别。
  • 用 HAL_PWR 接口进入停止模式，用 EXTI/RTC 唤醒。
  • 设计「周期采集 + 休眠」的低功耗节点主循环。

需要提前掌握的前置知识（对应学习路线阶段 4）：

  • RTC（stm32-rtc.html）：待机/停止模式用 RTC 唤醒最常用。
  • 外部中断（stm32-exti.html）：按键唤醒。
  • 时钟（stm32-clock.html）：停止模式关主时钟，唤醒要重新初始化。

本课会出现的新名词：WFI、睡眠模式、停止模式、待机模式、PWR、唤醒源、低功耗定时器、备份域、WU（唤醒）引脚。

二、基础概念铺垫

1. 三档功耗模式：省电与功能的「交易」

生活类比：手机屏幕关闭但后台待命 = 睡眠；飞行模式不联网 = 停止；关机拔电池再开要重新开机 = 待机。模式越深，省的电越多，但「回来干活」的成本（唤醒时间 + 状态恢复）也越高。

一句话定义（F103）： 睡眠：CPU 停转，外设/时钟全活——唤醒立即，RAM 全保（约 7mA@72MHz 降至约 2mA 量级）； 停止：CPU + 主时钟全停，仅 LSI/LSE 与 RTC 可活——RAM 保留，唤醒要重新初始化时钟（约 20µA）； 待机：除了复位/RTC/备份域几乎全断电——RAM 不保留，程序从头跑（约 2µA，最低功耗）。

例子：毫秒级响应要睡眠；周期采集要停止；「睡了就不管」的报警器用待机。

2. WFI：让 CPU「打盹」的指令

一句话定义：进入睡眠/停止模式的内核指令是 __WFI()（等待中断）或 __WFE()（等待事件）。执行后 CPU 停在此处，直到唤醒源到达才继续向下执行。HAL 封装：HAL_PWR_EnterSTOPMode(...) 内部就是配置 + __WFI()。

例子：主循环里执行 HAL_PWR_EnterSTOPMode 后，程序「暂停」在那一行，EXTI 中断一来到，从下一行继续跑。

3. 唤醒源：谁把芯片叫醒

一句话定义：睡眠：任何中断/事件都能唤醒；停止：EXTI 外部中断（PA0 等）、RTC 闹钟/唤醒定时器、串口等部分外设事件；待机：RTC 唤醒（WKUP 引脚 PA0 上升沿）、复位。周期唤醒的首选是 RTC 闹钟（对应 stm32-rtc.html 的 Alarm）。

例子：RTC 每 10 秒闹一次 → 唤醒 → 采一次数据 → 再睡——这是低功耗节点的标准节奏。

4. 状态保留：醒来还能不能接着干

一句话定义：睡眠：一切保留，醒来直接继续；停止：RAM 保留，但时钟树要重新初始化（唤醒后通常直接 SystemClock_Config() 重配 + 重新 Start 外设）；待机：RAM 全丢，程序从 main 重新执行（像复位）。变量要跨待机保留：放备份寄存器（RTC 备份域）。

例子：待机醒来判断「我是复位还是唤醒」：查 PWR_CSR 的 WUF 标志位。

三、原理介绍：三档功耗是怎么省出来的

低功耗不是一个开关，而是「逐级关掉芯片内部时钟和电源」的三档。理解每一档到底关了什么，就懂了为什么醒来要做不同的事。

整条链路：正常运行 → WFI 进 STOP（停主时钟、留 RAM）→ RTC 闹钟唤醒 → 时钟默认回 HSI → 重配 72MHz → 干活 → 再睡。

原理 1：睡眠/停止/待机——每档到底关了什么

  • Sleep 睡眠：只停 CPU 时钟，外设照常跑、RAM 全保留。任意中断都能立刻唤醒，醒来代码原地继续。省得最少（几 mA）。
  • Stop 停止：把 HSI/HSE/PLL 全停、主稳压器切低功耗，RAM 与寄存器内容保留，但所有外设时钟都停了。唤醒靠 EXT 或 RTC 闹钟，电流约 20µA。
  • Standby 待机：几乎全断电（连 RAM 也丢），本质是一次软复位，电流约 2µA，醒来程序从头跑。

原理 2：停止醒来为什么必须重配时钟

Stop 模式把所有主时钟都关了，唤醒后时钟树回到上电初态（HSI 8MHz）——不是你睡之前的 72MHz。若不立刻重新调 SystemClock_Config()，SysTick、串口波特率全错，HAL_Delay 直接失效。这是停止模式头号坑：醒来第一件事永远是把 72MHz 配回来，再用外设。

原理 3：待机为什么是「从头跑」、跨待机怎么存数

Standby 把 CPU 状态和 RAM 全断，醒来等同于复位、main 从头执行——行为最可预期，很多报警器就用它（醒来=重新初始化，代码简单）。代价是 RAM 里的变量全丢。要跨待机保留少量数据，就写进备份寄存器（由 VBAT 供电、待机不丢）。醒来后查 PWR_CSR 的 WUF 标志，就能区分「我是真复位进来的，还是待机被唤醒的」。

记忆点：Sleep=停 CPU 外设活、RAM 全保；Stop=主时钟全停 RAM 保留、醒来必须重配 72MHz（约 20µA）；Standby=几乎全断电 RAM 丢、程序从头跑（约 2µA）；进入用 HAL_PWR_EnterXMode+WFI；跨待机存数放备份寄存器；醒来查 WUF 区分复位/唤醒。

原理 4：PWR 寄存器 ↔ HAL 对照（PWR 挂在 APB1）

功耗管理由 PWR 外设负责，它挂在 APB1，用前要开 PWR 时钟（__HAL_RCC_PWR_CLK_ENABLE()，CubeMX 已自动开）。本讲动作对应的寄存器：

你做的事对应寄存器 / 位HAL 函数
进停止模式PWR_CR 的 LPDS 位(低功耗稳压器) + Cortex-M3 的 SLEEPDEEPHAL_PWR_EnterSTOPMode()
进待机模式PWR_CR 的 PDDS 位(深掉电) + SLEEPDEEPHAL_PWR_EnterSTANDBYMode()
使能 WKUP 引脚(PA0)PWR_CSR 的 EWUP 位HAL_PWR_EnableWakeUpPin()
读/清唤醒标志PWR_CSR 的 WUF 位__HAL_PWR_GET_FLAG / CLEAR_FLAG(PWR_FLAG_WU)
进睡眠模式不设 SLEEPDEEP，直接 __WFI()HAL_PWR_EnterSLEEPMode()

省电额外一招（教材提得少但实用）：即使不睡，进低功耗前把暂时不用的外设时钟关掉（__HAL_RCC_GPIOx_CLK_DISABLE() 等），每个挂在总线上的外设时钟停了都能省一点——FAQ 里「睡眠模式电流仍大」多半就是外设时钟没关。

四、硬件接线说明

低功耗是芯片内部行为，演示硬件极简：

资源用途说明
USB 串口打印「醒了」唤醒后串口报时（先重配时钟）
按键（PA0）EXTI 唤醒演示停止模式按键唤醒
万用表（电流档）串入 VCC 测电流对比三档模式实际功耗
RTC（片内）周期唤醒无需外接

为什么用万用表串电流：低功耗的「效果」就是电流数字——运行 30mA → 停止 20µA，肉眼可见的量级差距。测量技巧：万用表 mA 档串进 3.3V 供电线；唤醒瞬间电流脉冲会让读数跳动，用「最小/平均」档看稳态。

避坑 调试器（ST-Link）会干扰低功耗测量：J-Link/SWD 复位和时钟信号会阻止芯片真正休眠（电流虚高）。测量功耗时要断开调试器、用串口供电。另外开发板上的电源指示灯/LDO 自身也耗电，测到的是「板级功耗」不是「芯片功耗」——对比相对值即可。

五、完整代码

示例 1 停止模式 RTC 周期唤醒；示例 2 待机模式（从 main 重跑）。

示例 1：停止模式 + RTC 唤醒，每 10 秒醒一次

/* 低功耗节点：停止模式睡眠，RTC 每 10 秒唤醒，醒来打印后继续睡
   CubeMX：RTC 使能 WakeUp 定时器（中断），PWR 保持默认 */
#include "main.h"
#include <stdio.h>

extern RTC_HandleTypeDef hrtc;
extern UART_HandleTypeDef huart1;

int fputc(int ch, FILE *f)
{
    HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, 100);
    return ch;
}

/* 初始化 RTC 唤醒：每 10 秒触发一次闹钟中断 */
void rtc_wakeup_init(void)
{
    HAL_RTCEx_SetWakeUpTimer_IT(&hrtc, 9, RTC_WAKEUPCLOCK_CK_SPRE_16BITS);
    /* 9 + 1 = 10 秒（1Hz 基准，计数 N 则 N+1 秒） */
}

/* RTC 唤醒中断回调：HAL 自动调用（函数名固定） */
void HAL_RTCEx_WakeUpTimerEventCallback(RTC_HandleTypeDef *hrtc)
{
    printf("wake up!\r\n");       /* 唤醒提示（此处中断里轻量处理） */
}

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_RTC_Init();
    MX_USART1_UART_Init();
    rtc_wakeup_init();

    while (1) {
        printf("sleep...\r\n");
        HAL_Delay(50);            /* 等串口发完再睡 */

        /* 进入停止模式：低功耗稳压器 + WFI */
        HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);

        /* ===== 被唤醒后从这里继续 ===== */
        SystemClock_Config();     /* 关键：重配时钟 */
        MX_GPIO_Init();
        MX_USART1_UART_Init();    /* 串口也重新初始化 */
        HAL_Delay(10);
    }
}

示例 2：待机模式（醒来 = 程序重跑）

/* 待机模式：按 PA0（WKUP）唤醒，程序从 main 重新执行 */
#include "main.h"
#include <stdio.h>

extern UART_HandleTypeDef huart1;

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_USART1_UART_Init();

    printf("main start\r\n");

    /* 待机唤醒标志判断：1 = 上次是待机唤醒（不是普通复位） */
    if (__HAL_PWR_GET_FLAG(PWR_FLAG_WU) == SET) {
        printf("wakeup from standby!\r\n");
        __HAL_PWR_CLEAR_FLAG(PWR_FLAG_WU);   /* 清标志 */
    }

    /* 进入待机：先清除唤醒标志，配置 PA0 为 WKUP */
    __HAL_PWR_CLEAR_FLAG(PWR_FLAG_WU);
    HAL_PWR_EnableWakeUpPin(PWR_WAKEUP_PIN1);   /* PA0 上升沿唤醒 */
    HAL_PWR_EnterSTANDBYMode();                 /* 睡死，直到 PA0 */

    /* 不会执行到这里：待机唤醒后程序从 main 重头跑 */
}

六、代码逐段讲解

第一段：WakeUpTimer 的 N+1 秒机制

HAL_RTCEx_SetWakeUpTimer_IT(&hrtc, 9, RTC_WAKEUPCLOCK_CK_SPRE_16BITS)：第三个参数选 1Hz 计数基准（秒），计数值 9 → 9+1=10 秒后触发中断。为什么 +1：硬件计数到 0 才触发，所以设定值=目标秒数-1。这是 RTC 唤醒的经典细节，写错就成了 9 秒或 10 秒差 1。

第二段：EnterSTOPMode 的两个参数

PWR_LOWPOWERREGULATOR_ON 切低功耗稳压器（进一步省电）；PWR_STOPENTRY_WFI 用等待中断方式进入（对应 __WFI()）。唤醒后：WFI 一被中断打断，函数返回，程序从下一行执行——这行注释「从这里继续」标的就是这个意思。

第三段：醒来重配的三件套

SystemClock_Config() 恢复 72MHz 时钟树；MX_GPIO_Init() 恢复 IO；MX_USART1_UART_Init() 恢复串口。为什么只恢复这几个：停止模式里 RAM 没丢，变量值还在，但外设寄存器状态基于的时钟没了——凡依赖时钟的外设都要重配。RTC 本身在备份域（LSE 供电）不受影响，所以闹钟还继续走。

第四段：待机模式的「程序重跑」设计

待机唤醒不是「继续执行」而是复位重启——所以示例 2 在 main 开头判断 PWR_FLAG_WU：置位说明「我是被 PA0 唤醒的」，清掉标志继续正常流程。为什么 HAL_PWR_EnterSTANDBYMode 后面没有代码：一旦进入成功，代码永远到不了下一行（醒来重头跑）。为什么先 EnableWakeUpPin：待机时只有 WKUP 引脚（PA0）能唤醒，必须先配置再睡。

七、现象演示与验证

  • 停止模式：串口打印 sleep... → 10 秒后打印 wake up! 和 sleep...，循环。
  • 待机模式：串口打印 main start → 按 PA0 → 打印 wakeup from standby! → 再次 main start。
  • 电流对比：运行 ~30mA → 停止 ~20µA → 待机 ~2µA（板级含 LDO 会偏高）。

验证方法：

  1. 万用表 mA 档串供电线，分别观察运行/睡眠/停止/待机的稳态电流——记录四档数据。
  2. 把 WakeUpTimer 计数值从 9 改成 59（1 分钟），观察唤醒间隔变化。
  3. 注释掉醒来后的 SystemClock_Config，观察串口波特率错乱——亲眼验证「必须重配时钟」。

八、常见报错排查方案

报错现象可能原因解决方法
唤醒后串口乱码/程序跑飞没重配时钟树唤醒后先 SystemClock_Config() 再初始化外设
电流降不下来调试器连着 / LDO 指示耗电断开 ST-Link；用电池/稳压源供电测
RTC 唤醒不触发WakeUpTimer 计数值/时钟源配错核对 1Hz 基准与 N+1；确认唤醒中断已使能
停止模式按键唤不醒EXTI 没配成唤醒源停止模式用 EXTI（PA0 外部中断）唤醒，检查 NVIC 与 EXTI 线
待机后一直复位循环WKUP 引脚配置/电平不对待机只能 PA0 上升沿唤醒；清 WU 标志；防抖

九、课后练习与延伸

练习 1（必做）：把停止模式示例改成「醒后读取 RTC 时间并串口打印」——结合 stm32-rtc.html 的知识做完整时钟节点。

练习 2：测量并记录四档电流，算一算：2000mAh 电池、每 10 秒醒 1 次（每次 100ms），理论续航多少天。

练习 3（进阶）：待机模式 + 备份寄存器：待机前把计数写进备份寄存器，唤醒后读回累加——跨待机的「记忆」。

延伸学习：STM32 三篇进阶（CAN/内部 Flash/低功耗）完成。横向对比 ESP32 Deep Sleep：ESP32 也有 sleep 与 wakeup 源，思路一致、API 不同。回到 学习路线 阶段 4，低功耗 + 参数保存 + RTC 可以组合成完整的电池版温湿度记录仪毕设。
