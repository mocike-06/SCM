综合项目：温湿度采集

系列：51 单片机 进阶 更新：2026-10-24

收官实战：用 DHT11 这颗只用一根线的温湿度传感器读数，再把结果送到 LCD1602 上实时显示。本讲会把前面学的 IO、时序、液晶驱动全部串起来，重点搞懂「单总线」——一根线上怎么靠「高电平持续多久」区分 0 和 1。

一、本课目标与前置知识

学完本课你能做到：

  • 说清楚什么是单总线、DHT11 的起始信号/响应/数据位时序、校验和的作用。
  • 看懂 DHT11 读 40 位数据的代码，理解「等变高、数高电平宽度」的判别原理。
  • 把温湿度结果用 LCD1602 实时显示出来，能用哈气、手捏做物理验证。

需要提前掌握的前置知识（对应学习路线阶段 2 全部）：

  • 高低电平、sbit、IO 输入输出（mcu51-led.html）。
  • delay_ms / delay_us 粗延时的写法。
  • LCD1602 驱动（mcu51-lcd1602.html）：Lcd_Str 等函数可直接复用。

本课会出现的新名词：单总线、起始信号、响应信号、数据位宽度（0/1）、校验和、温湿度单位。

二、基础概念铺垫

1. 什么是单总线

生活类比：串口用了两根线（一发一收），LCD 用了 8 根数据线。DHT11 更省——只用一根线，既当输出又当输入，靠「什么时候谁说话、说多久」来区分。

一句话定义：单总线（1-Wire）是只用一根数据线（加共地）就能双向通信的协议：主机拉低发起请求，传感器再通过同一根线把数据发回来；线上平时被上拉电阻拉成高电平。

例子：DHT11 的 DATA 脚接 P2.3，同时接一个 4.7k~10kΩ 电阻到 VCC。平时这根线是高电平；单片机拉低表示「我要读数了」，之后松开，传感器再通过这根线返回 40 位数据。

2. 时序：起始信号与数据位 0/1 的宽度差异

生活类比：单总线没有时钟线，怎么区分 0 和 1？靠「高电平持续的时间长短」——像摩斯密码里的短点（·）和长划（—）。

一句话定义：DHT11 一次通信分三段——起始信号（主机拉低 ≥18ms 再拉高 20~40µs）、响应（传感器拉低 80µs 再拉高 80µs）、40 位数据（每位先约 50µs 低电平开头，接着高电平：26~28µs 表示 0，约 70µs 表示 1）。

例子：读每一位时，先等 50µs 低电平结束（线变高），延时约 30µs 后再看线还是不是高：如果已经变低了，说明高电平只有 26µs 左右 → 这一位是 0；如果还是高，说明高电平有 70µs → 这一位是 1。

3. 校验和

生活类比：快递送了 4 箱货，附一张纸条写「4 箱总重量」。你收到后把 4 箱称一遍加起来，和纸条对得上，就说明没漏没多。

一句话定义：DHT11 发完 40 位（5 个字节）后，最后一个字节是校验和 = 前 4 个字节相加的低 8 位。单片机收到后自己把前 4 个字节加起来，和第 5 个字节对得上，才说明这 40 位读对了。

例子：读到 hum_int=55、hum_dec=0、tem_int=26、tem_dec=0，和 = 81；校验和字节也应等于 81。不等就丢弃这次数据、显示错误，不显示乱值。

4. 温湿度单位

生活类比：DHT11 报的数就是日常说的「百分之几湿度」和「摄氏度温度」。

一句话定义：湿度单位是 %RH（相对湿度 0~100%）；温度单位是 ℃（摄氏度）。DHT11 精度不高（湿度 ±5%、温度 ±2℃），且小数位字节通常为 0（它只测整数温湿度）。

例子：hum_int=55 表示相对湿度 55%；tem_int=26 表示 26℃。对着哈气湿度会上升，手捏住温度会缓慢上升——这就是本项目的物理验证方法。

三、原理介绍：一根线怎么既能听又能说，还能分清 0 和 1

DHT11 是单总线（1-Wire）数字温湿度传感器，只用一根数据线双向通信。通信是严格的「主从问答」：主机（单片机）先发令、传感器再应答。

一次完整采集的流程：

  1. 单片机把 DATA 拉低 ≥18ms 发起始信号，再拉高 30µs 并转输入。
  2. DHT11 回应答：拉低 80µs + 拉高 80µs，表示「准备好了」。
  3. 循环读 5 字节：每位先 50µs 低电平开头，高电平长短代表 0/1。
  4. 前 4 字节相加与第 5 个校验字节比对，相等才认数据有效。
  5. 有效就送 LCD，无效显示 "DHT11 Err"。

40 位格式：湿度整数+湿度小数+温度整数+温度小数+校验和；校验和=前 4 字节之和的低 8 位。

原理 1：单总线为什么必须接一颗上拉电阻——开漏双向的本质

这根数据线是开漏（open-drain）结构：主机和传感器都只能把线拉低，谁也没本事主动把线拉高。那空闲时高电平从哪来？靠外接的 4.7k~10kΩ 上拉电阻——没人拉低时，电阻把线默默托到 VCC。这就是「双向共用一根线」的物理基础：两方都只会「拉低说话、松手释放」，靠上拉电阻回高电平，天然不会打架（不像两个推挽输出硬接会短路）。没有这颗电阻，线电平飘忽，起始信号发不出去、传感器也应答不了——这是单总线电路第一必查。

原理 2：没有时钟线，怎么靠「高电平多宽」分出 0 和 1

单总线没有独立时钟线，双方约定用高电平持续时间的长短来编码：每一位都先固定给约 50µs 低电平当「位头」，紧接着——

  • 高电平约 26~28µs → 这一位是 0；
  • 高电平约 70µs → 这一位是 1。

读代码的关键技巧：不用真去量高电平精确多宽，而是「等 50µs 低位过去 → 延时约 30~40µs → 在这段时间点采样线电平」。如果是 0，高电平早就在 30µs 左右结束了，此时线已变低，读到 0；如果是 1，70µs 的高电平还没结束，此时线仍高，读到 1。本质是「在 28µs 和 70µs 的中点附近采样」，靠时间窗口把两种宽度区分开——所以读代码里全是「等变高、等变低、延时再判断」的微秒级操作，时序余量极小，CPU 中途不能被打断。

原理 3：校验和为什么能防「读错」

单总线时序要求苛刻，稍不准就读错位。DHT11 多发一个校验和字节：它自己把前 4 个字节加起来取低 8 位一起发出来。主机收到后自己再把前 4 字节加一遍，和第 5 个字节比对——一致说明这 40 位没读错位；不一致说明这次时序飘了、数据作废。这是软件层面的最后一道保险：即使上拉太大、线太长导致个别位读歪了，校验和大概率能拦下错误数据，避免你看到一个莫名其妙的温度。所以代码里「和校验不过就显示 Err 而不是硬显示」是必要的，不是多余。

记忆点：单总线是开漏结构、双方都只会拉低，空闲高电平靠外接上拉电阻，不接就读不到；没时钟线，用高电平宽度编码（短≈28µs=0、长≈70µs=1），靠「延时30µs后采样」在时间窗口里区分；40 位末字节是校验和=前4字节之和低8位，对不上就丢弃这次读数。

四、硬件接线说明

DHT11 数据线接 P2.3，并接一个 4.7k~10kΩ 上拉电阻到 VCC；LCD1602 沿用上一讲的接线。

模块引脚单片机引脚说明
DHT11 DATAP2.3接 10kΩ 上拉到 VCC
DHT11 VCC / GND5V / GND供电
LCD1602 RS/RW/EP2.0/P2.1/P2.2同上一讲
LCD1602 D0~D7P0.0~P0.78 位数据口

为什么这样接：

  • 为什么 DATA 要接上拉电阻？ 单总线空闲时必须保持高电平。DHT11 不输出时这根线是高阻态，靠上拉电阻把它拉到 VCC；没这个电阻，线电平飘着，起始信号根本发不出去。
  • 为什么 DHT 单独用 P2.3、不和 LCD 共用？ LCD 占用 P0 全部 + P2.0~2.2，DHT 用 P2.3 互不干扰；共用引脚会让液晶写数据时把 DHT 的线乱拉。
  • 为什么 VCC 用 5V？ DHT11 是 5V 器件，3.3V 下虽然有时能用但读数不稳，统一 5V 最省心。

五、完整代码

整合 DHT11 读取与 LCD1602 显示：第一行显示湿度，第二行显示温度，约 1 秒刷新一次。

/* 综合项目：DHT11 温湿度 + LCD1602 显示 */
#include <reg52.h>
#include <stdio.h>

#define LCD_DATA P0
sbit RS = P2^0;
sbit RW = P2^1;
sbit E  = P2^2;
sbit DHT = P2^3;            /* DHT11 数据线 */

unsigned char hum_int, hum_dec, tem_int, tem_dec, check;

void delay_ms(unsigned int ms) {
    unsigned int i, j;
    for (i = 0; i < ms; i++)
        for (j = 0; j < 120; j++);
}
void delay_us(unsigned int us) { while(us--); }   /* 粗略微秒延时 */

/* ---- LCD1602 底层（沿用上一讲） ---- */
void Lcd_Cmd(unsigned char c) {
    RS=0; RW=0; LCD_DATA=c; E=1; delay_us(10); E=0; delay_us(100);
}
void Lcd_Dat(unsigned char d) {
    RS=1; RW=0; LCD_DATA=d; E=1; delay_us(10); E=0; delay_us(100);
}
void Lcd_Init(void) {
    Lcd_Cmd(0x38); Lcd_Cmd(0x0C); Lcd_Cmd(0x06); Lcd_Cmd(0x01);
}
void Lcd_Str(unsigned char row, unsigned char col, unsigned char *s) {
    Lcd_Cmd((row==0 ? 0x80 : 0x80+0x40) + col);
    while (*s) Lcd_Dat(*s++);
}

/* ---- DHT11：读一个字节（8 位） ---- */
unsigned char DHT_Read_Byte(void) {
    unsigned char i, dat=0;
    for (i=0; i<8; i++) {
        while(DHT == 0);        /* 等每位开头的 50us 低电平结束（线变高） */
        delay_us(30);           /* 等 30us：此时 0 的高电平(26us)已结束，1 的还在 */
        dat <<= 1;
        if (DHT == 1) {         /* 线还是高 => 高电平约 70us，这一位是 1 */
            dat |= 1;
            while(DHT == 1);    /* 等本次高电平结束，准备下一位 */
        }
    }
    return dat;
}

/* ---- DHT11：完整读一次，返回 1=成功 0=失败 ---- */
bit DHT_Read(void) {
    DHT = 0; delay_ms(20);      /* 主机起始：拉低 >=18ms */
    DHT = 1; delay_us(30);     /* 拉高 20~40us 后转为接收 */
    if (DHT == 1) return 0;     /* 没收到响应（线没被传感器拉低） */
    while(DHT == 0);            /* 等 80us 低响应结束 */
    while(DHT == 1);            /* 等 80us 高响应结束 */
    hum_int = DHT_Read_Byte();
    hum_dec = DHT_Read_Byte();
    tem_int = DHT_Read_Byte();
    tem_dec = DHT_Read_Byte();
    check   = DHT_Read_Byte();
    /* 校验：前4字节之和的低8位 == 第5字节 */
    return (check == (hum_int+hum_dec+tem_int+tem_dec));
}

void main(void) {
    char buf[16];
    Lcd_Init();
    while (1) {
        if (DHT_Read()) {
            sprintf(buf, "Humi: %d%%", hum_int);   /* 显示湿度 */
            Lcd_Str(0, 0, buf);
            sprintf(buf, "Temp: %d C", tem_int);   /* 显示温度 */
            Lcd_Str(1, 0, buf);
        } else {
            Lcd_Str(0, 0, "DHT11 Err");            /* 校验失败/没接好 */
        }
        delay_ms(1000);                             /* DHT11 采样间隔 ≥1 秒 */
    }
}

进阶实例：超限声光报警（改 main）

在上面 DHT_Read / LCD 驱动不变的前提下，给 main 加一个报警：温度超过 30℃ 或湿度低于 30% 时点亮 P1.0 的 LED（代表报警），正常时熄灭。这是「传感器读值 → 判断 → 执行机构」的最小闭环。

/* 进阶：保留上面所有函数，把 main 替换成本段 */
sbit ALARM = P1^0;          /* 报警 LED：0 亮 1 灭 */

void main(void) {
    char buf[16];
    Lcd_Init();
    while (1) {
        if (DHT_Read()) {
            sprintf(buf, "Humi: %d%%", hum_int);
            Lcd_Str(0, 0, buf);
            sprintf(buf, "Temp: %d C", tem_int);
            Lcd_Str(1, 0, buf);
            /* 报警判断：温度偏高或湿度偏低就亮灯 */
            if (tem_int >= 30 || hum_int <= 30) {
                ALARM = 0;      /* 触发报警，点灯 */
            } else {
                ALARM = 1;      /* 正常，灭灯 */
            }
        } else {
            Lcd_Str(0, 0, "DHT11 Err");
        }
        delay_ms(1000);
    }
}

烧录后：哈气让湿度持续偏低（或手捏让温度升到 30℃ 以上）时，P1.0 报警 LED 应点亮；恢复正常后自动熄灭。若报警阈值不符预期，改 30 这两个数即可。

六、代码逐段讲解

第 1 段：Lcd_Cmd / Lcd_Dat / Lcd_Init / Lcd_Str（第 14~25 行）

在做什么： 把上一讲 LCD1602 的驱动函数原样搬过来。

为什么这么写： 本项目是「传感器 + 显示」的综合，LCD 驱动属于已掌握的工具，直接复用，把注意力放在 DHT11 时序上。

不写会怎样： 不初始化 LCD，直接发数据，屏幕一片乱码或全白。

第 2 段：DHT_Read_Byte 读一个字节（第 27~39 行）

在做什么： 连续读 8 位，每位：等 50µs 低电平过去 → 延时 30µs → 看线电平 → 判断是 0 还是 1。

为什么这么写： 每位先有 50µs 低电平（区分位的开始），随后高电平 26µs（0）或 70µs（1）。延时 30µs 这个临界点是关键：30µs 时，0 的高电平（26µs）已经结束、线已变低；1 的高电平（70µs）还在、线仍高——此时读线电平，1 和 0 自然分开。dat <<= 1 是因为先发的是高位。

不写会怎样： 不延时 30µs 直接读 → 每位都读到高电平（50µs 低电平刚结束），全是 0xFF；延时位置错 → 温湿度全是乱值。

第 3 段：DHT_Read 起始 + 校验（第 41~52 行）

在做什么： 主机拉低 20ms 发起始信号 → 检测响应 → 读 5 个字节 → 校验和比对。

为什么这么写： if(DHT==1) return 0 是「传感器没响应」的保护：如果上拉电阻没接、传感器没接好，起始信号后线仍是高，直接判失败显示 Err，而不是读出一堆无效数。最后用校验和把关，只有前 4 字节加起来等于第 5 字节才认为数据可信。

不写会怎样： 不校验 → 时序偶尔错位时屏幕上温湿度乱跳；不检测响应 → 接线松动时程序卡死在 while(DHT==0) 之类的等待里。

第 4 段：main 主循环（第 54~66 行）

在做什么： 每秒读一次 DHT11，成功就格式化温湿度送 LCD，失败显示 Err。

为什么这么写： DHT11 数据手册要求采样间隔至少 1 秒，读太频繁它来不及稳定输出。%% 是 sprintf 里打印一个 % 号的转义写法。

不写会怎样： 间隔太短（如 100ms）→ 读数恒为 0 或跳变剧烈；不判失败就显示 → 用户看到错误数据以为是真的。

七、现象演示说明

烧录后，LCD1602 第一行显示当前湿度（如 Humi: 55%），第二行显示当前温度（如 Temp: 26 C），每秒刷新一次。

可量化的验证方法：

  • 哈气实验： 对着 DHT11 哈一口气，湿度数值应在 1~2 秒内明显上升（比如从 50% 跳到 70%+），过十几秒回落——证明湿度链路真的在测。
  • 手捏实验： 用手指捏住传感器金属帽，温度应从室温缓慢上升 1~3℃——证明温度链路有效。
  • 错误提示实验： 断开 DATA 线，屏幕应显示 DHT11 Err 而不是乱跳的数字——证明校验和保护起作用。

八、常见报错排查方案

报错现象可能原因解决方法
一直显示 DHT11 Err数据线没接上拉电阻 / 接线松DATA 与 VCC 之间接 10kΩ 电阻，重插杜邦线
读数恒为 0 或固定乱值微秒级延时不准导致时序错位按 11.0592MHz 校准 delay_us，必要时适当加长等待时间
温度湿度数字跳变剧烈读太频繁或校验没通过仍显示校验和不对就不刷新显示，并把采样间隔保持 1 秒以上
LCD 与 DHT 共用 IO 互相干扰引脚冲突确认 LCD 用 P0/P2.0~2.2，DHT 单独用 P2.3，不共用
哈气湿度不变化DHT11 是假货/坏件，或 VCC 只有 3.3V换一颗正品 DHT11；确认 VCC 接 5V
开了定时器/串口中断后 DHT11 读数随机错读 40 位的微秒级时序被中断打断，延时偏移导致位采样错位DHT_Read() 期间用 EA=0 关总中断、读完再 EA=1 恢复；这是单总线/软件时序类驱动的通用考点
