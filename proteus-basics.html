Proteus 入门与原理图绘制

系列：Proteus 仿真 入门 更新：2026-10-25

学习路线的第 3 站：仿真先行、再碰实物。本课从零认识 Proteus，学会新建工程、放元件、连线和接电源网络，亲手画出 51 最小系统原理图——下一课加载 HEX 程序就能看到它「跑」起来。

一、本课目标与前置知识

学完本课你能做到：

  • 说清「仿真」和「实物」的关系，知道 Proteus 能做什么、不能做什么。
  • 新建 Proteus 工程，放置单片机、电阻、LED、晶振、电容、按键等元件。
  • 完成连线并正确布置电源网络（VCC/GND），画出可运行的 51 最小系统。

需要提前掌握的前置知识：

  • 51 最小系统电路原理：知道电源、晶振、复位三要素，本课就是把它搬到电脑里。
  • C 语言基础三篇：知道程序要编译成 hex 文件。

本课会出现的新名词：仿真、原理图、元件库、放置/连线、网络标号、电源端子、电气规则检查（ERC）。

二、基础概念铺垫

1. 仿真：在电脑里「虚拟搭电路」

生活类比：仿真就像玩「电路版模拟城市」——不用买电阻、不用焊板子，在软件里拖元件、连线，软件按真实器件特性帮你算电压电流，甚至能跑程序。

一句话定义：Proteus 是英国 Labcenter 出品的电路仿真软件，既画原理图又跑仿真：把 Keil 编译出的 hex 文件加载进虚拟单片机，就能看到 LED 闪烁、数码管跳动、串口收发，原理与实物完全一致。

例子：没有开发板时，用 Proteus 就能完成 51 全系列实验；但要注意仿真≠实物——仿真里晶振精度、器件温度、接线接触问题都不存在，实物可能因这些原因不工作，所以仿真通过后仍需谨慎上实物。

2. 元件库：Proteus 的「电子元件超市」

一句话定义：Proteus 左侧的元件选择面板就是库，搜索关键字放元件。本课常用：AT89C52（51 单片机，仿真用 AT89C52 代替 STC89C52）、RES（电阻）、LED-RED（发光二极管）、CAP（电容）、CRYSTAL（晶振）、BUTTON（按键）、POWER（电源端子 VCC/GND）。

例子：搜不到某个元件不一定是库里没有，可能是分类名不同（如电容的电解是 CAP-ELEC）；实在没有再走 元件库导入教程。

3. 网络标号与电源端子：不画线也能「连接」

生活类比：同一栋楼的房间里都标着「NET-01」，表示它们属于同一条线路——网络标号就是给导线起名字，名字相同=电气上相连，即使图上没直接画线。

一句话定义：把鼠标放导线/引脚端点会变成 ✎ 符号，点击即可输入网络标号；POWER 元件拖出 VCC、GND 端子接到对应位置，就是「电源网络」——51 最小系统里几十个引脚的电源不能靠一根根线拉，全靠这两个端子。

例子：单片机 40 脚 VCC、9 脚复位电容、LED 阳极都接 VCC 端子；20 脚 GND、LED 阴极、晶振电容都接 GND 端子。

4. 电气规则检查（ERC）

一句话定义：画完图后 Proteus 可以检查「有没有接错的电」——比如两个输出端接在一起、电源没接、悬空引脚等，用 System → Check Electrical Rules 或快捷键调出。新手先知道这个功能存在，出现红色波浪标记就去查。

三、原理介绍：Proteus 凭什么能在电脑里「演」出一块真电路板

从写代码到仿真出画面，完整链条：

  1. Keil 写 C 编译出 .hex（机器码）。
  2. Proteus 画原理图：放元件、连线、接电源网络。
  3. 双击单片机 → 加载 hex（相当于把程序烧进虚拟芯片）。
  4. 点左下角 ▶ 运行：虚拟芯片逐条执行，LED 亮灭、串口输出可见。

原理 1：仿真引擎怎么工作——每个元件都是一段「行为模型」

Proteus 里的 8051、LED、电阻并不是真硬件，而是每个元件背后挂着一段描述它行为的模型文件(.MOD)。你放一颗虚拟 8051，它内部是一个指令集模拟器：你加载的 hex 被它逐条取指执行，每个机器码对应的 IO 寄存器(如 P1)状态变化，再实时反映到连在 P1 上的虚拟 LED 模型上。数字元件按「电平高低」跳变，模拟元件(电阻/电容/运放)按电路方程算电压电流——数字+模拟混合仿真。这就是为什么「数字逻辑层面」(代码、IO 电平、定时器、串口字节)和实物高度一致。

原理 2：ERC 为什么能查出「悬空 / 短路」

ERC(电气规则检查)是在你点运行前，先按元件模型里声明的引脚类型扫一遍整张图：每个引脚模型都标了它是「输出型/输入型/电源型/无源型」。于是它能机械地判出两类错：两个输出脚接在同一根网线上（一个推高一个拉低=硬件短路，模型标为冲突）、该接信号的输入脚悬空没接（模型标为 floating）。它不懂你的设计意图，只按引脚类型做规则匹配——所以红色波浪线=模型认为这里电气上不对，先去查。

原理 3：为什么「仿真能跑」不等于「实物能跑」——仿真把缺陷理想化掉了

仿真天然理想化掉的部分：①每根线理想导通，没有虚接/接触不良/杜邦线干扰；②晶振绝对精准(实物有±20ppm 漂移、温度影响)；③没有驱动能力边界——仿真一个引脚随便点多少 LED 都不衰减(实物要算灌/拉电流)；④第三方元件模型(如 DHT11)只演时序应答，不演真实上电自检/校准。结论：仿真负责提前消灭「程序逻辑+时序+接线拓扑」这三类最容易错的问题；实物最后还要单独过「供电、接触、驱动余量」三关——所以本站坚持「先仿真后实物」，把能在电脑里消灭的 bug 先消灭掉。

记忆点：Proteus仿真=每个元件背后一段行为模型(.MOD)，虚拟8051是指令集模拟器、逐条跑你的hex；ERC按引脚类型机械查「两输出短接/输入悬空」，不懂意图只对规则；仿真理想化掉了虚接/晶振漂移/驱动边界，所以仿真过了实物仍要过供电与接触关。

四、工程搭建步骤（跟着做）

第 1 步：新建工程。打开 Proteus 8，点 File → New Project，填名称与保存路径，一路 Next 直到出现原理图编辑区（蓝色网格）。

第 2 步：放置单片机。左侧面板点 P（Pick Devices），搜索 AT89C52 双击放入，再按同样方法放：8 个 RES（阻值双击改 220）、8 个 LED-RED、1 个 CRYSTAL（12MHz）、2 个 CAP（22pF）、1 个 CAP-ELEC（10µF）、1 个 RES（10kΩ）、1 个 BUTTON。

第 3 步：搭最小系统外围。按 最小系统原理 连接：40 脚接 VCC、20 脚接 GND；31 脚 EA 必须接 VCC（使能内部程序存储器，否则单片机无法执行内部 Flash 里的程序）；19/18 脚（XTAL1/XTAL2）接晶振两端，晶振两脚各接 22pF 电容到 GND（电容是并联到地，不是串联）；9 脚 RST 接 10µF 电解电容正极（电容负极接 VCC），RST 节点（电容正极）再经 10kΩ 电阻接地——上电瞬间 RST 被电容充电拉高、随后经电阻泄放回低，形成复位脉冲（具体极性以实物教程为准，仿真重在看结构）。

第 4 步：接 LED 电路。8 颗 LED 阳极统一接 VCC 端子，阴极各自经 220Ω 电阻接到 P1.0~P1.7（DIP40 封装的 1~8 脚，不是 21~28 脚——那是 P2 口）。

第 5 步：接按键。BUTTON 一脚接 GND，另一脚接 P3.2（12 脚）。P3 口是准双向口、自带弱上拉：按键松开读回高电平、按下拉低，无需外接上拉电阻。

第 6 步：布置电源网络。在元件搜索框搜 POWER，拖出 VCC 和 GND 端子（同名可复制多个），把刚才标记的每个 VCC/GND 位置都用端子接好。

第 7 步：保存并检查。Ctrl+S 保存工程；之后点 System → Check Electrical Rules 看是否有红色错误标记。

五、配套程序准备

画完图先不急，本课不加载程序；但建议把下一课要用的 hex 提前编译好。在 Keil 里新建工程（型号 STC89C52），粘贴 C 语言基础入门 里的 LED 闪烁代码，编译通过后记录 hex 输出路径（默认在工程目录的 Objects 或 Output 文件夹，文件名为工程名.hex）。

/* 配套程序：P1 口 8 颗 LED 闪烁（编译生成 led.hex 备用） */
#include <reg52.h>

void delay_ms(unsigned int ms) {
    unsigned int i, j;
    for (i = 0; i < ms; i++)
        for (j = 0; j < 120; j++);
}

void main(void) {
    while (1) {
        P1 = 0x00;          /* 全亮 */
        delay_ms(300);
        P1 = 0xFF;          /* 全灭 */
        delay_ms(300);
    }
}

第二实例：单灯跑马灯（同一套 Proteus 电路可直接仿真）。把上面「全亮全灭」换成「一颗灯从 P1.0 移到 P1.7」，烧进同一个 hex 就能在仿真里看到移动效果——同一张电路图、只换 hex 就能对比不同程序，这正是仿真调试的便利：

void delay_ms(unsigned int t) {   /* 11.0592MHz 下粗略延时 */
    unsigned int i, j;
    for (i = 0; i < t; i++)
        for (j = 0; j < 114; j++);
}

void main(void) {
    unsigned char i;
    while (1) {
        for (i = 0; i < 8; i++) {
            P1 = ~(1 << i);   /* 只让第 i 位为0=那颗灯亮，其余灭 */
            delay_ms(250);
        }
    }
}

为什么它能直接在你刚画好的图上跑：它和全闪程序用的是同一套 P1 口接线（8 颗 LED），只是内部逻辑从「整字节翻转」变成「逐位移位」。这说明Proteus 仿真里改程序不用重新画图——重编 hex、在单片机属性里重新指一下 hex 路径即可。

六、程序与工程的配合逻辑

很多新手困惑「为什么画图课要编译程序」——因为 Proteus 的仿真对象是 hex 文件，不是 .c 文件。链条是：

  1. Keil 把 .c 编译成 .hex（纯机器码，芯片能读懂）。
  2. Proteus 双击 AT89C52 → Program File 一栏选这个 hex → 点 OK。
  3. 运行仿真时，虚拟 CPU 从 hex 里读指令执行——和真实烧录到 Flash 是一回事。

所以「程序」和「电路」是两条独立的生产线，在 hex 加载这一步汇合。本课把 hex 准备好，下一课直接双击单片机加载即可；如果你现在就想看效果，也可以直接跳到 仿真调试教程 边画边跑。

记忆点：Keil 产 hex（软件生产线），Proteus 跑 hex（硬件仿真线），加载 hex 那一刻两条线合并。

七、本课成果检查

  • 画面完整：AT89C52 周围有晶振、复位、电源、8 颗 LED、按键，无悬空的引脚标记（绿点）。
  • 电源网络：所有 VCC 处都有 VCC 端子、所有 GND 处都有 GND 端子，而不是空着。
  • 属性正确：双击每个元件确认：晶振 12MHz、电阻 220Ω、电解电容 10µF。

验证方法：执行电气规则检查（System → Check Electrical Rules），不应出现红色错误项；把鼠标悬停每个引脚，能看到连线跟随移动，说明连接有效。

九、课后练习与延伸

练习 1（必做）：把本课电路画出来并保存为 minisys.pdsprj，完成电气规则检查。

练习 2：在电路上加一个 4 位共阴数码管（元件 7SEG-MPX4-CC），段选接 P2.0~P2.7，位选接 P3.0~P3.3——为定时器计数练习提前布线。

练习 3（进阶）：把按键改为接 INT0（P3.2）并标注网络名 INT0，预习外部中断章节的接法。

延伸学习：画完图立即进入 Proteus 仿真调试与虚拟仪器，加载刚才的 hex 让 LED 闪起来；碰到「元件库里没有某元件」再看 元件库导入。
