WiFi 连接（STA 模式）与 HTTP 请求

系列：ESP32 入门 更新：2026-10-25

让 ESP32 像手机一样连上家里的 2.4GHz 路由器，拿到内网 IP，再通过 HTTPClient 库向公网接口发起一次 GET 请求。本讲从零讲清 STA/AP 区别、SSID 与密码、IP 地址是什么、为什么 ESP32 只认 2.4GHz，初步体验「设备上云」。

一、本课目标与前置知识

学完本课你能做到：

  • 理解 STA 与 AP 两种 WiFi 角色的区别，知道家里路由器属于哪一种。
  • 用 WiFi.begin(ssid, password) 让 ESP32 连上路由器，并拿到 IP 地址。
  • 用 HTTPClient 库向 httpbin.org/get 发起一次 GET 请求并打印返回内容。

需要提前掌握的前置知识（对应学习路线阶段 5 前两篇）：

  • 环境搭建（esp32-env.html）：能烧录、会开串口监视器。
  • GPIO 基础（esp32-gpio.html）：会写 setup/loop、会用 Serial.println 调试。
  • C 语言字符串：知道 const char* 是什么。

本课会出现的新名词：STA、AP、SSID、密码、IP 地址、DHCP、WiFi.begin、WiFi.status、WiFi.localIP、HTTPClient、HTTP GET、状态码 200、2.4GHz 频段。

二、基础概念铺垫

1. STA 与 AP：ESP32 当「手机」还是当「路由器」

生活类比：WiFi 世界里有两种角色。AP（Access Point）像「路由器/热点」，负责向外广播信号、发号施令；STA（Station）像「手机/电脑」，是过来连热点的终端。你家的小米/华为路由器就是 AP，你的手机、笔记本就是 STA。

一句话定义：STA 模式下 ESP32 是一台无线终端，去连接已存在的路由器（AP），由路由器分配 IP、做上网转发；AP 模式下 ESP32 自己当热点，手机直连它但没有外网。

例子：本课用 STA 模式——ESP32 连你家路由器，从而能访问互联网；如果用 AP 模式，手机能连 ESP32 但上不了网。

2. SSID 与密码：WiFi 的「名字」和「门钥匙」

生活类比：SSID 就是 WiFi 的名字（你手机 WiFi 列表里看到的那个名字，如「ChinaNet-xxx」），密码就是进这个房间的钥匙。ESP32 要先报名字和钥匙，路由器才放行。

一句话定义：SSID 是 WiFi 网络的字符串标识，密码是 WPA2 加密密钥；WiFi.begin(ssid, password) 就是把这两样交给路由器去握手。

例子：WiFi.begin("MyHomeWiFi", "12345678"); 表示要连名为 MyHomeWiFi、密码 12345678 的路由器。注意大小写敏感。

3. IP 地址：局域网里的「门牌号」

生活类比：连上路由器后，路由器会给每台设备分配一个内网门牌号，比如 192.168.1.100。有了这个号，ESP32 才能和路由器、和其他设备互相找到对方。

一句话定义：IP 地址是设备在网络中的逻辑地址（如 192.168.x.x），由路由器通过 DHCP 自动分配；用 WiFi.localIP() 可以读回 ESP32 拿到的 IP。

例子：连接成功后串口打印 WiFi.localIP()，可能输出 192.168.1.105——这就是 ESP32 在你家局域网里的门牌号。

4. WiFi.status()：连接状态的「仪表盘」

生活类比：WiFi.begin 发起连接后，不是马上就连上了——像打电话拨号，要等几秒对方接。status() 就是那个「拨号中/已接通/占线」的状态灯。

一句话定义：WiFi.status() 返回一个枚举值，WL_CONNECTED（值 3）表示连上了，其它值表示还在连或失败。

例子：用 while (WiFi.status() != WL_CONNECTED) { delay(500); } 死等，直到状态变成已连接再继续往下走，避免读到 0.0.0.0 的假 IP。

5. 2.4GHz 频段：ESP32 只听这一段

生活类比：WiFi 信号分两个频道——2.4GHz（穿墙好、速度慢）和 5GHz（速度快、穿墙差）。ESP32 这台收音机只能调到 2.4GHz 那个频段，5GHz 的信号它根本收不到。

一句话定义：ESP32 硬件只支持 2.4GHz WiFi，不支持 5GHz。双频路由器若把 2.4G/5G 合并成同一个 SSID，ESP32 偶尔会连不上，需要在路由器后台单独开一个 2.4G 的 SSID。

例子：你家路由器若叫「HomeWiFi」同时跑 2.4G 和 5G，建议在后台再开一个「HomeWiFi_2.4G」专门给 ESP32 用，避免它随机连到 5G 而失败。

6. TCP/IP 五层模型：一次联网请求经过了哪几层

生活类比：你寄一个快递，要经过打包（应用层内容）→ 贴面单（传输端口）→ 写收件地址（网络层 IP）→ 选路段（链路层）→ 装车上路（物理层）。网络数据也是这样一层一层封装、一层一层拆开的。

一句话定义：教材把互联网协议栈分为五层——物理层（电磁波）、链路层（802.11 WiFi 帧）、网络层（IP 地址路由）、传输层（TCP/UDP 端口）、应用层（HTTP/MQTT/NTP）。ESP32 的 WiFi 属于链路层，IP 属网络层，TCP 属传输层，HTTP GET 属应用层。

例子：本课发 HTTP GET，数据在应用层是 GET /get HTTP/1.1 文本 → 下封成 TCP 段（带端口 80）→ 再封成 IP 包（带目的 IP）→ 再封成 802.11 无线帧 → 变成 2.4GHz 电磁波发出去。对面服务器一层层拆包，原理完全对称。

三、原理介绍

ESP32 联网发 HTTP 请求，背后是四层协议栈叠在一起：802.11 无线帧 → WiFi 固件 → TCP/IP → HTTP。你写的 WiFi.begin、HTTPClient 只是最上面一层 API，下面每一步都有真实的握手与报文。

一次「连上路由器并 GET 到网页」的链路：扫描 → 认证 → 关联 → DHCP 拿 IP → 建 TCP 连接 → 发 HTTP 请求 → 收响应。

原理 1：STA 关联四步——WiFi.begin 背后发生了什么

  1. 扫描：ESP32 在 2.4GHz 的 1~13 信道上各发探测请求，路由器回应自己的 SSID。
  2. 认证：双方按 WPA2 算法四次握手，验证「你知道密码」——密码错在这一步就被拒。
  3. 关联：认证通过后正式挂到路由器，建立 802.11 链路。
  4. DHCP：ESP32 在局域网里广播「请给我分配一个 IP」，路由器回一个 192.168.x.x——拿到 IP 后状态才变成 WL_CONNECTED。

为什么要等 1~3 秒：这四步里 WPA2 四次握手 + DHCP 都要多次无线往返，比网线慢一个数量级。这就是为什么 WiFi.status() != WL_CONNECTED 要轮询等待，而不是 begin 完立刻就能上网。

原理 2：为什么 ESP32 只支持 2.4GHz

无线射频是有硬件成本的：5GHz 射频前端（PA、滤波器、天线匹配电路）比 2.4GHz 贵且耗电。ESP32 定位是低功耗 IoT，芯片里只集成了 2.4GHz 射频（2412~2484MHz，14 个信道）。副作用：2.4GHz 很挤——蓝牙、微波炉、邻居的 WiFi 都挤在这一段，所以教程建议离路由器近、远离微波炉。这也是「频段限制」提示框背后的物理原因。

原理 3：HTTP GET 报文——http.GET() 到底发了什么

连上路由器后，ESP32 就是一台有 IP 的设备。它和服务器之间先由 WiFi 固件自动完成 TCP 三次握手，然后在这条连接上发一段纯文本请求：首行是 GET /get HTTP/1.1，再带一行 Host: httpbin.org。服务器回：状态行 HTTP/1.1 200 OK + 响应头 + 空行 + 响应体（JSON 或 HTML）。

http.GET() 的返回值就是那个 200；http.getString() 读出响应体；http.end() 关闭 TCP。为什么 end() 不能忘：每条 TCP 连接都占内存和端口号，不关就泄漏，几次请求后 WiFi 就动不了了。公网测试用 httpbin.org/get——它会把你的请求头、来源公网 IP 回显成 JSON，最适合验证「ESP32 真的上了网」。

记忆点：联网四步=扫描→WPA2 认证→关联→DHCP 拿 IP；握手慢所以要轮询等；ESP32 只有 2.4GHz 射频（硬件决定，不是设置问题）；HTTP=文本请求-响应，200=成功；end() 必须关 TCP 否则泄漏。

四、硬件接线说明

WiFi 是片上外设，不需要任何外部接线，仅靠 USB 供电即可。请确保无线路由器开启 2.4GHz 且密码已知。

模块引脚单片机引脚说明
USB 供电板载 USB 口WiFi 发射时峰值电流约 200mA，建议用电脑后置 USB 口或 5V/1A 以上电源
天线板载 PCB 天线不需要外接，远离金属遮挡即可
串口GPIO1 / GPIO3（已接板载 USB）用于查看连接状态与 IP，无需手动接线

为什么这样接：

  • 为什么 WiFi 不用接线？ WiFi 芯片和天线都集成在 ESP32 芯片和 PCB 上，软件初始化后直接用，不占外部 IO。
  • 为什么强调供电？ WiFi 射频发射瞬间电流可达 200mA，劣质 USB 线或前置口会导致电压跌到 3.0V 以下，ESP32 反复重启、WiFi 断连。
  • 为什么要远离金属？ PCB 天线靠电磁波辐射，金属外壳或紧贴桌面金属板会严重屏蔽信号，导致距离一远就断。

五、完整代码

把下面代码中的 ssid 与 password 改成你自己的 2.4GHz 路由器名称和密码（示例值，必须替换）。

/* ESP32 STA 模式连接 WiFi，并定期发起 HTTP GET 请求（零基础注释版） */
#include <WiFi.h>
#include <HTTPClient.h>

const char* ssid     = "YourWiFiName";      // TODO 改成你的 WiFi 名（仅 2.4GHz）
const char* password = "YourWiFiPassword";  // TODO 改成你的 WiFi 密码

void setup() {
  Serial.begin(115200);
  delay(200);

  WiFi.begin(ssid, password);                 // 发起连接
  Serial.print("正在连接 WiFi");
  while (WiFi.status() != WL_CONNECTED) {     // 死等到连上
    delay(500);
    Serial.print(".");                        // 每 500ms 打一个点
  }
  Serial.println();
  Serial.print("WiFi 已连接，IP 地址：");
  Serial.println(WiFi.localIP());            // 打印拿到的内网 IP
}

void loop() {
  if (WiFi.status() == WL_CONNECTED) {        // 已联网才发请求
    HTTPClient http;
    http.begin("http://httpbin.org/get");     // 公共回显接口
    int httpCode = http.GET();                // 发起 GET，返回状态码

    if (httpCode > 0) {                       // 状态码 >0 表示有响应
      String payload = http.getString();       // 读响应体
      Serial.print("HTTP 状态码：");
      Serial.println(httpCode);
      Serial.println(payload);
    } else {
      Serial.println("请求失败：" + http.errorToString(httpCode));
    }
    http.end();                               // 必须释放连接
  } else {
    Serial.println("WiFi 已断开，尝试重连…");
    WiFi.reconnect();
  }
  delay(10000);                               // 每 10 秒请求一次
}

第二个实例：断线自动重连（事件驱动，适合长期不掉电的设备）——主程序用的是「轮询 + 手动 reconnect」，这个变体改用 WiFi 事件回调，断开瞬间就触发重连：

/* WiFi 变体：事件驱动的断线自动重连 */
#include <WiFi.h>

const char *ssid     = "你的WiFi";
const char *password = "你的密码";

void onWiFiEvent(WiFiEvent_t event) {
  switch (event) {
    case WIFI_STA_DISCONNECTED:        // 掉线事件
      Serial.println("WiFi 断开，正在重连…");
      WiFi.begin(ssid, password);      // 立即重新发起连接
      break;
    case WIFI_STA_GOT_IP:              // 拿到 IP 事件
      Serial.print("已连接，IP: ");
      Serial.println(WiFi.localIP());
      break;
  }
}

void setup() {
  Serial.begin(115200);
  WiFi.onEvent(onWiFiEvent);           // 注册事件回调
  WiFi.mode(WIFI_STA);
  WiFi.begin(ssid, password);
}

void loop() {
  delay(2000);                         // 业务代码这里写
}

想换个测试目标？把 http.begin("http://httpbin.org/get") 改成 http.begin("http://example.com")，就能看到 example.com 的 HTML 源码打印在串口里。

六、代码逐段讲解

第 1 段：头文件与 WiFi 账号（第 2~6 行）

在做什么： 引入 WiFi.h（连路由器）和 HTTPClient.h（发 HTTP）两个库，再定义两个字符串常量存 SSID 和密码。

为什么这么写： 库不 include 会编译不过；把账号密码放顶部常量，换 WiFi 时只改这两行，不用在代码里到处找。

不写会怎样： 漏掉 include，IDE 报「WiFi 未定义」；账号密码写错或留占位，串口会一直打点、永远连不上。

第 2 段：setup() 里连接 WiFi（第 8~18 行）

在做什么： 打开串口 → 调 WiFi.begin → 用 while 循环等 WiFi.status() 变成 WL_CONNECTED → 打印 IP。

为什么这么写： WiFi.begin 只是发起动作，真正握手要 1~5 秒；不等就连读 IP，会读到 0.0.0.0。while 循环里打「.」是让你在串口里看到「正在拨号」的进度感。

不写会怎样： 去掉 while 直接读 localIP，多半打印 0.0.0.0；后续 http.begin 也会因为没网而失败。

第 3 段：loop() 里发 HTTP GET（第 20~35 行）

在做什么： 检查 WiFi 还连着 → 建 HTTPClient → begin 网址 → GET → 状态码大于 0 就读响应体打印 → end 释放。

为什么这么写： httpCode > 0 表示服务器回了状态码（200/404 等），≤0 表示连不上/DNS 失败。getString 一次性读全部响应，对入门演示够用；end 不调会导致内存逐渐耗尽、几轮后崩溃。

不写会怎样： 漏掉 http.end，跑一段时间 ESP32 会因为内存泄漏反复重启；不判断 httpCode 直接 getString，失败时会打印空字符串误导你。

第 4 段：断网重连（第 36~39 行）

在做什么： 每轮 loop 先看 WiFi.status()，如果不是 CONNECTED 就打日志并调 WiFi.reconnect()。

为什么这么写： 路由器重启、ESP32 走远都会导致断连；不主动重连的话，程序就一直躺在「已断开」状态里再也不联网。

不写会怎样： 断一次就永久失去联网能力，必须手动按复位键才能恢复。

第 5 段：WiFi 事件 ↔ Arduino API 三层对照（教材视角）

和 GPIO 一样，WiFi 也是分层封装：Arduino 的 WiFi 类底下是乐鑫 ESP-IDF 的 esp_wifi_* / esp_event 驱动 API，最底下才是 802.11 固件与射频硬件。教材常见对照如下：

你写的 Arduino 函数底层 ESP-IDF API / 事件说明
WiFi.begin(ssid,pwd)esp_wifi_set_config() + esp_wifi_connect()配置 STA 并发起连接
WiFi.onEvent(cb)esp_event_handler_register(WIFI_EVENT, …)注册 WiFi/IP 事件回调
WIFI_STA_GOT_IP 事件IP_EVENT_STA_GOT_IPDHCP 拿到 IP 的事件
WiFi.localIP()esp_netif_get_ip_info()读 netif 里的 IP

为什么重要：课程设计里若要用事件驱动重连（见第二个实例），理解「WiFi.onEvent 就是封装 esp_event」后，你就能看懂官方例程里 WIFI_STA_DISCONNECTED / WIFI_STA_GOT_IP 这些事件名从哪来。

七、现象演示说明

  • 现象 1：上电后串口先打印一串「.」，约 2~5 秒后停止，并输出「WiFi 已连接，IP 地址：192.168.x.x」。
  • 现象 2：每隔 10 秒打印一段 JSON，其中 "origin" 字段就是 ESP32 当前出口公网 IP。
  • 现象 3（验证上行）：登录路由器后台查看「已连接设备」，应能看到一个名为「espressif…」的设备，IP 与串口打印一致。
  • 现象 4（断网测试）：关掉路由器 2.4G，串口应打印「WiFi 已断开，尝试重连…」；路由器恢复后 ESP32 自动重连并继续打印 JSON。

可量化的验证方法：

  • 数间隔：从两行「已发布」之间掐表，应约为 10 秒（delay(10000) 决定）。
  • 改间隔看变化：把 delay(10000) 改成 delay(3000)，打印频率应变快到 3 秒一次。
  • 查 origin IP：串口 JSON 里的 origin 应该和你电脑浏览器访问 ip.cn 看到的公网 IP 一致（同一出口）。
