DMA 直接存储器访问

系列：STM32 进阶 更新：2026-10-25

串口收 100 字节、ADC 采 500 个点、SPI 搬 4KB 数据——如果都靠 CPU 逐字节搬，主循环就被「搬砖」占死了。DMA（直接存储器访问）就是芯片里的「专职搬运工」：设定好「从哪搬到哪、搬多少」，它自己搬完，CPU 全程只负责下命令。本课把 DMA 讲透，并给出串口 DMA 收发的最常用写法。

一、本课目标与前置知识

学完本课你能做到：

  • 说清 DMA 是什么、为什么能解放 CPU、和中断有什么分工。
  • 看懂 DMA 的「源地址 / 目的地址 / 传输长度」三要素和通道映射。
  • 用 HAL 完成串口 DMA 发送与接收，并理解回调函数。

需要提前掌握的前置知识（对应学习路线阶段 4）：

  • 串口基础（stm32-usart.html）：DMA 最常见的搭档就是串口。
  • 存储器地址（stm32-register.html）：DMA 就是在「地址之间」搬数据。
  • 中断与回调（stm32-exti.html）：DMA 完成时会触发中断，回调函数写法与 EXTI 类似。

本课会出现的新名词：DMA、通道/请求映射、源/目的地址、传输计数、半传输/传输完成中断、循环模式、HAL_UART_Receive_DMA、DMA 回调。

二、基础概念铺垫

1. 为什么需要 DMA：别让 CPU 当快递员

生活类比：老板（CPU）有一批文件要搬去仓库（外设/内存）。如果老板亲自一趟趟跑，一趟一字节，几百趟下来别的活全耽误了。正确做法：雇一个专职快递员（DMA），告诉他「从 1 号柜搬到 2 号柜、搬 100 件」，老板转头去干别的，快递员搬完自己汇报。

一句话定义：DMA 是一种不经过 CPU 内核、直接在存储器与外设之间搬运数据的硬件模块。CPU 只需配置一次「从哪搬、搬到哪、搬多少」，DMA 自动完成，搬完用中断通知。

例子：串口要发 1KB 数据：不用 DMA 时 CPU 一个字节一个字节写 SBUF；用 DMA 后 CPU 设好源地址（内存数组）和目标（USART 数据寄存器），1KB 自动发完，CPU 去算别的。

2. 通道与请求映射：快递员的「专属线路」

生活类比：DMA 有多个通道（F103 共 2 个控制器、7+5 个通道），每个通道像一条专属快递线路：串口发送走 4 号线、ADC 走 1 号线、SPI 接收走 2 号线——不能乱走。

一句话定义：每个外设的 DMA 请求（如 USART1_TX、ADC1、SPI1_RX）都对应固定的 DMA 通道。CubeMX 里勾选外设的 DMA 后自动分配通道；手册里的「DMA 请求映射表」规定了谁走哪个通道，乱配则不工作。

例子：USART1_TX 固定在 DMA1 通道 4，USART1_RX 在 DMA1 通道 5——CubeMX 勾选后自动生成，但你要知道「为什么是这个通道」。

3. 源地址 / 目的地址 / 传输长度：三要素

一句话定义：DMA 配置的核心三要素：源地址（数据从哪来：内存数组 或 外设数据寄存器）、目的地址（数据到哪去）、传输长度（搬多少字节/半字/字）。外设侧地址一般固定（如 &huart1.Instance->DR），内存侧地址由你给。方向决定源和目的的角色。

例子：串口发送 DMA：源 = 你的数组 buf，目的 = USART1->DR，方向 = 内存→外设。

4. 循环模式与单次模式

一句话定义：单次模式：搬完指定长度就停（发一次数据）；循环模式：搬完自动从头再搬，适合持续接收（串口收流、ADC 连续采样）。CubeMX 里 DMA Mode 选 Normal（单次）或 Circular（循环）。

例子：串口「发一条数据」用 Normal；「持续接收上位机发来的不定长数据」常配合 Circular + 空闲中断（进阶话题）。

三、原理介绍：一次 DMA 串口发送的完整过程

DMA 是芯片里独立于 CPU 的「搬运工」：你只配一次「从哪搬到哪、搬多少」，它就在硬件里搬完一整批才叫你一声。

整条链路：CPU 配好源/目的/长度 → 启动 DMA → 外设请求一来 DMA 自动搬一字节 → 搬完触发完成中断 → CPU 只在最后被叫一次。

原理 1：三要素——一次搬运要告诉 DMA 哪三件事

DMA 通道必须先配三个参数：源地址（内存 buf 或外设 DR）、目的地址（外设 DR 或内存）、传输长度（字节数）。以串口发为例：源=内存 buf、目的=USART1->DR、长度=len。CPU 调一次 HAL_UART_Transmit_DMA() 就立刻返回，主循环照跑，搬运全由 DMA 硬件做。

教材必补：数据宽度必须两端对齐（PAR/MAR size）。DMA 每个通道有两组「数据宽度」配置——外设寄存器侧(PAR)和存储器侧(MAR)，可选字节(8 位)/半字(16 位)/字(32 位)。UART 的 DR 是 8 位、ADC 的 DR 是 16 位，所以：串口 DMA 两端都选 Byte；ADC+DMA 采集 uint16_t 数组必须选 Half-Word。经典坑：ADC 是 16 位结果，你却把 DMA 宽度配成 Byte，DMA 会按字节拆着搬，uint16_t 数组里高/低字节错位，读出来的值全是错的（且不报错）；反之把 8 位串口数据按 Word 搬，会把相邻内存也当数据一起搬走。CubeMX 里 Peripheral Data Size 与 Memory Data Size 要和外设寄存器真实位宽一致。

原理 2：为什么 DMA 比逐字节中断快

中断模式每收发一字节就打断 CPU 一次——压栈、跳转、读寄存器、出栈，一次几十个周期。发 100 字节就被打断 100 次。DMA 则是「搬完一整批才中断一次」。数据量越大差距越明显，而且搬运期间 CPU 可同时干别的（这就是 ADC+DMA 边采集边算、CPU 不被拖慢的原因）。

原理 3：Normal vs Circular——为什么接收常用环形

Normal 模式搬完预设长度就停下，再来字节直接丢——适合「发固定长度命令」。Circular 循环模式搬到末尾后指针自动绕回开头接着搬，永不停止。串口这种「一直在发、不知何时结束」的场景用 Circular：DMA 后台持续填缓冲、主循环随时读最新数据，既不丢字节，也不必每字节约一次中断——这就是不定长接收省 CPU 的关键。

记忆点：DMA 三要素=源/目的/长度，CPU 配一次、搬一批、才中断一次；比逐字节中断快在「少打断」；Normal 搬完停、Circular 指针绕回永不停止，串口接收用 Circular。

四、硬件接线说明

DMA 是芯片内部功能，无需额外接线。硬件上只需：

模块接线说明
USB 转 TTL 模块TX→PA10(RX1)、RX→PA9(TX1)、GND 共地串口 1 接电脑，观察 DMA 收发
LED（可选）PC13 或板载演示「发送完成回调」时翻转
按键（可选）PA0 接 GND触发一次 DMA 发送

为什么不需要给 DMA 接线：DMA 在芯片内部连接存储器和外设，物理上没有任何外部引脚——它只是「搬运路径」，外设（串口）的引脚接线不变。这也是 DMA 好用的原因：软件配置，零硬件成本。

避坑 CubeMX 里勾了 DMA 后，工程会多出 MX_DMA_Init()，且它必须在 MX_USART1_Init() 之前调用（生成代码已排好序，别乱改 main.c 的顺序）。

五、完整代码

CubeMX 配置要点：USART1 波特率 115200；在 DMA Settings 里给 USART1_TX 加 DMA（Normal 模式）。核心代码：

示例 1：DMA 发送 + 按键触发 + 完成回调翻灯

/* DMA 串口发送：主循环不阻塞，发送完成回调翻转 LED */
#include "main.h"

extern UART_HandleTypeDef huart1;

uint8_t msg[] = "Hello DMA, CPU is free now!\r\n";

/* DMA 发送完成回调：HAL 自动调用（不可改函数名与签名） */
void HAL_UART_TxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart == &huart1) {
        HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);   /* 每发完一次翻一次 LED */
    }
}

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_DMA_Init();              /* 必须先于外设初始化 */
    MX_USART1_Init();           /* 内含 DMA 句柄绑定 */

    while (1) {
        if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) {
            /* 启动 DMA 发送：此函数立即返回，不阻塞主循环 */
            HAL_UART_Transmit_DMA(&huart1, msg, sizeof(msg) - 1);
            HAL_Delay(100);     /* 简单消抖 */
        }
        /* 主循环还能干别的事，发送由 DMA 在后台完成 */
    }
}

示例 2：DMA 固定长度接收（接收 10 字节后自动处理）

/* DMA 接收：提前启动，收满 10 字节回调处理 */
#include "main.h"

extern UART_HandleTypeDef huart1;

uint8_t rx_buf[10];
uint8_t rx_done = 0;            /* 置 1 表示已收满一批 */

/* 接收完成回调：HAL 自动调用 */
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart == &huart1) {
        rx_done = 1;            /* 标记：这批数据可用 */
        /* 再次启动接收，准备下一批（循环接收的标准写法） */
        HAL_UART_Receive_DMA(&huart1, rx_buf, 10);
    }
}

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_DMA_Init();
    MX_USART1_Init();

    /* 先启动接收：DMA 在后台等数据，来一个存一个 */
    HAL_UART_Receive_DMA(&huart1, rx_buf, 10);

    while (1) {
        if (rx_done) {
            rx_done = 0;
            /* 此时 rx_buf[0..9] 是刚收到的 10 字节，处理它 */
            HAL_UART_Transmit_DMA(&huart1, rx_buf, 10);  /* 原样回显 */
        }
    }
}

六、代码逐段讲解

第一段：TxCpltCallback——DMA 完成的「汇报」

HAL 库规定回调函数名字和签名不能改（框架按名字找它）。参数 huart 告诉你哪个串口完成了。为什么先判断 huart==&huart1：工程可能开了多个串口，判断是哪个完成的，避免误处理。不写会怎样：不写回调 = 发送照样完成，只是没有「完成后动作」——很多新手以为必须写，其实它是可选的，按需用。

第二段：Transmit_DMA 与普通 Transmit 的区别

HAL_UART_Transmit(&huart1, ...) 是阻塞式：函数不返回，直到发完；HAL_UART_Transmit_DMA(...) 是异步式：函数立刻返回，搬运交给 DMA。什么时候用哪个：要立刻回数据且数据短 → 阻塞式简单；数据长或主循环不能等 → DMA。注意坑：DMA 传输期间不能修改源数组 msg，否则发出去的是改后的数据。

第三段：Receive_DMA 的「提前启动」逻辑

接收 DMA 必须先开再等：HAL_UART_Receive_DMA(&huart1, rx_buf, 10) 一启动，DMA 就在后台等数据，收满 10 字节自动触发回调。为什么回调里要再次启动：单次（Normal）模式收满就停了，想继续收下一批必须重新启动——「收一批 → 处理 → 再收一批」是接收的标准循环。

第四段：rx_done 标志的意义

回调发生在中断上下文，主循环在普通上下文——两者不能直接共享复杂逻辑，用 rx_done 标志「交接」：中断里置位，主循环看到再处理。为什么不用直接在主循环轮询缓冲：你无法知道 DMA 什么时候写满，轮询会漏或重复处理；标志位是中断与主循环通信的最简方式。

七、现象演示与验证

  • 发送实验：按一次按键，串口助手收到 Hello DMA, CPU is free now!，同时板载 LED 翻转一次。
  • 接收实验：串口助手发 10 字节，收到原样回显的 10 字节（回调里再次启动后继续收）。

验证方法：

  1. 在 HAL_UART_Transmit_DMA 下一行放断点，单步后主循环立即返回——证明函数非阻塞。
  2. 发送期间立刻改 msg[0] 的值再观察串口——体会「DMA 传的是地址指向的数据」。
  3. 把 Receive 的长度改成 5，串口助手发 5 字节回显、发 8 字节只回显前 5——验证固定长度接收的边界。

八、常见报错排查方案

报错现象可能原因解决方法
DMA 发送没反应MX_DMA_Init 顺序错 / 通道没绑对确认 DMA_Init 在外设 Init 前；CubeMX 重新生成，核对 DMA 请求
发送内容乱码或不全传输期间改了源数组 / 长度给错发送完成前别改数组；长度 = 实际字节数（不含 \0）
接收不到数据没提前启动 Receive_DMA初始化后立刻 HAL_UART_Receive_DMA(...)
回调不执行函数名写错 / 没判断 huart对照头文件核对 HAL_UART_TxCpltCallback 拼写
收完一批后不再收Normal 模式收完即停回调里重新启动 Receive_DMA（标准循环）
和 ADC/SPI 同时用 DMA 冲突通道被占用（如 ADC1 与 TIM 冲突）查 DMA 请求映射表，改用另一个通道/控制器
ADC+DMA 采进 uint16_t 数组，数值高低字节错位、全是错值（教材宽度坑）DMA 数据宽度配成了 Byte(8 位)，而 ADC DR 是 16 位；半字/全字宽度与外设寄存器位宽不一致CubeMX DMA Settings 里把 Peripheral/Memory Data Size 都设为 Half Word(16 位) 配 ADC；串口 DR 8 位则两端都设 Byte。宽度配错不报错，只会静默搬错
