74HC573 总线扩展与 IO 复用

系列：51 单片机 进阶 更新：2026-10-25

51 单片机总共 32 根 IO，又要显示、又要键盘、又要传感器，引脚总不够用。教材的解法是「总线扩展」：用锁存器把一套数据线变出多套输出。本课用 74HC573 把 P0 口「复用」成段码线和位选线，驱动 8 位数码管。

一、本课目标与前置知识

学完本课你能做到：

  • 说清锁存器的「透明」与「锁存」两个状态，以及 OE、LE 引脚的作用。
  • 理解 P0 口分时复用：先送段码锁存、再送位选锁存。
  • 用两个 74HC573 驱动 8 位数码管显示多位数字。

需要提前掌握的前置知识（对应学习路线阶段 2）：

  • 数码管显示：本课是它的大屏升级版。
  • 位运算：位选用移位生成。
  • IO 输出：P0 口上电默认高阻，要开漏驱动。

本课会出现的新名词：总线扩展、锁存器、透明锁存、LE（锁存使能）、OE（输出使能）、分时复用、74HC573、74HC138 译码器。

二、基础概念铺垫

1. 为什么需要总线扩展：引脚不够用是常态

生活类比：你只有一只手（P0 口 8 根线），却要同时给 8 个柜子（8 位数码管）送东西。怎么办？叫 8 个「保管员」（锁存器）站成一排，你把东西交给其中一个保管员，他先替你拿着（锁存），你再把同样的东西交给下一个——手只有一只，但东西最终都送到了。

一句话定义：总线扩展 = 用少数数据线 + 使能信号，控制多组输出。51 里最常见的做法：P0 口输出 8 位数据，经锁存器分发给不同的外设（段码、位选、LCD 数据……），每组外设由一根「锁存信号线」决定「什么时候接住 P0 的数据」。

例子：上一课 4 位数码管用了段 P0 + 位 P2 共 12 根线；用两个 573 后，P0 8 根线 + 2 根锁存信号就够，省下 4 根 IO。

2. 锁存器：一个「听口令的透明仓库」

一句话定义：74HC573 是 8 位 D 型锁存器：输入 D0~D7，输出 Q0~Q7，控制脚 LE（锁存使能）和 OE（输出使能）。LE=1 时透明：输出跟随输入变化（仓库门开着）；LE 从 1 变 0（下降沿）时锁存：输入再怎么变，输出保持刚才的值（门关上，货物被固定）。OE=0 时输出有效（OE=1 时输出高阻，一般直接接地）。

例子：先把段码放上 P0 → LE 给一个下降沿 → 段码被「冻住」在 573 的输出上 → 之后 P0 随便换数据，数码管的段不变。

3. 分时复用：一根总线轮着用

一句话定义：P0 同一时刻只能输出一个 8 位数据，所以「段码」「位选」要轮流送：送段码 → 锁存段码；送位选 → 锁存位选。两个 573 各有一个 LE，谁被触发谁就接住当前数据。这样 P0 在不同时刻扮演不同角色，就叫分时复用。

例子：动态扫描 8 位数码管的每轮循环：P0=段码 → LE1 下降沿 → P0=位选 → LE2 下降沿 → 延时 1ms → 下一位。8 位轮一圈，人眼看到 8 位同时亮。

4. 74HC138：3 根线选 8 路

一句话定义：74HC138 是 3-8 译码器：输入 3 根选择线（A0~A2），输出 Y0~Y7 八路中恰好一路为低。当位选需要 8 路且追求更省线时，用 138 代替「8 个位选 IO + 573」：3 根线就能选中 8 位中的任意一位（0b000~0b111）。本课代码以 573 为主，138 作为延伸。

例子：给 138 输入 101，Y5 输出低电平，第 5 位数码管位选通。

三、原理介绍：P0 只有 8 根线，怎么同时稳住「段码」和「位选」两套数据

电路核心：P0 → 两个 74HC573 的 D 输入；573-1 的 Q 接段码(a~dp)、LE1 接 P2.6；573-2 的 Q 接位选、LE2 接 P2.7。两个 573 的 OE 都接地常开。

一轮动态扫描的步骤：

  1. 消隐：位选 573 送 0x00 锁存，关掉所有位（防残影）。
  2. 送段码：P0=seg[当前位]；LE1 给下降沿锁存段码。
  3. 送位选：P0=0x01<<i；LE2 给下降沿锁存位选。
  4. 延时约 1ms 保持，i++ 重复。

原理 1：锁存器为什么能把 P0 的数据「冻住」

74HC573 是 8 位 D 锁存器，行为由 LE 一脚决定：LE=1（透明）时，输出 Q 完全跟着输入 D 走——像开着门的仓库，P0 上是什么，输出就是什么；LE 从 1 变 0（下降沿）那一刻，把此刻 D 的值「拍快照」锁进输出，之后 P0 怎么变、输出都不动。为什么数码管非得要这个：动态扫描时 P0 要不停在「段码」和「位选」两个数据间切换，但数码管的段码必须从头到尾稳住不能变——否则位选切换瞬间段码也跟着变，就花屏了。锁存器就是这块「快照」：段码拍一次照冻在 573-1 输出上，之后 P0 空出来去送位选，段码纹丝不动。

原理 2：两个 573 共用一根 P0，为什么不打架——分时复用

关键在于两个 573 的 LE 接了不同引脚（P2.6/P2.7）。同一时刻，你只让一个 573 的 LE 出现下降沿——只有它接住 P0 当前数据并锁存，另一个 LE 一直是低、输出保持原来的快照。于是 P0 在不同时刻轮流扮演两种角色：这一拍送段码给 573-1、下一拍送位选给 573-2，靠「LE 轮流触发」把本来要 16 根线（8 段+8 位选）的事压缩到 8 根 P0 + 2 根 LE。这就是总线分时复用——P0 是「公共舞台」，两个锁存器是「轮流上台接戏的人」，同一时刻只有一个在接。

原理 3：为什么 P0 必须外接上拉排阻

和 P1~P3 不同，P0 口内部没有上拉电阻，是真正的开漏输出——写 1 时内部两个 MOS 都截止，引脚既不拉高也不拉低、处于高阻态。直接接 74HC573 的输入，高电平没有任何东西把它托起来，识别不准。所以 P0 外扩总线时必须加 8 路 10kΩ 排阻上拉到 VCC，让写 1 时确有高电平输出。这也解释了为什么 P0 适合做地址/数据总线：它正好需要这种外部上拉的开漏结构来做双向分时，而 P1~P3 的弱上拉反而不适合。

记忆点：573 的 LE=1 透明(Q 跟 D)、下降沿锁存(拍快照冻住)；段码必须稳住、位选要轮切，靠两个 573 的 LE 轮流触发把段码/位选「分时」挤进同一条 P0；P0 是开漏口、无内部上拉，外扩必须加排阻。

四、硬件接线说明

以 8 位共阴数码管 + 2 个 74HC573 为例：

模块引脚单片机引脚说明
573-1 D0~D7P0.0 ~ P0.7段码数据输入
573-1 LE1P2.6段码锁存信号（下降沿锁存）
573-2 D0~D7P0.0 ~ P0.7位选数据输入（与段码同线）
573-2 LE2P2.7位选锁存信号
573 的 OEGND接地，输出常开
573-1 Q0~Q7数码管段 a~dp段码输出
573-2 Q0~Q7数码管位 COM1~COM8位选输出（共阴：输出 1 点亮）

为什么段码和位选共用 P0 不冲突：两个 573 的 LE 由不同引脚控制，同一时刻只有一个 573「透明接住」P0 数据，另一个保持锁存——这就是分时复用的硬件前提。

避坑 Proteus 里 74HC573 元件名 74HC573（或 74LS573 同脚位）；共阴数码管选 7SEG-MPX8-CC。若用共阳数码管，位选逻辑要取反（输出 0 点亮），段码表也不同——先确认板子类型再写代码。

五、完整代码

两个 573 驱动 8 位数码管动态显示 20241025（共阴、段码接 P0）。

/* 74HC573 双锁存器驱动 8 位数码管 */
#include <reg52.h>

sbit LE_SEG = P2^6;              /* 段码锁存使能（573-1） */
sbit LE_BIT = P2^7;              /* 位选锁存使能（573-2） */

/* 共阴段码表：0~9 */
unsigned char code seg[10] = {0x3F,0x06,0x5B,0x4F,0x66,
                              0x6D,0x7D,0x07,0x7F,0x6F};

void delay_ms(unsigned int ms) {
    unsigned int i, j;
    for (i = 0; i < ms; i++)
        for (j = 0; j < 120; j++);
}

/* 段码锁存：把 P0 当前值锁进 573-1（先高透明，再拉低锁存） */
void lock_seg(void) {
    LE_SEG = 1;                  /* 透明：输出跟随 P0 */
    LE_SEG = 0;                  /* 下降沿：锁存当前段码 */
}

/* 位选锁存：把 P0 当前值锁进 573-2 */
void lock_bit(void) {
    LE_BIT = 1;
    LE_BIT = 0;
}

/* 动态扫描一帧：按 num[8] 显示 8 位数字 */
void display(unsigned char *num) {
    unsigned char i;
    for (i = 0; i < 8; i++) {
        /* 1. 消隐：位选全 0，避免残影 */
        P0 = 0x00;
        lock_bit();
        /* 2. 送段码并锁存 */
        P0 = seg[num[i]];
        lock_seg();
        /* 3. 送位选并锁存：第 i 位点亮（共阴输出 1） */
        P0 = 0x01 << i;
        lock_bit();
        /* 4. 保持点亮约 1ms */
        delay_ms(1);
    }
}

void main(void) {
    unsigned char buf[8];
    /* 要显示的数字 2 0 2 4 1 0 2 5 */
    buf[0] = 2; buf[1] = 0; buf[2] = 2; buf[3] = 4;
    buf[4] = 1; buf[5] = 0; buf[6] = 2; buf[7] = 5;
    while (1) {
        display(buf);            /* 无限循环扫描，视觉上 8 位同亮 */
    }
}

变体：让数字每秒走动——一个秒表。上面显示的是写死的 8 位数字，把它改成「从 0 开始每秒 +1」就能看到动态扫描真的在持续刷新、内容真的在变。display() 必须被高频反复调用（每次只点亮一位、1ms 后切下一位），所以「计时」不能用阻塞延时——而是数 display() 被调了多少次来估算 1 秒：

/* 变体：8 位数码管秒表，从 0 每秒自增（复用上面的 seg 表/display） */
void main(void) {
    unsigned long sec = 0;       /* 已过秒数，用 long 防止溢出 */
    unsigned char buf[8];
    unsigned int loop_cnt;
    /* 上电先全 0 */
    buf[0]=buf[1]=buf[2]=buf[3]=buf[4]=buf[5]=buf[6]=buf[7]=0;
    while (1) {
        /* 把 sec 拆成 8 位数字放进 buf（从个位 buf[0] 开始） */
        {
            unsigned long t = sec;
            unsigned char k;
            for (k = 0; k < 8; k++) { buf[k] = t % 10; t /= 10; }
        }
        /* display 一帧约 8ms，循环约 125 帧 ≈ 1 秒 */
        for (loop_cnt = 0; loop_cnt < 125; loop_cnt++) {
            display(buf);        /* 这一帧里不断扫描才不闪 */
        }
        sec++;                   /* 满 1 秒，数字 +1 */
    }
}

为什么要数 display 次数而不是 delay_ms(1000)：如果在主循环里 delay_ms(1000)，这 1 秒内 display() 一次都没被调用，数码管会全灭或严重闪烁——动态扫描要求每位每 5~10ms 就被重新点亮一次。所以做法是「边扫描边数数」：display 一帧约 8ms，数满约 125 帧（≈1 秒）才让秒数 +1。这也是真实项目里数码管/键盘扫描都放在主循环高频轮询、而把定时交给定时器的原因。

六、代码逐段讲解

第一段：两个 lock 函数是分时复用的核心

lock_seg() 里 LE_SEG = 1; LE_SEG = 0; 就是「透明 → 锁存」两步：先让 573 跟随 P0，再下降沿把此刻的 P0 数据冻住。段码锁存后，P0 才能安全地换成语义完全不同的位选数据——顺序绝不能反：先锁段码，再送位选。

第二段：动态扫描四步与消隐

每轮先 P0=0x00; lock_bit(); 把位选全关（消隐），再依次送段码、锁段码、送位选、锁位选。为什么必须消隐：不消隐的话，切换过程中「上一位的段码 + 下一位的位选」会短暂组合，产生鬼影闪烁。消隐这 1 行，是动态扫描画质的分水岭。

第三段：位选 0x01 << i 的含义

0x01 << i 生成第 i 位为 1 的掩码（i=0 → 0x01，i=3 → 0x08），对应共阴数码管「输出 1 点亮该位」。为什么用移位：8 位位选本质就是 8 个标志位，位运算课讲的「用位表示多路开关」在这里直接落地。

第四段：main 里的 buf 数组

要显示的数字先装进 buf[8]，display() 只负责「按数组扫一遍」。为什么数据与扫描分离：这样后续做秒表时，只要每秒改 buf 里的值，显示代码一行不用动——与蜂鸣器课「音符表/节拍表分离」是同一个工程思想。

七、现象演示与验证

  • 静态验证：显示 20241025 8 位数字，无闪烁、无残影、无缺笔画。
  • 锁存验证：把 lock_seg() 注释掉，段码会随 P0 变化乱跳——证明锁存的作用。
  • 消隐验证：把消隐两行注释掉，可看到换位瞬间的鬼影。

验证方法：

  1. 改 buf 显示 88888888，逐位检查 8 段是否全亮、有无共用串线。
  2. 把延时从 1ms 加到 5ms，观察闪烁（扫描频率不够）；降到 0.5ms，观察亮度变化（占空比下降）。
  3. 用示波器（或 Proteus 虚拟示波器）看 LE_SEG 与 LE_BIT：两个信号交替出现下降沿，验证分时复用。
