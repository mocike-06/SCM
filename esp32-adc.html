ADC 模拟读取与电压换算

系列：ESP32 进阶 更新：2026-10-25

上一课用 PWM 输出「假模拟」，这一课读真正的模拟量：电位器旋钮、光敏电阻、电池电压——都是连续变化的电压，ESP32 用内置 ADC 把它们变成 0~4095 的数字。本课讲透 12 位分辨率、参考电压、衰减（attenuation）这三个 ESP32 特有的坑，并做出「光敏测光 + 串口打印」的完整例子。

一、本课目标与前置知识

学完本课你能做到：

  • 说清 ADC 的分辨率、参考电压、量化误差，会算电压换算公式。
  • 正确使用 analogRead 与 analogSetPinAttenuation，避开 ESP32 的衰减坑。
  • 用光敏电阻 + 分压电路测光，把数字量换算成电压显示。

需要提前掌握的前置知识（对应学习路线阶段 5）：

  • PWM 概念（esp32-pwm.html）：PWM 是输出、ADC 是输入，一对「模拟量双胞胎」。
  • 51 的 ADC0832 或 STM32 ADC（阶段 2/4）：分辨率/参考电压概念完全一致。
  • 欧姆定律与分压电路（初中物理即可）：光敏测光靠分压。

本课会出现的新名词：ADC、模拟量/数字量、分辨率、参考电压、量化、衰减（attenuation）、analogRead、analogSetPinAttenuation、分压电路。

二、基础概念铺垫

1. ADC：把连续电压「数格子」

生活类比：量杯测水高度——刻度越细，读数越准。ADC 就是给电压画刻度：0~3.3V 的连续电压，被切成若干格，每格对应一个整数。

一句话定义：ADC（模数转换器）把引脚上的模拟电压转换成数字。ESP32 内置 ADC 是 12 位：把输入范围切成 4096 格（0~4095），分辨率 = 参考电压 / 4096（若参考 3.3V，一格 ≈ 0.8mV）。

例子：GPIO34 输入 1.65V → analogRead(34) 大约返回 2048（一半）。

2. 参考电压与衰减：ESP32 特有的两个坑

生活类比：量杯的「满刻度」就是参考电压。普通单片机满刻度=供电电压（3.3V）；但 ESP32 的 ADC 硬件参考电压是 1.1V，直接量 3.3V 会爆表——所以需要「衰减」（attenuation），相当于给量杯加了个分流器，把 0~3.3V 压进 0~1.1V 再测量。

一句话定义：衰减档位决定 ADC 能安全测量的最大电压：ADC_0db（满量程 1.1V）、ADC_2_5db（1.5V）、ADC_6db（2.2V）、ADC_11db（满量程约 3.9V，常用）。配错衰减的后果：电压超量程读数顶格 4095 且非线性。

例子：量 0~3.3V 信号必须 analogSetPinAttenuation(34, ADC_11db)，否则超过 1.1V 后读数失真。

3. analogRead：一步读出数字

一句话定义：analogRead(引脚) 返回该引脚的 ADC 数字值（0~4095）。ESP32 的 ADC 可用引脚有限制：ADC1（GPIO32~39） 在 Arduino 里直接可用；ADC2（GPIO0、2、4、12~15 等） 与 WiFi 共用硬件，WiFi 开启时 ADC2 会失灵——所以传感器一律优先接 GPIO32~39。

例子：光敏分压接 GPIO34（ADC1 通道 6），analogRead(34) 实时返回光照对应的数字。

4. 分压电路：传感器电压怎么来

一句话定义：很多传感器是「可变电阻」（光敏电阻、热敏电阻），不能直接量电阻值——把它和固定电阻串成分压电路，中间抽头电压随电阻变化，ADC 量这个电压就「间接量出电阻」。公式：Vout = VCC × R2 / (R1 + R2)。

例子：光敏电阻 R1 + 固定 10kΩ R2 串联接 3.3V，抽头接 GPIO34：光照强 → 光敏电阻小 → Vout 高；光照弱 → Vout 低。ADC 数值直接反映光照。

三、原理介绍：从模拟电压到数字的完整链路

ADC（模数转换器）把引脚上的模拟电压变成一个数字。ESP32 的 ADC 有个反直觉的设计：内部比较器只能测 0~1.1V，却要让你测 3.3V——全靠中间的衰减网络。理解「采样保持→量化→衰减映射」这条链，才能搞懂为什么衰减档决定量程、为什么 analogRead 是 0~4095。

一次读电压的链路：采样保持抓住引脚电压 → 与内部基准比较量化成 N → 按衰减档反推实际电压 → 软件平均去噪。

原理 1：采样保持与量化——为什么 analogRead 是 0~4095

ADC 工作分两步：采样保持——采样瞬间内部电容充电到引脚电压，把「这一瞬间的电压」冻住；量化——把冻住的电压和内部基准比较，切成若干档，输出最近的档数 N。ESP32 是 12 位 ADC，即 2¹² = 4096 档，所以 N 从 0 到 4095——位数越高档越细，但转换越慢越贵，12 位是精度与速度的折中。还原电压：电压 = N × 实际满量程 / 4096。

原理 2：衰减网络——为什么内部 1.1V 基准能测 3.3V

问题来了：内部基准只有 1.1V，引脚上来个 3.3V 不是超量程了？解法是衰减器——它是一个可编程分压网络，先把外部电压按比例缩小再送进比较器。ADC_0db 不衰减，只能测约 1.1V；ADC_11db 衰减后可测到约 3.9V。代价是分辨率被摊薄：同样 4096 档，量程从 1.1V 拉到 3.9V，每档代表的电压从约 0.27mV 变成约 0.95mV——所以测小信号选小衰减档，测 3.3V 电源才用 11dB。这就是「衰减档决定量程」的物理含义。

原理 3：为什么要多次平均，以及 ADC1/ADC2 的坑

每次量化都有 ±几档的噪声，直接读会跳动——工程上连续读 8~16 次取平均就稳了。另外 ESP32 把 ADC 分两组：ADC1（GPIO32~39）独立于 WiFi，开着 WiFi 也能稳定用；ADC2（GPIO0/2/4/12~15 等）和 WiFi 共用射频校准，WiFi 一连上它就读数飘——所以教程一律把模拟输入接 ADC1。为什么满量程不能写死 3.3V：衰减档不同实际满量程不同（11dB 约 3.9V），追求精度要做两点校准（量个已知电压反推真实满量程）。

记忆点：ADC=采样保持冻住电压→量化成 0~4095；内部基准只有 1.1V，靠衰减网络分压才能测 3.3V（0dB≈1.1V、11dB≈3.9V），衰减越大每档越粗；ADC1（GPIO32~39）开 WiFi 也稳，ADC2 会飘；噪声大就读多次取平均。

四、硬件接线说明

光敏测光：光敏电阻 + 固定电阻分压，抽头接 GPIO34（ADC1，不受 WiFi 影响）：

元件接法说明
光敏电阻 R1一端 3.3V，一端接抽头光照强阻值小（约几 kΩ）
固定电阻 R2抽头一端，另一端 GND建议 10kΩ，和光敏阻值同量级
抽头节点GPIO34ADC1 通道 6，WiFi 可用
电位器（练习用）两端 3.3V/GND，抽头 GPIO34替代光敏，先熟悉旋钮读数

为什么抽头必须接 GPIO32~39：这些是 ADC1 引脚，WiFi 连接时不受影响；而 ADC2 引脚（GPIO4、12~15 等）WiFi 一开就失灵——物联网项目几乎都要连 WiFi，传感器接 ADC1 是铁律。接线时还要注意：ADC 输入不能超过衰减量程，分压抽头电压上限要算清楚。

避坑 光敏电阻两个脚没有极性，但分压顺序有讲究：想让「光越强读数越大」，就把光敏放在上臂（3.3V 侧）；接反了现象会反过来（光强读数小），不是坏了。接线前先量一下抽头电压范围是否在量程内。

五、完整代码

示例 1：光敏测光 + 电压换算 + 串口打印

/* 光敏电阻测光：analogRead + 电压换算 + 平均值滤波 */
const int adcPin = 34;      /* ADC1 引脚（WiFi 下可用） */

void setup() {
  Serial.begin(115200);
  /* 关键：量 0~3.3V 必须开 11db 衰减，否则超 1.1V 后读数失真 */
  analogSetPinAttenuation(adcPin, ADC_11db);
}

int readAvg(int pin, int n) {
  long sum = 0;
  for (int i = 0; i < n; i++) {
    sum += analogRead(pin);   /* 读一次 0~4095 */
    delay(2);                 /* 两次采样间隔，稳定电压 */
  }
  return (int)(sum / n);      /* 取平均，压制噪声 */
}

void loop() {
  int n = readAvg(adcPin, 16);       /* 平均 16 次 */
  /* 电压换算：满量程按 3.3V 近似（11db 实际略高，要精确需校准） */
  float v = n * 3.3f / 4095.0f;

  Serial.print("ADC=");
  Serial.print(n);
  Serial.print("  Voltage=");
  Serial.print(v, 2);                 /* 保留 2 位小数 */
  Serial.println(" V");

  delay(500);                         /* 0.5 秒采一次 */
}

示例 2：手动遮挡光敏，LED 亮度随光自动调节（PWM 联动）

/* 光控灯：光照越强 LED 越暗（路灯逻辑），PWM + ADC 联动 */
const int adcPin = 34;
const int ledPin = 4;

void setup() {
  analogSetPinAttenuation(adcPin, ADC_11db);
  ledcSetup(0, 5000, 8);
  ledcAttachPin(ledPin, 0);
}

void loop() {
  int n = analogRead(adcPin);             /* 0(暗) ~ 4095(亮) */
  /* 取反映射：光越强 duty 越小；4095 → 0，0 → 255 */
  int duty = map(n, 0, 4095, 255, 0);
  ledcWrite(0, duty);
  delay(50);
}

六、代码逐段讲解

第一段：analogSetPinAttenuation 为什么必须调

这句最容易漏。不写会怎样：默认衰减档很小（约 1.1V 量程），3.3V 直接超量程，读数在超过 1.1V 后顶格 4095——光敏在中高亮度时读数「卡死」，你以为程序 bug，其实是衰减没配。ADC_11db 的含义：最大衰减档，量程扩大到约 3.9V，覆盖 3.3V 全范围，是量「板子电压范围信号」的标配。

第二段：readAvg 的平均滤波

连续读 16 次累加再平均。为什么非平均不可：ADC 读数有 ±2~3 个 LSB 的随机噪声，单次读数会在某个值附近跳（如 2000、2003、1998）；平均后稳定很多，电压显示不乱跳。为什么采样间 delay(2)：给 ADC 电容重新充电、电压稳定一点时间，连续狂读会互相干扰。

第三段：电压换算公式的口径

n * 3.3f / 4095.0f 是「满量程 3.3V」近似。注释里明确标了「11db 实际满量程略高于 3.3V，要精确需校准」——为什么不能写死 4096 或 3.9：4096 是理论档位（0~4095 共 4096 格，除以 4096 才对，这里用 4095 是常见近似，差一档无感）；满量程随衰减档变化。严谨做法是两点校准，教程给近似 + 说明，正是「先能用、再调精」的学习路径。

第四段：map 的联动逻辑

map(n, 0, 4095, 255, 0) 把 0~4095 线性映射到 255~0（取反）：光强 n 大 → duty 小 → LED 暗。为什么参数顺序这样写：map 的格式是 map(值, 源下限, 源上限, 目标下限, 目标上限)——目标上下限反过来写就是取反映射，比手写公式直观不易错。

第五段：寄存器 ↔ 驱动 API ↔ Arduino 函数三层对照

教材视角下，ADC 的三层关系如下：

你写的 Arduino 函数底层 ESP-IDF 驱动 API最终操作的硬件寄存器
analogRead(34)adc1_get_raw()SENS 模块 ADC 数据寄存器（12 位结果）
analogSetPinAttenuation(34, ADC_11db)adc1_config_channel_atten()SENS 模块 ADC 衰减配置寄存器
引脚配成模拟输入adc1_channel_config()IO_MUX 把引脚切到 ADC 通道

为什么重要：ESP32 的 ADC 属于 SENS（传感器）模块，analogRead 底下是 adc1_get_raw 去读 SENS 数据寄存器。课程设计若要高精度采集，就要回到 ESP-IDF 的 ADC 校准 API（esp_adc_cal），理解这层关系才找得到门。

七、现象演示与验证

  • 串口读数：串口每 0.5 秒打印一行 ADC=xxxx Voltage=x.xx V；手遮光敏，ADC 与电压明显下降；强光下回升。
  • 光控灯：遮住光敏 LED 变亮，松开变暗，无闪烁。

验证方法：

  1. 用万用表量抽头电压，与串口打印的 Voltage 对比，误差应在 ±0.1V 内（近似换算下）。
  2. 故意注释掉 analogSetPinAttenuation 重烧，手动遮挡看读数是否在中段「卡 4095」——亲手验证衰减的必要性。
  3. 把光敏换成电位器，旋到底应读到接近 0/4095 两端——验证分压与量程边界。

八、常见报错排查方案

报错现象可能原因解决方法

读数全是 0 或乱跳引脚不是 ADC 引脚 / 悬空没接确认用 GPIO32~39；接好分压抽头，别让引脚悬空

九、课后练习与延伸

练习 1（必做）：把示例 1 的电压换算改成「实测校准」：用万用表量抽头电压 V_real，串口同时打印 V_real 与 ADC 值，反推满量程并更新公式。

练习 2：把光控灯阈值化：光线暗到一定程度（ADC < 500）串口输出 "Too dark!" 并开灯——加上 WiFi/MQTT 就能做成物联网智能路灯。

练习 3（进阶）：用两个 ADC 通道同时采光敏和电位器，串口画个简易「折线」（每 100ms 打一个亮度符号），观察两条曲线——多通道 ADC 的基础。

延伸学习：ADC 是「被动读」，下一课学 定时器与中断——让采样变成「定时自动发生」，不用 loop 里傻等，系统更高效。
